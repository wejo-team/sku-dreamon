# 논리 모델 리뷰 기준

이 문서는 [모델 인덱스](README.md)의 검토용 설계를 명세와 대조하는 기준입니다. 아래 시나리오는 **설계 리뷰 항목**이며 구현 테스트를 실행했다는 결과가 아닙니다. 새로운 정책을 이 문서에서 확정하지 않습니다.

## 영역 간 권한

`허용`도 현재 계정 상태·해당 자원 존재·유효한 관계를 재확인한다는 뜻입니다. 탈퇴 효력은 별도 미정이며 아래 표는 정상 이용 계정 기준입니다.

| 자원·행동 | 비로그인 | 본인 | 일반 로그인 사용자 | 해당 팀장 | 현재 팀원 | 공고 관리자 |
| --- | --- | --- | --- | --- | --- | --- |
| 공개 공모전·팀 모집 정보 | 허용 | 허용 | 허용 | 허용 | 허용 | 허용 |
| 사람 검색·일반 상세 | 불가 | 본인 열람 가능 | 공개 프로필만 | 일반 탐색은 공개만 | 공개만 | 관리자 역할만으로 비공개 예외 없음 |
| 기존 지원자의 전체 현재 프로필 | 불가 | 본인 허용 | 비공개 예외 없음 | 자기 팀에 지원한 관계에서 허용 | 소속만으로 비공개 예외 없음 | 공고 관리 권한만으로 허용하지 않음 |
| 지원 메시지·본인 지원 이력 | 불가 | 해당 지원자 허용 | 불가 | 받은 지원만 | 불가 | 공고 관리 권한만으로 허용하지 않음 |
| 팀 공간 | 불가 | 소속에 따라 판정 | 불가 | 자기 팀 허용 | 현재 소속 팀 허용 | 공고 관리 권한만으로 허용하지 않음 |
| 모집 종료·재개·지원자 선발 | 불가 | 팀장인 경우 | 불가 | 자기 팀에서 조건 충족 시 | 불가 | 공고 관리 권한만으로 허용하지 않음 |
| 공고 등록·수정 | 불가 | 관리자 역할 필요 | 불가 | 팀장 역할만으로 불가 | 불가 | 허용; 화면·운영 도구 TBD |
| 일반 AI | 불가 | 로그인 후 허용 | 공개 범위 내 허용 | 일반 대화에 지원자 예외 혼합 금지 | 공개 범위 내 허용 | 같은 일반 AI 권한 |
| 지원자 AI 검토 | 불가 | 지원자라는 이유만으로 불가 | 불가 | 자기 팀의 지원 관계에서 허용 | 불가 | 공고 관리 권한만으로 허용하지 않음 |
| 개인 알림·읽음 처리 | 불가 | 수신자만 | 타인 항목 불가 | 자기 수신 항목만 | 자기 수신 항목만 | 타인 항목 불가 |

팀장·현재 팀원·관리자는 서로 다른 관계입니다. 전역 `role=leader` 하나로 모든 팀의 지원자를 볼 수 있게 하지 않습니다. 관리자 역할의 범위를 공고 관리 이상으로 확대하지 않습니다. 팀장 변경은 제공하지 않으므로 승계 기능을 설계에 추가하지 않습니다.

## 설계 검증 시나리오

| 상황 | 모델이 표현해야 하는 결과 |
| --- | --- |
| 사용자 U가 공모전 C의 A·B팀과 다른 공모전 D의 E팀에 지원한 뒤 A에서 선발 | A 지원은 선발, A 소속 1건, B 대기 지원은 폐기, E 지원은 유지 |
| A 선발 처리가 도중에 실패 | A 소속·B 폐기·성공 알림 중 일부만 남지 않음 |
| 같은 선발을 다시 요청 | 소속·정원·폐기 사건·알림을 중복 생성하지 않음 |
| A 선발 후 본인이 취소 | A 소속 종료·자리 반환. B 폐기 유지. A가 닫혔다면 팀장 재개 전 신규 지원 불가 |
| 마지막 자리 선발과 동시에 다른 지원자를 선발 | 정원 안의 한 명만 성공. 실패한 지원자의 다른 대기 지원은 폐기하지 않음 |
| 같은 공모전의 두 팀이 같은 사람을 동시에 선발 | 소속 한 건만 성공. 확정된 상태를 다른 선발이 덮어쓰지 않음 |
| 공모전/팀 기한이 지났거나 정원이 찬 팀의 재개 | 재개 실패·기존 상태 유지. 원문 시간대를 적용한 경계 사용 |
| 자격 분류·학과가 공고 설명과 다르거나 학적 정보 미입력 | 자동 차단하지 않고 원문 안내. 비공개 신규 지원 등 다른 제한은 정상 적용 |
| 지원 후 비공개 전환, 이후 다른 팀 선발로 해당 지원 폐기 | 일반 검색/AI 사람 추천 제외. 받은 팀장은 최신 전체 프로필 검토 가능하나 새 선발 후보 제외 |
| 전공 소속 개편 후 기존 프로필의 소개만 수정 | 기존 학사 경로 유지. 새 선택은 현행 유효 경로만 허용 |
| 과거 선발 알림을 누를 때 이미 취소·소속 종료 | 당시 사건은 유지하지만 현재 팀 공간 권한을 복구하지 않음 |
| AI 응답 생성 도중 일반 추천 대상이 비공개로 변경 | 이전 공개 근거·카드·복사 내용으로 우회 노출하지 않도록 현재 권한 재검증 |

## 실제·시연 데이터의 구분

[시연 데이터 정책](../specs/sprint-1.md#demo-data-scope)에 따라 Account·Contest·Team 각각에 `is_demo`를 두는 설계안을 사용합니다. 시연 표시를 위한 출처 구분이며 일반 권한·마감·정원·지원·선발 조건을 우회하는 값이 아닙니다. 시연 계정과 실제 팀, 실제 계정과 시연 공고의 연결도 허용하므로 같은 값끼리만 연결하는 제약을 만들지 않습니다.

지원·소속은 관련 계정·팀·공고의 구분을 조회하며 별도 모순된 시연 여부를 복제하지 않습니다. 팀의 시연 여부를 생성자 계정에서 무조건 상속하는 정책도 추가하지 않습니다. 초기 데이터 준비·구분값 부여·표시 UI는 담당 명세의 후속 범위입니다. 논리 모델링에서는 시연 비밀번호·가상 운영 데이터 삽입 코드를 작성하지 않습니다.

## 아직 확정하지 않은 부분

이번 결정으로 해결된 항목을 다시 미정으로 돌리지 않습니다. 아래는 남은 범위이며 해당 기능의 최종 제약/저장 계약을 확정하기 전에 결정해야 합니다.

| 미정 범위 | 모델에서 보류한 것 |
| --- | --- |
| 회원 탈퇴의 서비스 효력·복구·아이디 재사용, 팀장 탈퇴·팀 삭제 | 소속 자동 종료·권한 회수 시점·연쇄 삭제·영구 보존·자동 위임을 확정하지 않음 |
| 이미 확정 소속이 있는 사용자의 다른 팀 신규 지원, 팀 생성 시 대기 지원 | 선발 시 폐기 규칙을 다른 사건에 임의 확대하지 않음 |
| 미선발·폐기 뒤 새 지원, 검토·미선발 진입, 마감 뒤 실제 선발 | 상태는 표현하지만 미승인 전이는 열지 않음 |
| 모집 편집·지원 메시지 수정·과거 이력 표시 | 새로운 수정 권한·상세 이력 화면을 만들지 않음 |
| 팀 생성·개인화 추천의 최소 프로필 요구 | 신규 지원의 필수 프로필 규칙을 모든 행동에 자동 확대하지 않음 |
| 주최 측 조건 변경의 기존 팀·지원 영향 | 요청대로 TBD. 자동 퇴출·일괄 폐기·과거 조건 고정 없음 |
| 관리자 페이지·권한 부여/회수·수집/갱신 도구 | 관리자 관리 책임만 모델링; 승인 단계·운영 UI 없음 |
| 인증 세션·계정 복구, AI 대화/결과·알림·지원의 보존/삭제 | 저장소나 기간을 임의 결정하지 않음 |
| 현행 학사 목록·관계·공통 코드 사전 | 운영 데이터 검증이 필요한 항목으로 표시 |
| 별도 매칭 상태·공고 요약 | 업무 의미·MVP 포함 여부 결정 전 별도 확정 엔터티로 만들지 않음 |
| LLM 내부 아키텍처 | 논리 정보 경계만 제안; 공급자·검색·프롬프트·실행·평가·캐시 설계 보류 |

이 미정 사항이 전체 초안 작성을 막는 것은 아닙니다. 영향을 받는 전이·관계만 미확정으로 표시하고, 이미 정해진 계정·프로필·공고·팀·지원·소속 관계부터 리뷰합니다.
