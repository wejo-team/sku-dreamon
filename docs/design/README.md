# 공식 디자인 레퍼런스

서경드림온의 **모바일 제품 디자인 기준**입니다. 프론트엔드 개발자는 저장소의 [실행 앱](../../design-reference/README.md)을 로컬에서 열고, 담당 화면의 코드·명세·상태를 함께 확인합니다. GPT Sites 링크를 개발의 기준으로 사용하지 않습니다.

| 문서 | 읽는 시점 |
| --- | --- |
| [개발 인계](handoff.md) | 처음 실행하거나 제품 프론트로 옮길 때, 데이터·인증·AI 구현 범위를 확인할 때 |
| [화면과 기능 명세](screens.md) | 담당 화면의 경로·소스·정상/예외 상태와 남은 정책을 찾을 때 |
| [스타일과 컴포넌트](tokens.md) | 색상·간격·모바일 배치·shadcn/ui 컴포넌트를 적용하거나 변경할 때 |

`design-reference/`는 디자인을 클릭하며 확인하는 독립 앱이고, `frontend/`는 실제 제품을 구현하는 앱입니다. 서비스 정책 원본은 [기능 명세](../specs/README.md), 화면·인터랙션 원본은 같은 커밋의 레퍼런스 코드입니다. 차이를 발견하면 디자인과 명세를 함께 검토하며, 모의 데이터 처리 방식을 실제 API 계약으로 확정하지 않습니다.

디자인 변경은 관련 명세·레퍼런스 코드·필요한 확인 자료를 같은 PR에서 추적합니다. 화면 이미지를 추가하더라도 실행 가능한 코드와 상태 검증을 대신하지 않습니다. 실제 기능·LLM·백엔드의 구현 상태는 각 명세와 제품 구현 PR에서 별도로 확인합니다.

화면과 검사 결과는 [검증 기록·모바일 스크린샷](verification.md)에서 확인합니다.
