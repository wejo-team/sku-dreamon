# 프론트엔드 개발 인계

팀의 공식 화면·인터랙션 기준은 저장소의 `design-reference/`입니다. 제품 개발에서는 같은 브랜치·커밋의 레퍼런스와 명세를 참조합니다. 배포된 GPT Sites가 이후 변경되더라도 저장소에 반영되지 않은 내용을 자동으로 공식 기준으로 사용하지 않습니다.

이번 레퍼런스 변경은 [선행 문서 PR #93](https://github.com/wejo-team/sku-dreamon/pull/93)과 [#77 최신 결정](https://github.com/wejo-team/sku-dreamon/issues/77#issuecomment-6260435650)을 기준으로 합니다. 새 입력 계약·프로필 공개 조건·공고와 정원·AI 검토·알림 정책을 담당 명세에서 먼저 확인합니다. 문서 검토, 디자인 반영, 실제 제품 구현과 배포 완료는 각각 구분합니다.

## 로컬 실행

저장소 루트에서 시작합니다. Node·npm 버전은 [레퍼런스 package.json](../../design-reference/package.json)과 [.nvmrc](../../design-reference/.nvmrc)에 고정돼 있습니다.

```bash
cd design-reference
nvm use
npm ci
npm run dev
```

[로컬 레퍼런스 열기](http://127.0.0.1:5174/)로 접속합니다. 개발 서버는 `127.0.0.1:5174`를 사용하고 포트가 사용 중이면 실패합니다. 다른 앱을 종료하거나 포트를 임의 변경하기 전에 현재 실행 중인 서버를 확인합니다. 백엔드·DB·환경 변수·API 키는 필요하지 않습니다.

| 항목 | 값 |
| --- | --- |
| 아이디 | `dreamondemo` |
| 비밀번호 | `DreamonReview2026!` |
| 시작 경로 | `/` → `/design-preview/login?returnTo=%2Fdesign-preview%2Fexplore` |
| 탐색 | `/design-preview/explore` |
| AI | `/design-preview/ai` |

위 계정은 공개된 로컬 UI 확인용 문자열입니다. 실제 서비스 계정·비밀값이나 인증 구현이 아닙니다. 로그인 전에도 공개 공모전·팀을 볼 수 있고 사람 탐색·AI·개인 화면에는 로그인 안내가 표시됩니다. AI는 공모전·팀·사람 등 요청 대상과 관계없이 로그인 후에만 이용하며 직접 주소에도 같은 제한을 적용합니다.

모바일 화면으로 확인하며 별도 데스크톱 서비스 디자인은 제공하지 않습니다. 넓은 창에서는 최대 480px 화면이 가운데 배치됩니다. 브라우저의 모바일 에뮬레이션에서 폭 320px·390px·430px을 확인하고 입력창 키보드·안전 영역·바닥 메뉴는 실제 기기에서도 검증합니다.

## 데이터·인증·AI의 실제 범위

- 데이터는 메모리에 있으므로 새로고침하면 초기 로그인·프로필·팀·지원 상태로 돌아갑니다. 다른 브라우저나 팀원의 화면과 공유되지 않습니다. 탭 이동 중 유지되는 상태도 영구 저장을 뜻하지 않습니다.
- 로그인은 고정 문자열을 검사하며 계정 발급·비밀번호 해시·서버 세션을 제공하지 않습니다. 가입 화면은 아이디를 ASCII 영문 소문자·숫자 4~24자로 정규화하고, 비밀번호는 NFC 후 코드 포인트 15~128자·공백 보존을 적용합니다. 보기/숨기기·붙여넣기·자동완성을 허용합니다. 중복 확인은 공개 테스트 아이디에 한정하며 흔한 비밀번호 4개 fixture만 차단합니다. 실제 유출 비밀번호 목록·갱신이나 새 계정 등록을 구현한 것이 아니며 가입한 값으로 로그인할 수 없습니다.
- 지원·취소·선발·정원·팀 공간은 로컬 상태 전환을 확인합니다. 실제 여러 사용자 간 동시 요청, 서버 권한 검사·트랜잭션·DB 보존은 제품에서 구현해야 합니다.
- 프로필은 기본 비공개이며 하나의 스위치가 등록된 모든 항목에 적용됩니다. 전환 Drawer 확인 후 저장하며 취소·닫기·실패는 기존 상태를 유지합니다. **신규 팀 지원은 공개 상태에서만 제출**합니다. 비공개 사용자는 같은 공개 팝업을 거쳐 저장 후 현재 지원 조건을 다시 확인하며 자동 접수하지 않습니다. 공개면 일반 로그인 사용자의 사람 검색·AI 사람 추천·상세에서 전체 항목을 볼 수 있고 비공개면 제외합니다.
- 지원 후 비공개 전환은 기존 지원·팀 소속을 바꾸지 않습니다. 해당 지원을 받은 팀장은 전체 현재 프로필을 직접 보고 AI 검토에 최신 프로필을 반영할 수 있습니다. 일반 팀원·미지원 팀장·일반 AI 사람 추천으로 이 권한을 확대하지 않습니다. 인증 정보·미수집 연락처·외부 포트폴리오 내용 수집은 포함하지 않습니다. 화면은 이 관계를 모의 처리하며 실제 모델 입력 필드·보존·삭제는 여전히 설계 대상입니다.
- 프로필은 이름 1~50자, 관심 분야 1~3개, 희망 역할 1~2개를 필수로 받습니다. 학적·학년은 선택, 역량은 목록 내 개수 상한 없이 선택합니다. 경험은 미입력/경험 없음/최대 500자 서술, 자기소개는 300자, 포트폴리오 제목은 50자까지입니다. 기타·보충 설명 입력은 제거합니다. 앞뒤 공백을 제거한 뒤 검증하며 초과 입력을 보존해 수정하도록 안내합니다. 비밀번호 외 Unicode 계수는 제품 계약 TBD로, 레퍼런스는 코드 포인트를 사용합니다.
- 주당 참여 가능 시간은 **모든 참여 프로젝트를 합산한 자기신고 예상 총량**으로 `5시간 미만 / 5~10시간 미만 / 10~20시간 미만 / 20시간 이상` 중 하나를 선택하거나 미입력으로 둡니다. 팀별 약속·잔여 시간·일정 교집합이 아닙니다. 기존 요일별 시간 입력과 팀 생성 시간 입력을 제공하지 않으며, 팀 공간의 일정 조율은 후속 기능입니다. 저장 코드·실제 기존 데이터 전환은 미정입니다.
- 공모전은 공통 관심 분야를 복수 사용하고 참가 대상을 대학생/일반인/제한 없음/미확인으로 구분합니다. 대학생·일반인은 함께 선택 가능하고 제한 없음·미확인은 단독 값입니다. 개인/팀 참가 유형과 준비 모임 예외를 제거하며, 모든 팀 목표 정원은 공고의 최소·최대 인원을 따릅니다. 고정 N명은 N명, 범위·상한 없음은 팀장이 직접 입력하고 정원 1명은 추가 모집하지 않습니다. 공모전 카드 숫자는 모집 상태와 관계없이 연결된 모든 팀 수입니다.
- AI는 로그인한 세션에서 예시 데이터로 로컬 응답을 만드는 UI입니다. 사용자 메시지는 최대 1,000자이고 초과 입력을 자르지 않습니다. 답변당 추천 카드는 종류 합계 최대 3개이며 같은 대화에서 추가 요청할 수 있습니다. 새 대화는 현재 메시지·초안을 초기화하고 과거 대화 목록은 제공하지 않습니다. 로그아웃하면 대화·초안도 제거합니다. 제품 추천은 [LLM 기반](../specs/matching.md)이지만 내부 아키텍처는 TBD이며 로컬 응답 코드를 제품 추천 알고리즘으로 복사하지 않습니다.
- 팀장의 기존 지원자 AI 검토 결과 확인·재요청은 모집 마감·정원 충족 후에도 허용합니다. 새 선발 후보는 유효한 지원 완료·검토 중만 포함하고 선발·미선발·취소는 제외합니다. 기존 유효 지원자는 비공개 전환만으로 제외하지 않으며 신규 지원 제한·정원 초과 선발 금지는 유지합니다.
- 알림은 성공한 업무 변경을 기준으로 내 지원 상태 변경/팀장에게 온 신규 지원 두 계열을 생성합니다. 발생 건·수신자 조합으로 중복을 막고 다음 상태는 새 미읽음 항목으로 추가하며 이전 이력을 유지합니다. 마감 알림은 제외합니다. 메모리의 읽음·발생 이력이며 영구 보존·기기 동기화·푸시·이메일·실시간 서버 이벤트를 구현하지 않습니다. 알림함에서 브라우저 뒤로 가기는 현재 화면을 떠나기 전에 알림함을 닫습니다.
- 공고·인물·팀·학사 선택지는 화면 확인용 데이터입니다. 학사 종속 선택은 같은 소속 관계의 유효값을 유지하고 다른 관계로 이동하면 무효 하위값만 초안에서 비우며 저장·취소를 구분합니다. 현재 학사 fixture는 소속별 문자열이므로 다른 부모 아래 같은 이름을 동일 학과·전공으로 연결하지 않습니다. 학사 데이터의 운영 연도·정규 코드와 실제 공고의 출처·조건은 담당 명세대로 검증합니다. 레퍼런스의 외부 링크를 실제 공고가 존재하거나 접수 가능하다는 근거로 사용하지 않습니다.
- 실제 제품 시연의 계정·데이터·AI 연동 안내는 [시연 기준](../specs/sprint-1.md#web-demo)을 따릅니다. 공식 디자인의 제품 문구와 모의 구현에 관한 개발자 설명을 구분합니다.

## 제품 구현에 옮기는 순서

1. [화면 목록](screens.md)에서 담당 경로·소스·명세 완료 조건을 확인하고 정상·빈 상태·오류·권한 상태를 직접 눌러 봅니다.
2. [스타일](tokens.md)과 재사용 가능한 UI 구성 요소를 참고해 `frontend/`의 해당 기능에 구현합니다. `design-reference/`를 제품 앱의 런타임 의존성으로 연결하지 않습니다.
3. 화면이 필요로 하는 실제 API 계약·서버 권한·저장을 개발 계획에서 정합니다. 메모리 Provider·예시 타입을 그대로 서버 계약으로 사용하지 않습니다.
4. 로컬 상태 예시를 실제 요청의 대기·성공·실패·재시도에 연결하고 명세의 검증·권한을 적용합니다. 사용자 데이터가 없는 첫 사용 상태도 확인합니다.
5. 해당 기능의 실제 구현·검증 결과를 PR에 연결합니다. 디자인 반영과 제품 완료를 구분해 명세 상태를 갱신합니다.

기능 정책이 바뀌면 먼저 해당 명세에 반영하고 관련 화면·테스트·인계표를 같은 변경에서 맞춥니다. 중요한 TBD를 모의 데이터의 값으로 결정하지 않습니다. 남은 정책은 [화면별 미정 사항](screens.md#remaining-decisions)에서 찾습니다.

## 확인 명령

디자인 변경에 필요한 명령을 `design-reference/`에서 골라 실행합니다. 전용 CI는 두지 않습니다.

```bash
npm run lint
npm run format:check
npm run typecheck
npm test
npm run build
npm run preview
```

production build 미리보기는 [127.0.0.1:4174](http://127.0.0.1:4174/)입니다. 정적 빌드는 레퍼런스의 로컬 동작을 확인하는 용도이며 백엔드·LLM이 연결되지는 않습니다. 필요할 때 수행하는 수동 확인과 PR 검사 범위는 [테스트·CI](../development/testing.md#design-reference)에서 설명합니다.

브라우저 검사는 별도 터미널에서 실행 중인 5174 레퍼런스와 Playwright Chromium이 필요합니다. 처음에는 브라우저를 설치한 뒤 같은 `design-reference/` 폴더에서 실행합니다. 로컬의 별도 런타임을 사용하는 경우 `PLAYWRIGHT_MODULE`·`CHROMIUM_PATH`로 경로를 지정할 수 있습니다.

```bash
npx playwright install chromium
npm run check:ui
```
