# API 설계

**상태: 설계가 확정된 비AI API 구현 · AI 스트리밍 백엔드 main 병합.** 화면과 서버가 주고받을 요청·응답, 오류와 권한을 안내합니다. 현재 등록된 경로는 [앱 연결](../../backend/app/main.py)과 실행 앱의 `/docs`·`/openapi.json`에서 확인합니다. 아래 구현 범위는 저장소 코드 기준이며 전체 기능의 완료·운영 배포를 뜻하지 않습니다.

## 읽는 순서

| 문서 | 현재 구현 범위 | 남은 범위 |
| --- | --- | --- |
| [공통 계약](conventions.md) | DTO·성공 응답·페이지·오류·인증 의존성 | 후속 API에 같은 기반 적용 |

| [선택지 API](catalogs.md) | 공통 enum·학사 계층 조회 | 공식 운영 학사 원장 검증 |

| [지원 API](applications.md) | 신규 지원·본인 조회·취소, 팀장 지원자 조회·검토·미선발·선발 | 실서버 브라우저 회귀·운영 검증 |
| [AI API](ai.md) | 일반 추천·지원자 검토/추천 스트림, 실행 제어·결과 재검증 | 프론트 연결·운영 배포·실제 자료 품질 평가 |
| [알림 API](notifications.md) | 본인 조회·읽음, 신규 지원·상태 변경·팀 생성에 따른 사건/알림 | 실서버 브라우저 회귀·운영 검증 |

각 영역 문서에서 실제 라우터·DTO·검증 코드로 이동합니다. 정책·DB·API의 대조 방법은 [정합성 확인 기준](#consistency)을 따릅니다. 개발용 학사·사용자·팀 시드는 [#161](https://github.com/wejo-team/sku-dreamon/pull/161)로 제공하며 [실행 안내](../development/local-development.md)에 따라 별도 적재합니다. 공식 운영 학사 원장과 실제 공고 준비는 별도이며, 빈 조회 결과를 데이터 준비 완료로 해석하지 않습니다. 비AI 화면 API 계층은 #160으로 연결됐고 실제 연동 검증은 [bug bash](../development/bug-bash.md)에서 기록합니다.

각 영역 문서는 **경로·권한·응답 → 요청 조건 → 데이터 필드 → 상태·실패 처리** 순서로 읽습니다. JSON 성공 응답의 실제 결과는 최상위 `data`에서 읽습니다. 표의 `Success<T>`·`Page<T>`, 본문 없는 204, AI SSE의 구분은 [공통 성공 응답](conventions.md#success-responses)을 참조합니다.

문서는 기능의 책임을 기준으로 나눕니다. `/contests/{contestId}/teams`는 팀, `/teams/{teamId}/applications`는 지원 문서에서 정의합니다. 지원자 AI 검토는 AI 문서에 두고, 실제 지원 상태를 바꾸는 검토·선발은 지원 문서에서 정의합니다.

## 문서별 책임

| 정보 | 원본 | 이 문서에서 하는 일 |
| --- | --- | --- |
| 기능 동작·정책·완료 조건 | [기능 명세](../specs/README.md) | 관련 절을 연결하고 적용할 정책 확인 |
| 테이블·컬럼·키·제약·트랜잭션 | [DB 설계](../database/README.md) | 저장 원본과 API의 조회·변경 경계 연결 |
| 구현 전 요청·응답·필드·권한·오류 | 이 폴더의 공통·영역별 Markdown | 프론트·백엔드가 같은 입력·출력·예외를 검토 |
| 구현된 API의 정확한 전송 계약 | FastAPI 라우터·Pydantic 모델과 자동 생성 문서 | 구현 PR에서 설계와 대조하고 해당 코드·생성 문서로 연결 |

수동 OpenAPI YAML은 관리하지 않습니다. API 객체는 DB 행을 그대로 노출하는 구조가 아니므로, 필드마다 저장값·계산값·권한에 따른 값의 차이를 각 영역 표에서 확인합니다. 같은 객체를 여러 곳에서 쓰면 한 정의를 링크하며 필드 표를 복사하지 않습니다.

## 정합성 확인 기준

설계 변경 PR에서는 아래 항목을 대조합니다. 문서의 링크 검사는 참조 오류를 찾고, 정책·상태·동시성의 의미는 교차 검토합니다.

| 변경 또는 확인 대상 | 함께 확인할 것 |
| --- | --- |
| 경로·메서드·접근 권한 | 화면의 행동과 대응하는 요청이 있는지, 본인·팀장·현재 팀원·일반 조회를 구분하는지 |
| 필드·타입·필수값·NULL | 요청/응답 표와 DB 원본·계산 규칙이 맞는지, 선택값 삭제와 필드 생략을 구분하는지. 성공 본문의 최상위 `data`와 페이지 부가 정보·204를 구분하는지 |
| 선택지·글자 수·조합 제약 | 해당 기능 명세를 참조하는지, 상태별 필수/NULL·배열 개수·중복 조건이 빠지지 않았는지 |
| 쓰기·상태 전이·재시도 | 성공 코드·버전·요청 식별자·실패 코드와 DB 트랜잭션·유일 제약이 함께 성립하는지 |
| 공개 범위·시연 데이터 | 목록·총원·상세·지원자·AI 결과에서 현재 권한과 표시용 분류가 일치하는지 |
| 목록·필터·정렬 | 기본값·동률 기준·페이지 보정과 목록/총원의 조회 범위가 같은지 |
| 미정 사항 | 실제로 결정되지 않은 정책을 API나 DB에서 먼저 확정하지 않았는지 |

변경 범위에 맞춰 `python3 scripts/check_docs.py`, 문서 빌드, `python3 scripts/check_docs_site.py`로 링크·게시 결과를 확인합니다. 전체 실행 안내는 [문서 관리](../development/documentation.md)의 로컬 검사 절에 둡니다. 문서를 작성했다는 사실만으로 구현의 정합성이 자동 보장되지는 않으며, 구현 PR에서는 아래 인계 절차와 실제 API·DB 검증이 필요합니다.

## FastAPI 구현으로 인계

1. 담당 API의 정책·필드·오류와 선행 미정 사항을 검토합니다. 필요한 결정을 먼저 명세에 반영합니다.
2. 라우터·Pydantic 요청/응답·인증 의존성·업무 오류 응답을 구현합니다. 자동 문서가 서비스 코드의 권한이나 모든 실패 응답을 추론한다고 가정하지 않습니다.
3. 생성된 OpenAPI와 실제 요청·응답을 이 설계와 대조합니다. 정상 응답뿐 아니라 누락/NULL·금지 필드·권한 거부·409·422·재시도·상태 변경을 해당 API의 검증 범위에 포함합니다.
4. 해당 API의 구현 상태와 검증 근거를 기능 명세·구현 PR에 남깁니다. **구현이 끝난 API의 상세 필드 표는 실제 코드·자동 생성 문서 링크로 대체**하고, 설계 이유·정책 연결·상태/트랜잭션 설명은 유지합니다. 미구현 API의 설계 표는 계속 남깁니다.

FastAPI의 기본 제공 경로는 `/docs`(Swagger UI), `/redoc`(ReDoc), `/openapi.json`(생성 명세)입니다. 등록된 제품 API는 라우터·DTO에서 자동 문서를 생성합니다. 파일 내보내기가 필요해지면 코드에서 생성한 산출물로 취급하며 직접 수정하는 원본을 다시 만들지 않습니다. [FastAPI 자동 문서](https://fastapi.tiangolo.com/tutorial/first-steps/), [백엔드 작성 규칙](../development/backend.md)

## 후속 구현에 남은 결정

인증은 [서버 세션 정책](../specs/authentication.md#session-policy)을 따릅니다. 구현된 CSRF 필드·쿠키 속성·실패 처리는 [인증 DTO](../../backend/app/schemas/auth.py), [쿠키 처리](../../backend/app/routers/auth_cookies.py), [CSRF 검사](../../backend/app/dependencies/csrf.py)가 원본이며 전송 계약은 [병합된 PR #124](https://github.com/wejo-team/sku-dreamon/pull/124)와 [공통 계약](conventions.md#csrf-transport)을 따릅니다. 가입·로그인·아이디 확인과 공유 시도 제한은 구현했습니다. 운영 origin·키·차단 목록 설정, 운영 CORS·도메인은 후속 범위이며 로컬 HTTPS 검증은 [bug bash](../development/bug-bash.md)를 따릅니다.

일반 텍스트 NFC·코드 포인트, 팀 생성의 필수 프로필·공개 불필요 조건, 공고 목록 전체 상태 기본값과 인증 시도 제한·로컬 차단 목록 공급 방식은 2026-10-24 결정으로 확정했습니다. 실제 차단 목록/운영 설정 배포·종료 세션 정리와 보존, 학사 시드 원장의 범위, 공고 입력·갱신 운영 절차는 후속 결정으로 남습니다. AI는 `create_agent`·OpenAI Luna·실시간 답변을 선택했으며 백엔드 전송·실행·메타데이터 저장은 [SDD](../development-plans/ai-agent.md)에 따라 로컬 구현했습니다. 프론트 연결·운영 정리/보존·비용/품질 평가는 후속 작업입니다. 모집 정보·지원 메시지 편집과 공고 변경 영향도 [공통 계약의 보류 목록](conventions.md#deferred) 및 각 기능 명세를 따릅니다. 확정된 모집·지원 전이는 [모집 상태 변경](teams.md#transitions)과 [지원 상태 변경](applications.md#transitions)을 참조합니다. [계정 복구](../specs/authentication.md#account-recovery)는 MVP 범위 밖이며 현재 인증 구현의 선행 조건이 아닙니다.

JSON 이름과 접두사는 [저장소 API 작성 규칙](../development/conventions.md)을 따릅니다. 저장 모델·마이그레이션의 구현 범위는 [DB 인덱스](../database/README.md), 로컬 실행·검사는 [개발 안내](../development/local-development.md)에서 확인합니다.
