# AI 실행 메타데이터

**상태: 백엔드 로컬 구현 · 운영 DB 미적용.** 원문을 보존하지 않고 요청 소유권·실행 상태·중복/취소·현재 결과 검증을 공유합니다. [AI API](../api/ai.md)와 [SDD](../development-plans/ai-agent.md)를 함께 봅니다.

물리 스키마의 원본은 [AiRun 모델](../../backend/app/models/ai_runs.py), 적용 이력은 [20261025_07](../../backend/alembic/versions/20261025_07_ai_runs.py)입니다. SQL·행 잠금은 [레포지토리](../../backend/app/repositories/ai_runs.py), 트랜잭션·소유권·시도 전이는 [실행 서비스](../../backend/app/services/ai_runs.py)에 있습니다.

## 저장 정보

| 영역 | 저장값과 의미 |
| --- | --- |
| 식별·소유 | `ai_run_id` PK, `account_id`·`auth_session_id` FK. API의 `requestId`를 PK로 사용하며 실행 전에 클라이언트가 만든 UUID로 응답 유실 후 상태를 찾음. ID만으로 열람 권한을 얻지 않음 |
| 목적·대상 | 목적, 대화/메시지 ID 또는 팀·지원 FK. 목적별 필수/NULL 조합 CHECK |
| 실행 제어 | 현재 시도·상태·실패 코드·생성/갱신 시각·실행 기한·보존 기한 |
| 입력 중복 방지 | 정규화된 원래 입력·목적·대상의 SHA-256. 원문은 저장하지 않음 |
| 결과 검증 | 결과 SHA-256, 조회된 자료의 종류·ID·관련 ID·사용한 프로필 버전·근거 해시, 선택된 자료의 key |

`references`와 `selected_keys`는 JSONB이지만 임의 도구 출력 저장소가 아닙니다. 서비스가 검증한 식별자·버전·해시만 넣습니다. 대화·프로필·답변 전문, API 키, 도구 인자나 모델 원문을 넣지 않습니다. JSONB 참조의 실제 존재·접근 범위는 사용 시 서비스에서 다시 검증합니다.

## 제약과 동시성

- `(auth_session_id, conversation_id, client_message_id)` UNIQUE로 같은 대화 메시지의 중복 실행을 막습니다.
- `status='pending'`인 `(account_id, scope_key)` 부분 UNIQUE로 같은 대화/검토 대상의 진행 요청을 하나로 제한합니다.
- 계정 행을 잠근 뒤 진행 수·사용량·기존 요청을 검사하고 생성 또는 재시도를 커밋합니다. 시도 번호와 현재 상태를 잠금 안에서 검사하여 이전 취소·완료가 새 시도를 덮지 못하게 합니다.
- 성공/빈 결과에는 결과 해시가, 실패에는 실패 코드가 있어야 합니다. 목적·상태·양의 시도·기한 관계는 CHECK로 제한합니다.
- 본문 전송 전에는 계정 → 공고 → 팀 → 지원 → 프로필 순서의 SHARE 잠금과 실행/세션 잠금을 사용합니다. 데이터 검증과 짧은 ASGI 전송이 끝나면 해제하며 LLM 대기에는 유지하지 않습니다.

## 만료와 정리

실행 기한은 기본 90초, 메타데이터 접근 만료는 시도 시작 기준 기본 24시간입니다. 기한이 지난 진행 실행은 상태 조회 또는 정리에서 재시도 가능한 실패로 바뀝니다. 보존 기한 뒤에는 ID를 알아도 404이며 새 실행의 정리 또는 `uv run python -m app.cli.ai_runs`로 행을 삭제합니다.

정리 명령은 별도 LLM worker가 아니며 모델을 호출하지 않습니다. 정기 실행·운영 백업의 보존/삭제는 배포 설정에서 관리해야 하며 이 테이블이 존재한다는 사실만으로 자동 삭제 스케줄이 설치되지는 않습니다. 지원자 검토 결과도 원문을 저장하지 않으므로 현재 탭에서 가진 결과와 실행 참조로만 재검증하며 새로고침 복원용 GET은 제공하지 않습니다.
