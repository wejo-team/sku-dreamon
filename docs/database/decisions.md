# 설계 결정과 검토

**이 문서는 기능 정책의 복사본이 아닙니다.** 설계 선택의 이유, 아직 확정할 수 없는 경계, 구현 시 확인할 사례를 모읍니다.

<a id="ai-storage"></a>

## AI의 물리 저장 경계

[AI API](../api/ai-notifications.md)는 대화·메시지·요청·결과의 식별과 상태를 설계합니다. 이 식별자가 존재한다는 이유만으로 모두 PostgreSQL 영구 테이블이 되지는 않습니다.

| 정보 | 현재 설계 범위 | 아직 확정하지 않는 것 |
| --- | --- | --- |
| 현재 대화·작성 메시지 | 소유자, 순서, 새 대화와 이전 응답 구분 | 서버 보존 기간, 새로고침 복원, 기기 동기화 |
| 추천 실행·결과 | 요청 상태, 재시도·중단, 검증된 대상 참조 | 작업 큐, 캐시, 제공자, 모델, 실행 저장소 |
| 지원자 AI 검토 | 실제 지원 관계, 사용한 프로필 버전, 현재 접근 검사 | 모델 입력 전문·응답 원문의 저장·삭제 |
| 추천 카드 | 공고·팀·프로필 ID와 결과 근거 | 외부 검색 인덱스·벡터 DB·임베딩 스키마 |

영속화를 선택할 때는 관계형 FK 또는 그에 준하는 참조 검증을 적용하고, 존재하지 않는 대상 ID를 카드로 내보내지 않습니다. 이 문서에서 임의의 `ai_messages`·벡터 테이블을 확정하지 않는 이유는 [MATCH-10·12·13](../specs/matching.md#open-questions)의 선행 결정이 남아 있기 때문입니다.

## 구현 전 남은 결정

| 결정 | 이 설계에서 가능한 것 | 결정 전 확정하지 않을 것 | 정책 원본 |
| --- | --- | --- | --- |
| 남은 인증·세션 운영 정책 | 서버 세션·지속 쿠키 전달, 가입 후 자동 로그인, 토큰 해시 저장, 유휴 24시간·절대 7일 만료, 독립된 동시 세션·현재 세션 즉시 회수 | CSRF 전달·검증 세부, 쿠키 이름·경로, 운영 도메인·시도 제한 수치·정리 및 보존 기간·라이브러리 | [세션 정책](../specs/authentication.md#session-policy), [AUTH 미정](../specs/authentication.md#open-questions) |
| 학교 이메일 인증 · 후속 | 로그인 아이디와 별개인 학교 이메일·인증 완료 시각 저장 필드. 현재는 모두 NULL | 대상 도메인·구성원·인증 수단·주소 정규화·중복 사용·유효 기간·재인증과 API | [저장 필드](identity.md#accounts), [AUTH-02](../specs/authentication.md#open-questions) |
| 계정 탈퇴·데이터 보존 | 안정된 계정 FK, 종료된 소속·지원 이력 | 연쇄 삭제·익명화·아이디 재사용 정책 | [프로필 미정](../specs/profile.md#open-questions) |
| 공고·모집 조건 변경 | 현재 조건과 생성·수정 시각 저장 | 기존 지원 자동 취소·소속 변경 | [주최 측 변경](../specs/contests.md#eligibility-changes) |
| 관리자 운영 | 공고 등록·수정·등록 전 확인의 관리자 책임 | 관리자 계정·인증·권한 저장 방식, 관리자 화면·권한 부여·관리 API | [공고 운영](../specs/contests.md#operation-flow) |
| 코드·학사 원장 확정 | 안정된 코드·변하지 않는 경로 구조 | 확인하지 않은 실제 원장 식별자·임의 분류 추가 | [선택지](../specs/profile-options.md), [학사 구조](../specs/academic-structure.md) |
| AI 운영·저장·미완성 프로필 | 외부 HTTP 계약·소유·대상 권한 | 내부 제공자·영속화·개인화 허용 범위 | [MATCH 미정](../specs/matching.md#open-questions) |
| 알림 전달·보존 | DB 저장·읽음·중복 방지·정렬 설계 | 실시간 채널·보존 기한·삭제·운영 상한 | [NOTIFY 미정](../specs/notifications.md) |

테이블에 상태 코드가 있다고 보류한 기능까지 구현하지 않습니다. API에서도 확정 경로와 정책 결정이 필요한 경로를 구분합니다.

TEAM-02·03·04는 2026-10-21 사용자 결정으로 위 팀·지원 전이와 재지원·소속 정책에 반영했습니다. 팀장의 선발 취소·강퇴·탈퇴·팀 삭제 및 별도 팀 전체 확정 단계는 [MVP 제외 범위](../specs/team-recruitment.md#membership-exclusions)이며 미정인 필수 구현 항목으로 남기지 않습니다. 모집글 편집·조건 변경 영향·계정 탈퇴와 보존 정책까지 확정한 것은 아닙니다.

[계정 복구](../specs/authentication.md#account-recovery)는 MVP 범위에서 제외한 후속 검토 항목이며, 현재 가입·로그인 개발을 막는 선행 결정이 아닙니다. 복구 API·저장 구조를 이번 설계에 추가하지 않습니다.

[공고 등록자·수정자 이력](../specs/contests.md#operation-flow)은 MVP에서 제외합니다. 관리자 권한 테이블과 공고의 등록자·수정자 FK는 이번 설계에 포함하지 않으며, 관리자 계정의 저장 방식은 운영 설계에서 정합니다.

## 구현 시 검증할 사례

아래는 **테스트 계획**이며, 이번 문서 PR에서 실제 DB·API로 통과했다는 뜻이 아닙니다.

| 사례 | 확인할 결과 |
| --- | --- |
| 가입 중 자체 로그인 정보를 포함한 계정 행 또는 세션 행 저장 오류 | 전체 rollback으로 계정·세션 모두 생성하지 않음. 부분 가입 성공 응답·세션 쿠키 발급 없음 |
| 가입 전체 commit 뒤 성공 응답·쿠키 전달 유실 | 저장된 계정·세션은 유지. 가입 rollback으로 안내하지 않고 가입한 아이디·비밀번호의 일반 로그인으로 새 세션을 받을 수 있음 |
| 로그인 세션 저장 실패 | 세션 쿠키 미발급, 원문 토큰이 DB·로그에 남지 않음 |
| 회수·유휴 만료·절대 만료된 세션으로 요청 | 정리 작업 실행 여부와 무관하게 인증 실패, 최근 사용 갱신으로 세션을 되살리지 않음 |
| 마지막 유효 활동부터 24시간 직전·정확한 경계·직후를 각각 독립된 사례로 요청 | 회수·절대 만료가 없다면 직전 요청만 유효. 정확히 24시간부터 인증 실패하며, 만료 검사 전에 `last_seen_at`을 갱신하지 않음 |
| 유효 활동을 계속한 세션이 발급부터 UTC 168시간 직전·정확한 경계·직후에 각각 요청 | 회수·유휴 만료가 없다면 직전 요청만 유효. 정확히 168시간부터 인증 실패하며 활동으로 절대 만료를 연장하지 않음 |
| 브라우저 재시작 후 유휴 24시간·절대 7일 경계 전후에 각각 독립된 사례로 요청 | 기존 쿠키·세션으로 같은 만료 기준 적용. 재시작 자체로 발급·활동·만료 시각을 초기화하지 않고, 이미 만료된 세션은 쿠키가 남아 있어도 거부 |
| 동일 계정으로 새 세션 B 생성 후 활동, 기존 세션 A는 활동 없음 | B 생성으로 A를 회수하지 않음. B 활동이 A의 `last_seen_at`을 바꾸지 않아 A는 자체 기준으로 유휴 만료 |
| 동일 계정의 유효 세션 A에서 로그아웃, B에서는 계속 요청 | A 회수 commit 뒤 쿠키 삭제, A의 이전 토큰 인증 실패. B의 만료·회수 상태는 변경되지 않음 |
| 로그아웃 뒤 이전 쿠키 재사용·최근 사용 갱신과 회수의 경쟁 | 서버 회수 상태 유지, 이전 토큰으로 새 인증을 허용하지 않음 |
| 세션 발급 뒤 팀 소속·지원 관계·프로필 공개 범위 변경 | 현재 관계·공개 상태로 권한 재검사, 세션 보유만으로 이전 접근 권한 유지하지 않음 |
| 두 팀이 같은 공모전의 같은 지원자를 동시에 선발 | 활성 소속 하나, 승리한 선발만 성공, 다른 대기 지원 폐기·알림 각 한 번 |
| 빈자리 하나에 서로 다른 지원자를 동시에 선발 | 정원 초과 없음, 실패한 선발의 사건·소속·알림 없음 |
| 선발 중 같은 사용자가 다른 팀에 신규 지원 | 잠금 순서로 직렬화하고 현재 정책·소속 재검증. 선발 직전 새 지원 누락 폐기 방지 |
| 서로 다른 공모전의 팀장들이 상대 팀에 동시 지원 | 사용자별 직렬화를 유지하면서 팀장 알림의 계정 FK 참조 허용. 계정 잠금과 FK 검사 사이의 순환 대기 없음 |
| 선발·폐기 저장 중 오류 | 부분 변경 없이 전체 rollback |
| 팀 생성과 같은 공모전 신규 지원·다른 팀 선발의 경쟁 | 계정 기준으로 직렬화해 확정 소속 하나만 유지. 생성이 먼저면 신규 지원·선발 실패, 지원이 먼저면 생성 성공 때 그 대기 지원도 폐기 |
| 팀 생성 중 소속·대기 지원 폐기·알림 저장 실패 | 새 팀·팀장 소속·폐기·알림 전체 rollback. 생성 재전송으로 중복 폐기·알림 없음 |
| 팀 생성 성공 후 폐기 사건의 원인 조회 | 같은 계정·공모전의 실제 팀장 소속을 참조. 존재하지 않는 선발 사건을 만들지 않으며 다른 공모전·종결 지원은 유지 |
| 잘못된 폐기 원인 저장 | 다른 사용자·공모전 참조는 FK로 거부. 같은 문맥의 일반 소속·같은 팀·과거 생성 원인 참조는 서비스 검사로 거부 |
| 지원 목록·상세·AI 결과 조회와 명시적 검토 시작 | 조회만으로 상태·사건·알림을 변경하지 않음. 검토 시작 성공에만 대기 지원을 검토 중으로 변경 |
| 미선발 처리와 재지원·선발·본인 취소의 경쟁 | 동일 지원·계정의 현재 상태를 재검사. 미선발 성공 후 같은 팀 재접수·취소 전환·뒤늦은 선발 금지, 다른 팀 지원은 현재 조건 적용 |
| 취소·폐기 후 재지원 | 현재 무소속·모집 조건 충족 시 새 지원 ID로 접수. 종료된 지원·소속을 복원하지 않고 이전 요청이 새 지원을 변경하지 않음 |
| 팀장 종료·팀 모집 기한 경과 뒤 기존 지원 선발 | 공고 접수 마감 전이고 여석·현재 권한·소속 조건을 충족하면 성공. 신규 접수는 계속 차단 |
