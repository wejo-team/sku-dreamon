# 서비스 알림함

- 구현 상태: 예정
- 명세 검토: 2026-10-18 공식 디자인 반영, 2026-10-19 현재 프로토타입 대조는 이 변경 PR에서 사람 검토 대기
- 구현 작업: 미등록

상단 알림 버튼에서 사용자가 본인의 지원·선발 결과와 팀장으로서 확인할 지원자·마감 정보를 볼 수 있게 합니다. 알림은 원래 업무 상태를 연결해 안내하며 지원·선발·모집 상태의 원본을 대체하지 않습니다. 상태의 원본은 [팀 모집과 지원](team-recruitment.md), 공고 마감은 [공모전](contests.md)입니다.

## 범위와 사용자 흐름

1. 상단 벨 버튼에 읽지 않은 알림이 있음을 표시합니다. 하단 프로필 탭과 별도의 진입점입니다.
2. 버튼을 누르면 모바일 알림함이 열립니다. 열기만으로 전체를 읽음 처리하지 않습니다.
3. 사용자는 `전체` 또는 `읽지 않음`으로 보고 개별 알림을 선택합니다. 선택한 항목의 읽음 처리가 성공하면 알림함을 닫고 관련 지원·지원자·공고 화면으로 이동합니다. 실패하면 현재 화면·미읽음 상태를 유지하고, 같은 항목의 읽음 재시도가 성공한 뒤 이동합니다.
4. `모두 읽음`을 누르면 현재 제공된 알림을 읽음 처리합니다. 항목은 삭제하지 않으며 `전체`에서 다시 확인할 수 있습니다.
5. 닫기·바깥 영역·뒤로 닫기 등 일반 팝업 종료 후 기존 화면을 유지합니다. 알림 없는 상태와 읽지 않은 항목이 없는 상태를 구분합니다.

## 알림 대상과 연결

| 대상 | 제공할 정보와 조건 | 이동 |
| --- | --- | --- |
| 지원한 사용자 | 본인의 지원 접수·검토·선발·미선발·취소 등 현재 실제 상태 | 내 지원 현황 또는 해당 지원 상세 |
| 팀장 | 자신이 팀장인 팀에 실제 접수된 지원자 정보 | 해당 지원자의 상세·검토 화면 |
| 팀장 | 자신이 관리하는 팀의 공모전 마감까지 7일 이하이고 아직 마감 전인 경우 | 해당 공고 상세 |

- 실제 데이터에서 확인할 수 없는 선발 결과·초대·읽은 시각·이벤트 발생 시각을 만들어 표시하지 않습니다. 이벤트 시각을 표시한다면 실제 기록에 근거합니다.
- 지원 상태가 바뀌면 그 결과를 새로 확인할 수 있어야 합니다. 알림을 읽거나 모두 읽음 처리해도 지원 상태·정원·팀원 관계가 바뀌지 않습니다.
- 마감 안내의 일수는 공고의 확인된 일정에 근거합니다. 날짜만 있는 공고의 마감 시각·시간대는 [공고의 TBD](contests.md#deadline-policy)를 유지하며, 임의로 시각을 정해 접수 상태를 바꾸지 않습니다.
- 알림에 지원자 정보를 포함할 때도 [프로필 공개 범위](profile.md#visibility)를 적용합니다. 알림 제목·본문·미리보기를 열람 권한이 없는 비공개 프로필의 우회 노출 경로로 사용하지 않습니다.
- 일반 프로필 수정의 알림·변경 배지·변경 전후 안내는 제공하지 않습니다. 현재 정책에 없는 초대·프로필 조회·마감 임박 푸시를 추가하지 않습니다.

## 권한과 예외

| 상황 | 동작 |
| --- | --- |
| 비로그인 | 개인 항목·미읽음 수를 제공하지 않고 로그인 안내 표시 |
| 타인 계정 또는 다른 팀 | 그 사용자의 알림·팀장 전용 지원자 항목에 접근 불가 |
| 알림 없음 | 새 알림이 없음을 안내 |
| 전체 알림은 있고 미읽음 없음 | `전체`에는 기존 항목, `읽지 않음`에는 모두 확인했음을 안내 |
| 대상이 변경·삭제되거나 접근 권한이 사라짐 | 이동 시 현재 권한·존재 여부를 다시 확인. 알림 링크만으로 이전 권한 복원하지 않음 |
| 읽음 처리 실패 | 처리 성공으로 고정하지 않고 미읽음 수·항목을 유지하며 재시도 안내. 개별 항목은 읽음 성공 전 관련 화면으로 이동하지 않음 |

읽음 상태는 사용자별로 관리하고 일반적인 화면 이동 중 유지합니다. 알림 생성·중복 방지·읽음 저장·새로고침 이후 및 여러 기기 간 동기화·보존 기간의 내부 구현은 후속 설계에서 정합니다. 공식 디자인의 로컬 상태 초기화 방식은 실제 서비스의 영구 저장 정책이 아닙니다.

## 현재 디자인 레퍼런스와 남은 차이

배포 v11과 대응하는 디자인 소스 `030d2df`에는 아래 화면 동작이 있습니다. 전체 대조 기준은 [프로토타입·명세 일치 검증](prototype-alignment.md)을 따르며, 이 표는 서버 알림 기능의 구현 완료를 뜻하지 않습니다.

| 항목 | 현재 참고 화면의 동작과 한계 |
| --- | --- |
| 알림 진입 | 상단 벨의 미읽음 점과 접근성 이름의 미읽음 수. 별도 페이지 대신 아래에서 열리는 알림함이며 열기만으로 읽음 처리하지 않음 |
| 항목·이동 | 내 지원 상태는 내 지원 목록으로, 팀장이 받은 지원은 해당 지원자 상세로, 관리 팀의 공모전 마감 안내는 공고 상세로 이동 |
| 읽음 상태 | 전체·읽지 않음 필터, 개별 읽음·모두 읽음, 미읽음 없음·알림 없음 상태. 전체 읽음 후에도 항목을 남기며 화면 이동 중 읽음 상태 유지 |
| 실패·재시도 | `scenario=notification-error`로 최초 읽음 실패를 재현. 개별 읽음 실패 시 이동하지 않고, 재시도가 성공하면 원래 대상 화면으로 이동. 서버 저장 실패를 실제로 발생시킨 검증은 아님 |
| 닫기 | 닫기 버튼·바깥 영역·Escape로 닫는 팝업 동작을 사용. 브라우저·기기 뒤로가기를 알림함 닫기로 처리하는 기능은 아직 없으며 위 흐름 5의 요구와 남은 차이로 유지 |
| 데이터·지속성 | 브라우저의 예시 지원·팀 관계에서 항목을 계산. 읽음 상태는 현재 화면 세션의 메모리에 있으며 로그아웃·새로고침 후 서버 복원·다른 기기 동기화·보존·정렬 정책은 구현하지 않음 |

근거는 [Notifications.tsx](https://github.com/wejo-team/sku-dreamon/blob/030d2df9761334f7f47f870c1afdf163212be1bc/design-reference/src/features/design-preview/Notifications.tsx), [알림 동작 테스트](https://github.com/wejo-team/sku-dreamon/blob/030d2df9761334f7f47f870c1afdf163212be1bc/design-reference/src/features/design-preview/Notifications.test.tsx), [Drawer 구성](https://github.com/wejo-team/sku-dreamon/blob/030d2df9761334f7f47f870c1afdf163212be1bc/design-reference/src/components/ui/drawer.tsx)입니다. 현재 목록의 배열 순서·알림 식별자·메모리 초기화 방식은 실제 생성·정렬·영구 저장 정책의 결정이 아닙니다.

## 완료 조건

체크는 실제 구현·검증을 뜻하며 공식 디자인 추가만으로 완료 처리하지 않습니다.

- [ ] AC-01: 미읽음 표시로 알림함에 진입하고 전체·읽지 않음으로 구분해 볼 수 있다. 열기만으로 읽음 처리하지 않는다.
- [ ] AC-02: 알림 선택 시 해당 항목의 읽음 처리가 성공한 뒤 올바른 지원·지원자·공고 화면으로 이동한다. 읽음 실패 시 이동과 읽음 확정을 보류하고 재시도 성공 후 같은 대상으로 이동한다.
- [ ] AC-03: 모두 읽음 후 알림은 전체 목록에 남고 읽지 않음 목록과 상단 미읽음 표시가 갱신된다.
- [ ] AC-04: 본인의 지원·팀장 관계와 실제 마감 일정에 따른 항목만 표시하며 비로그인·다른 사용자의 항목을 노출하지 않는다.
- [ ] AC-05: 알림 없음·미읽음 없음·읽음 처리 실패를 구분하고, 현재 접근 권한이 없는 대상은 알림 링크로도 열람할 수 없다.
- [ ] AC-06: 프로필 수정 알림이나 확인되지 않은 이벤트·발생 시각을 만들지 않고, 알림 내용에도 현재 프로필 공개 범위를 적용한다.
