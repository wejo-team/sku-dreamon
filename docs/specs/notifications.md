# 서비스 알림함

- 구현 상태: 예정
- 명세 검토: 2026-10-18 공식 디자인 반영, 2026-10-19 [#77 F14](https://github.com/wejo-team/sku-dreamon/issues/77)의 생성·이력·중복 방지와 마감 알림 제외 결정 반영
- 구현 작업: 미등록

상단 알림 버튼에서 사용자가 본인의 지원 상태 변경과 팀장으로서 받은 신규 지원을 확인합니다. 현재는 이 두 계열만 서비스 내부 알림함에서 제공하며 공모전·팀 모집 마감 알림은 제외합니다. 알림은 당시 발생한 사실을 전달하고 [팀 모집과 지원](team-recruitment.md)의 현재 업무 상태를 대체하지 않습니다.

## 범위와 사용자 흐름

1. 상단 벨 버튼에 읽지 않은 알림이 있음을 표시합니다. 하단 프로필 탭과 별도의 진입점입니다.
2. 버튼을 누르면 모바일 알림함이 열립니다. 열기만으로 전체를 읽음 처리하지 않습니다.
3. 사용자는 `전체` 또는 `읽지 않음`으로 보고 개별 알림을 선택합니다. 선택한 항목의 읽음 처리가 성공하면 알림함을 닫고 관련 지원·지원자 화면으로 이동합니다. 실패하면 현재 화면·미읽음 상태를 유지하고, 같은 항목의 읽음 재시도가 성공한 뒤 이동합니다.
4. `모두 읽음`을 누르면 현재 제공된 알림을 읽음 처리합니다. 항목은 삭제하지 않으며 `전체`에서 다시 확인할 수 있습니다.
5. 닫기·바깥 영역·뒤로 닫기 등 일반 팝업 종료 후 기존 화면을 유지합니다. 알림 없는 상태와 읽지 않은 항목이 없는 상태를 구분합니다.

## 알림 대상과 연결

| 대상 | 제공할 정보와 조건 | 이동 |
| --- | --- | --- |
| 지원한 사용자 | 본인의 지원 접수·검토·선발·미선발·취소 등 실제 상태 변경 발생 사실 | 내 지원 현황 또는 해당 지원 상세 |
| 팀장 | 자신이 팀장인 팀에 새 지원이 실제 접수된 사실 | 해당 지원자의 상세·검토 화면 |

- 실제 데이터에서 확인할 수 없는 선발 결과·초대·읽은 시각·이벤트 발생 시각을 만들어 표시하지 않습니다. 이벤트 시각을 표시한다면 실제 기록에 근거합니다.
- 지원 상태가 바뀌면 새 미읽음 항목으로 결과를 확인할 수 있어야 합니다. 알림을 읽거나 모두 읽음 처리해도 지원 상태·정원·팀원 관계가 바뀌지 않습니다.
- 공모전·팀 모집 마감 알림, 7일 임박 안내, 그 기간 중 팀 생성 안내와 일정 변경 후 재알림은 현재 개발 범위에서 제외합니다. 향후 도입 시 검토하며 이번 구현의 미정 필수 항목으로 남기지 않습니다. 공고의 마감 표시·지원/생성 제한은 [공고 정책](contests.md#deadline-policy)을 그대로 적용합니다.
- 알림에 지원자 정보를 포함할 때도 [프로필 공개 범위](profile.md#visibility)를 적용합니다. 알림 제목·본문·미리보기를 열람 권한이 없는 비공개 프로필의 우회 노출 경로로 사용하지 않습니다.
- 일반 프로필 수정의 알림·변경 배지·변경 전후 안내는 제공하지 않습니다. 현재 정책에 없는 초대·프로필 조회·마감 임박 푸시를 추가하지 않습니다.

## 생성·중복 방지·이력

1. 알림 대상인 **실제 업무 변경이 성공한 경우 수신자별로 한 번** 생성합니다. 목록 조회·새로고침·같은 상태 재저장·동일 처리 재시도만으로 새 알림을 만들지 않습니다.
2. 같은 발생 건과 수신자의 조합으로 중복을 판단합니다. 같은 지원이 같은 상태에 다시 도달하더라도 별개의 실제 변경이면 새 발생 건입니다. 상태 이름이나 관련 대상만으로 새 변경을 중복 처리하지 않습니다.
3. 다음 변경은 **새 미읽음 항목으로 추가**하고 이전 알림·읽음 여부는 유지합니다. 이전 알림은 당시 발생한 사실이며 목적지에서는 현재 지원 상태·대상 존재·접근 권한을 다시 확인합니다. 이전 선발 알림이 현재 선발 상태를 보장하지 않습니다.
4. 취소 후 재지원은 새 지원 건입니다. 이전 지원의 발생 건·중복 기준을 재사용하여 재접수 알림이 사라지지 않게 합니다. 재접수는 지원자 본인의 접수 알림과 지원받은 팀장의 신규 지원 알림 대상입니다.
5. 공통으로 구분할 의미는 **알림 종류·수신자·관련 대상·실제 발생 시각·읽음 여부·발생 건 식별**입니다. 새 알림 종류를 도입하면 같은 생성·중복·읽음 원칙을 사용하되 새 수신자나 채널을 자동 추가하지 않습니다.

이 규칙은 특정 이벤트 시스템·API·DB 테이블·전달 수단을 지정하지 않습니다. 업무 변경과 알림 저장의 원자성·장애 복구·재시도 방식은 후속 개발 계획에서 정합니다. 이전 항목 유지는 영구 보존을 뜻하지 않으며 보존 기간·삭제는 별도 미정입니다.

## 권한과 예외

| 상황 | 동작 |
| --- | --- |
| 비로그인 | 개인 항목·미읽음 수를 제공하지 않고 로그인 안내 표시 |
| 타인 계정 또는 다른 팀 | 그 사용자의 알림·팀장 전용 지원자 항목에 접근 불가 |
| 알림 없음 | 새 알림이 없음을 안내 |
| 전체 알림은 있고 미읽음 없음 | `전체`에는 기존 항목, `읽지 않음`에는 모두 확인했음을 안내 |
| 대상이 변경·삭제되거나 접근 권한이 사라짐 | 이동 시 현재 권한·존재 여부를 다시 확인. 알림 링크만으로 이전 권한 복원하지 않음 |
| 읽음 처리 실패 | 처리 성공으로 고정하지 않고 미읽음 수·항목을 유지하며 재시도 안내. 개별 항목은 읽음 성공 전 관련 화면으로 이동하지 않음 |

읽음 상태는 사용자별로 관리하고 일반적인 화면 이동 중 유지합니다. 생성·중복·이력의 사용자 동작은 위 규칙으로 확정하며, 읽음 저장·새로고침 이후 및 여러 기기 간 동기화·보존 기간의 내부 구현은 후속 설계에서 정합니다. 공식 디자인의 로컬 상태 초기화 방식은 실제 서비스의 영구 저장 정책이 아닙니다.

## 현재 디자인 레퍼런스와 남은 차이

아래는 #77 F14 반영 전 배포 v12과 대응하는 디자인 소스 `e3c4f4f`의 관찰 기록입니다. 최신 두 계열·발생 건별 이력 정책과 차이가 있으며 전체 대조 기준은 [프로토타입·명세 일치 검증](prototype-alignment.md)을 따릅니다. 이 표는 서버 알림 기능의 구현 완료를 뜻하지 않습니다.

| 항목 | 현재 참고 화면의 동작과 한계 |
| --- | --- |
| 알림 진입 | 상단 벨의 미읽음 점과 접근성 이름의 미읽음 수. 별도 페이지 대신 아래에서 열리는 알림함이며 열기만으로 읽음 처리하지 않음 |
| 항목·이동 | 내 지원 상태는 내 지원 목록으로, 팀장이 받은 지원은 해당 지원자 상세로 이동. 이전 버전의 관리 팀 공모전 마감 알림은 F14에서 제외했으므로 제거할 대상 |
| 읽음 상태 | 전체·읽지 않음 필터, 개별 읽음·모두 읽음, 미읽음 없음·알림 없음 상태. 전체 읽음 후에도 항목을 남기며 화면 이동 중 읽음 상태 유지 |
| 실패·재시도 | `scenario=notification-error`로 최초 읽음 실패를 재현. 개별 읽음 실패 시 이동하지 않고, 재시도가 성공하면 원래 대상 화면으로 이동. 서버 저장 실패를 실제로 발생시킨 검증은 아님 |
| 닫기 | 닫기 버튼·바깥 영역·Escape로 닫는 팝업 동작을 사용. 브라우저·기기 뒤로가기를 알림함 닫기로 처리하는 기능은 아직 없으며 위 흐름 5의 요구와 남은 차이로 유지 |
| 데이터·지속성 | 브라우저의 현재 지원·팀 관계에서 항목을 매번 계산하여 실제 변경별 알림 이력을 유지하지 못함. F14의 발생 건별 한 번 생성·이전 항목/읽음 유지가 필요한 변경 대상. 서버 복원·다른 기기 동기화·보존·정렬은 별도 미구현 |

근거는 [Notifications.tsx](https://github.com/wejo-team/sku-dreamon/blob/e3c4f4f7d374d53956ec1fd5447bed3a4b58c7f6/design-reference/src/features/design-preview/Notifications.tsx), [알림 동작 테스트](https://github.com/wejo-team/sku-dreamon/blob/e3c4f4f7d374d53956ec1fd5447bed3a4b58c7f6/design-reference/src/features/design-preview/Notifications.test.tsx), [Drawer 구성](https://github.com/wejo-team/sku-dreamon/blob/e3c4f4f7d374d53956ec1fd5447bed3a4b58c7f6/design-reference/src/components/ui/drawer.tsx)입니다. 현재 목록의 배열 순서·알림 식별자·메모리 초기화 방식은 실제 생성·정렬·영구 저장 정책의 결정이 아닙니다.

## 완료 조건

체크는 실제 구현·검증을 뜻하며 공식 디자인 추가만으로 완료 처리하지 않습니다.

- [ ] AC-01: 미읽음 표시로 알림함에 진입하고 전체·읽지 않음으로 구분해 볼 수 있다. 열기만으로 읽음 처리하지 않는다.
- [ ] AC-02: 알림 선택 시 해당 항목의 읽음 처리가 성공한 뒤 올바른 지원·지원자 화면으로 이동한다. 읽음 실패 시 이동과 읽음 확정을 보류하고 재시도 성공 후 같은 대상으로 이동한다.
- [ ] AC-03: 모두 읽음 후 알림은 전체 목록에 남고 읽지 않음 목록과 상단 미읽음 표시가 갱신된다.
- [ ] AC-04: 본인 지원 상태 변경·팀장 신규 지원의 두 계열만 제공하며, 비로그인·다른 사용자의 항목이나 공모전·팀 모집 마감 알림을 생성·노출하지 않는다.
- [ ] AC-05: 알림 없음·미읽음 없음·읽음 처리 실패를 구분하고, 현재 접근 권한이 없는 대상은 알림 링크로도 열람할 수 없다.
- [ ] AC-06: 프로필 수정 알림이나 확인되지 않은 이벤트·발생 시각을 만들지 않고, 알림 내용에도 현재 프로필 공개 범위를 적용한다.
- [ ] AC-07: 같은 업무 변경 발생 건·수신자에는 한 알림만 생성하며 조회·새로고침·같은 상태 저장·재시도로 중복 항목을 만들지 않는다. 실패한 업무 변경으로 성공 알림을 만들지 않는다.
- [ ] AC-08: 다음 실제 상태 변경은 새 미읽음 알림으로 추가하고 이전 항목·읽음 상태를 유지한다. 같은 상태의 별도 발생 건도 구분하며 과거 알림을 누른 목적지에서는 현재 상태·권한을 적용한다.
- [ ] AC-09: 취소 후 재지원은 새 지원 건으로 기록하여 본인 접수·팀장 신규 지원 알림을 각각 생성하고, 이전 지원의 중복 기준 때문에 새 접수가 누락되지 않는다.
