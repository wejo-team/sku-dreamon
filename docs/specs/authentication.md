# 가입과 교내 인증

- 구현 상태: 예정
- 명세 검토: [PR #14](https://github.com/wejo-team/wejo-app/pull/14)
- 구현 작업: 미등록

기획 문서의 가입·인증 요구사항을 옮긴 초안입니다. 실제 인증 방식과 시연 방식은 아직 확정되지 않았습니다.
프로필의 이름·공개 범위를 변경할 때만 [프로필 정책](profile.md)을 함께 읽습니다.

## 목적과 사용자

교내 사용자가 가입하고 자신의 인증 상태를 확인한 뒤 프로필 설정과 공모전 참여 흐름을 시작할 수 있게 합니다.

## 범위

| 항목 | 스프린트 1 범위 |
| --- | --- |
| 로그인·교내 인증 화면 | 가입과 인증 상태 표시 |
| 교내 구성원 확인 | 학교 이메일 인증을 기준으로 정의하되 실제 연동 여부는 미정 |
| 시연용 인증 | 실제 인증과 구분해 안내하는 시연 경로; 사용 여부와 방법은 미정 |
| 별도 본인확인 | 신분증 등을 통한 실명 진위 확인은 제외 |

가입·인증을 거친 필수 프로필 작성은 [프로필 입력 항목](profile.md#fields)에서 정의합니다.
로그인 제공자, 이메일 발송 방식, 비밀번호·세션 설계는 이 문서에서 확정하지 않습니다.

## 사용자 흐름과 동작

1. 사용자가 로그인·교내 인증 화면에 접근합니다.
2. 선택된 실제 교내 인증 또는 시연용 인증 경로를 거쳐 가입합니다.
3. 화면에서 자신의 인증 상태와 현재 사용하는 인증 방식의 한계를 확인합니다.
4. 가입 후 프로필 설정 흐름으로 이동해 필수 정보를 작성합니다.

2단계에서 사용할 구체적인 수단은 아래 미정 사항을 결정한 뒤 흐름을 보완합니다.

## 정책과 예외

<a id="verification-meaning"></a>

### 교내 인증의 의미

- 학교 이메일 인증은 교내 구성원 여부를 확인하는 수단입니다.
- 이메일 인증 성공을 등록된 실명의 진위가 확인된 것으로 취급하지 않습니다.
- 서비스가 요구하는 것은 실명 입력이며, 신분증 등 별도 본인확인은 스프린트 1에 포함하지 않습니다.
- 이메일 주소와 인증 여부의 다른 사용자 대상 공개 기준은 [프로필 공개 범위](profile.md#visibility)를 따릅니다.

### 시연용 인증 안내

- 실제 교내 인증과 시연용 인증을 구분해 안내합니다.
- 시연용 인증을 실제 보안 인증이 구현된 것으로 설명하지 않습니다.
- 시연용 공고·계정과 실제 데이터의 사용 여부를 시연 준비 시 구분합니다.
- 실제 인증 연동 여부는 화면·문서·발표에서 사실에 맞게 표시합니다.

### 아직 정의되지 않은 실패 흐름

원문에는 인증 실패·만료·재시도·계정 중복의 처리 방식이 없습니다. 미정 사항을 해결하기 전에는 구체적인 제한 횟수나 유효기간을 확정 정책으로 사용하지 않습니다.

<a id="acceptance-criteria"></a>

## 완료 조건

다음 조건의 체크는 구현과 검증을 의미하며, 이관이나 명세 검토만으로 체크하지 않습니다.

- [ ] AC-01: 선택한 실제 인증 또는 시연 인증 경로로 가입한 사용자가 자신의 인증 상태를 화면에서 확인할 수 있다.
- [ ] AC-02: 시연용 인증을 사용하면 사용자가 실제 교내 인증과 구분할 수 있는 안내를 확인할 수 있다.
- [ ] AC-03: 이메일 인증을 완료해도 화면·문서에서 실명 진위 확인을 완료했다고 표시하지 않는다.
- [ ] AC-04: 가입을 마친 사용자가 프로필 설정 흐름을 시작할 수 있다.

<a id="open-questions"></a>

## 미정 사항

| ID | 결정할 내용 | 결정이 필요한 이유 |
| --- | --- | --- |
| AUTH-01 | 실제 학교 이메일 인증 연동 또는 시연용 인증의 사용 범위 | 원문의 스프린트 시작 전 확정 항목 |
| AUTH-02 | 인증 대상 이메일 도메인·대상 구성원, 인증 수단 | 원문에 구체적인 대상·방법이 없음 |
| AUTH-03 | 미인증 사용자에게 허용할 화면·행동 | 인증 상태 표시는 있으나 접근 허용 범위가 없음 |
| AUTH-04 | 인증 실패·만료·재시도·중복 계정의 사용자 흐름 | 예외 동작과 관찰 가능한 완료 조건을 추가해야 함 |
