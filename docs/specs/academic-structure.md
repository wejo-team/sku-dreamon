서경대학교 학사 분류를 기획 원문에서 옮긴 초안입니다. 아래 목록은 원문 보존용 이관 목록이며, 적용 학년도와 공식 자료 전체와의 일치는 아직 확정되지 않았습니다.
입력 필수 여부·공개 범위는 [프로필](profile.md), 공통 선택지 관리 원칙은 [공통 데이터 관리](profile-options.md#catalog-management)에 둡니다. 학사 변경의 근거는 아래 목록 유지 정책을 따릅니다.

## 목적과 범위

사용자가 자신의 대학·학부·학과·전공을 일관된 계층에서 선택할 수 있게 합니다. 학사 목록은 명시적 참가 자격·팀 모집 조건을 확인할 때 사용하며, 학년·전공만으로 사람의 일반적인 우수성을 판단하지 않습니다. 학적·학년은 선택 입력이며, 미입력만으로 지원을 막지 않습니다. 개별 자격 정보가 부족하면 원문 확인 안내 후 일반 팀 지원으로 접수하되 자격 충족으로 표시하지 않는 [지원 정책](profile.md#before-application)을 적용합니다. LLM 추천으로의 전환이 학사 정보 공개 범위를 확대하지 않습니다. 항목별 적용 범위와 원문의 미정 사항은 [추천 필수 조건](matching.md#eligibility)을 따릅니다.

## 선택 흐름

| 단계 | 선택 방식 | 처리 규칙 |
| --- | --- | --- |
| 1. 단과대학 | 단일 선택 | 선택한 대학에 해당하는 학부·학과만 표시 |
| 2. 학부·학과 | 단일 선택 | 독립 학과라면 이 단계에서 종료 |
| 3. 세부전공 | 조건부 표시·단일 선택·선택 입력 | 세부전공이 있는 학부에만 표시; 선택하지 않으면 학부 소속까지만 저장·표시 |

- 세부전공이 없는 학부·학과는 마지막 선택 단계를 생략합니다.
- 자유전공학부를 포함해 학부·학과까지만 선택할 수 있으며, 선택한 항목의 ID와 부모 경로로 프로필 소속을 표시합니다.
- 동일 이름 전공이 여러 학부에 있어도 원문 목록의 소속 관계를 임의로 합치지 않습니다.
- 학부별 실제 선택 가능 전공과 부모 관계는 공식 자료 검증이 필요합니다.

## 새 선택과 기존 과거 소속

[이슈 #42의 결정](https://github.com/wejo-team/sku-dreamon/issues/42#issuecomment-6234780726)에 따라 **새로운 소속 선택에는 현행 목록만 사용하고, 이미 저장된 과거 소속은 유지**합니다. 신규 입력과 소속 변경 모두 현행 항목만 선택할 수 있으며, 과거·비활성 항목의 ID를 새 선택값으로 저장할 수 없습니다.

| 상황 | 적용 정책 |
| --- | --- |
| 소속을 처음 등록 | 공식 자료로 확정한 현행 목록에서만 선택 |
| 기존 소속을 다른 소속으로 변경 | 새로 선택하는 값은 현행 목록으로 제한; 과거 항목으로 새 변경 불가 |
| 기존에 저장한 소속이 과거·비활성 항목이 됨 | 기존 값과 연결을 유지하며 삭제하거나 현행 항목으로 자동 치환하지 않음 |
| 과거 소속을 유지한 채 자기소개 등 다른 프로필 항목을 수정 | 기존 소속을 그대로 유지하며 현행 소속 재선택을 요구하지 않음 |

현행 목록의 실제 항목·적용 학년도·전공 관계와 기존 데이터의 ID 대응은 아직 확정하지 않았습니다. 아래 31행 이관 표를 현행 선택 목록으로 승인하거나 전체 검증을 완료한 것으로 취급하지 않습니다. 이 결정은 가입 자격이나 대상 학번을 제한하는 정책이 아닙니다. 상위 대학·학부를 변경했을 때 하위 선택값은 아래 [종속 선택값 처리](#dependent-selection)를 따릅니다.

### 단일 계층과 항목 식별

2026-10-22 사용자 결정으로 [학사 저장 구조](../database/catalogs.md#academic-tables)는 `academic_unit_id`·`name`·`parent_id`·`is_selectable`의 단일 인접 리스트로 단순화합니다. PK 컬럼명은 [DB 명명 규칙](../database/conventions.md#primary-key-names)을 따르며 API의 `id`는 유지합니다. ID는 DB가 발급하는 증가형 정수이며, 프로필은 가장 깊게 선택한 항목 ID 하나를 참조합니다. 기존 소속 보존 정책은 유지합니다.

단과대학은 루트, 학부·학과는 두 번째 단계, 세부전공은 세 번째 단계입니다. 이름이 같아도 다른 소속이면 다른 ID로 구분합니다. 조직 개편·실질적 항목 변경은 기존 부모 연결을 바꾸지 않고 새 항목을 만들며, 이동한 하위 전공도 새 부모 아래 새 ID로 등록합니다. 이전 항목은 신규 선택만 막고 기존 사용자의 참조를 유지합니다. 같은 의미의 단순 표기 정리는 기존 ID를 유지합니다.

같은 날 사용자 결정으로 프로필 소속은 선택한 학사 ID 하나로만 표현하며 전공 배정 여부를 별도로 저장하지 않습니다. 학부·학과까지만 선택하면 그 항목의 ID, 세부전공까지 선택하면 전공 ID를 저장하고, 학사 정보 전체가 미입력이면 NULL로 둡니다. 화면에는 선택한 항목까지의 부모 경로를 표시하며 전공 미선택을 미배정으로 추정하지 않습니다. 조회·선택·저장 처리 순서는 [학사 선택·저장 흐름](../api/catalogs.md#academic-unit)을 따릅니다.

## 상위 소속 변경과 종속 선택값

[#77의 최신 결정](https://github.com/wejo-team/sku-dreamon/issues/77#issuecomment-6260435650)에 따라 상위 소속을 바꾸면 **새 소속 관계에서 유효하지 않은 하위값만 비우고, 계속 유효한 값은 유지**합니다.

- 단과대학을 변경하면 기존 학부·학과와 전공이 새 대학 아래의 같은 항목·관계로 유효한지 확인합니다. 학부·학과를 변경하면 기존 전공이 새 관계에서도 유효한지 확인합니다. 유효하지 않은 하위값은 초안에서 지우고 필요한 재선택을 안내합니다.
- 표시 이름이 같거나 비슷하다는 이유만으로 다른 소속의 전공을 같은 값으로 취급하지 않습니다. 동일 의미의 표기를 정리해도 기존 식별자·선택 연결을 보존하며 실제로 다른 학과·전공을 합치지 않습니다. 실제 목록·부모 관계와 기존 데이터의 ID 대응은 ACADEMIC-01~04에서 확정합니다.
- 변경은 편집 초안에만 반영하고, 최종 프로필 저장 성공 후 저장값을 바꿉니다. 편집을 취소하면 이전 저장 소속을 그대로 유지합니다. 저장 실패를 저장 완료로 처리하지 않습니다.
- 학적·학년은 선택 입력이며 이 동작으로 필수 입력으로 바꾸지 않습니다. 상위 소속을 변경하지 않고 다른 프로필 항목만 수정하는 경우에는 위 [과거 소속 유지 정책](#selection-policy)을 적용합니다. 목록 개편만으로 기존 소속을 지우거나 재선택을 요구하지 않습니다.

<a id="maintenance"></a>

## 목록 유지 정책

- 학교 공식 학사 정보를 기준으로 갱신합니다.
- 표시 이름과 증가형 ID를 구분하고, 폐지·통합된 항목은 과거 기록 연결을 유지하도록 비활성화합니다. 2026-10-22 사용자 결정에 따라 시드·마이그레이션으로 목록을 반영하고, 공식 출처·적용 대상·변경 사유는 [문서·PR](../database/catalogs.md#catalog-changes)에 남깁니다. 별도 DB 변경 이력은 관리하지 않습니다.
- [새 선택과 기존 과거 소속](#selection-policy)을 구분합니다. 비활성화한 과거 항목은 신규 선택에서 제외하되, 이미 저장된 사용자 소속을 삭제하거나 자동 치환하지 않습니다.
- 증가형 ID 형식은 확정했으며, 실제 적용 학년도·학부별 전공 관계·기존 데이터의 ID 대응 자료는 아직 확정되지 않았습니다.
- 이름만 같다는 이유로 소속 관계를 합치거나 원문의 행을 삭제하지 않습니다.

<a id="prototype-reference"></a>

## 현재 디자인 레퍼런스

[공식 디자인 PR](https://github.com/wejo-team/sku-dreamon/pull/74)의 참고 앱 동작입니다. 소스·배포 버전과 수행한 검증은 [프로토타입·명세 대조 기록](prototype-alignment.md)에서 관리하며, 아래 화면 동작을 실제 서버 기능의 완료로 취급하지 않습니다.

참고 앱은 위 **31행 이관 목록을 화면 확인용 데이터**로 사용합니다. 공식 운영 목록·적용 학년도·현행 여부를 검증하거나 영구 코드를 확정한 것이 아닙니다.

| 참고 화면 동작 | 제품 정책과 구분할 점 |
| --- | --- |
| 단과대학 선택 후 해당 학부·학과, 학부·학과 선택 후 해당 세부전공 표시 | 상위 선택 전에는 하위 입력을 비활성화합니다. 세부전공이 없는 독립 학과는 전공 입력을 생략합니다. 학적·학년을 포함한 학사 정보는 선택 입력입니다. |
| 자유전공학부의 전공 미배정 선택 | 기존 참고 화면의 표현입니다. 변경된 제품 정책은 학부 ID만 저장하고 별도 배정 상태를 표시하지 않습니다. 화면 반영은 후속 구현 대상이며 실제 목록·부모 관계는 ACADEMIC-01·03에서 확인합니다. |
| 상위 소속을 실제로 바꾸면 기존 관계의 하위 초안을 비움 | 같은 상위 항목을 유지하면 하위값도 유지합니다. 서로 다른 단과대학의 동명 학과를 같은 소속으로 간주하지 않으며, 운영 코드에 따른 유효 관계 검사는 별도 구현 대상입니다. 저장 전에는 기존 프로필 소속을 변경하지 않습니다. |
| 목록에 없는 기존 저장값을 `기존 소속`으로 표시 | 다른 필드를 수정해 저장할 때 기존 소속을 유지하며 과거 항목을 새 선택으로 다시 고르지는 못합니다. 실제 DB 항목 비활성화·공식 현행 목록 조회는 미구현입니다. |

폼은 표시 문자열과 메모리 상태를 사용합니다. 화면에서 선택할 수 있다는 이유만으로 현행 소속·학교 인증·참가 자격이 확인된 것으로 취급하지 않습니다.

<a id="acceptance-criteria"></a>

## 완료 조건

- [ ] AC-01: 대학을 선택하면 그 대학에 속한 학부·학과만 선택 대상으로 나타난다.
- [ ] AC-02: 세부전공이 있는 학부에서는 세부전공을 선택할 수 있고, 독립 학과에서는 세부전공 단계를 생략한다.
- [ ] AC-03: 자유전공학부를 포함해 학부·학과까지만 선택해 저장할 수 있고, 프로필에는 선택한 항목까지의 소속 경로를 표시한다. 전공 배정 상태를 별도로 저장하거나 추정하지 않는다.
- [ ] AC-04: 같은 이름 전공의 서로 다른 학부 소속 관계를 구분할 수 있다.
- [ ] AC-05: 학사 목록을 추가·수정·비활성화할 때 공식 출처·적용 대상·변경 사유를 관련 문서·PR에서 확인할 수 있고, 기존 사용자 기록과의 연결을 유지한다.
- [ ] AC-06: 소속 최초 등록과 소속 변경에서 확정된 현행 목록의 항목만 새로 선택·저장할 수 있으며, 과거·비활성 항목의 ID를 새 선택값으로 저장할 수 없다. 실제 목록·부모 관계와 기존 데이터 대응을 확정한 뒤 검증한다.
- [ ] AC-07: 이미 저장된 소속이 과거·비활성 항목이 되어도 기존 값과 연결이 유지되고 삭제·현행 값으로의 자동 치환이 발생하지 않는다. 자기소개 등 다른 프로필 항목만 수정하면 소속이 그대로 유지되며 현행 소속 재선택을 요구하지 않는다.

- [ ] AC-08: 상위 대학·학부를 변경하면 새 관계에서 유효하지 않은 하위 선택값만 초안에서 지우고 계속 유효한 값은 유지한다. 같은 이름의 다른 항목을 동일한 관계로 간주하지 않는다.
- [ ] AC-09: 학사 변경은 최종 저장 성공 후 반영하며 편집 취소·저장 실패가 이전 저장 소속을 변경하지 않는다. 다른 항목만 수정할 때 과거 소속 유지 정책을 적용한다.

<a id="open-questions"></a>

## 미정 사항

| ID | 결정할 내용 |
| --- | --- |
| ACADEMIC-01 | 실제 현행 목록의 확정, 적용 학년도·자료의 대상 학번과 현행·과거 항목 구분. 새 선택은 현행 목록으로 제한하고 이미 저장된 과거 소속을 유지하는 범위는 [이슈 #42 정책](#selection-policy)으로 결정 |
| ACADEMIC-02 | 공식 출처와 다른 대학 소속, 원문에 없는 전공, 이름 변경·통합 항목의 반영 |
| ACADEMIC-03 | 학부별 실제 선택 가능한 전공과 부모 관계의 공식 확인. 전공 배정 상태를 별도 저장·표시하지 않는 방식은 확정 |
| ACADEMIC-04 | 증가형 ID와 부모 연결로 식별하는 구조는 확정. 실제 목록의 초기 적재와 기존 문자열·코드 데이터를 새 ID로 대응하는 방법 |

ACADEMIC-05는 [유효하지 않은 하위값만 초기화하고 유효한 값은 유지하는 정책](#dependent-selection)으로 정했습니다. 실제 현행 목록·학년도·관계 검증은 위 후속 항목에 남깁니다.
