# 공모전·팀·지원자 추천

- 구현 상태: 예정
- 명세 검토: [PR #17](https://github.com/wejo-team/wejo-app/pull/17)
- 구현 작업: 미등록

스프린트 1의 추천 대상, 필수 조건, 점수 계산과 표시 정책을 정의합니다. 공모전 추천은 정책 확정 부록의 가중치 `60/40`을 적용합니다. 팀·지원자 추천은 아래 결정에 따라 시간 요소를 제외하며, 최종 가중치·산식은 추후 정의합니다.
입력·공개 범위는 [프로필 정책](profile.md), 분류와 코드는 [공통 선택지](profile-options.md), 모집·지원 상태는 [팀 모집과 지원](team-recruitment.md)에서 관리합니다.

## 추천 정책 결정

| 항목 | 현재 정책 | 결정 기록 |
| --- | --- | --- |
| 모집 역할 | 역할 불일치로 추천 후보를 제외하거나 지원을 강제 차단하지 않습니다. 팀장이 최신 모집 정보를 안내하고 실제 선발을 판단합니다. | [#30](https://github.com/wejo-team/wejo-app/issues/30#issuecomment-6232752606) |
| 활동·가능 시간 | 입력 여부와 관계없이 추천 점수·동점 판정·추천 이유에 사용하지 않습니다. 추천 알고리즘의 세부 사항은 후속 정의합니다. | [#31](https://github.com/wejo-team/wejo-app/issues/31#issuecomment-6232752842) |
| 관심 분야 비교 | 공모전 분야와 팀 관심 분야의 중복을 제거한 합집합과 사용자 관심 분야를 비교합니다. | [#32](https://github.com/wejo-team/wejo-app/issues/32#issuecomment-6232753124) |

이 결정은 원문의 필수 역할 필터, 팀·지원자 가중치 `40/25/25/10`, 시간 겹침 계산과 시간 동점 기준을 대체합니다. 시간 항목을 뺀 나머지를 75점 만점으로 계산하거나 임의로 100점에 재분배하지 않습니다. 시간 입력 필드·권장 입력 여부와 기존 상세 일정 공개 제한은 [프로필](profile.md)을 따릅니다.

## 목적과 사용자

일반 사용자는 참여할 공모전을 찾고, 팀을 찾는 사용자는 선택한 공모전의 모집 팀을 비교하며, 팀장은 실제 지원자를 검토합니다. 각 사용자는 조건에 맞는 후보와 실제 데이터에 근거한 추천 이유를 확인합니다.

## 범위

| 포함 | 제외 |
| --- | --- |
| 공모전 추천, 팀 추천, 실제 지원자 추천 | 지원하지 않은 전체 사용자 대상 지원자 추천 |
| 필수 조건 확인, 규칙 기반 점수·순위 계산, 추천 이유 표시 | 자연어 대화형 매칭, AI가 추정한 경험·역량으로 점수 계산 |
| 고정 가중치의 설정값·버전·적용일 관리 | 포트폴리오 내용 또는 AI 분석 결과의 추천 점수 반영 |

공고문 요약 등 AI의 별도 역할과 후속 스프린트 범위는 [스프린트 1 범위](sprint-1.md)에서 정의합니다.

## 추천 유형과 실행 시점

| 유형 | 사용자와 추천 대상 | 실행 시점 | 노출 위치 |
| --- | --- | --- | --- |
| 공모전 추천 | 일반 사용자에게 관심 분야·참가 자격·경험·일정에 맞는 공모전 | 프로필 저장·수정 시 또는 사용자가 갱신할 때 | 홈·공모전 목록 |
| 팀 추천 | 팀을 찾는 사용자에게 선택한 공모전에서 신규 지원 가능한 팀 | 공모전 선택 시 또는 프로필 변경 후 갱신할 때 | 공모전 상세·팀 목록 |
| 지원자 추천 | 팀장에게 팀 모집 조건에 맞는 실제 지원자 | 새 지원 접수·모집 조건 변경 시, 지원자 프로필 변경 후 조회·갱신 시 | 팀 관리 화면 |

위 표의 설명에서 참가 자격·마감·참가 가능 여부는 필수 조건이며 공모전 점수 요소가 아닙니다. 공모전 계산은 아래 산식을 따르고, 팀·지원자의 최종 계산은 시간 제외 후 세부 알고리즘을 정한 뒤 적용합니다.

지원자 프로필 변경 후에는 [현재 프로필 기준](profile.md#application-profile)에 따라 다음 조회·갱신에서 검토 정보와 추천의 필수 조건 판단·점수·순위·이유를 함께 맞춥니다. 이전 프로필로 계산한 결과를 현재 프로필과 섞어 표시하지 않습니다. 일반 프로필 값 변경의 알림이나 이미 열린 화면의 실시간 자동 갱신은 MVP에서 요구하지 않습니다. 공개 설정 변경·동의 철회는 [저장 성공 즉시 열람 기준에 적용](profile.md#visibility-changes)하며, 상태별 추천 대상은 MATCH-01에서 별도로 정합니다.

## 사용자 흐름과 동작

1. 사용자가 위 실행 시점에 추천을 요청하거나 추천 결과를 확인합니다.
2. 모집 상태·마감·정원·참가 자격 등 필수 조건을 먼저 검사합니다. 자격을 확인할 수 없는 후보는 자동 통과시키지 않고 `확인 필요`로 분리합니다.
3. 필수 조건을 통과한 후보의 요소를 비교합니다. 공모전은 확정 산식으로 계산하며, 팀·지원자의 최종 가중치·산식은 TBD입니다.
4. 최종 산식이 확정된 유형은 점수 내림차순으로 정렬하고 실제 계산에 반영된 항목을 추천 이유로 표시합니다.
5. 동점 처리의 세부는 [미정 사항](#open-questions)에서 정합니다. 활동·가능 시간은 동점 판정에도 사용하지 않습니다.

## 필수 조건과 선호 조건

필수 조건은 후보 포함 여부를 정하고, 선호 조건은 통과한 후보 사이의 점수와 순위를 정합니다. 경험이 적다는 이유만으로 초보자를 자동 제외하지 않습니다.

| 공통 필수 조건 | 처리 규칙 |
| --- | --- |
| 공고·팀 모집 상태와 마감 | 신규 지원 대상은 공고·팀의 접수가 열려 있고 마감 전일 때 포함. 팀은 [검토 중 접수 정책](team-recruitment.md#recruitment-review)에 따라 ‘지원자 검토’ 상태만으로 신규 지원 대상 후보에서 제외하지 않음 |
| 모집 정원 | 정원이 찬 팀은 신규 지원을 허용하지 않으며, 신규 지원자 및 신규 지원 대상 팀 후보에서 제외 |
| 참가 자격 | 공고에 명시된 학교·학적 상태·학년·전공·학과 등 자격 조건을 모두 충족해야 통과. 미충족이 확인되면 제외하고, 정보가 없거나 확인되지 않으면 `확인 필요`로 분리 |
| 중복·상태 | 같은 팀의 현재 지원이 유효한 동안 중복 지원을 만들지 않음. 취소 후에는 [현재 모집 조건을 충족하면 즉시 재지원](team-recruitment.md#reapplication) 가능. 실제 지원자 추천은 해당 팀의 현재 지원을 기준으로 평가하며 미지원자는 제외 |

위 표의 모집 상태·마감·정원 조건은 신규 지원 대상 판단에 적용합니다. [이슈 #46의 보류 결정](https://github.com/wejo-team/wejo-app/issues/46#issuecomment-6232873014)에 따라 마감·정원 충족 후 기존 지원자의 추천·순위 열람은 명시적으로 TBD이며, 알고리즘을 구체화할 때 함께 정합니다. 신규 접수를 닫는 것만으로 기존 지원자 추천을 유지하거나 중단한다고 해석하지 않습니다.

지원 취소 이력만으로 사용자를 현재 지원자처럼 평가하지 않으며, 재지원 접수가 성공하면 취소된 이전 지원과 구분해 현재 지원을 기준으로 판단합니다. 취소 이력을 재지원의 영구 제외 사유로 사용하지 않습니다. 검토 중·선발·미선발 등 구체 상태별 추천 포함 여부와 정원 충족·모집 마감 후 기존 지원자 평가는 MATCH-01에서 정합니다. 미선발 이후 재지원은 [팀 명세의 미정 사항](team-recruitment.md#open-questions)으로 남깁니다.

[취소·미선발 후 팀장의 프로필 열람 관계 유지](profile.md#former-applicant-visibility)는 추천 대상에 포함하는 결정과 별개입니다. 프로필 열람이 가능하다는 이유만으로 취소된 지원을 현재 지원자 추천에 포함하지 않습니다.

| 항목 | 필수·선호 구분과 사용 원칙 |
| --- | --- |
| 관심 분야 | 선호 조건. 일치도가 높을수록 점수에 반영 |
| 희망 역할 | 팀장 판단과 선호 비교를 위한 정보. 역할 불일치 자체를 후보 제외 조건으로 사용하지 않음 |
| 관련 경험·역량 | 선호 조건. 명시적인 경험 없음과 미입력을 구분 |
| 활동 가능 시간 | 현재 추천 점수·동점 판정·추천 이유에서 제외. 추천 외 활용·표시 범위는 후속 검토 |
| 학적 상태·학년·단과대학·전공·학과 | 일반 점수 요소가 아님. 공고 참가 자격이나 팀 모집 조건에 명시된 경우에만 필수 필터에 사용하며, 조건이 없으면 이 항목 때문에 순위를 올리거나 내리지 않음 |

학적 상태는 공고 자격, 학년·단과대학은 명시적인 공고 또는 팀 조건, 전공·학과는 명시적인 공고 전공 제한에 사용한다는 항목별 기준도 있습니다. 이 기준과 부록의 공통 필터 원칙 사이에서 팀의 학적·전공 제한 허용 범위는 미정 사항으로 남깁니다.

팀이 개발·디자인을 모집할 때의 역할 조건은 아래와 같습니다. 다른 필수 조건을 통과해야 추천 대상이 되며, 역할만으로 실제 선발을 보장하지 않습니다.

| 사용자 희망 역할 | 역할 조건에 따른 자동 제외 |
| --- | --- |
| 개발만 | 제외하지 않음 |
| 디자인만 | 제외하지 않음 |
| 개발·디자인 모두 | 제외하지 않음 |
| 발표만 | 제외하지 않음 |

역할 불일치만으로 지원 제출도 막지 않습니다. 팀장은 [모집 정보 관리](team-recruitment.md#recruitment-information)를 통해 이미 모집된 분야와 현재 필요한 역할을 안내하고 실제 지원자를 검토·선발합니다. 역할별 자동 정원 차감이나 역할 충족 판정은 이번 결정에 포함하지 않습니다.

<a id="contest-score"></a>

## 공모전 추천 점수

| 요소 | 가중치 | 요소 점수 산정 규칙 |
| --- | --- | --- |
| 관심 분야 일치 | 60점 | 사용자 관심 분야와 공모전 분류의 일치 분야 수 ÷ 사용자 관심 분야 수 × 100 |
| 관련 경험 | 40점 | 표준 분류로 사용자 경험 분야와 공모전 분야의 관련도 비교. 직접 관련 경험 `100`, 인접 분야 경험 `60`, 관련 경험 없음 `40`, 미입력 `50` |

참가 자격·마감·참가 가능 여부는 점수에 더하지 않고 필수 조건으로 처리합니다. 전공·학년은 공고의 명시적 자격일 때만 필터에 사용합니다. 공모전 추천의 관심 분야 미입력 점수와 분모가 0인 경우의 처리는 원문에 없습니다.

<a id="team-score"></a>

## 팀·지원자 추천 점수

팀 추천과 지원자 추천은 아래 비교 요소를 공유합니다. 시간 요소 제외에 따른 최종 가중치·산식은 TBD이며, 기존 팀·지원자 총점 산식은 현재 정책으로 사용하지 않습니다. 아래 표는 요소별 비교 기준입니다.

| 요소 | 최종 가중치 | 요소 점수 산정 규칙 |
| --- | --- | --- |
| 희망 역할 일치 | TBD | 사용자 희망 역할과 팀 모집 역할이 일치하면 `100`, 일치하지 않으면 `0`. 후보 제외 필터는 아니며 복수 역할의 점수 판정은 MATCH-02에서 후속 정의 |
| 관심 분야 일치 | TBD | [중복 제거 합집합](#interest-union)과 일치하는 사용자 관심 분야 수 ÷ 사용자 관심 분야 수 × 100. 사용자 관심 분야 미입력 시 `50` |
| 관련 경험·역량 | TBD | 팀 역할과 직접 관련된 프로젝트·공모전 경험이 있으면 `100`, 관련 역량은 있으나 경험 등록이 없으면 `70`, 관련 경험·역량이 없다고 명시하면 `40`, 미입력이면 `50` |

사용자 시간 미입력·겹침 0%·겹침 100% 모두 현재 추천에서는 시간 점수를 산출하지 않습니다. 시간의 미입력과 불일치라는 입력 상태를 합치는 뜻은 아니며, 다른 입력과 조건이 같으면 시간값 변경만으로 추천 점수·순위를 바꾸지 않습니다.

복수 역할의 점수 판정과 경험·역량 조건이 중첩될 때의 선택 순서는 미정입니다. 관련 분류·관계표는 [공통 선택지](profile-options.md)에서 관리하며, 계산에 필요한 후속 결정은 아래에 남깁니다.

<a id="interest-union"></a>

### 관심 분야 비교

팀·지원자 추천의 비교 대상은 **공모전 분야 ∪ 팀 관심 분야**이며, 같은 분야는 한 번만 셉니다. 사용자 관심 분야의 개수를 분모로 유지합니다. 아래는 관심 분야 요소만의 예시이며 최종 추천 점수가 아닙니다.

| 공모전 분야 | 팀 관심 분야 | 사용자 관심 분야 | 관심 분야 요소 점수 |
| --- | --- | --- | --- |
| IT·기술 | IT·기술 | IT·기술 | 중복 없이 1 ÷ 1 × 100 = 100 |
| IT·기술 | 디자인 | 디자인 | 1 ÷ 1 × 100 = 100 |
| IT·기술, 디자인 | 디자인, 교육 | IT·기술, 디자인, 교육, 환경 | 중복 없이 3 ÷ 4 × 100 = 75 |
| IT·기술 | 디자인 | 환경 | 0 ÷ 1 × 100 = 0 |

표의 `IT·기술`은 하나의 표준 분야 이름입니다. 양쪽 분야가 모두 미등록인 경우의 처리는 MATCH-03에서 별도로 정하며, 이번 합집합 결정으로 임의의 결측값 점수를 만들지 않습니다.

<a id="calculation"></a>

## 계산·정렬과 변경 관리

요소 점수는 0~100 범위입니다. 현재 확정된 공모전 최종 산식은 다음과 같습니다.

```text
공모전 점수 = 관심 분야 점수 × 0.60 + 관련 경험 점수 × 0.40
```

팀·지원자의 최종 가중치·산식은 MATCH-11에서 정합니다. 시간 요소를 제외했다는 이유로 나머지 비율을 자동 재분배하거나 새 총점을 계산하지 않습니다.

- 최종 점수는 소수점 첫째 자리까지 저장·표시합니다. 반올림·절사 방식, 중간 계산 정밀도와 정렬에 사용할 정밀도는 미정입니다.
- 최종 산식이 확정된 유형은 점수 내림차순으로 정렬합니다. 팀·지원자와 공모전의 동점 처리 세부는 MATCH-05에서 정하며, 시간 점수는 사용하지 않습니다.
- 미입력·미확인은 불일치로 바꾸지 않고 별도 상태로 보존합니다. 이 문서에 명시된 미입력 점수만 적용하며, 없는 규칙을 추정하지 않습니다.
- 가중치는 코드 여러 곳에 임의로 흩어 두지 않고 설정값으로 관리합니다. 변경 시 버전과 적용일을 기록합니다. 설정 파일·저장 방식 등 구현 설계는 개발 계획에서 정합니다.
- 표준 코드와 계산 규칙의 공통 활용, 분류 목록의 변경 이력은 [공통 데이터 관리](profile-options.md#catalog-management)를 따릅니다. 기존 추천 결과에 변경된 가중치를 언제 다시 적용할지는 미정입니다.

### 요소 계산 예시

다음은 계산 확인을 위한 가상 합성 데이터입니다. 실제 사용자나 팀을 나타내지 않습니다. 모집·마감·정원·참가 자격을 모두 통과하고, 팀장이 평가할 경우 해당 팀에 지원 완료한 사용자를 가정합니다.

- 사용자 희망 역할과 팀 모집 역할이 모두 `디자인`이므로 역할 요소 점수는 `100`입니다.
- 사용자 관심 분야 4개 중 공모전·팀 분야의 중복 제거 합집합과 2개가 일치하므로 관심 분야 요소 점수는 `2 ÷ 4 × 100 = 50`입니다.
- 팀 역할에 관련된 역량은 있지만 경험 등록이 없으므로 경험·역량 요소 점수는 `70`입니다.

시간 요소와 기존 총점 `74.5` 예시는 더 이상 적용하지 않습니다. 최종 총점은 새 가중치·산식을 정한 뒤 검증 사례를 추가합니다.

최종 알고리즘에서 해당 요소를 실제 반영한 경우 `희망 역할이 모집 역할과 일치합니다`, `관심 분야 2개가 일치합니다`를 근거로 표시할 수 있습니다. 시간 겹침은 추천 근거로 표시하지 않습니다. 이 표시는 해당 근거를 열람자에게 공개할 수 있는 경우의 예시이며, 비공개 정보가 포함된 경우에는 아래 공개 정책과 MATCH-10을 따릅니다. 관련 역량만 확인했으므로 프로젝트 경험이 있다고 표시하면 안 됩니다.

## 결과와 추천 이유 표시

| 추천 결과 | 표시할 정보 |
| --- | --- |
| 공모전 | 공모전명, 마감일, 참가 자격, 매칭 이유, 공식 링크 |
| 팀 | 팀명, 공모전명, 필요한 역할, 모집 인원, 마감일, 매칭 이유 |
| 지원자 | 등록된 실명, 희망 역할, 공개가 허용된 관련 경험, 매칭 이유 |

PDF 본문의 지원자 `닉네임` 표시는 부록의 [실명·공개 정책](profile.md#visibility)으로 대체합니다. 이메일과 구체적인 개인 일정은 공개하지 않으며, 추천에 사용할 수 있는 정보와 열람자가 확인할 수 있는 정보는 프로필 공개 정책을 함께 따릅니다.

지원자 추천에도 [비공개 설정 우선 원칙](profile.md#visibility-priority)을 적용합니다. 비공개 관심 분야·경험·자기소개 내용은 지원 팀장에게 표시하지 않으며, 추천 이유에 해당 내용을 옮겨 표시하지 않습니다. 비공개 정보의 계산 사용과 점수·요약 근거를 통한 간접 노출의 허용 범위는 MATCH-10에서 별도로 정합니다.

추천 이유는 점수에 실제 반영된 데이터만 사용합니다. 확인되지 않은 경험·역량을 추정하거나 근거 없이 적합하다고 설명하지 않습니다. 관심 분야·희망 역할을 설명할 때도 실제 입력과 계산 결과가 뒷받침되어야 합니다. 시간 겹침의 자동 계산·표시는 현재 추천 요구사항에 포함하지 않으며, 추천 외 시간 활용·표시 범위는 후속 검토합니다.

## 완료 조건

- [ ] AC-01: 세 추천 유형이 정해진 실행 시점에 갱신되고 각각 홈·공모전 목록, 공모전 상세·팀 목록, 팀 관리 화면에서 대상에 맞는 후보를 확인할 수 있다. 지원자 프로필 변경 후 다음 조회·갱신도 지원자 추천의 갱신 시점에 포함한다.
- [ ] AC-02: 필수 조건을 위반한 후보는 추천에서 제외되며, 필수 자격 정보가 없거나 미확인인 후보는 자동 통과하지 않고 `확인 필요`로 구분된다.
- [ ] AC-03: 정원이 찬 팀과 모집 종료·마감 후 신규 지원 대상은 제외된다. 팀이 지원자 검토를 시작해도 마감·정원 등 현재 신규 접수 조건을 충족하면 팀 추천 후보에서 제외하지 않는다. 모집 역할이 일치하지 않는다는 이유만으로는 추천 후보에서 제외하지 않는다.
- [ ] AC-04: 팀장의 지원자 추천은 실제 현재 지원을 기준으로 판단한다. 취소된 이전 지원을 현재 지원처럼 평가하지 않으며, 재지원 접수가 성공한 사용자를 취소 이력만으로 제외하지 않는다. 구체 상태별 평가 범위는 MATCH-01에서 확정한 기준을 따른다.
- [ ] AC-05: 공모전 점수는 관심 분야 `60%`·경험 `40%`로 계산된다. 팀·지원자의 최종 점수는 MATCH-11에서 새 가중치·산식을 정한 뒤 검증하며, 기존 시간 포함 산식은 적용하지 않는다.
- [ ] AC-06: 공모전 경험의 `100/60/40/50`, 팀 경험·역량의 `100/70/40/50`, 팀·지원자 추천에서 사용자 관심 분야 미입력 `50`이 각각 해당 입력 상태에 적용된다. 시간 미입력에 대한 대체 점수는 산출하지 않는다.
- [ ] AC-08: 최종 산식이 확정된 유형은 점수 내림차순으로 표시된다. 동점은 MATCH-05에서 정한 기준으로 검증하며, 활동·가능 시간은 동점 판정에 사용하지 않는다.
- [ ] AC-09: 공고·팀에 학적·학년·전공 조건이 없으면 해당 값만 다른 사용자의 점수·순위가 그 차이 때문에 달라지지 않는다.
- [ ] AC-10: 유형별 표시 정보와 실제 계산에 사용한 추천 이유를 공개가 허용된 범위에서 확인할 수 있으며, 지원자 이름은 실명 정책을 따르고 이메일·구체적인 개인 일정·추정한 경험은 표시되지 않는다. 비공개 관심 분야·경험·자기소개 내용은 다른 사용자에게 보이는 지원자 정보와 추천 이유에 표시되지 않는다.
- [ ] AC-11: 포트폴리오 유무·내용·AI 분석 결과가 추천 점수에 사용되지 않으며, 경험이 적다는 이유만으로 필수 조건을 통과한 후보가 제외되지 않는다.
- [ ] AC-12: 가중치 변경 시 적용한 설정값과 버전·적용일을 확인할 수 있다.
- [ ] AC-13: 지원 후 역할을 바꾸고 저장한 사용자를 다시 조회하면, 검토 화면과 추천이 같은 현재 프로필을 사용하되 역할 불일치만으로 추천 후보에서 제외하지 않는다. 다른 입력과 조건이 같으면 시간·자기소개 수정·포트폴리오 삭제만으로 점수·순위가 바뀌지 않는다.
- [ ] AC-14: 사용자 시간 미입력·겹침 0%·겹침 100% 모두 추천 시간 점수를 산출하지 않는다. 다른 입력과 조건이 같으면 시간값만으로 점수·순위가 달라지지 않고 시간 겹침을 추천 이유로 표시하지 않는다.
- [ ] AC-15: [관심 분야 비교 사례](#interest-union)의 동일 분야·서로 다른 분야·일부 중복·불일치 결과가 각각 100·100·75·0으로 계산되며, 같은 분야가 공모전과 팀에 있어도 한 번만 센다. 최종 총점과는 구분한다.
- [ ] AC-16: 개발·디자인을 모집하는 팀에 개발만·디자인만·둘 다·발표만 희망하는 경우 모두 역할 조건 자체로는 추천에서 제외하거나 지원을 차단하지 않는다. 다른 필수 조건과 실제 팀장 선발은 별도로 적용한다.

기존 AC-07의 시간 분모·총점 `74.5` 검증은 시간 요소 제외로 폐기했습니다. 번호는 재사용하지 않으며, 현재 시간 미사용 정책은 AC-14에서 검증합니다.

체크는 실제 구현·검증을 뜻합니다. 미정 사항이 연결된 조건의 상세 검증 사례는 해당 결정을 반영한 뒤 보완하며, 명세 이관만으로 체크하지 않습니다.
