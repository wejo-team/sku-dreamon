# 공모전·팀·지원자 추천

- 구현 상태: 예정
- 명세 검토: [PR #17](https://github.com/wejo-team/wejo-app/pull/17)
- 구현 작업: 미등록

스프린트 1의 추천 대상, 필수 조건, 점수 계산과 표시 정책을 정의합니다. PDF 본문의 가중치 `35/25/25/15`는 초기 예시이며, 이 문서는 정책 확정 부록의 공모전 `60/40`, 팀·지원자 `40/25/25/10`을 적용합니다.
입력·공개 범위는 [프로필 정책](profile.md), 분류와 코드는 [공통 선택지](profile-options.md), 모집·지원 상태는 [팀 모집과 지원](team-recruitment.md)에서 관리합니다.

## 목적과 사용자

일반 사용자는 참여할 공모전을 찾고, 팀을 찾는 사용자는 선택한 공모전의 모집 팀을 비교하며, 팀장은 실제 지원자를 검토합니다. 각 사용자는 조건에 맞는 후보와 실제 데이터에 근거한 추천 이유를 확인합니다.

## 범위

| 포함 | 제외 |
| --- | --- |
| 공모전 추천, 팀 추천, 실제 지원자 추천 | 지원하지 않은 전체 사용자 대상 지원자 추천 |
| 필수 조건 확인, 규칙 기반 점수·순위 계산, 추천 이유 표시 | 자연어 대화형 매칭, AI가 추정한 경험·역량으로 점수 계산 |
| 고정 가중치의 설정값·버전·적용일 관리 | 포트폴리오 내용 또는 AI 분석 결과의 추천 점수 반영 |

공고문 요약 등 AI의 별도 역할과 후속 스프린트 범위는 [스프린트 1 범위](sprint-1.md)에서 정의합니다.

## 추천 유형과 실행 시점

| 유형 | 사용자와 추천 대상 | 실행 시점 | 노출 위치 |
| --- | --- | --- | --- |
| 공모전 추천 | 일반 사용자에게 관심 분야·참가 자격·경험·일정에 맞는 공모전 | 프로필 저장·수정 시 또는 사용자가 갱신할 때 | 홈·공모전 목록 |
| 팀 추천 | 팀을 찾는 사용자에게 선택한 공모전에서 모집 중인 팀 | 공모전 선택 시 또는 프로필 변경 후 갱신할 때 | 공모전 상세·팀 목록 |
| 지원자 추천 | 팀장에게 팀 모집 조건에 맞는 실제 지원자 | 새 지원 접수 또는 모집 조건 변경 시 | 팀 관리 화면 |

위 표의 설명에서 참가 자격·마감·참가 가능 여부는 필수 조건이며 공모전 점수 요소가 아닙니다. 실제 계산은 아래 확정 산식을 따릅니다.

## 사용자 흐름과 동작

1. 사용자가 위 실행 시점에 추천을 요청하거나 추천 결과를 확인합니다.
2. 모집 상태·마감·정원·참가 자격 등 필수 조건을 먼저 검사합니다. 자격을 확인할 수 없는 후보는 자동 통과시키지 않고 `확인 필요`로 분리합니다.
3. 필수 조건을 통과한 후보만 해당 유형의 가중치로 0~100점의 적합도 점수를 계산합니다.
4. 점수 내림차순으로 정렬하고 실제 일치한 항목을 추천 이유로 표시합니다.
5. 동점이면 희망 역할 일치 점수, 활동 가능 시간 점수 순으로 비교합니다. 공모전 추천과 최종 동점의 처리 범위는 [미정 사항](#open-questions)을 따릅니다.

## 필수 조건과 선호 조건

필수 조건은 후보 포함 여부를 정하고, 선호 조건은 통과한 후보 사이의 점수와 순위를 정합니다. 경험이 적다는 이유만으로 초보자를 자동 제외하지 않습니다.

| 공통 필수 조건 | 처리 규칙 |
| --- | --- |
| 공고·팀 모집 상태와 마감 | 공고 또는 팀이 모집 중이고 마감 전인 경우만 후보에 포함. 모집 중인 공고·팀만 지원 가능 |
| 모집 정원 | 정원이 찬 팀은 신규 지원을 허용하지 않으며, 신규 지원자 및 신규 지원 대상 팀 후보에서 제외 |
| 참가 자격 | 공고에 명시된 학교·학적 상태·학년·전공·학과 등 자격 조건을 모두 충족해야 통과. 미충족이 확인되면 제외하고, 정보가 없거나 확인되지 않으면 `확인 필요`로 분리 |
| 팀의 필수 역할 | 팀이 특정 역할을 필수로 지정하면 그 역할을 희망 역할로 선택한 사용자만 지원자 추천 후보에 포함. 단순 우대 역할은 필터 대신 점수로 반영 |
| 중복·상태 | 이미 해당 팀에 지원했거나 지원 취소·미선발 상태인 사용자는 중복 지원 대상에서 제외. 실제 지원자 추천은 해당 팀에 지원 완료한 사용자만 평가 |

마지막 행은 신규 지원 대상과 팀장의 실제 지원자 평가를 구분한 원문 표현입니다. `지원 완료`가 지원 이력 전체인지 특정 상태인지, 검토 중·선발 등의 상태를 평가에 포함할지는 여기서 임의로 확정하지 않습니다. 정원 충족·모집 마감 후 기존 지원자 평가와 필수 역할을 팀 추천에 적용하는 방식도 미정입니다.

| 항목 | 필수·선호 구분과 사용 원칙 |
| --- | --- |
| 관심 분야 | 선호 조건. 일치도가 높을수록 점수에 반영 |
| 희망 역할 | 선호 또는 팀이 지정한 필수 조건. 우대 역할은 점수에만 반영 |
| 관련 경험·역량 | 선호 조건. 명시적인 경험 없음과 미입력을 구분 |
| 활동 가능 시간 | 선호 조건. 팀 필수 활동 시간과 겹치는 비율을 점수에 반영 |
| 학적 상태·학년·단과대학·전공·학과 | 일반 점수 요소가 아님. 공고 참가 자격이나 팀 모집 조건에 명시된 경우에만 필수 필터에 사용하며, 조건이 없으면 이 항목 때문에 순위를 올리거나 내리지 않음 |

학적 상태는 공고 자격, 학년·단과대학은 명시적인 공고 또는 팀 조건, 전공·학과는 명시적인 공고 전공 제한에 사용한다는 항목별 기준도 있습니다. 이 기준과 부록의 공통 필터 원칙 사이에서 팀의 학적·전공 제한 허용 범위는 미정 사항으로 남깁니다.

## 공모전 추천 점수

| 요소 | 가중치 | 요소 점수 산정 규칙 |
| --- | --- | --- |
| 관심 분야 일치 | 60점 | 사용자 관심 분야와 공모전 분류의 일치 분야 수 ÷ 사용자 관심 분야 수 × 100 |
| 관련 경험 | 40점 | 표준 분류로 사용자 경험 분야와 공모전 분야의 관련도 비교. 직접 관련 경험 `100`, 인접 분야 경험 `60`, 관련 경험 없음 `40`, 미입력 `50` |

참가 자격·마감·참가 가능 여부는 점수에 더하지 않고 필수 조건으로 처리합니다. 전공·학년은 공고의 명시적 자격일 때만 필터에 사용합니다. 공모전 추천의 관심 분야 미입력 점수와 분모가 0인 경우의 처리는 원문에 없습니다.

<a id="team-score"></a>

## 팀·지원자 추천 점수

팀 추천과 지원자 추천은 같은 요소와 가중치를 사용합니다.

| 요소 | 가중치 | 요소 점수 산정 규칙 |
| --- | --- | --- |
| 희망 역할 일치 | 40점 | 사용자 희망 역할과 팀 모집 역할이 일치하면 `100`, 일치하지 않으면 `0`. 필수 역할 조건은 점수 계산 전에 별도로 적용 가능 |
| 관심 분야 일치 | 25점 | 사용자 관심 분야와 공모전·팀 관심 분야의 일치 개수 ÷ 사용자 관심 분야 개수 × 100. 사용자 관심 분야 미입력 시 `50` |
| 활동 가능 시간 겹침 | 25점 | 사용자가 가능하다고 선택한 구간과 겹치는 팀 필수 활동 시간 구간 수 ÷ 팀 필수 활동 시간 구간 수 × 100. 팀이 시간대를 등록하지 않았으면 `50` |
| 관련 경험·역량 | 10점 | 팀 역할과 직접 관련된 프로젝트·공모전 경험이 있으면 `100`, 관련 역량은 있으나 경험 등록이 없으면 `70`, 관련 경험·역량이 없다고 명시하면 `40`, 미입력이면 `50` |

시간 계산의 분모는 사용자의 전체 가능 시간이 아니라 **팀이 등록한 필수 활동 시간 구간 수**입니다. 사용자 가능 시간 미입력과 명시적으로 겹치는 시간이 없는 경우를 임의로 같은 상태로 취급하지 않습니다.

역할·관심 분야를 복수 선택했을 때의 일치 판정, 공모전과 팀의 관심 분야를 합치는 방법, 경험·역량 조건이 중첩될 때의 선택 순서는 원문에 구체화되어 있지 않습니다. 관련 분류·관계표와 입력 시간 구간은 [공통 선택지](profile-options.md)에서 관리하며, 계산에 필요한 미정 사항은 아래에 남깁니다.

## 계산·정렬과 변경 관리

요소 점수는 0~100 범위이며, 최종 점수는 다음과 같이 계산합니다.

```text
최종 점수 = (각 요소 점수 × 해당 가중치)를 모두 더한 값 ÷ 100
공모전 점수 = 관심 분야 점수 × 0.60 + 관련 경험 점수 × 0.40
팀·지원자 점수 = 역할 점수 × 0.40 + 관심 분야 점수 × 0.25
               + 시간 겹침 점수 × 0.25 + 경험·역량 점수 × 0.10
```

- 최종 점수는 소수점 첫째 자리까지 저장·표시합니다. 반올림·절사 방식, 중간 계산 정밀도와 정렬에 사용할 정밀도는 미정입니다.
- 점수 내림차순으로 정렬하고, 동점이면 희망 역할 일치 점수와 활동 가능 시간 점수 순으로 비교합니다. 공모전 점수에는 두 요소가 없으므로 공모전 동점 규칙은 별도 결정이 필요합니다.
- 미입력·미확인은 불일치로 바꾸지 않고 별도 상태로 보존합니다. 이 문서에 명시된 미입력 점수만 적용하며, 없는 규칙을 추정하지 않습니다.
- 가중치는 코드 여러 곳에 임의로 흩어 두지 않고 설정값으로 관리합니다. 변경 시 버전과 적용일을 기록합니다. 설정 파일·저장 방식 등 구현 설계는 개발 계획에서 정합니다.
- 표준 코드와 계산 규칙의 공통 활용, 분류 목록의 변경 이력은 [공통 데이터 관리](profile-options.md#catalog-management)를 따릅니다. 기존 추천 결과에 변경된 가중치를 언제 다시 적용할지는 미정입니다.

### 계산 예시

다음은 계산 확인을 위한 가상 합성 데이터입니다. 실제 사용자나 팀을 나타내지 않습니다. 모집·마감·정원·참가 자격을 모두 통과하고, 팀장이 평가할 경우 해당 팀에 지원 완료한 사용자를 가정합니다.

- 사용자 희망 역할과 팀 모집 역할이 모두 `디자인`이므로 역할 요소 점수는 `100`입니다.
- 사용자 관심 분야 4개 중 공모전·팀에 동일하게 등록된 분야 2개가 일치하므로 관심 분야 요소 점수는 `2 ÷ 4 × 100 = 50`입니다.
- 팀의 필수 활동 시간 5개 구간 중 사용자 가능 시간과 3개가 겹치므로 시간 요소 점수는 `3 ÷ 5 × 100 = 60`입니다.
- 팀 역할에 관련된 역량은 있지만 경험 등록이 없으므로 경험·역량 요소 점수는 `70`입니다.

```text
100 × 0.40 + 50 × 0.25 + 60 × 0.25 + 70 × 0.10
= 40 + 12.5 + 15 + 7
= 74.5점
```

이 경우 `희망 역할이 모집 역할과 일치합니다`, `관심 분야 2개가 일치합니다`, `팀 필수 활동 시간의 60%에 참여할 수 있습니다`를 실제 계산 근거로 표시할 수 있습니다. 관련 역량만 확인했으므로 프로젝트 경험이 있다고 표시하면 안 됩니다.

## 결과와 추천 이유 표시

| 추천 결과 | 표시할 정보 |
| --- | --- |
| 공모전 | 공모전명, 마감일, 참가 자격, 매칭 이유, 공식 링크 |
| 팀 | 팀명, 공모전명, 필요한 역할, 모집 인원, 마감일, 매칭 이유 |
| 지원자 | 등록된 실명, 희망 역할, 관련 경험, 가능한 시간의 겹침 정보, 매칭 이유 |

PDF 본문의 지원자 `닉네임` 표시는 부록의 [실명·공개 정책](profile.md#visibility)으로 대체합니다. 이메일과 구체적인 개인 일정은 공개하지 않으며, 추천에 사용할 수 있는 정보와 열람자가 확인할 수 있는 정보는 프로필 공개 정책을 함께 따릅니다.

추천 이유는 점수에 실제 반영된 데이터만 사용합니다. 확인되지 않은 경험·역량을 추정하거나 근거 없이 적합하다고 설명하지 않습니다. 원문의 예시처럼 관심 분야·희망 역할·시간 겹침을 설명할 때도 실제 입력과 계산 결과가 뒷받침되어야 합니다.

## 완료 조건

- [ ] AC-01: 세 추천 유형이 정해진 실행 시점에 갱신되고 각각 홈·공모전 목록, 공모전 상세·팀 목록, 팀 관리 화면에서 대상에 맞는 후보를 확인할 수 있다.
- [ ] AC-02: 필수 조건을 위반한 후보는 추천에서 제외되며, 필수 자격 정보가 없거나 미확인인 후보는 자동 통과하지 않고 `확인 필요`로 구분된다.
- [ ] AC-03: 정원이 찬 팀과 모집 종료·마감 후 신규 지원 대상은 제외되고, 필수 역할과 단순 우대 역할이 각각 필터와 점수 규칙에 따라 처리된다.
- [ ] AC-04: 팀장의 지원자 추천에는 실제 지원자만 평가되며, 중복 지원 대상과 지원 상태별 평가 범위는 MATCH-01에서 확정한 기준을 따른다.
- [ ] AC-05: 공모전 점수는 관심 분야 `60%`·경험 `40%`, 팀·지원자 점수는 역할 `40%`·관심 분야 `25%`·시간 `25%`·경험과 역량 `10%`로 계산된다.
- [ ] AC-06: 공모전 경험의 `100/60/40/50`, 팀 경험·역량의 `100/70/40/50`, 팀 관심 분야 미입력 `50`, 팀 시간대 미등록 `50`이 각각 해당 입력 상태에 적용된다.
- [ ] AC-07: 시간 점수의 분모가 팀 필수 시간 구간 수로 계산되고, 위 가상 예시의 최종 점수가 `74.5`로 저장·표시된다.
- [ ] AC-08: 결과가 점수 내림차순으로 표시되며, 같은 총점의 팀·지원자 후보는 역할 일치 점수와 시간 점수 순으로 비교된다. 최종 동점과 공모전 동점은 MATCH-05에서 확정한 기준을 따른다.
- [ ] AC-09: 공고·팀에 학적·학년·전공 조건이 없으면 해당 값만 다른 사용자의 점수·순위가 그 차이 때문에 달라지지 않는다.
- [ ] AC-10: 유형별 표시 정보와 실제 계산에 사용한 추천 이유를 확인할 수 있으며, 지원자 이름은 실명 정책을 따르고 이메일·구체적인 개인 일정·추정한 경험은 표시되지 않는다.
- [ ] AC-11: 포트폴리오 유무·내용·AI 분석 결과가 추천 점수에 사용되지 않으며, 경험이 적다는 이유만으로 필수 조건을 통과한 후보가 제외되지 않는다.
- [ ] AC-12: 가중치 변경 시 적용한 설정값과 버전·적용일을 확인할 수 있다.

체크는 실제 구현·검증을 뜻합니다. 미정 사항이 연결된 조건의 상세 검증 사례는 해당 결정을 반영한 뒤 보완하며, 명세 이관만으로 체크하지 않습니다.

## 미정 사항

| ID | 결정할 내용 |
| --- | --- |
| MATCH-01 | 실제 지원자 평가에서 `지원 완료`가 뜻하는 상태 범위, 검토 중·선발·미선발·취소 처리, 정원 충족·모집 마감 후 기존 지원자 평가 범위. 신규 지원 후보 제외와 실제 지원자 평가를 같은 규칙으로 단정하지 않음 |
| MATCH-02 | 팀 필수 역할의 팀 추천 적용 방식, 필수 역할을 복수 지정했을 때 전부 또는 일부 일치를 요구하는지, 복수 희망·모집 역할의 일치 판정 |
| MATCH-03 | 공모전 추천에서 사용자 관심 분야 미입력·분모 0, 공고·팀 자체의 관심 분야 미등록, 사용자 역할·가능 시간 미입력 처리. 팀·지원자 추천의 사용자 관심 분야 미입력은 위 확정값 50점을 유지하며, 필수 프로필 미완성 사용자의 추천 허용 범위는 별도로 결정 |
| MATCH-04 | 공모전·팀 관심 분야의 합집합 또는 다른 결합 기준, 경험의 직접·인접 관계와 복수 경험 평가, 관련 역량 대응표, 경험·역량 조건이 중첩되거나 명시적 무경험과 역량 입력이 함께 있을 때의 우선순위 |
| MATCH-05 | 역할·시간 점수가 없는 공모전의 동점 처리, 팀·지원자에서 두 보조 점수까지 같은 경우의 최종 순서 |
| MATCH-06 | 소수점 처리 방식·중간 계산 정밀도·정렬 기준 정밀도, 점수 변경 후 기존 결과의 재계산·적용 시점 |
| MATCH-07 | 팀 필수 시간 구간 입력 방식, 사용자 시간 구간과의 대응·중복 구간 계산·시간대 및 주 경계. 공통 선택지의 시간 미정 사항과 함께 결정 |
| MATCH-08 | 자격 `확인 필요` 목록의 노출 위치·확인 절차·지원 허용 여부, 명시된 참가 가능 여부를 판정할 입력과 기준, 후보가 없을 때의 안내 |
| MATCH-09 | 학적·전공의 항목별 사용 제한과 공통 필터 원칙 사이에서 팀이 지정할 수 있는 자격 조건의 범위 |
| MATCH-10 | 공개 설정으로 제한된 정보의 추천 계산 사용·이유 노출 범위. 프로필 공개 정책과 충돌하지 않도록 확정 |
