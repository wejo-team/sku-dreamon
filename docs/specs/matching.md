# LLM 기반 공모전·팀·지원자 추천

- 구현 상태: 예정
- 명세 검토: 기존 [PR #17](https://github.com/wejo-team/sku-dreamon/pull/17); 2026-10-18 LLM 전환·공식 디자인 반영 변경은 이 변경 PR에서 사람 검토 대기
- 구현 작업: 미등록

공모전·팀·실제 지원자 추천을 **LLM 기반 추천**으로 변경합니다. 이 문서는 사용자에게 제공할 동작, 근거와 공개 범위를 정의하며 내부 아키텍처는 TBD입니다. 저장소의 실행 가능한 공식 디자인은 화면·상태·인터랙션의 참고 자료이며 실제 LLM·서버 구현 완료를 뜻하지 않습니다.

입력·공개 범위는 [프로필](profile.md), 분류는 [공통 선택지](profile-options.md), 모집·지원의 권한과 상태는 [팀 모집과 지원](team-recruitment.md)에서 관리합니다.

<a id="policy-decisions"></a>

## 변경 결정과 범위

2026-10-18 사용자 요청에 따라 기존의 규칙 기반 추천 로직을 제외합니다. 공모전·팀·지원자의 고정 가중치, 요소별 점수, 총점 산식, 관심 분야 합집합 비율, 점수 순 정렬·동점 처리, 시간 값 변경에 따른 결과 불변 보장은 더 이상 구현 요구사항이 아닙니다. 이 변경을 기존 산식의 가중치 조정으로 해석하지 않습니다.

| 포함 | 제외 또는 미정 |
| --- | --- |
| AI 탭의 자연어 탐색·추천 대화와 후속 조건 수정 | 모델·제공자·프롬프트·검색/검색증강·도구 호출·캐시·실행 구조는 TBD |
| 공모전·팀·실제 지원자의 추천 결과와 확인 가능한 근거 | 고정 적합도 점수·일치율·점수별 순위·기존 산식 재사용 |
| 로그인한 사용자의 공개 사람 탐색을 돕는 대화 | 미지원자를 팀장의 실제 지원자로 표시하거나 자동 지원·선발 |
| 권한·공개 범위·모집 제한을 지키는 응답 | 비공개 정보 노출, 없는 자격·경험·역량 추정, 포트폴리오 수집·AI 분석 |

LLM 전환으로 참가 자격·마감·정원·중복 지원·공모전별 소속 제한이나 접근 권한을 없애지 않습니다. 추천 결과는 지원 접수·선발·팀원 확정을 대신하지 않습니다. 역할 불일치만으로 추천·지원을 차단하지 않고 경험이 적다는 이유만으로 초보자를 자동 제외하지 않는 [모집 정책](team-recruitment.md#recruitment-information)을 유지합니다.

## 추천 유형과 이용 흐름

| 유형 | 사용자와 대상 | 진입·갱신 | 결과에서 가능한 행동 |
| --- | --- | --- | --- |
| 공모전 추천 | 사용자가 관심·참여 조건에 맞는 공모전을 찾음 | AI 탭에서 자연어 요청, 탐색에서 추천 진입, 조건 수정·다시 요청 | 공고 상세·공식 원문 확인 |
| 팀 추천 | 사용자가 공모전과 선호에 맞는 모집 팀을 찾음 | AI 탭 또는 공모전 상세에서 요청, 공모전·조건 변경 후 다시 요청 | 팀 상세 확인 후 직접 지원 |
| 지원자 추천 | 팀장이 자기 팀에 실제 접수된 지원자를 검토함 | 팀장 관리에서 요청·다시 조회; 현재 지원·프로필·모집 정보를 사용 | 허용된 프로필 확인 후 팀장이 직접 선발 |
| 공개 사람 탐색 보조 | 로그인한 사용자가 공개에 동의한 사람을 찾음 | AI 탭에서 사람 탐색 요청 | [사람 탐색](profile.md#people-directory)과 동일한 공개 범위의 상세 확인 |

사람 탐색 보조와 지원자 추천은 구분합니다. 사람 목록에 보인다는 이유로 해당 팀에 지원한 것으로 표시하거나 선발 버튼을 제공하지 않습니다. 비로그인의 개인화 추천 허용은 [인증 미정 사항](authentication.md#open-questions)에 남기며, 비로그인에게 타인 프로필·지원자·개인 알림을 제공하지 않습니다.

지원자 검토와 추천에는 [현재 프로필 기준](profile.md#application-profile)을 함께 적용합니다. 변경 후 다음 조회·갱신에 이전 프로필 근거를 현재 프로필과 섞지 않습니다. 일반 프로필 변경 알림이나 열린 화면의 실시간 자동 갱신은 요구하지 않으며, 공개 동의 철회는 [저장 성공 즉시 열람 기준](profile.md#visibility-changes)에 적용합니다.

## 자연어 대화와 화면 상태

1. AI 탭에서 요청 예시를 선택하거나 자연어로 입력합니다. 예시는 실제 후보가 있다는 보장이 아니라 입력을 돕는 문구입니다.
2. 요청을 보내면 사용자 메시지와 응답 준비 상태를 구분합니다. 필요한 조건이 불명확하면 짧게 확인하거나 현재 이해한 조건을 보여 줍니다.
3. 응답은 설명과 연결된 공모전·팀·허용된 사람 카드로 구성합니다. 해당 대화 맥락에서 조건을 추가·수정해 다시 탐색할 수 있습니다.
4. 카드를 누르면 일반 상세 화면으로 이동합니다. 지원·팀 생성·선발은 각 화면의 확인과 권한 검사를 거치며 대화만으로 자동 실행하지 않습니다.
5. 응답 중에는 중단할 수 있고 실패하면 같은 요청을 다시 시도할 수 있습니다. 새 대화는 현재 대화 초기화, 답변 복사는 표시된 답변 복사를 제공합니다.

| 상태 | 사용자에게 보이는 동작 |
| --- | --- |
| 시작 전 | 요청 예시, 입력창, 보낼 수 있는 상태 안내 |
| 준비 중 | 진행 상태와 중단 동작. 요청을 실수로 중복 전송하지 않도록 처리 |
| 성공 | 답변·실제 연결 가능한 결과 카드·추천 근거 |
| 결과 없음 | 결과가 없음을 명시하고 조건 수정 또는 일반 탐색으로 이동 가능. 가상의 후보를 만들지 않음 |
| 실패 | 기존 대화와 요청을 유지하고 재시도 제공. 실패를 추천 결과 없음으로 표시하지 않음 |
| 중단 | 중단됐음을 구분하고 새 요청 가능. 중단된 요청의 늦은 응답이 새 대화를 덮지 않음 |
| 새 대화 | 현재 대화 초기화. 영구 대화 보존·다른 기기 동기화는 TBD |

같은 로그인 세션에서 탭을 오갈 때 대화·작성 중 입력을 유지하는 경험을 제공합니다. 새로고침 이후 보존·서버 저장·보존 기간·로그아웃 시 서버 기록 삭제 방식은 MATCH-13에서 결정합니다. 화면에는 개발 환경·시안·미연동 배너를 상시 배치하지 않으며, 레퍼런스의 모의 동작은 저장소 설명에서 명시합니다. 실제 제품 시연의 사실 안내는 [시연 기준](sprint-1.md#web-demo)을 따릅니다.

## 모집 제한과 자격 확인

다음은 추천 알고리즘이 아니라 서비스의 참가·공개 정책입니다. LLM 응답이나 사용자의 요청으로 우회할 수 없습니다.

| 조건 | 처리 |
| --- | --- |
| 공고 공개·모집 기간 | 공개가 허용된 공고를 사용하며 마감·종료된 대상은 신규 지원 가능한 후보처럼 안내하지 않음 |
| 팀 정원·모집 상태 | 정원이 찼거나 모집을 종료한 팀은 신규 지원 추천에서 제외. 검토 시작 자체로 접수를 닫지 않는 [정책](team-recruitment.md#recruitment-review) 유지 |
| 참가 자격 | 확인된 미충족 후보를 참여 가능한 추천으로 제시하지 않음. 정보 누락·미확인은 `확인 필요`로 구분하고 자격 충족을 추정하지 않음 |
| 중복·취소·재지원 | 현재 유효한 지원과 취소된 이전 지원을 구분. 취소 이력만으로 영구 제외하지 않고 [재지원 정책](team-recruitment.md#reapplication) 적용 |
| 팀장의 지원자 추천 | 자기 팀에 실제 접수된 지원만 대상. 취소된 지원을 현재 지원으로 평가하지 않음 |
| 소속·선발 | [공모전별 한 팀 소속](team-recruitment.md#membership-limit), [선발 즉시 확정과 정원 차감](team-recruitment.md#membership-capacity)을 실제 행동 시 다시 확인 |
| 학사 정보 | 명시적인 공고·팀 참가 조건을 확인하는 데 사용. 학년·전공의 높고 낮음으로 사람의 일반적인 우수성을 단정하지 않음 |

모든 지원 직전에는 [필수 정보 점검·보완](profile.md#before-application)을 적용합니다. 필수값 입력 완료와 자격 확인 완료는 다릅니다. 자격 `확인 필요`의 접수 허용·판정 기준은 [#33](https://github.com/wejo-team/sku-dreamon/issues/33#issuecomment-6233084109), 마감·정원 충족 후 기존 지원자 추천은 [#46](https://github.com/wejo-team/sku-dreamon/issues/46#issuecomment-6232873014)의 TBD를 유지합니다. 선발·미선발 등 상태별 추천 포함 여부도 MATCH-01에서 정합니다.

프로필 열람 관계를 유지하는 것과 현재 지원자 추천 대상인 것은 다릅니다. [취소·미선발 후 열람 정책](profile.md#former-applicant-visibility)만으로 추천 대상에 포함하지 않습니다. 팀이 명시할 수 있는 학사 자격의 상세 범위는 MATCH-09에 남깁니다.

## 근거·공개 범위와 결과 표시

| 결과 | 표시 정보 |
| --- | --- |
| 공모전 | 공모전명·마감·참가 자격·추천 이유·공식 원문 또는 해당 정보가 있는 상세 링크 |
| 팀 | 팀명·공모전·현재 필요한 역할·팀장 포함 총 정원·모집 마감·추천 이유 |
| 실제 지원자 | 등록된 실명·희망 역할·열람이 허용된 경험·역량·추천 이유·지원자 상세 |
| 공개 사람 | 사람 탐색에 동의한 사용자의 최소 정보와 공개한 항목만 표시 |

- 추천 이유는 현재 확인 가능한 서비스 데이터와 사용자가 요청한 조건을 연결합니다. 존재하지 않는 경험·역량·공고 조건·마감일·시간 겹침을 만들거나 확인되지 않은 후보를 등록된 후보로 표시하지 않습니다.
- 일치율·신뢰도·합격 가능성·고정 적합도 점수를 근거 없이 표시하지 않습니다. 기존 숫자 점수의 자리를 임의의 LLM 점수로 채우지 않습니다.
- 이메일·상세 개인 일정·비공개 프로필·공유 동의 없는 포트폴리오를 답변·카드·추천 이유에 노출하지 않습니다. 전역 항목별 비공개 설정은 지원 팀장에게도 우선합니다.
- 타인의 비공개 정보를 LLM 입력이나 간접 추천 근거로 사용할 수 있는 범위는 [#49](https://github.com/wejo-team/sku-dreamon/issues/49#issuecomment-6234827892)에 따른 MATCH-10의 TBD입니다. 미정 상태를 사용 허가로 해석하지 않으며, 공식 디자인은 열람이 허용된 정보만 사용합니다. 실제 모델 전송 범위·동의·간접 노출 검증은 구현 전에 정합니다.
- 포트폴리오 URL 등록은 외부 내용을 수집하거나 분석하는 동의가 아닙니다. [포트폴리오 AI 분석 제외](profile.md#portfolio)를 유지합니다.
- 공개 철회나 접근 관계 변경 후의 새 조회·추천에 이전 공개 정보를 재사용하지 않습니다. 과거 대화·캐시의 재노출 방지 방식은 내부 설계에서 검증합니다.

## 폐기한 추천 로직과 내부 설계

위 앵커는 과거 문서·PR 링크의 호환을 위해 유지합니다. 연결된 예전 고정 점수·가중치·합집합 비율·정렬·동점 산식은 폐기됐으며 현재 요구사항은 이 문서의 LLM 기반 동작입니다. 이전 공식이나 요소별 점수를 대체 구현으로 사용하지 않습니다.

모델·제공자, 프롬프트, 후보 검색·선정, LLM 실행·응답 검증, 스트리밍, API·DB 계약, 캐시·갱신, 운영 비용·제한과 품질 평가를 포함한 **내부 아키텍처는 TBD**입니다. 본 문서의 사용자 경험을 만족할 설계는 후속 개발 계획에서 제안합니다. 공식 디자인의 로컬 데이터·응답 예시를 이 아키텍처의 결정이나 실제 LLM 연동으로 취급하지 않습니다.

## 완료 조건

기존 AC-01~04·09~11·13은 추천 대상·접수 조건·공개·현재 프로필 원칙을 새 AC-17~21로 통합합니다. AC-05~08·12·14·15의 고정 계산·정렬 관련 조건은 폐기하며 번호를 재사용하지 않습니다. 체크는 실제 기능 구현과 검증을 뜻하고 디자인 참고 자료 추가만으로 체크하지 않습니다.

- [ ] AC-16: AI 탭에서 자연어로 탐색·추천을 요청하고 후속 메시지로 조건을 바꿀 수 있으며, 설명과 연결된 공모전·팀 결과를 확인할 수 있다.
- [ ] AC-17: 공모전·팀·실제 지원자 추천이 각 사용자의 권한과 대상에 맞게 제공되며, 공개 사람 탐색 결과를 해당 팀의 실제 지원자로 표시하지 않는다.
- [ ] AC-18: 마감·종료·정원·현재 지원 관계 등 위 사업 정책이 추천 결과와 실제 행동에 적용된다. 미확인 자격은 `확인 필요`이며 자동 통과하지 않는다. 세부 TBD 상태는 결정 후 검증한다.
- [ ] AC-19: 역할 불일치·경험 부족만으로 후보를 자동 제외하지 않으며, 취소 이력을 재지원의 영구 제외 사유로 사용하지 않는다. 고정 점수·가중치·기존 산식은 제공하지 않는다.
- [ ] AC-20: 실제 데이터와 요청 조건으로 추천 이유를 설명하고, 비공개 항목·이메일·상세 일정·포트폴리오 내용·추정 경험을 노출하지 않는다. 타인의 비공개 데이터 사용은 MATCH-10 결정 전 허용하지 않는다.
- [ ] AC-21: 프로필·공개 범위 변경 후 새 조회·추천은 현재 정보와 권한을 따르며, 이전 근거를 현재 정보처럼 표시하지 않는다. 일반 프로필 변경 알림은 제공하지 않는다.
- [ ] AC-22: 준비 중·성공·빈 결과·실패·중단을 구분하고 실패한 요청을 재시도할 수 있다. 빈 결과를 가상의 후보로 채우지 않는다.
- [ ] AC-23: 새 대화와 답변 복사, 같은 세션 내 탭 이동 시 대화·입력 유지가 동작한다. 중단·새 대화 이후 늦은 응답이 현재 대화를 덮지 않는다.
- [ ] AC-24: 추천에서 상세로 이동한 뒤 사용자가 직접 지원·생성·선발하며, LLM이 참여·선발·인증 결과를 자동 확정하지 않는다.
