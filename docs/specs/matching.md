# 공모전·팀·지원자 추천

- 구현 상태: 예정
- 명세 검토: [PR #16](https://github.com/wejo-team/wejo-app/pull/16)
- 구현 작업: 미등록

이 문서는 추천 후보에 조건을 적용하는 순서, 점수 계산, 갱신과 표시를 관리합니다. 참가 자격·마감은 [공고의 참가 자격](contests.md#eligibility)·[마감](contests.md#deadlines), 지원 가능 여부·모집 상태는 [팀](teams.md#application-rules), 열람 권한은 [프로필](profile.md#visibility)이 원본입니다.
입력 분류나 시간 구간을 바꿀 때만 [공통 선택지](profile-options.md#choices)를, 학사 자격의 계층을 확인할 때만 [학사 선택 흐름](academic-structure.md#selection-flow)를 추가로 읽습니다.

## 목적과 범위

학생에게 참여 조건에 맞는 공모전과 팀을, 팀장에게 모집 조건에 맞는 실제 지원자를 보여 줍니다. 필수 조건과 선호 점수를 구분하고, 실제 입력 데이터로 추천 이유를 설명합니다.

- 포함: 공모전 추천, 선택한 공모전의 팀 추천, 해당 팀의 지원자 추천, 조건 확인, 점수·정렬·추천 이유.
- 제외: 전체 사용자 중 팀원 자동 발굴, 자동 선발·팀원 확정, 자연어 대화형 매칭, 포트폴리오 AI 분석, AI가 추정한 경험·역량 평가.
- 규칙 기반 계산을 사용합니다. 공고 AI 요약은 [공고 명세](contests.md), 작업 분해·회의 시간 추천의 후속 범위는 [스프린트 1](sprint-1.md)을 참조합니다.

<a id="refresh"></a>

## 사용자 흐름과 갱신

| 추천 | 사용자와 노출 위치 | 실행 시점 |
| --- | --- | --- |
| 공모전 | 일반 사용자, 홈·공모전 목록 | 프로필 저장·수정 또는 사용자의 갱신 요청 |
| 팀 | 팀을 찾는 학생, 공모전 상세·팀 목록 | 공모전 선택 또는 프로필 변경 후 갱신 |
| 지원자 | 팀장, 팀 관리 화면 | 새 지원 접수 또는 모집 조건 변경 |

지원자 추천은 해당 팀에 지원 완료한 사용자만 평가합니다. 추천 순위는 팀장의 검토를 돕는 정보이며 선발 결과로 취급하지 않습니다.

사용자는 조건을 확인한 후보 목록과 추천 이유를 보고 공고·팀 상세로 이동합니다. 팀장은 지원자의 공개 가능한 정보와 추천 근거를 검토한 뒤 [팀 명세](teams.md)의 선발 흐름을 사용합니다.

<a id="processing"></a>

## 공통 처리 순서

1. 공고·팀의 모집 상태, 마감, 정원, 명시된 참가 자격과 필수 모집 조건을 확인합니다.
2. 불충족이 확인된 후보는 제외하고, 필수 자격을 확인할 수 없는 후보는 `확인 필요`로 분리합니다.
3. 필수 조건을 통과한 후보에 한해 각 요소를 0~100점으로 계산하고 가중치를 적용합니다.
4. 최종 점수 내림차순으로 정렬하고, 점수에 실제 반영된 항목으로 추천 이유를 표시합니다.
5. 동점 정렬과 소수점 표시는 아래 규칙을 적용합니다. 정의가 없는 경우는 미정 사항을 먼저 결정합니다.

<a id="filters"></a>

### 필수 조건의 적용

| 조건 | 추천에서 적용하는 방식 | 정책 원본 |
| --- | --- | --- |
| 모집 상태·마감 | 모집 중이며 마감 전인 공고·팀을 후보로 포함 | [공고](contests.md), [팀](teams.md) |
| 팀 정원 | 정원이 찬 팀은 신규 지원 대상 팀·신규 지원자 후보에서 제외 | [팀](teams.md) |
| 참가 자격 | 공고가 명시한 자격을 모두 확인하며, 누락·미확인은 자동 통과시키지 않음 | [공고](contests.md) |
| 필수 역할 | 팀이 필수로 지정한 역할을 희망 역할로 선택한 사용자만 지원자 추천 후보에 포함 | [팀](teams.md) |
| 중복·지원 상태 | 이미 지원했거나 취소·미선발 상태인 사용자는 같은 팀의 중복 지원 대상에서 제외 | [팀](teams.md) |
| 실제 지원자 평가 | 해당 팀에 지원 완료한 사용자만 지원자 추천에서 평가 | [팀](teams.md) |

단순 우대 역할은 필터가 아닌 점수로 반영합니다. 취소·미선발 상태에 대한 위 규칙을 재지원 자체의 영구 금지로 확대하지 않으며, 재지원 허용 여부는 [팀 명세](teams.md#open-questions)의 미정 사항입니다.

학적 상태·학년·단과대학·전공·학과는 공고 참가 자격이나 팀 모집 조건에 명시된 경우에만 필터에 사용합니다. 조건이 없으면 해당 항목으로 순위를 올리거나 내리지 않습니다. 경험이 적다는 이유로 후보를 자동 제외하지 않습니다.

<a id="missing-values"></a>

### 미입력과 불일치

- 미입력·미확인은 불일치와 구분합니다. 필수 자격 미확인은 `확인 필요`이며 점수를 계산해 통과 후보로 섞지 않습니다.
- 선호 요소의 미입력 점수는 각 계산표에 명시된 값만 사용합니다. 어느 표에도 없는 경우에 임의로 0점·50점을 넣지 않습니다.
- `경험 없음`을 명시한 경우와 경험을 입력하지 않은 경우를 구분합니다. 원문의 서로 다른 점수를 아래에 유지하며, 의도 검토는 미정 사항에 남깁니다.

<a id="contest-scoring"></a>

## 공모전 추천 점수

요소 점수를 `I`(관심 분야), `E`(관련 경험)라고 할 때 최종 점수는 `I × 0.60 + E × 0.40`입니다.

| 요소 | 가중치 | 요소 점수 계산 |
| --- | --- | --- |
| 관심 분야 일치 | 60% | 사용자와 공모전의 일치 분야 수 ÷ 사용자의 관심 분야 수 × 100 |
| 관련 경험 | 40% | 등록한 경험 분야와 공모전 분야를 표준 분류로 비교하여 아래 점수 적용 |

| 경험 상태 | 요소 점수 |
| --- | --- |
| 직접 관련 경험 | 100 |
| 인접 분야 경험 | 60 |
| 관련 경험 없음 | 40 |
| 미입력 | 50 |

참가 자격·마감·참가 가능 여부는 선행 필터이며 점수 요소가 아닙니다. 전공·학년은 일반 점수에 반영하지 않습니다.

계산 확인 예: 사용자 관심 분야 4개 중 공모전과 2개가 일치하고 직접 관련 경험이 있으면 `50 × 0.60 + 100 × 0.40 = 70.0`점입니다. 이 예는 수식 검토용이며 경험 관련도 판정 기준을 새로 정의하지 않습니다.

<a id="team-scoring"></a>

## 팀·지원자 추천 점수

같은 요소와 가중치를 팀 추천과 지원자 추천에 사용합니다. 요소 점수를 `R`(희망 역할), `I`(관심 분야), `T`(활동 시간), `E`(경험·역량)라고 할 때 최종 점수는 `R × 0.40 + I × 0.25 + T × 0.25 + E × 0.10`입니다.

| 요소 | 가중치 | 요소 점수 계산 |
| --- | --- | --- |
| 희망 역할 일치 | 40% | 사용자 희망 역할과 팀 모집 역할이 일치하면 100, 일치하지 않으면 0 |
| 관심 분야 일치 | 25% | 사용자와 공모전·팀의 일치 분야 수 ÷ 사용자의 관심 분야 수 × 100; 사용자 관심 분야 미입력은 50 |
| 활동 가능 시간 겹침 | 25% | 겹치는 팀 필수 시간 구간 수 ÷ 팀 필수 시간 구간 수 × 100; 팀 시간대 미등록은 50 |
| 관련 경험·역량 | 10% | 팀 역할과의 관련성 및 입력 상태에 따라 아래 점수 적용 |

| 경험·역량 상태 | 요소 점수 |
| --- | --- |
| 팀 역할과 직접 관련된 프로젝트·공모전 경험 있음 | 100 |
| 관련 역량은 있으나 경험 등록 없음 | 70 |
| 관련 경험·역량이 없다고 명시 | 40 |
| 미입력 | 50 |

사용자 활동 시간 입력은 [공통 선택지의 요일·시간 구간](profile-options.md#time-slots)을 사용합니다. 팀 필수 시간과 사용자가 가능하다고 선택한 시간의 겹침 비율을 계산하며, 팀에도 동일 슬롯을 적용할지는 [선택지의 미정 사항 OPTIONS-05](profile-options.md#open-questions)에서 확정합니다. 구체적인 개인 일정의 열람 권한은 [프로필 공개 범위](profile.md#visibility)를 따릅니다.

계산 확인 예: 역할 일치 100, 관심 분야 2개/4개 일치로 50, 팀 필수 시간 3개/4개 겹침으로 75, 관련 역량만 있어 70이면 `40 + 12.5 + 18.75 + 7 = 78.25`점입니다. 원점수이며 소수점 첫째 자리 저장·표시의 반올림 방식은 미정입니다.

## 정렬·표시·추천 이유

<a id="sorting"></a>

### 점수와 정렬

- 최종 점수는 각 요소 점수와 가중치를 곱한 합으로 계산합니다. 가중치의 합은 100%이며 최종 점수 범위는 0~100점입니다.
- 소수점 첫째 자리까지 저장·표시합니다. 반올림·절삭 방식과 정렬에 사용할 정밀도는 미정입니다.
- 최종 점수 내림차순으로 정렬합니다. 동점이면 희망 역할 일치 점수, 활동 가능 시간 점수 순으로 비교합니다.
- 희망 역할·시간 요소가 없는 공모전 추천의 동점 기준과 모든 요소가 같은 최종 동점 기준은 미정입니다.

<a id="display"></a>

### 결과에 표시할 정보

| 추천 | 표시 정보 |
| --- | --- |
| 공모전 | 공모전명, 마감일, 참가 자격, 매칭 이유, 공식 링크 |
| 팀 | 팀명, 공모전명, 필요한 역할, 모집 인원, 마감일, 매칭 이유 |
| 지원자 | 등록된 실명, 희망 역할, 관련 경험, 활동 시간 겹침 정보, 매칭 이유 |

지원자 이름은 원문 본문의 닉네임 예시 대신 부록의 실명 입력·표시 정책을 적용합니다. 경험과 시간은 위 목록만으로 공개 권한이 생기지 않으며 [프로필 공개 정책](profile.md#visibility)에 따라 표시합니다.

추천 이유는 점수에 실제 반영된 데이터만 사용합니다. 다음 문장은 해당 근거가 확인된 경우의 예입니다.

- 희망 역할이 모집 역할과 일치합니다.
- 관심 분야 2개가 일치합니다.
- 팀 필수 활동 시간의 75%에 참여할 수 있습니다.

미입력 기본 점수를 실제 경험·역량이 확인된 것으로 설명하지 않습니다. 확인되지 않은 정보를 추정하거나 포트폴리오 내용의 AI 분석 결과를 점수·이유에 사용하지 않습니다.

<a id="rule-management"></a>

### 규칙 관리

동일한 표준 코드와 계산 규칙을 추천·검색 필터·통계에 공통으로 사용합니다. 표준 목록과 변경 이력은 [공통 선택지](profile-options.md#choices)를 따릅니다. 가중치는 설정값으로 관리하고 변경 시 버전·적용일을 기록합니다. 본문 초안의 팀 점수 예시 35/25/25/15 대신 정책 부록의 40/25/25/10을 적용합니다.

<a id="acceptance-criteria"></a>

## 완료 조건

- [ ] AC-01: 세 추천 유형이 지정된 화면과 실행 시점에서 각각 공모전·팀·실제 지원자 후보를 제공한다.
- [ ] AC-02: 모집 종료·마감·정원·명시적 자격·필수 역할·중복 상태를 먼저 검사하고, 자격 불충족과 확인 필요를 통과 후보와 구분한다.
- [ ] AC-03: 공고·팀이 요구하지 않은 학적·학년·전공 정보로 후보를 배제하거나 일반 점수를 바꾸지 않으며, 경험이 적다는 이유만으로 후보를 자동 제외하지 않는다.
- [ ] AC-04: 공모전 요소에 60/40을 적용하며 관심 분야 2/4 일치·직접 관련 경험의 계산 결과가 70.0점이다.
- [ ] AC-05: 팀·지원자 요소에 40/25/25/10을 적용하며 역할 100·분야 50·시간 75·경험 70의 가중 합이 78.25점이다.
- [ ] AC-06: 경험 없음과 미입력, 팀 시간대 미등록 등 명시된 입력 상태에 각 계산표의 요소 점수를 적용한다.
- [ ] AC-07: 점수 내림차순과 확정된 동점·소수점 규칙으로 정렬·표시한다. 미정인 동점·반올림 규칙을 확정한 뒤 검증한다.
- [ ] AC-08: 추천 이유는 실제 일치한 항목·개수·시간 비율을 표시하고, 공개 권한을 따르며 미입력·AI 추정 정보를 확인된 사실로 설명하지 않는다.
- [ ] AC-09: 가중치를 변경하면 적용 버전과 적용일을 확인할 수 있다.

체크는 구현·검증 완료를 뜻하며 명세 검토 완료만으로 체크하지 않습니다.

<a id="open-questions"></a>

## 미정 사항

아래는 원문에서 계산이나 동작을 일관되게 확정하기 어려운 항목입니다. 구현에 영향을 주는 항목은 명세 확정 전에 결정합니다.

| 번호 | 결정할 내용 |
| --- | --- |
| M-01 | 경험 분야의 직접·인접 관련도를 정할 표준 관계표와 역할별 관련 역량 관계표가 필요하다. 자유 서술 경험을 표준 분류에 연결하는 입력·검토 방식, 여러 경험 중 적용할 점수도 결정한다. AI가 임의 판정하는 방식은 현재 범위에 없다. |
| M-02 | 공모전 관심 분야 계산의 사용자 분야 미입력·분모 0 처리와 공모전 분류 누락 처리. 팀 관심 분야에는 미입력 50점이 명시되어 있으나 공모전으로 자동 확대하지 않는다. |
| M-03 | 팀 추천에서 공모전·팀 관심 분야가 다를 때 비교 대상이 합집합인지 별도 우선순위인지, 중복 분야를 어떻게 세는지 결정한다. |
| M-04 | 사용자의 활동 시간 미입력 처리. 팀 미등록의 50점은 정의되어 있지만 사용자 미입력의 점수는 정의되어 있지 않다. 팀 필수 구간이 존재하고 사용자 시간이 입력됐으나 겹침이 0개인 경우는 비율식에 따라 0점이다. |
| M-05 | 팀의 ‘필수 활동 시간’은 점수 계산의 분모로 쓰인다. 하나라도 불참하면 지원을 막는 조건인지 여부는 팀 정책과 함께 확정해야 하며, 현재 문구만으로 자동 탈락시키지 않는다. |
| M-06 | 복수 필수 역할에서 하나 이상 일치·모두 일치 중 어떤 조건을 적용할지, 희망 역할 미입력 처리, 관련 경험이 간접적이거나 경험·역량 입력이 섞인 경우의 점수를 정한다. |
| M-07 | 공모전 동점, 역할·시간까지 같은 최종 동점, 소수점 반올림·절삭 방식, 표시 정밀도와 정렬 정밀도를 확정한다. |
| M-08 | ‘경험 없음’ 40점보다 ‘미입력’ 50점이 높은 정책 의도를 확인한다. 이관 단계에서는 원문의 값을 유지한다. |
| M-09 | 모집 마감·정원 도달 뒤 기존 지원자 순위 제공 여부와 지원자의 프로필 수정·지원 취소 시 재계산 시점을 정한다. 신규 후보 제외와 기존 지원자 검토를 혼동하지 않는다. |
| M-10 | 공고·팀 조건 변경과 시간 경과로 인한 결과 갱신 시점, `확인 필요` 결과의 노출 위치·안내·정보 보완 후 재평가 방식을 정한다. |
