# LLM 기반 공모전·팀·지원자 추천

- 구현 상태: 진행 중 — 백엔드 [PR #157](https://github.com/wejo-team/sku-dreamon/pull/157) 병합, 제품 프론트 [PR #192](https://github.com/wejo-team/sku-dreamon/pull/192) 실제 API 연결, 단일 ReAct·입력 가드 [PR #206](https://github.com/wejo-team/sku-dreamon/pull/206) 구현·미배포
- 명세 검토: 기존 [PR #17](https://github.com/wejo-team/sku-dreamon/pull/17), LLM 전환 [PR #73](https://github.com/wejo-team/sku-dreamon/pull/73), AI 로그인 전용·프로필 공개 정책 [PR #75](https://github.com/wejo-team/sku-dreamon/pull/75); 2026-10-19 [#77](https://github.com/wejo-team/sku-dreamon/issues/77)의 입력·결과 제한과 #33·#36·#46·#49 연결 결정 반영
- 화면 구현과 후속: [AI 화면 연결 #163](https://github.com/wejo-team/sku-dreamon/issues/163), [실제 자료 품질·보존 #164](https://github.com/wejo-team/sku-dreamon/issues/164), [운영 배포 #165](https://github.com/wejo-team/sku-dreamon/issues/165)

공모전·팀·실제 지원자 추천을 **LLM 기반 추천**으로 변경합니다. 이 문서는 사용자에게 제공할 동작, 근거와 공개 범위를 정의합니다. `create_agent`·OpenAI Luna·실시간 스트리밍·현재 탭 메모리 유지는 확정했으며, 백엔드 구현과 후속 범위는 [AI 에이전트 SDD](../development-plans/ai-agent.md)에서 관리합니다. 저장소의 실행 가능한 공식 디자인은 화면·상태·인터랙션의 참고 자료이며 실제 LLM·서버 구현 완료를 뜻하지 않습니다.

입력·공개 범위는 [프로필](profile.md), 분류는 [공통 선택지](profile-options.md), 모집·지원의 권한과 상태는 [팀 모집과 지원](team-recruitment.md)에서 관리합니다.

## 변경 결정과 범위

2026-10-18 사용자 요청에 따라 기존의 규칙 기반 추천 로직을 제외합니다. 공모전·팀·지원자의 고정 가중치, 요소별 점수, 총점 산식, 관심 분야 합집합 비율, 점수 순 정렬·동점 처리, 시간 값 변경에 따른 결과 불변 보장은 더 이상 구현 요구사항이 아닙니다. 이 변경을 기존 산식의 가중치 조정으로 해석하지 않습니다.

| 포함 | 제외 또는 미정 |
| --- | --- |
| AI 탭의 자연어 탐색·추천 대화와 실시간 답변·후속 조건 수정 | `create_agent`·OpenAI Luna 사용. 백엔드 조회·검증·실행과 제품 화면의 실제 API 연결 구현. 실제 모델을 사용한 화면 통합 검사·운영·품질 평가는 후속 |
| 새 대화·답변 복사·현재 브라우저 탭 안의 화면 이동 시 대화 유지 | 새로고침·탭 종료 후 복원, 기기·브라우저 탭 간 동기화, 과거 대화 목록·검색·다시 열기 제외 |
| 공모전·팀·실제 지원자의 추천 결과와 확인 가능한 근거 | 고정 적합도 점수·일치율·점수별 순위·기존 산식 재사용 |
| 로그인한 사용자의 공개 사람 탐색을 돕는 대화 | 미지원자를 팀장의 실제 지원자로 표시하거나 자동 지원·선발 |
| 권한·공개 범위·모집 제한을 지키는 응답과 지원받은 팀장의 기존 지원자 검토 | 권한 없는 비공개 정보 노출, 없는 자격·경험·역량 추정, 포트폴리오 수집·AI 분석 |

LLM 전환으로 마감·정원·중복 지원·공모전별 소속 제한이나 접근 권한을 없애지 않습니다. 참가 자격은 원문 확인을 안내하며 비즈니스 로직의 차단 조건으로 사용하지 않는 [최신 정책](team-recruitment.md#recruitment-conditions)을 적용합니다. 추천 결과는 지원 접수·선발·팀원 확정을 대신하지 않습니다. 역할 불일치만으로 추천·지원을 차단하지 않고 경험이 적다는 이유만으로 초보자를 자동 제외하지 않는 [모집 정책](team-recruitment.md#recruitment-information)을 유지합니다.

## 추천 유형과 이용 흐름

| 유형 | 사용자와 대상 | 진입·갱신 | 결과에서 가능한 행동 |
| --- | --- | --- | --- |
| 공모전 추천 | 로그인한 사용자가 관심·참여 조건에 맞는 공모전을 찾음 | AI 탭에서 자연어 요청, 탐색에서 추천 진입, 조건 수정·다시 요청 | 공고 상세·공식 원문 확인 |
| 팀 추천 | 로그인한 사용자가 공모전과 선호에 맞는 모집 팀을 찾음 | AI 탭 또는 공모전 상세에서 요청, 공모전·조건 변경 후 다시 요청 | 팀 상세 확인 후 직접 지원 |
| 지원자 검토·후보 추천 | 팀장이 자기 팀의 기존 지원자를 검토함. 새 선발 후보는 지원 완료·검토 중인 유효 지원만 포함 | 팀장 관리에서 결과 확인·다시 요청. 모집 마감·정원 충족 후에도 허용하며 현재 지원·프로필 정보를 사용 | 허용된 프로필 확인 후 팀장이 직접 선발. 검토 허용이 신규 지원·정원 초과 선발 허용을 뜻하지 않음 |
| 공개 사람 탐색 보조 | 로그인한 사용자가 공개 상태인 사람을 찾음 | AI 탭 또는 사람 탐색 검색창의 AI 아이콘에서 진입 | [사람 탐색](profile.md#people-directory)과 동일한 공개 범위의 상세 확인 |

사람 탐색 보조와 지원자 추천은 구분합니다. 사람 목록에 보인다는 이유로 해당 팀에 지원한 것으로 표시하거나 선발 버튼을 제공하지 않습니다. AI 기능 전체는 [로그인 후에만 이용](authentication.md#access-policy)합니다. 공모전·팀 추천도 예외가 아니며, 하단 AI 탭·검색창 아이콘·직접 주소 모두 같은 조건을 적용합니다. 비로그인은 일반 공개 공고·팀 모집 정보를 계속 탐색할 수 있지만 AI 대화·추천 요청과 결과는 제공하지 않습니다.

지원자 검토와 추천에는 [현재 프로필 기준](profile.md#application-profile)을 함께 적용합니다. 변경 후 다음 조회·갱신에 이전 프로필 근거를 현재 프로필과 섞지 않습니다. 일반 프로필 변경 알림이나 열린 화면의 실시간 자동 갱신은 요구하지 않으며, 프로필 공개 상태 전환은 [저장 성공 즉시 열람 기준](profile.md#visibility-changes)에 적용하며 지원 팀장의 전체 현재 프로필 열람 예외를 유지합니다.

<a id="applicant-review"></a>

### 기존 지원자 검토와 새 선발 후보

- 팀장은 모집이 마감되거나 정원이 찬 뒤에도 자기 팀의 기존 지원자 AI 검토 결과를 확인하고 현재 정보로 다시 요청할 수 있습니다. 매번 현재 팀장 권한·지원 관계·데이터 접근 범위를 확인하며 이전 열람 이력만으로 권한을 복원하지 않습니다.
- 새 선발 후보는 `지원 완료`·`검토 중`인 유효 지원자로 한정합니다. `선발`·`미선발`·`지원 취소`·`폐기`는 새 후보에서 제외하지만 기록 자체를 삭제하거나 기존 직접 열람 권한을 없애지 않습니다. 이 열람 허용으로 별도 개별 재검토 모드를 추가하지 않습니다. 폐기는 [동시 지원 정책](team-recruitment.md#parallel-applications)에 따라 실제 발생한 지원 상태이며, 폐기된 지원을 새 후보로 복원하지 않습니다.
- 지원 후 비공개로 전환해도 기존 지원을 받은 팀장의 AI 검토에는 **최신 프로필 수정 내용을 반영**합니다. 지원 당시 사본에 고정하지 않으며 현재 비공개라는 이유로 유효 지원자를 후보에서 제외하지 않습니다. 과거 답변의 실시간 자동 재작성은 요구하지 않습니다.
- 이 허용은 해당 지원을 받은 팀장의 검토에 한정합니다. 일반 AI 사람 추천·다른 팀·일반 팀원에게 비공개 프로필 접근 권한을 주지 않습니다. 신규 지원은 공개 프로필에서만 제출하며 공개 전환 확인·저장 후 나머지 조건을 다시 확인합니다.
- 검토·재요청은 지원의 `검토 중` 전환이나 선발·정원 변경을 실행하지 않습니다. 검토 중은 [팀장의 명시적 행동](team-recruitment.md#application-transitions)으로만 전환합니다. 팀 모집 종료·기한 경과 뒤의 실제 선발은 [공고 접수 마감 전·여석 등 현재 조건](team-recruitment.md#selection-window)을 검사하며 공고 접수 마감 후에는 새 선발을 허용하지 않습니다. 기존 지원자 AI 검토·후보 요청의 허용 범위는 유지합니다.

## 자연어 대화와 화면 상태

1. 로그인 후 AI 탭에서 요청 예시를 선택하거나 자연어로 입력합니다. 예시는 실제 후보가 있다는 보장이 아니라 입력을 돕는 문구입니다.
2. 요청을 보내면 사용자 메시지와 응답 준비 상태를 구분합니다. 필요한 조건이 불명확하면 짧게 확인하거나 현재 이해한 조건을 보여 줍니다.
3. 생성되는 답변을 실시간으로 표시하고 검증된 공모전·팀·허용된 사람 카드를 제공합니다. 전체 답변이 완성된 뒤 글자만 지연 표시하는 모의 응답으로 대체하지 않습니다. 해당 대화 맥락에서 조건을 추가·수정해 다시 탐색할 수 있습니다.
4. 카드를 누르면 일반 상세 화면으로 이동합니다. 지원·팀 생성·선발은 각 화면의 확인과 권한 검사를 거치며 대화만으로 자동 실행하지 않습니다.
5. 응답 중에는 중단할 수 있고 실패하면 같은 요청을 다시 시도할 수 있습니다. 재시도로 같은 사용자 메시지를 중복 추가하지 않습니다. 새 대화는 현재 대화·작성 중 입력·진행 중 응답을 초기화하며, 답변 복사는 표시된 답변과 현재 열람 가능한 결과 정보를 복사합니다. 복사 실패는 성공으로 표시하지 않고 재시도할 수 있게 안내합니다.

사용자 메시지는 한 개당 **최대 1,000자**, 답변 한 번의 추천 카드는 공모전·팀·사람 등 종류를 합해 **최대 3개**입니다. 더 필요하면 같은 대화에서 이어서 요청할 수 있으며 전체 대화 횟수나 대화 전체의 카드 수를 3개로 제한하지 않습니다. 적합한 결과가 3개보다 적으면 실제 결과만 표시합니다. 초과 입력은 유지한 채 수정을 안내하고 잘라 전송하지 않습니다. 이 수치는 토큰·호출 비용·빈도 제한이나 450ms 응답 보장을 뜻하지 않습니다.

### 조건 탐색과 제목·이름 검색

2026-10-31 사용자 요청에 따라 AI 검색은 구조화된 조건 탐색과 실제 제목·이름 검색을 구분합니다. 조건 탐색·이름 검색은 구현했으며 기존 일반 탐색 화면의 검색 범위를 유지합니다. 프롬프트는 조회·검증·최종 답변 단계의 역할과 데이터 경계를 구분합니다.

- 관심 분야·역할·접수 상태는 [공통 선택지](profile-options.md)와 공모전 상태에 정의된 코드로 조회합니다. “IT 공모전”은 IT·기술 분야 조건이며 제목에 `IT`가 포함되어야 한다는 뜻이 아닙니다. 도구 설명은 허용 코드와 한국어 의미, 생략 시 동작, 조합 방식과 예시를 제공합니다.
- 실제 공모전 제목·팀 이름·사람 이름을 지정한 요청은 해당 항목의 문자 그대로 부분 일치로 검색하고, 함께 지정한 구조화된 조건은 모두 충족해야 합니다. 이름 앞뒤 공백은 검색 전에 제거하고 빈 이름은 받지 않습니다. `%`·`_`를 전체 일치 문법으로 해석하지 않습니다.
- 공모전은 분야·접수 상태·마감까지 남은 일수, 팀은 모집 역할, 공개 사람은 역할·관심 분야를 조건으로 받습니다. 지원하지 않는 조건을 제목·이름에 섞거나 조용히 제거하지 않습니다. 주최자·소개·역량 등 직접 필터가 없는 조건은 허용된 상세 자료로 확인할 수 있는 범위를 설명하거나 필요한 조건을 질문합니다. 확인하지 못한 조건을 충족했다고 말하지 않습니다.
- 공모전의 접수 상태를 생략하면 전체 상태를 탐색하며 기존 마감순 정렬을 유지합니다. 명시한 `N일 이내 마감`은 조회의 서버 기준 시각보다 뒤이면서 그 시각부터 `N × 24시간` 이내인 마감입니다. N은 1~365의 정수이며 상한 시각을 포함합니다. 기준 시각과 실제 적용한 날짜 범위를 확인할 수 있어야 합니다. 이미 종료된 상태와 미래 마감 범위를 동시에 요청하는 모순은 오류로 구분합니다.
- “마감 임박”처럼 일수가 없으면 접수 중인 공모전을 마감순으로 확인하고 실제 마감일을 설명할 수 있습니다. 임의로 7일 같은 조건을 확정하지 않습니다. “이번 주” 같은 달력 구간을 같은 길이의 상대 일수로 바꾸지 않습니다.
- 빈 페이지나 제한된 조회만으로 전체 자료가 없거나 모두 마감됐다고 단정하지 않습니다. 다음 페이지와 조회 한도를 구분하고, 한도에 도달하면 조건을 좁히도록 안내합니다. 결과에 실제 적용 조건을 남겨 잘못 선택한 인자를 추적할 수 있어야 합니다.

조회·검증 단계와 최종 답변 단계의 프롬프트는 역할·도구 선택·카탈로그·검증·출력·데이터 경계를 구분합니다. 최종 답변 단계에는 추가 조회를 요구하지 않으며, 실제로 검증된 자료만 사용합니다. 입력 분류의 정상 요청·차단 기준과 기존 권한·공개 범위·카드 제한은 유지합니다.

### 입력 검사와 답변 범위

2026-10-28 사용자 결정으로 단일 ReAct 에이전트에 읽기 도구와 middleware를 연결합니다. 사용자 입력 검사는 **매 메시지마다 에이전트 실행 전에** 수행하며, 정규식 신호와 도구 없는 LLM 의미 분류를 함께 사용합니다. 후속 발화의 의미를 판단할 때 제한된 최근 사용자 발화를 참고합니다. 클라이언트가 보낸 역할·권한 주장이나 이전 발화를 시스템 지시로 취급하지 않습니다.

- 공모전·팀·공개 사람 탐색, 현재 조건의 수정, 기존 지원자 검토와 관련된 요청을 처리합니다. 서비스 도움말은 프로필 공개·팀 모집·지원·AI 이용 방법·권한·제한의 안내까지 포함합니다. 무관한 범용 비서 작업은 지원 범위를 안내합니다.
- 숨겨진 시스템·개발자 지시 원문이나 인증 비밀 요구, 지시 우선순위·권한을 덮어쓰려는 요청, 상대를 모욕·괴롭히는 문구를 생성하려는 요청은 실행하지 않습니다. 공격 문구를 인용한 신고·분석·불만, 단순 욕설 포함 불만, AI·앱·보안 분야 공모전 탐색은 해당 단어만으로 차단하지 않습니다.
- 정책상 처리하지 않는 요청에는 새로운 자료 조회나 자유 생성 없이 고정 안내와 빈 카드 목록을 반환합니다. 정상 완료된 안내로 표시하고 일반 채팅 저장 규칙을 적용합니다. 입력 검사 자체의 장애·시간 초과·판정 형식 오류는 허용으로 간주하지 않고 재시도 가능한 일시 실패로 처리합니다.
- 입력 검사 결과는 데이터 열람 권한을 부여하지 않습니다. 모델 입력 이전의 서버 필드 허용 목록, 공개 범위, 실제 지원 관계와 전송 시점의 현재 권한 검사는 계속 적용합니다. 비공개 본인 프로필 자동 개인화·외부 웹/포트폴리오 수집·자동 지원·선발은 추가하지 않습니다.
- 모델의 조회 중간 발화·추론·도구 JSON은 화면 답변에 포함하지 않습니다. 최종 답변 전 서버가 실제 조회한 후보 ID·중복·카드 수·현재 권한을 검증하고 후보 집합을 확정해야 합니다. 도움말·확인 질문·정책 안내는 빈 후보 집합을 검증하며 불필요한 자료 조회를 요구하지 않습니다. 모델이 검증을 생략하거나 검증이 실패하면 답변과 카드를 게시하지 않습니다. 이후 생성되는 최종 텍스트는 전체 완료를 기다리지 않고 전송합니다.
- 도구 결과와 최종 답변에 추가 LLM 검사를 넣거나 전체 답변·문장을 검토용으로 버퍼링하지 않습니다. 입력 분류와 확정된 후보 검증은 자연어 답변의 모든 사실성·추천 품질을 보장하지 않으며 실제 자료 평가는 별도 후속입니다.

| 상태 | 사용자에게 보이는 동작 |
| --- | --- |
| 비로그인·세션 만료 | 로그인 안내. 대화·요청 실행·결과 제공을 허용하지 않음 |
| 시작 전 | 로그인 후 요청 예시, 입력창, 보낼 수 있는 상태 안내 |
| 준비 중 | 진행 상태와 중단 동작. 요청을 실수로 중복 전송하지 않도록 처리 |
| 답변 생성 중 | 생성되는 텍스트를 순차 표시. 부분 답변을 완료된 추천으로 표시하지 않음 |
| 성공 | 답변·실제 연결 가능한 결과 카드·추천 근거 |
| 결과 없음 | 결과가 없음을 명시하고 조건 수정 또는 일반 탐색으로 이동 가능. 가상의 후보를 만들지 않음 |
| 실패 | 기존 대화와 요청을 유지하고 재시도 제공. 실패를 추천 결과 없음으로 표시하지 않음 |
| 중단 | 중단됐음을 구분하고 새 요청 가능. 중단된 요청의 늦은 응답이 새 대화를 덮지 않음 |
| 새 대화 | 현재 대화·작성 중 입력·진행 중 응답 초기화. 과거 대화 목록에서 복구하는 기능은 제공하지 않음 |

현재 대화·작성 중 입력은 **현재 브라우저 탭의 메모리에서만 유지**합니다. 같은 탭 안에서 앱의 다른 화면·상세로 이동했다 돌아오면 유지하고, 새로고침·탭 종료·새 대화·로그아웃 시 초기화합니다. 새 탭이나 다른 기기로 동기화하지 않으며 대화 복원을 위해 localStorage·sessionStorage·IndexedDB에 보관하지 않습니다. 로그아웃·새 대화는 진행 중 응답도 취소하고 뒤늦은 결과를 반영하지 않습니다.

**과거 대화 목록·검색·다시 열기와 새로고침 후 대화 복원은 제공하지 않습니다.** 서버는 일반 채팅의 접수된 사용자 입력과 완성된 AI 답변을 계정 소유 대화로 보존합니다. 실행 메타데이터·근거/결과 해시는 별도로 유지하며, 대화 저장이 기록 조회 API·새로고침 복원·모델 맥락 자동 로드를 추가하지는 않습니다. 실패·취소·완료 전 권한 무효화된 부분 답변은 저장하지 않습니다. 지원자 검토 원문도 서버에 저장하지 않고 현재 탭의 결과를 재검증합니다. 운영 정리·로그/백업 보존은 MATCH-13의 후속 범위입니다.

화면에는 개발 환경·시안·미연동 배너를 상시 배치하지 않으며, 레퍼런스의 모의 동작은 저장소 설명에서 명시합니다. 실제 제품 시연의 사실 안내는 [시연 기준](sprint-1.md#web-demo)을 따릅니다.

| 항목 | 참고 화면의 동작과 한계 |

| 질문 작성·길이 | 시작 예시·후속 질문을 눌러 보내거나 Enter로 전송합니다. Shift+Enter 줄바꿈·한글 조합 확정을 구분하며 1,000자 초과 입력은 유지하고 전송을 막습니다. |

| 추천 수·추가 요청 | 한 답변은 합계 최대 3개 카드이며 같은 조건으로 추가 요청하면 아직 보여주지 않은 결과를 이어서 제공합니다. 적합한 결과가 없으면 없는 결과를 만들지 않습니다. |
| 현재 권한 재확인 | 카드 표시·복사 시 현재 공개 범위·모집 상태·마감·정원·본인 소속·동일 팀 지원 이력을 확인합니다. 취소 이력은 재추천의 영구 제외 사유로 쓰지 않고, 더 이상 가능한 후보가 아니면 정보 변경 안내로 대체합니다. |
| 일반 사람 추천 | 공개된 프로필만 사용합니다. 현재 비공개인 본인 프로필을 자동 읽거나 지원자 검토 권한을 일반 사람 탐색으로 확장하지 않습니다. |
| 지원자 검토 | 자기 팀의 기존 지원자를 현재 프로필과 지원 메시지로 검토하는 요청·준비·실패·재시도·재요청을 제공합니다. 마감·정원 충족·지원 후 비공개 전환만으로 막지 않으며, 새 후보 요청은 지원 완료·검토 중에 한정합니다. |
| 이전 지원자 검토 결과 | 현재 실행 중 결과를 보존하고 현재 팀장 권한으로 다시 열람합니다. 결과에 사용한 프로필 정보가 바뀌면 이전 결과임을 구분하고 재요청으로 갱신합니다. 실제 서버 보존·새로고침 복원 정책을 확정한 것은 아닙니다. |
| 모의 응답과 서버 영역 | 일반 대화는 로컬 단어 해석과 예시 데이터, 지원자 검토는 등록 사실을 정리한 로컬 응답입니다. 실제 LLM·스트리밍·모델 전송·서버 권한·기기 동기화는 구현하지 않았습니다. |

지원되는 예시 단어·모의 지연·문자열 기반 계수는 제품 LLM 아키텍처나 성능 목표가 아닙니다. 최신 참가 자격 비차단·폐기 후보 제외 정책의 디자인 적용은 [후속 대조](prototype-alignment.md#policy-follow-up)로 구분합니다. 2026-10-21 확정한 동일 공모전 소속 중 신규 지원 금지·종료 사유별 재지원·팀 생성 폐기와 실제 선발 기한은 [팀 명세](team-recruitment.md#membership-limit)를 따르며, 이번 문서 변경으로 참고 앱에 적용·검증됐다고 보지 않습니다. 정책과 검증 근거는 [대조 기록](prototype-alignment.md)에서 구분합니다.

## 모집 제한과 자격 확인

다음은 추천 알고리즘이 아니라 서비스의 참가·공개 정책입니다. LLM 응답이나 사용자의 요청으로 우회할 수 없습니다.

| 조건 | 처리 |
| --- | --- |
| 공고 접수 기간 | 등록 공고는 모두 공개. 접수 예정·접수 중·접수 마감을 구분하며 현재 접수할 수 없는 대상을 신규 지원 가능한 후보처럼 안내하지 않음. [원문 우선·누락 시 시간대/시각 보완 기준](contests.md#deadline-policy)을 목록·상세·지원·추천에 동일 적용 |
| 팀 정원·모집 상태 | 정원이 찼거나 모집을 종료한 팀은 신규 지원 추천에서 제외. 검토 시작 자체로 접수를 닫지 않는 [정책](team-recruitment.md#recruitment-review) 유지 |
| 참가 자격 | 원문 참가 조건과 확인 안내를 제공하되 자격 판정으로 추천 후보·지원·선발을 차단하지 않음. 자격 충족·합격 가능성을 보장하지 않으며 미확인 정보는 추정하지 않음 |
| 중복·취소·재지원 | 현재 유효한 지원과 종료된 이전 지원을 구분. 취소·폐기는 현재 조건 충족 시 새 지원 가능, 미선발된 같은 팀은 재지원 불가인 [정책](team-recruitment.md#reapplication)을 신규 지원 대상 추천에도 적용 |
| 팀장의 지원자 검토·후보 추천 | 모집 마감·정원 충족 자체로 기존 결과 확인·재요청을 막지 않음. 새 선발 후보는 자기 팀의 지원 완료·검토 중인 유효 지원만 포함하며 선발·미선발·취소·폐기는 제외 |
| 소속·선발 | 같은 공모전 소속 중 신규 지원 대상 팀 추천을 제한하고 [공모전별 한 팀 소속](team-recruitment.md#membership-limit), [선발 즉시 확정과 정원 차감](team-recruitment.md#membership-capacity)을 실제 행동 시 다시 확인. 다른 공모전에는 이 제한을 확대하지 않음 |
| 학사 정보 | 원문 조건 확인과 팀장 판단을 위한 참고 정보. 구조화된 학적·학년·전공 조건으로 지원·후보를 차단하지 않으며 팀별 추가 학사 자격 제한을 두지 않음. 학년·전공의 높고 낮음으로 사람의 일반적인 우수성을 단정하지 않음 |

모든 지원 직전에는 [필수 정보 점검·보완](profile.md#before-application)과 공개 상태를 확인합니다. 학적·학년은 선택 입력입니다. [#77의 #33 연결 결정](https://github.com/wejo-team/sku-dreamon/issues/77)에 따라 자격 정보가 부족해도 원문 확인을 안내한 뒤 일반 지원으로 접수하며 별도 확인 대기 지원 상태를 만들지 않습니다. 필수값 입력 완료·접수 성공을 자격 검증 완료로 표시하지 않고, 마감·정원·중복·소속 제한과 신규 지원 공개 조건은 유지합니다. 2026-10-19 추가 사용자 결정에 따라 정보 부족 여부와 관계없이 참가 자격을 비즈니스 로직의 차단 조건으로 두지 않습니다. 팀별 추가 학사 자격 제한도 제공하지 않습니다.

프로필 열람 관계를 유지하는 것과 현재 지원자 추천 대상인 것은 다릅니다. [취소·미선발·폐기 후 열람 정책](profile.md#former-applicant-visibility)만으로 추천 대상에 포함하지 않습니다. 같은 공모전에서 다른 팀에 선발되거나 본인이 팀을 생성해 폐기된 지원은 새 후보에서 제외하며, 해당 지원을 받은 팀장의 최신 프로필 직접 열람·기존 지원서 AI 검토 범위는 유지합니다.

## 근거·공개 범위와 결과 표시

| 결과 | 표시 정보 |
| --- | --- |
| 공모전 | 공모전명·마감·참가 자격·추천 이유·공식 원문 또는 해당 정보가 있는 상세 링크 |
| 팀 | 팀명·공모전·현재 필요한 역할·팀장 포함 총 정원·모집 마감·추천 이유 |
| 실제 지원자 | 등록된 실명·희망 역할·열람이 허용된 경험·역량·추천 이유·지원자 상세 |
| 공개 사람 | 공개 상태인 사용자의 현재 프로필 요약·상세 링크. 상세에서는 등록된 모든 항목 열람 가능 |

- 추천 이유는 현재 확인 가능한 서비스 데이터와 사용자가 요청한 조건을 연결합니다. 존재하지 않는 경험·역량·공고 조건·마감일·시간 겹침을 만들거나 확인되지 않은 후보를 등록된 후보로 표시하지 않습니다.
- [수강 과목](profile.md#courses)은 열람이 허용된 현재 프로필의 학수번호·과목명만 모델에 전달합니다. 수강 중인 과목을 포함한 자기신고 목록이며 이수 완료·성적·숙련도·전공 소속을 증명하지 않습니다. 과목 설명·연도별 내용은 제공하지 않으므로 특정 언어·도구·프로젝트를 배웠다고 만들어내지 않습니다. 미등록을 수강 이력 없음으로 간주하지 않습니다.
- 일치율·신뢰도·합격 가능성·고정 적합도 점수를 근거 없이 표시하지 않습니다. 기존 숫자 점수의 자리를 임의의 LLM 점수로 채우지 않습니다.
- 일반 AI 사람 탐색은 공개 프로필만 후보로 사용하고 비공개 프로필을 답변·카드·추천 이유·직접 상세 링크로 우회 노출하지 않습니다. 공개된 프로필의 주당 참여 가능 시간·포트폴리오 URL·제목도 [전체 프로필 공개 정책](profile.md#visibility)에 포함합니다. 인증 정보는 제공하지 않습니다.
- [주당 참여 가능 시간](profile-options.md#weekly-availability)은 참여 중인 모든 프로젝트를 합산한 자기신고 참고값입니다. 특정 팀에 배정할 시간·잔여 시간·확정 일정·다른 사람과 겹치는 시간으로 해석하거나 프로젝트 수로 나누어 추정하지 않습니다. 이 값만으로 참석 가능 여부나 지원 자격을 확정하지 않으며, 세부 일정 조율은 팀 공간의 후속 검토 범위입니다. 추천의 데이터 접근에는 아래 #49 기준을 별도로 적용합니다.
- [#77의 #49 연결 결정](https://github.com/wejo-team/sku-dreamon/issues/77)에 따라 지원받은 팀장은 이후 비공개로 전환한 기존 지원자의 **최신 프로필을 반영한 AI 검토**를 계속 이용할 수 있습니다. 이전의 비공개 데이터 사용 전면 보류 설명은 이 관계 범위에서 대체합니다. 일반 사람 검색·AI 사람 추천에는 비공개 프로필을 포함하지 않고, 다른 팀의 지원 이력이나 일반 팀원 관계만으로 이 권한을 확장하지 않습니다.
- 공개 전환 안내에는 일반 검색·AI 사람 추천에 등록 항목이 공개됨을, 비공개 전환 안내에는 일반 검색·AI 사람 추천에서 숨겨져도 기존 지원·소속·지원받은 팀장의 직접 열람과 최신 프로필 기반 AI 검토는 유지됨을 설명합니다. 새로운 별도 동의 단계나 지원 심사 상태는 추가하지 않습니다.
- 모델 입력 필드·제공자·실행 구조·일반 대화 저장은 [AI 아키텍처](../development/ai-architecture.md)에 따라 구현했습니다. 대화 보존 기간·삭제/익명화·운영 로그와 백업 정책은 후속 결정입니다. 최신 프로필 반영이 모든 항목의 무조건 전송·인증 정보 제공·외부 포트폴리오 수집/분석을 허용하거나 과거 모델 입력의 즉시 삭제를 보장하지 않습니다. 일반 대화에서 비공개 기본 프로필을 자동으로 읽는 권한도 추가하지 않습니다.
- 포트폴리오 URL 등록은 외부 내용을 수집하거나 분석하는 동의가 아닙니다. [포트폴리오 AI 분석 제외](profile.md#portfolio)를 유지합니다.
- 비공개 전환이나 접근 관계 변경 후의 새 조회·추천에 현재 권한 밖의 이전 공개 정보를 재사용하지 않습니다. 과거 대화·캐시의 재노출 방지 방식은 내부 설계에서 검증합니다.
