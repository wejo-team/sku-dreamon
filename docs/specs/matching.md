# LLM 기반 공모전·팀·지원자 추천

- 구현 상태: 예정
- 명세 검토: 기존 [PR #17](https://github.com/wejo-team/sku-dreamon/pull/17), LLM 전환 [PR #73](https://github.com/wejo-team/sku-dreamon/pull/73), AI 로그인 전용·프로필 공개 정책 [PR #75](https://github.com/wejo-team/sku-dreamon/pull/75); 2026-10-19 [#77](https://github.com/wejo-team/sku-dreamon/issues/77)의 입력·결과 제한과 #33·#36·#46·#49 연결 결정 반영
- 구현 작업: 미등록

공모전·팀·실제 지원자 추천을 **LLM 기반 추천**으로 변경합니다. 이 문서는 사용자에게 제공할 동작, 근거와 공개 범위를 정의하며 내부 아키텍처는 TBD입니다. 저장소의 실행 가능한 공식 디자인은 화면·상태·인터랙션의 참고 자료이며 실제 LLM·서버 구현 완료를 뜻하지 않습니다.

입력·공개 범위는 [프로필](profile.md), 분류는 [공통 선택지](profile-options.md), 모집·지원의 권한과 상태는 [팀 모집과 지원](team-recruitment.md)에서 관리합니다.

<a id="policy-decisions"></a>

## 변경 결정과 범위

2026-10-18 사용자 요청에 따라 기존의 규칙 기반 추천 로직을 제외합니다. 공모전·팀·지원자의 고정 가중치, 요소별 점수, 총점 산식, 관심 분야 합집합 비율, 점수 순 정렬·동점 처리, 시간 값 변경에 따른 결과 불변 보장은 더 이상 구현 요구사항이 아닙니다. 이 변경을 기존 산식의 가중치 조정으로 해석하지 않습니다.

| 포함 | 제외 또는 미정 |
| --- | --- |
| AI 탭의 자연어 탐색·추천 대화와 후속 조건 수정 | 모델·제공자·프롬프트·검색/검색증강·도구 호출·캐시·실행 구조는 TBD |
| 현재 대화의 새 대화 시작·답변 복사·같은 세션 내 탭 이동 유지 | 과거 대화 목록·검색·다시 열기 화면은 현재 범위 제외 |
| 공모전·팀·실제 지원자의 추천 결과와 확인 가능한 근거 | 고정 적합도 점수·일치율·점수별 순위·기존 산식 재사용 |
| 로그인한 사용자의 공개 사람 탐색을 돕는 대화 | 미지원자를 팀장의 실제 지원자로 표시하거나 자동 지원·선발 |
| 권한·공개 범위·모집 제한을 지키는 응답과 지원받은 팀장의 기존 지원자 검토 | 권한 없는 비공개 정보 노출, 없는 자격·경험·역량 추정, 포트폴리오 수집·AI 분석 |

LLM 전환으로 참가 자격·마감·정원·중복 지원·공모전별 소속 제한이나 접근 권한을 없애지 않습니다. 추천 결과는 지원 접수·선발·팀원 확정을 대신하지 않습니다. 역할 불일치만으로 추천·지원을 차단하지 않고 경험이 적다는 이유만으로 초보자를 자동 제외하지 않는 [모집 정책](team-recruitment.md#recruitment-information)을 유지합니다.

## 추천 유형과 이용 흐름

| 유형 | 사용자와 대상 | 진입·갱신 | 결과에서 가능한 행동 |
| --- | --- | --- | --- |
| 공모전 추천 | 로그인한 사용자가 관심·참여 조건에 맞는 공모전을 찾음 | AI 탭에서 자연어 요청, 탐색에서 추천 진입, 조건 수정·다시 요청 | 공고 상세·공식 원문 확인 |
| 팀 추천 | 로그인한 사용자가 공모전과 선호에 맞는 모집 팀을 찾음 | AI 탭 또는 공모전 상세에서 요청, 공모전·조건 변경 후 다시 요청 | 팀 상세 확인 후 직접 지원 |
| 지원자 검토·후보 추천 | 팀장이 자기 팀의 기존 지원자를 검토함. 새 선발 후보는 지원 완료·검토 중인 유효 지원만 포함 | 팀장 관리에서 결과 확인·다시 요청. 모집 마감·정원 충족 후에도 허용하며 현재 지원·프로필 정보를 사용 | 허용된 프로필 확인 후 팀장이 직접 선발. 검토 허용이 신규 지원·정원 초과 선발 허용을 뜻하지 않음 |
| 공개 사람 탐색 보조 | 로그인한 사용자가 공개 상태인 사람을 찾음 | AI 탭 또는 사람 탐색 검색창의 AI 아이콘에서 진입 | [사람 탐색](profile.md#people-directory)과 동일한 공개 범위의 상세 확인 |

사람 탐색 보조와 지원자 추천은 구분합니다. 사람 목록에 보인다는 이유로 해당 팀에 지원한 것으로 표시하거나 선발 버튼을 제공하지 않습니다. AI 기능 전체는 [로그인 후에만 이용](authentication.md#access-policy)합니다. 공모전·팀 추천도 예외가 아니며, 하단 AI 탭·검색창 아이콘·직접 주소 모두 같은 조건을 적용합니다. 비로그인은 일반 공개 공고·팀 모집 정보를 계속 탐색할 수 있지만 AI 대화·추천 요청과 결과는 제공하지 않습니다.

지원자 검토와 추천에는 [현재 프로필 기준](profile.md#application-profile)을 함께 적용합니다. 변경 후 다음 조회·갱신에 이전 프로필 근거를 현재 프로필과 섞지 않습니다. 일반 프로필 변경 알림이나 열린 화면의 실시간 자동 갱신은 요구하지 않으며, 프로필 공개 상태 전환은 [저장 성공 즉시 열람 기준](profile.md#visibility-changes)에 적용하며 지원 팀장의 전체 현재 프로필 열람 예외를 유지합니다.

<a id="applicant-review"></a>

### 기존 지원자 검토와 새 선발 후보

- 팀장은 모집이 마감되거나 정원이 찬 뒤에도 자기 팀의 기존 지원자 AI 검토 결과를 확인하고 현재 정보로 다시 요청할 수 있습니다. 매번 현재 팀장 권한·지원 관계·데이터 접근 범위를 확인하며 이전 열람 이력만으로 권한을 복원하지 않습니다.
- 새 선발 후보는 `지원 완료`·`검토 중`인 유효 지원자로 한정합니다. `선발`·`미선발`·`지원 취소`는 새 후보에서 제외하지만 기록 자체를 삭제하거나 기존 직접 열람 권한을 없애지 않습니다. 별도 개별 재검토 모드나 새 지원 상태를 추가하지 않습니다.
- 지원 후 비공개로 전환해도 기존 지원을 받은 팀장의 AI 검토에는 **최신 프로필 수정 내용을 반영**합니다. 지원 당시 사본에 고정하지 않으며 현재 비공개라는 이유로 유효 지원자를 후보에서 제외하지 않습니다. 과거 답변의 실시간 자동 재작성은 요구하지 않습니다.
- 이 허용은 해당 지원을 받은 팀장의 검토에 한정합니다. 일반 AI 사람 추천·다른 팀·일반 팀원에게 비공개 프로필 접근 권한을 주지 않습니다. 신규 지원은 공개 프로필에서만 제출하며 공개 전환 확인·저장 후 나머지 조건을 다시 확인합니다.
- 검토·재요청은 선발·정원 변경을 실행하지 않습니다. 마감·정원 등 신규 지원 제한과 정원 초과 선발 금지는 유지합니다.

## 자연어 대화와 화면 상태

1. 로그인 후 AI 탭에서 요청 예시를 선택하거나 자연어로 입력합니다. 예시는 실제 후보가 있다는 보장이 아니라 입력을 돕는 문구입니다.
2. 요청을 보내면 사용자 메시지와 응답 준비 상태를 구분합니다. 필요한 조건이 불명확하면 짧게 확인하거나 현재 이해한 조건을 보여 줍니다.
3. 응답은 설명과 연결된 공모전·팀·허용된 사람 카드로 구성합니다. 해당 대화 맥락에서 조건을 추가·수정해 다시 탐색할 수 있습니다.
4. 카드를 누르면 일반 상세 화면으로 이동합니다. 지원·팀 생성·선발은 각 화면의 확인과 권한 검사를 거치며 대화만으로 자동 실행하지 않습니다.
5. 응답 중에는 중단할 수 있고 실패하면 같은 요청을 다시 시도할 수 있습니다. 재시도로 같은 사용자 메시지를 중복 추가하지 않습니다. 새 대화는 현재 대화·작성 중 입력·진행 중 응답을 초기화하며, 답변 복사는 표시된 답변과 현재 열람 가능한 결과 정보를 복사합니다. 복사 실패는 성공으로 표시하지 않고 재시도할 수 있게 안내합니다.

사용자 메시지는 한 개당 **최대 1,000자**, 답변 한 번의 추천 카드는 공모전·팀·사람 등 종류를 합해 **최대 3개**입니다. 더 필요하면 같은 대화에서 이어서 요청할 수 있으며 전체 대화 횟수나 대화 전체의 카드 수를 3개로 제한하지 않습니다. 적합한 결과가 3개보다 적으면 실제 결과만 표시합니다. 초과 입력은 유지한 채 수정을 안내하고 잘라 전송하지 않습니다. 이 수치는 토큰·호출 비용·빈도 제한이나 450ms 응답 보장을 뜻하지 않습니다.

| 상태 | 사용자에게 보이는 동작 |
| --- | --- |
| 비로그인·세션 만료 | 로그인 안내. 대화·요청 실행·결과 제공을 허용하지 않음 |
| 시작 전 | 로그인 후 요청 예시, 입력창, 보낼 수 있는 상태 안내 |
| 준비 중 | 진행 상태와 중단 동작. 요청을 실수로 중복 전송하지 않도록 처리 |
| 성공 | 답변·실제 연결 가능한 결과 카드·추천 근거 |
| 결과 없음 | 결과가 없음을 명시하고 조건 수정 또는 일반 탐색으로 이동 가능. 가상의 후보를 만들지 않음 |
| 실패 | 기존 대화와 요청을 유지하고 재시도 제공. 실패를 추천 결과 없음으로 표시하지 않음 |
| 중단 | 중단됐음을 구분하고 새 요청 가능. 중단된 요청의 늦은 응답이 새 대화를 덮지 않음 |
| 새 대화 | 현재 대화·작성 중 입력·진행 중 응답 초기화. 과거 대화 목록에서 복구하는 기능은 제공하지 않음 |

같은 로그인 세션에서 탭을 오갈 때 대화·작성 중 입력을 유지하는 경험을 제공합니다. **과거 대화 기록을 목록으로 조회·검색하거나 다시 여는 화면은 현재 범위에 포함하지 않습니다.** 현재 열린 대화를 유지하는 것과 과거 기록을 조회하는 기능은 구분합니다. 새로고침 이후 현재 대화 보존·서버 저장·보존 기간·로그아웃 시 서버 기록 삭제 방식은 MATCH-13에서 결정하며, 이 TBD가 과거 기록 조회 UI를 추가한다는 뜻은 아닙니다. 로그아웃 후에는 화면의 계정별 대화·초안을 제거하고 진행 중 응답을 취소합니다.

화면에는 개발 환경·시안·미연동 배너를 상시 배치하지 않으며, 레퍼런스의 모의 동작은 저장소 설명에서 명시합니다. 실제 제품 시연의 사실 안내는 [시연 기준](sprint-1.md#web-demo)을 따릅니다.

## 현재 디자인 레퍼런스와 남은 차이

[공식 디자인 PR](https://github.com/wejo-team/sku-dreamon/pull/74)의 참고 앱 동작입니다. 소스·배포 버전과 수행한 검증은 [프로토타입·명세 대조 기록](prototype-alignment.md)에서 관리하며, 아래 화면 동작을 실제 서버 기능의 완료로 취급하지 않습니다.

| 항목 | 참고 화면의 동작과 한계 |
| --- | --- |
| 진입·권한 | 탐색 검색창 AI 아이콘·하단 AI 탭·직접 주소에 같은 로그인 조건을 적용합니다. 비로그인은 대화·결과 없이 로그인 안내를 보고 이후 원래 AI 주소로 복귀합니다. |
| 질문 작성·길이 | 시작 예시·후속 질문을 눌러 보내거나 Enter로 전송합니다. Shift+Enter 줄바꿈·한글 조합 확정을 구분하며 1,000자 초과 입력은 유지하고 전송을 막습니다. |
| 새 대화·응답 상태 | 새 대화 아이콘은 대화·초안·준비 중 응답을 초기화합니다. 준비·중단·빈 결과·실패·재시도와 답변 복사 성공·실패를 구분합니다. 탭·상세 이동 중 대화·초안을 유지하고 로그아웃 시 제거합니다. |
| 추천 수·추가 요청 | 한 답변은 합계 최대 3개 카드이며 같은 조건으로 추가 요청하면 아직 보여주지 않은 결과를 이어서 제공합니다. 적합한 결과가 없으면 없는 결과를 만들지 않습니다. |
| 현재 권한 재확인 | 카드 표시·복사 시 현재 공개 범위·모집 상태·마감·정원·본인 소속·동일 팀 지원 이력을 확인합니다. 취소 이력은 재추천의 영구 제외 사유로 쓰지 않고, 더 이상 가능한 후보가 아니면 정보 변경 안내로 대체합니다. |
| 일반 사람 추천 | 공개된 프로필만 사용합니다. 현재 비공개인 본인 프로필을 자동 읽거나 지원자 검토 권한을 일반 사람 탐색으로 확장하지 않습니다. |
| 지원자 검토 | 자기 팀의 기존 지원자를 현재 프로필과 지원 메시지로 검토하는 요청·준비·실패·재시도·재요청을 제공합니다. 마감·정원 충족·지원 후 비공개 전환만으로 막지 않으며, 새 후보 요청은 지원 완료·검토 중에 한정합니다. |
| 이전 지원자 검토 결과 | 현재 실행 중 결과를 보존하고 현재 팀장 권한으로 다시 열람합니다. 결과에 사용한 프로필 정보가 바뀌면 이전 결과임을 구분하고 재요청으로 갱신합니다. 실제 서버 보존·새로고침 복원 정책을 확정한 것은 아닙니다. |
| 모의 응답과 서버 영역 | 일반 대화는 로컬 단어 해석과 예시 데이터, 지원자 검토는 등록 사실을 정리한 로컬 응답입니다. 실제 LLM·스트리밍·모델 전송·서버 권한·기기 동기화는 구현하지 않았습니다. |

지원되는 예시 단어·모의 지연·문자열 기반 계수는 제품 LLM 아키텍처나 성능 목표가 아닙니다. 확인된 세부 참가 자격의 자동 판정, 동일 공모전의 다른 팀 소속자에 대한 신규 지원 범위 등 미정 정책을 이 참고 코드로 확정하지 않습니다. 정책과 검증 근거는 [대조 기록](prototype-alignment.md)에서 구분합니다.

## 모집 제한과 자격 확인

다음은 추천 알고리즘이 아니라 서비스의 참가·공개 정책입니다. LLM 응답이나 사용자의 요청으로 우회할 수 없습니다.

| 조건 | 처리 |
| --- | --- |
| 공고 접수 기간 | 등록 공고는 모두 공개. 접수 예정·접수 중·접수 마감을 구분하며 현재 접수할 수 없는 대상을 신규 지원 가능한 후보처럼 안내하지 않음. [원문 우선·누락 시 시간대/시각 보완 기준](contests.md#deadline-policy)을 목록·상세·지원·추천에 동일 적용 |
| 팀 정원·모집 상태 | 정원이 찼거나 모집을 종료한 팀은 신규 지원 추천에서 제외. 검토 시작 자체로 접수를 닫지 않는 [정책](team-recruitment.md#recruitment-review) 유지 |
| 참가 자격 | 확인된 미충족 후보를 참여 가능한 추천으로 제시하지 않음. 정보 누락·미확인은 `확인 필요`로 구분하고 자격 충족을 추정하지 않음 |
| 중복·취소·재지원 | 현재 유효한 지원과 취소된 이전 지원을 구분. 취소 이력만으로 영구 제외하지 않고 [재지원 정책](team-recruitment.md#reapplication) 적용 |
| 팀장의 지원자 검토·후보 추천 | 모집 마감·정원 충족 자체로 기존 결과 확인·재요청을 막지 않음. 새 선발 후보는 자기 팀의 지원 완료·검토 중인 유효 지원만 포함하며 선발·미선발·취소는 제외 |
| 소속·선발 | [공모전별 한 팀 소속](team-recruitment.md#membership-limit), [선발 즉시 확정과 정원 차감](team-recruitment.md#membership-capacity)을 실제 행동 시 다시 확인 |
| 학사 정보 | 명시적인 공고·팀 참가 조건을 확인하는 데 사용. 학년·전공의 높고 낮음으로 사람의 일반적인 우수성을 단정하지 않음 |

모든 지원 직전에는 [필수 정보 점검·보완](profile.md#before-application)과 공개 상태를 확인합니다. 학적·학년은 선택 입력입니다. [#77의 #33 연결 결정](https://github.com/wejo-team/sku-dreamon/issues/77)에 따라 자격 정보가 부족해도 원문 확인을 안내한 뒤 일반 지원으로 접수하며 별도 확인 대기 지원 상태를 만들지 않습니다. 필수값 입력 완료·접수 성공을 자격 검증 완료로 표시하지 않고, 마감·정원·중복·소속 제한과 신규 지원 공개 조건은 유지합니다. 확인된 자격 미충족의 별도 판정·제출 규칙은 이 결정만으로 새로 확정하지 않습니다.

프로필 열람 관계를 유지하는 것과 현재 지원자 추천 대상인 것은 다릅니다. [취소·미선발 후 열람 정책](profile.md#former-applicant-visibility)만으로 추천 대상에 포함하지 않습니다. 팀이 명시할 수 있는 학사 자격의 상세 범위는 MATCH-09에 남깁니다.

## 근거·공개 범위와 결과 표시

| 결과 | 표시 정보 |
| --- | --- |
| 공모전 | 공모전명·마감·참가 자격·추천 이유·공식 원문 또는 해당 정보가 있는 상세 링크 |
| 팀 | 팀명·공모전·현재 필요한 역할·팀장 포함 총 정원·모집 마감·추천 이유 |
| 실제 지원자 | 등록된 실명·희망 역할·열람이 허용된 경험·역량·추천 이유·지원자 상세 |
| 공개 사람 | 공개 상태인 사용자의 현재 프로필 요약·상세 링크. 상세에서는 등록된 모든 항목 열람 가능 |

- 추천 이유는 현재 확인 가능한 서비스 데이터와 사용자가 요청한 조건을 연결합니다. 존재하지 않는 경험·역량·공고 조건·마감일·시간 겹침을 만들거나 확인되지 않은 후보를 등록된 후보로 표시하지 않습니다.
- 일치율·신뢰도·합격 가능성·고정 적합도 점수를 근거 없이 표시하지 않습니다. 기존 숫자 점수의 자리를 임의의 LLM 점수로 채우지 않습니다.
- 일반 AI 사람 탐색은 공개 프로필만 후보로 사용하고 비공개 프로필을 답변·카드·추천 이유·직접 상세 링크로 우회 노출하지 않습니다. 공개된 프로필의 주당 참여 가능 시간·포트폴리오 URL·제목도 [전체 프로필 공개 정책](profile.md#visibility)에 포함합니다. 인증 정보는 제공하지 않습니다.
- [주당 참여 가능 시간](profile-options.md#weekly-availability)은 참여 중인 모든 프로젝트를 합산한 자기신고 참고값입니다. 특정 팀에 배정할 시간·잔여 시간·확정 일정·다른 사람과 겹치는 시간으로 해석하거나 프로젝트 수로 나누어 추정하지 않습니다. 이 값만으로 참석 가능 여부나 지원 자격을 확정하지 않으며, 세부 일정 조율은 팀 공간의 후속 검토 범위입니다. 추천의 데이터 접근에는 아래 #49 기준을 별도로 적용합니다.
- [#77의 #49 연결 결정](https://github.com/wejo-team/sku-dreamon/issues/77)에 따라 지원받은 팀장은 이후 비공개로 전환한 기존 지원자의 **최신 프로필을 반영한 AI 검토**를 계속 이용할 수 있습니다. 이전의 비공개 데이터 사용 전면 보류 설명은 이 관계 범위에서 대체합니다. 일반 사람 검색·AI 사람 추천에는 비공개 프로필을 포함하지 않고, 다른 팀의 지원 이력이나 일반 팀원 관계만으로 이 권한을 확장하지 않습니다.
- 공개 전환 안내에는 일반 검색·AI 사람 추천에 등록 항목이 공개됨을, 비공개 전환 안내에는 일반 검색·AI 사람 추천에서 숨겨져도 기존 지원·소속·지원받은 팀장의 직접 열람과 최신 프로필 기반 AI 검토는 유지됨을 설명합니다. 새로운 별도 동의 단계나 지원 심사 상태는 추가하지 않습니다.
- 실제 모델에 사용할 필드·제공자·내부 아키텍처·처리된 요청 기록의 보존/삭제는 후속 설계입니다. 최신 프로필 반영이 모든 항목의 무조건 전송·인증 정보 제공·외부 포트폴리오 수집/분석을 허용하거나 과거 모델 입력의 즉시 삭제를 보장하지 않습니다. 일반 대화에서 비공개 기본 프로필을 자동으로 읽는 권한도 추가하지 않습니다.
- 포트폴리오 URL 등록은 외부 내용을 수집하거나 분석하는 동의가 아닙니다. [포트폴리오 AI 분석 제외](profile.md#portfolio)를 유지합니다.
- 비공개 전환이나 접근 관계 변경 후의 새 조회·추천에 현재 권한 밖의 이전 공개 정보를 재사용하지 않습니다. 과거 대화·캐시의 재노출 방지 방식은 내부 설계에서 검증합니다.

## 폐기한 추천 로직과 내부 설계

위 앵커는 과거 문서·PR 링크의 호환을 위해 유지합니다. 연결된 예전 고정 점수·가중치·합집합 비율·정렬·동점 산식은 폐기됐으며 현재 요구사항은 이 문서의 LLM 기반 동작입니다. 이전 공식이나 요소별 점수를 대체 구현으로 사용하지 않습니다.

모델·제공자, 프롬프트, 후보 검색·선정, LLM 실행·응답 검증, 스트리밍, API·DB 계약, 캐시·갱신, 운영 비용·제한과 품질 평가를 포함한 **내부 아키텍처는 TBD**입니다. 본 문서의 사용자 경험을 만족할 설계는 후속 개발 계획에서 제안합니다. 공식 디자인의 로컬 데이터·응답 예시를 이 아키텍처의 결정이나 실제 LLM 연동으로 취급하지 않습니다.

## 완료 조건

기존 AC-01~04·09~11·13은 추천 대상·접수 조건·공개·현재 프로필 원칙을 새 AC-17~21로 통합합니다. AC-05~08·12·14·15의 고정 계산·정렬 관련 조건은 폐기하며 번호를 재사용하지 않습니다. 체크는 실제 기능 구현과 검증을 뜻하고 디자인 참고 자료 추가만으로 체크하지 않습니다.

- [ ] AC-16: 로그인한 사용자가 AI 탭에서 자연어로 탐색·추천을 요청하고 후속 메시지로 조건을 바꿀 수 있으며, 설명과 연결된 공모전·팀 결과를 확인할 수 있다.
- [ ] AC-17: 공모전·팀·실제 지원자 추천이 각 사용자의 권한과 대상에 맞게 제공되며, 공개 사람 탐색 결과를 해당 팀의 실제 지원자로 표시하지 않는다.
- [ ] AC-18: 접수 기간·정원·현재 지원 관계·공개 상태 등 사업 정책을 추천과 실제 행동에 적용한다. 자격 정보 부족은 원문 확인 안내 후 일반 지원 접수를 허용하되 자격 충족으로 추정하지 않으며, 목록·상세·지원·추천에 같은 마감 경계를 사용한다.
- [ ] AC-19: 역할 불일치·경험 부족만으로 후보를 자동 제외하지 않으며, 취소 이력을 재지원의 영구 제외 사유로 사용하지 않는다. 고정 점수·가중치·기존 산식은 제공하지 않는다.
- [ ] AC-20: 실제 데이터와 요청 조건으로 추천 이유를 설명하고, 일반 AI 사람 탐색에서 비공개 프로필·인증 정보·외부 포트폴리오 내용·추정 경험을 노출하지 않는다. 해당 지원을 받은 팀장의 최신 프로필 기반 AI 검토 허용을 일반 사람 추천·다른 팀·일반 팀원에게 확대하지 않는다.
- [ ] AC-21: 프로필·공개 범위 변경 후 새 조회·추천은 현재 정보와 권한을 따르며, 이전 근거를 현재 정보처럼 표시하지 않는다. 일반 프로필 변경 알림은 제공하지 않는다.
- [ ] AC-22: 준비 중·성공·빈 결과·실패·중단을 구분하고 실패한 요청을 재시도할 수 있다. 빈 결과를 가상의 후보로 채우지 않는다.
- [ ] AC-23: 새 대화와 답변 복사, 같은 세션 내 탭 이동 시 대화·입력 유지가 동작한다. 중단·새 대화 이후 늦은 응답이 현재 대화를 덮지 않는다.
- [ ] AC-24: 추천에서 상세로 이동한 뒤 사용자가 직접 지원·생성·선발하며, LLM이 참여·선발·인증 결과를 자동 확정하지 않는다.
- [ ] AC-25: 비로그인·로그아웃·세션 만료 시 공모전·팀·사람 등 모든 AI 요청과 결과를 제한하며, AI 아이콘·하단 탭·직접 주소로도 우회할 수 없다. 로그인한 사용자는 사람 탐색 검색창의 AI 아이콘으로 진입할 수 있다.
- [ ] AC-26: 과거 대화 목록·검색·다시 열기 기능 없이 현재 대화를 이용한다. 새 대화는 현재 대화·초안·진행 중 응답을 초기화하고, 로그아웃 후 다른 로그인 상태에 이전 계정의 대화나 늦은 응답을 노출하지 않는다.
- [ ] AC-27: 주당 참여 가능 시간을 설명할 때 모든 프로젝트의 합산 참고값임을 유지하고, 팀별 배정 시간·잔여 시간·공통 회의 가능 시간으로 변환하거나 이를 근거로 참석·자격을 보장하지 않는다.
- [ ] AC-28: 사용자 메시지는 1,000자까지 허용하고 초과 입력을 잘라 전송하지 않는다. 한 답변의 추천 카드는 종류 합계 3개 이하이며, 적합한 결과만 표시하고 같은 대화에서 추가 추천을 요청할 수 있다.
- [ ] AC-29: 모집 마감·정원 충족 후에도 팀장이 기존 지원자 AI 검토 결과를 확인·재요청할 수 있다. 새 선발 후보는 지원 완료·검토 중인 유효 지원자만 포함하며 선발·미선발·지원 취소는 제외한다. 신규 지원·정원 초과 선발은 허용하지 않는다.
- [ ] AC-30: 지원 뒤 비공개로 전환해도 기존 지원·소속과 지원받은 팀장의 직접 열람·AI 검토를 유지하고 다음 검토 요청에는 최신 프로필을 반영한다. 일반 AI 사람 추천에서는 제외하며, 새 지원은 공개 전환 확인·저장 후 현재 조건을 다시 확인해 제출한다.
