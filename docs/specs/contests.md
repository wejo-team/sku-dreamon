# 공모전 공고 탐색과 운영

- 구현 상태: 예정
- 명세 검토: [PR #15](https://github.com/wejo-team/wejo-app/pull/15)
- 구현 작업: 미등록

## 목적과 사용자

사용자는 공모전의 참가 자격과 일정을 확인하고 참여할 공모전을 고릅니다. 운영자는 확인한 공고를 등록·수정하고, 공개할 정보와 마감 상태를 관리합니다.

## 범위

- 공모전 목록·상세 조회와 공식 원문 확인을 제공합니다.
- 운영자가 교내 공모전·지원 프로그램 및 공식 공모전 공고를 직접 등록·관리합니다.
- 공고 요약과 조건 정리에 AI를 활용하는 경우 운영자의 원문 검토를 거쳐 공개합니다. 실제 AI 사용 여부와 입력 형식은 미정입니다.
- 초기 데이터는 프로젝트 팀이 확인한 공고로 구성합니다.
- 외부 사이트 자동 수집은 초기 범위에서 제외합니다.

초기 시연은 소수의 신뢰할 수 있는 공고로도 서비스 흐름을 보여줄 수 있습니다. 최소 공고 개수는 원문에 정의되지 않았습니다.

이 문서는 공고 데이터, 공개 절차, 참가 자격과 공고 마감을 정의합니다. 공모전 선택 이후 모집글 작성·팀 지원은 [팀 모집과 지원](teams.md)에서 관리합니다. 개인화 추천의 후보 선정과 점수 계산은 이 문서의 범위에 포함하지 않습니다.

<a id="contest-data"></a>

## 공고 데이터

| 구분 | 항목 | 정책 |
| --- | --- | --- |
| 필수 | 공모전명, 주최 기관 | 공식 공고를 기준으로 입력 |
| 필수 | 참가 자격 | 공고에 명시된 참가 조건 입력 |
| 필수 | 모집·마감 일정 | 원문에 안내된 일정 확인 |
| 필수 | 참가 방식 | 개인·팀 참가 여부 입력 |
| 필수 | 팀 인원 조건 | 공고의 인원 조건 입력 |
| 필수 | 공식 링크 | 사용자가 원문을 확인할 수 있는 공식 URL 저장 |
| 확인 가능한 경우 추가 | 분야, 제출물, 시상 내용, 문의처 | 확인한 정보만 추가 |
| 확인 가능한 경우 추가 | 마지막 확인일, 공고 상태 | 공고를 확인한 날짜와 확인된 상태 기록 |

공고 상태를 입력하는 항목과 별개로, 서비스는 마감된 공고에 대한 신규 지원을 막을 수 있어야 합니다. 상태의 종류와 전환 방식은 미정 사항에서 관리합니다.

## 사용자 흐름과 동작

<a id="browse"></a>

### 공고 탐색

1. 사용자는 홈·공모전 목록에서 등록된 공모전과 모집 중인 공고를 확인합니다.
2. 공모전 상세에서 참가 자격, 마감일, 확인된 제출물과 공식 링크를 확인합니다.
3. 공식 링크로 원문을 확인하거나, 선택한 공모전의 팀 목록으로 이동합니다.

공모전 추천 결과에서는 공모전명, 마감일, 참가 자격, 공식 링크를 확인할 수 있습니다. 추천 결과에 표시할 매칭 이유는 실제 추천에 사용한 데이터에 근거해야 합니다. 일반 목록의 카드별 표시 항목은 원문에서 별도로 확정하지 않았습니다.

<a id="publication"></a>

### 운영자 등록과 공개

1. 운영자가 공식 공고를 확인해 공고 데이터를 입력합니다.
2. AI 요약을 사용하는 경우 등록한 공고에서 요약·조건 정리 초안을 만듭니다.
3. 운영자가 원문과 대조하여 참가 자격과 마감일을 확인합니다.
4. 확인한 공고를 공개합니다.
5. 원문 변경이나 마감이 확인되면 공고 정보와 상태를 수정합니다.

<a id="summary"></a>

### AI 요약과 불명확한 정보

- AI는 긴 공고의 요약과 조건 정리에 사용합니다. 참가 가능 여부나 마감 여부를 AI의 추측으로 결정하지 않습니다.
- AI 결과의 참가 자격과 마감일은 운영자가 원문을 검토한 뒤 공개합니다.
- 확인할 수 없는 정보는 임의로 채우지 않고 `미확인` 표시 또는 원문 확인 안내를 제공합니다.
- 실제 AI API 연동 여부는 시연에서 명확히 표시합니다.
- AI 사용 여부, 입력 데이터 형식, AI를 사용하지 않거나 요약에 실패한 경우의 처리 방식은 아직 확정하지 않습니다.

## 정책과 예외

<a id="eligibility"></a>

### 참가 자격

- 학교, 학적 상태, 학년, 전공·학과 등 공고에 명시된 자격 조건을 모두 충족해야 자격 조건을 통과합니다.
- 자격 미충족이 확인되면 추천 후보에서 제외합니다.
- 자격 정보가 없거나 확인되지 않으면 자동 통과시키지 않고 `확인 필요`로 구분합니다.
- 학적 상태·학년·단과대학·전공은 명시된 자격 조건을 확인할 때 사용합니다. 조건이 없는데 해당 정보를 이유로 참가 자격을 제한하지 않습니다.
- `확인 필요` 상태가 실제 팀 지원을 허용하는지는 [팀 모집과 지원](teams.md#open-questions)의 미정 사항으로 남깁니다.

사용자 학적 정보의 입력 기준이나 학교 목록을 바꿀 때는 각각 [프로필 입력 항목](profile.md#fields), [학사 선택 흐름](academic-structure.md#selection-flow)를 함께 확인합니다.

<a id="deadlines"></a>

### 마감

- 모집 중이고 마감 전인 공고만 신규 참여 후보가 됩니다.
- 마감된 공고는 신규 지원이 불가능하도록 상태를 변경합니다.
- 마감 여부는 날짜와 상태를 기준으로 판단합니다.
- 공고 마감과 별도로 팀의 모집 마감·정원 조건도 충족해야 합니다. 해당 조건은 [팀 모집과 지원](teams.md)에서 정의합니다.

<a id="acceptance-criteria"></a>

## 완료 조건

- [ ] AC-01: 운영자가 필수 공고 정보를 등록·수정하고, 사용자가 공고 목록을 탐색하고 상세에서 등록된 필수 정보를 확인할 수 있다.
- [ ] AC-02: 공고별 공식 링크를 통해 원문을 확인할 수 있다.
- [ ] AC-03: AI 요약을 사용하는 경우 운영자가 원문과 참가 자격·마감일을 대조한 뒤 공개한다.
- [ ] AC-04: 불명확한 정보는 임의의 값 대신 미확인 표시 또는 원문 확인 안내로 나타난다.
- [ ] AC-05: 확인된 자격 미충족과 자격 확인 필요를 구분하며, 확인 필요를 자동 통과로 처리하지 않는다.
- [ ] AC-06: 마감된 공고에 대해 신규 지원할 수 없다.
- [ ] AC-07: 선택한 공모전에서 관련 팀 목록으로 이동할 수 있다.

<a id="open-questions"></a>

## 미정 사항

- 공고 요약의 실제 AI 사용 여부, 입력 데이터 형식과 요약 실패·미사용 시 처리 방식.
- 운영자 권한을 부여하고 확인하는 방식.
- 공고 상태의 종류, 모집·마감 시각의 기준과 상태를 전환하는 방식.
- 필수 정보가 미확인인 공고의 공개 허용 범위와 확인 절차.
- 공고 내용 변경이나 마감 이후 기존 팀·지원 내역을 처리하는 방식.
