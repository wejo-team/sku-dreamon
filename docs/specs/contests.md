- 변경 근거: 2026-10-19 [#77 사용자 결정](https://github.com/wejo-team/sku-dreamon/issues/77)의 참가 대상·분야·접수 상태·인원·팀 집계와 #33·#36·#46 정책. 디자인·배포 검증 상태는 [대조 기록](prototype-alignment.md)에서 별도 관리

공고의 출처·등록 전 확인·접수 상태·마감과 사용자 탐색을 정의합니다. LLM 추천 후보와 근거는 [추천 매칭](matching.md), 공고를 선택한 뒤의 팀 생성·지원은 [팀 모집과 지원](team-recruitment.md)에서 관리합니다.

## 목적과 사용자

교내 사용자가 신뢰할 수 있는 공모전의 참가 자격·일정·원문을 확인하고 참여할 팀을 찾을 수 있게 합니다. 공고 등록·수정·등록 전 확인은 관리자가 담당합니다. 수집·DB 적재·갱신 방식, 관리자 권한 부여·회수 절차와 관리자 페이지는 TBD입니다.

## 범위

| 포함 | 제외·미정 |
| --- | --- |
| 교내 공모전·지원 프로그램 및 공식 공모전 공고 | 수동 입력·크롤링 등 수집·DB 적재 방식은 TBD |
| 관리자의 공고 등록·수정·등록 전 확인 | 관리자 계정·인증·권한 저장 방식, 관리자 페이지와 수집·적재 도구는 TBD. 등록자·수정자 이력은 MVP 제외 |
| 공모전 목록·상세·공식 링크, 공식 인원 조건을 따르는 팀 연결 | 원문을 대신하는 공모전 접수·제출 기능은 정의되지 않음 |
| 참가 조건 정리와 등록 전 필수 정보 확인 | 확인 방법·도구, 별도 요약의 사용처·필요성·MVP 포함 여부와 AI 연동은 [TBD](#summary-scope) |
| 마감 상태 반영·신규 지원 제한과 마감 후 공개 상세 열람 | 마감 공고의 목록 배치·정렬·필터, 별도 삭제·보존 기간과 재개 세부 규칙은 미정 |

초기 시연은 소수의 신뢰할 수 있는 공고로 전체 흐름을 보여 줄 수 있습니다. 자동 수집이나 많은 공고 수를 완료 조건으로 삼지 않습니다. 실제·시연 공고와 계정·팀의 추천·지원·선발은 [시연 데이터 정책](sprint-1.md#demo-data-scope)에 따라 서로 허용하며, 시연 표시와 등록 전 확인 원칙을 유지합니다.

2026-10-19 사용자 결정에 따라 **공고는 관리자가 관리하며 관리자 페이지는 TBD**입니다. 일반 회원·팀장에게 공고 등록·수정 권한을 부여하지 않습니다. [이슈 #34](https://github.com/wejo-team/sku-dreamon/issues/34#issuecomment-6232606000)의 수집·DB 적재 방식은 계속 미정이며, 관리자 책임을 확정한 것이 수동 입력·크롤링 등 구현 방식을 선택한 것은 아닙니다.

## 공고 데이터

| 구분 | 항목 |
| --- | --- |
| 필수 | 공모전명, 주최 기관, 참가 대상·원문 참가 조건, 접수 시작·마감 일정 |
| 필수 | 공식 최소·최대 참가 인원 조건, 공식 원문 URL, 접수 상태 |
| 확인 가능한 경우 추가 | 동등한 복수 분야(최대 3개), 제출물, 시상 내용, 문의처, 마지막 확인일 |

공식 URL은 공고별로 저장합니다. 불명확한 값을 추정해서 채우지 않으며 [등록 전 확인](#publication-policy)을 적용합니다. 개별 지원자의 정보 부족은 공고 자체의 필수 자료 미확인과 구분하고 [자격 정보 부족 시 지원 정책](team-recruitment.md#recruitment-conditions)을 따릅니다.

### 참가 대상과 분야

[#77의 F01·F02 결정](https://github.com/wejo-team/sku-dreamon/issues/77)에 따라 참가 대상은 `대학생`·`일반인`·`제한 없음`·`미확인`으로 표현합니다. `대학생`과 `일반인`은 함께 선택할 수 있으며, `제한 없음`과 `미확인`은 각각 단독으로만 선택합니다. 기타는 제공하지 않습니다. 대학생은 의미상 대학원생을 포함하지만 이는 넓은 분류이며, 개별 사용자의 세부 자격을 자동 판정하는 규칙이 아닙니다. 세부 조건은 원문으로 확인합니다.

분야는 [공통 관심 분야 목록](profile-options.md#catalog-management)에서 **공모전당 최대 3개**를 동등하게 선택합니다. 대표 분야를 별도로 관리하지 않습니다. 목록·상세에는 등록한 분야들을 표시하며, 검색·분야 필터는 같은 전체 분야 집합을 사용합니다. 팀의 관심 분야도 연결 공모전의 이 값을 그대로 사용합니다.

### 접수 상태

공고는 `접수 예정`·`접수 중`·`접수 마감`으로 구분합니다. 접수 기간 전은 예정, 접수 시작부터 [마감 경계](#deadline-policy) 전까지는 접수 중, 경계부터는 접수 마감으로 안내합니다. 등록된 공고는 상태와 관계없이 공개하며 별도 공개/비공개 설정을 두지 않습니다. 접수 상태와 사용자에게 보이는지 여부를 같은 값으로 취급하지 않습니다.

<a id="publication-policy"></a>

## 등록 전 확인과 공개

[#77의 F03 결정](https://github.com/wejo-team/sku-dreamon/issues/77)에 따라 **미확인 자료는 등록 전에 확인하고 등록된 공고는 모두 공개**합니다. 과거 #35의 ‘미확인 공고를 등록해 비공개로 둔다’는 표현은 이 정책으로 대체합니다. 등록 전 확인은 관리자가 담당하고 확인 방법·도구는 TBD이며, 별도 관리자 승인 단계나 비공개 공고 관리 화면을 새로 요구하지 않습니다.

| 정보 상태 | 등록·표시 원칙 |
| --- | --- |
| 필수 자료가 확인됨 | 등록된 공고는 모두 공개하며 별도 공개 전환 없음 |
| 필수 자료가 미확인 | 등록 전에 원문 자료를 확인. 미확인을 임의의 확정값·제한 없음으로 바꾸어 등록하지 않음 |
| 선택 정보가 미확인 | 미확인 또는 원문 확인 안내로 구분. 선택 정보 부족을 사용자 자격 미충족으로 취급하지 않음 |

예를 들어 참가 대상의 `미확인`이나 인원 조건의 `미확인`은 정보 부족을 나타내는 값이며, 해당 자료를 확인하지 않고 등록해도 된다는 허가가 아닙니다. 날짜만 확인된 마감일의 시각·시간대는 [확정한 서비스 보완 기준](#deadline-policy)을 적용하고 그 사실을 안내합니다.

등록 후 정보 변경의 재확인 대상·순서와 변경 값을 반영하는 운영 절차는 [#50](https://github.com/wejo-team/sku-dreamon/issues/50)의 후속 결정입니다. 현재 제품에 공개/비공개 스위치를 도입하는 것으로 해석하지 않습니다.

<a id="operation-flow"></a>

## 운영 흐름

공고 등록·수정·등록 전 확인의 책임 주체는 관리자입니다. 관리자 계정·인증·권한 저장 방식, 관리자 페이지·권한 부여/회수와 세부 운영 절차는 확정하지 않습니다.

2026-10-21 사용자 결정에 따라 MVP에서는 공고를 누가 등록·수정했는지 이력을 관리하지 않습니다. 관리자 계정을 일반 회원 계정과 함께 저장할지도 운영 방식과 함께 정하며, 이번 DB 설계에 관리자 권한 테이블이나 공고의 등록자·수정자 참조를 추가하지 않습니다. 공고의 생성·수정 시각과 등록 전 확인 시각은 유지합니다.

1. 공고 정보와 공식 원문 URL을 준비합니다. 확인된 JSON 자료의 신규 적재는 [운영 입력 CLI](../api/contests.md#contest-import-cli)를 사용합니다. 크롤링과 갱신 절차는 후속 범위입니다.
2. 참가 자격·일정·제출물 등 확인된 정보를 정리합니다. 별도 요약의 사용처·필요성과 MVP 포함 여부는 [요약 범위](#summary-scope)에서 먼저 결정하고, AI 연동 여부는 그 뒤에 정합니다.
3. [등록 전 확인](#publication-policy)을 거친 자료로 공고를 등록하며 등록된 공고는 모두 공개합니다. 등록·확인은 관리자가 담당하며 방법·관리자 페이지는 TBD입니다.
4. 등록 후 정보 갱신·재확인·노출 순서는 수집·갱신 방식을 정할 때 논의합니다. 현재 단계에서 관리자 승인이나 기존 공개본 유지 절차를 확정하지 않습니다.

### 공고 요약의 사용처와 MVP 범위

[이슈 #38의 보류 판단](https://github.com/wejo-team/sku-dreamon/issues/38#issuecomment-6235004516)에 따라 **별도 요약의 사용처·필요성과 MVP 포함 여부는 TBD**입니다. 기존 명세에는 긴 공고를 읽기 쉽게 정리하려는 목적은 있으나, 요약을 표시할 화면·내용·완료 조건은 정의되어 있지 않습니다. [주요 화면](sprint-1.md#screens)의 공모전 상세는 참가 자격·마감일·제출물·공식 링크를 제공하며, 별도 요약 영역을 확정하지 않습니다.

화면 기획 때 요약이 필요한지와 어디서 사용하는지를 먼저 정하고, 포함하기로 한 경우 내용·생성 방식·표시 기준을 구체화합니다. 실제 AI API 호출·수동 작성·사전 생성 중 어느 방식도 기본값으로 채택하지 않으며, AI 연동 여부는 사용처를 정한 뒤 결정합니다. 이번 보류는 요약의 MVP 제외 결정이 아닙니다.

원문 참가 조건 안내·마감 판단과 [등록 전 확인](#publication-policy)은 유지합니다. 추천은 [LLM 기반 추천](matching.md)을 따르며 공고 요약 제공 여부와 별도로 정의합니다. 요약을 제공하더라도 원문 확인을 대신하지 않습니다. [이슈 #52](https://github.com/wejo-team/sku-dreamon/issues/52)는 실제 AI 사용을 선택했을 때만 실패 시 등록·대체 요약 정책을 논의하는 조건부 대기이며, 재시도 동작도 미정입니다. 실제 API 사용 여부는 [시연 기준](sprint-1.md#web-demo)에 따라 사실대로 안내하되, 표시 기준만으로 AI 연동을 필수화하지 않습니다.

## 사용자 탐색 흐름

1. 사용자는 [로그인 없이 공개 공고](authentication.md#access-policy)를 목록·상세에서 탐색할 수 있습니다. AI 탐색·추천은 [로그인 후에만 이용](authentication.md#access-policy)하며, 세부 제공 범위는 [추천 매칭](matching.md)을 따릅니다.
2. 공모전 상세에서 참가 자격, 마감일, 제출물 등 확인된 정보를 읽고 공식 링크로 원문을 확인합니다.
3. 공모전 상세에서 해당 공모전의 공개 팀 목록을 바로 확인하고 팀 카드를 눌러 모집글로 이동합니다. 팀 모집글 작성·지원은 로그인 후 이용하고, 신규 지원에는 [프로필 공개와 필수 정보 조건](profile.md#before-application)을 적용합니다.

추천 표시 정보·이용 흐름·근거는 [추천 매칭](matching.md)에 둡니다. 서비스의 팀 연결은 주최 측 공모전 접수·제출을 대신하지 않습니다.

### 탐색 목록과 상세의 정보 구분

공모전 탐색은 공고를 고르는 데 필요한 정보를 간결하게 표시하고, 참가 조건·정확한 일정·원문은 상세에서 확인합니다. 목록에서 참가 대상·마감일 행을 생략해도 [필수 공고 데이터](#data)나 [등록 전 확인](#publication-policy)을 삭제하는 것은 아닙니다.

| 영역 | 제공하는 정보·행동 |
| --- | --- |
| 공모전 카드 왼쪽 | 세로형 포스터 영역과 D-day 배지. 포스터 비율을 보존하고 이미지 아래에 별도 문구를 두지 않음 |
| 공모전 카드 오른쪽 | 제목 → 분야 → 주최자 순서. 우하단에 팀 아이콘과 공모전에 연결된 전체 팀 수를 표시하고, 접근성 이름에는 숫자의 의미를 포함 |
| 카드 이동 | 카드 전체로 상세에 이동. 별도 `상세보기` 문구·화살표를 두지 않으며 hover·키보드 포커스·누르는 상태를 녹색으로 구분 |
| 이미지 미등록·로드 실패 | 서경대학교 마스코트 기반 기본 이미지를 표시. 이미지 실패 때문에 제목·상세 이동을 사용할 수 없게 하지 않음 |
| 상세 | 제목·주최자·분야·공고 설명, 참가 대상, 접수 시작·마감, 공식 참가 인원 조건, 확인된 제출물·정보 확인일·공식 원문 링크 |
| 팀 연결 | 해당 공모전의 공개 팀 목록을 상세 안에 바로 표시. 별도 `팀 찾기` 버튼은 두지 않고 팀 생성·AI 진입은 아이콘으로 제공. 공모전 접수 자체는 주최 기관에서 진행한다고 안내 |

공모전 검색은 이름·주최자·분야로 결과를 좁힙니다. 분야는 필터 아이콘으로 여는 하단 팝업(Drawer)에서 하나를 선택하고 **적용했을 때** 반영합니다. 적용하지 않고 취소하거나 닫으면 기존 조건을 유지하며, 다시 열면 적용된 값을 표시합니다. 활성 조건 수를 필터 아이콘에 표시하고 선택한 탐색 탭을 구분합니다.

정렬은 `등록순`과 `마감 임박순`을 제공하고, 검색어·필터·정렬 조건이 있으면 초기화 아이콘을 표시합니다. 정렬만 바꾼 경우도 초기화할 수 있습니다. 검색어만 지우는 행동과 전체 조건 초기화를 구분하고, 초기화해도 현재 탐색 탭은 유지합니다. 결과 수를 표시하며 결과가 없으면 검색어 변경·조건 초기화를 안내합니다. 아이콘 행동에는 목적을 알 수 있는 접근성 이름을 제공합니다.

목록은 [탐색 공통 페이지 이동 정책](sprint-1.md#exploration-pagination)에 따라 페이지 번호로 조회하고, 현재 조건의 전체 결과 수·총페이지를 표시합니다. 검색·탭·필터·정렬 변경 시 1페이지로 이동하고 상세에서 탐색으로 복귀할 때는 조건과 페이지를 유지합니다. 검색창 안의 AI 아이콘은 일반 검색과 분리된 진입점이며, 기존 검색어를 자동 전송하는 동작을 뜻하지 않습니다. AI 이용 권한은 [로그인 정책](authentication.md#access-policy)을 따릅니다.

<a id="contest-teams"></a>

### 상세 안의 팀 목록과 행동

상세의 팀 영역에는 **공모전 식별자가 현재 공모전과 일치하는 공개 팀**만 표시합니다. 다른 공모전의 팀이나 지원자 관리·팀 공간을 이 목록에 노출하지 않습니다. 팀 카드를 누르면 공개 모집글로 이동하고 돌아오면 원래 공모전 상세를 확인할 수 있습니다. 팀의 모집 상태를 표시하되 목록에 보인다는 이유로 지원할 수 있다고 보장하지 않으며 [기한·정원·모집 정책](team-recruitment.md#recruitment-conditions)을 그대로 적용합니다.

- 별도 `팀 찾기` 버튼을 두지 않습니다. 팀 영역의 생성 아이콘은 현재 공모전을 선택한 팀 생성 흐름으로, AI 아이콘은 로그인 전용 AI 대화로 연결합니다. AI 진입 시 현재 공모전 정보나 검색 요청을 자동 전달하지 않습니다. 두 행동 모두 [로그인 정책](authentication.md#access-policy)을 적용합니다.
- 아이콘에는 `팀 만들기`·`AI로 팀 찾기`처럼 목적을 알 수 있는 접근성 이름을 제공하고 최소 44×44px의 조작 영역을 확보합니다. 공식 인원이 1명인 공고도 같은 팀 생성 흐름을 사용하되 추가 모집이 없는 1인 정원으로 안내합니다.
- 공개 팀이 없고 공고가 접수 중이면 팀이 없음을 알리고 새 팀을 만들어 보도록 안내합니다. 팀 생성은 기존 공모전별 소속·정원 등 정책을 따르며, 빈 상태를 새 팀 생성 완료나 지원 가능 보장으로 표시하지 않습니다.
- 마감 공고에서는 기존 공개 팀·공고 정보는 열람할 수 있지만 새 팀 생성·신규 AI 팀 추천 행동과 팀 생성 권유를 제공하지 않습니다. 팀이 없으면 현재 표시할 팀이 없다는 안내만 제공합니다. 기존 팀의 신규 지원도 기존 마감 정책대로 차단합니다.

### 디자인 레퍼런스와 제품 구현의 경계

[공식 디자인 PR](https://github.com/wejo-team/sku-dreamon/pull/74)의 참고 앱 동작입니다. 소스·배포 버전과 수행한 검증은 [프로토타입·명세 대조 기록](prototype-alignment.md)에서 관리하며, 아래 화면 동작을 실제 서버 기능의 완료로 취급하지 않습니다.

참고 앱은 동등한 복수 분야, 넓은 참가 대상과 원문 조건, 공식 최소·최대 인원, 접수 예정·중·마감을 표시합니다. 마감은 원문 시각·시간대를 우선하고 누락 보완 안내를 제공하며 목록·상세·팀 접수·신규 추천에서 같은 경계를 사용합니다. 카드의 팀 수는 전체 연결 팀을 집계합니다. 고정 1명·상한 없음·접수 예정 예시도 같은 상세·팀 생성 흐름으로 확인할 수 있습니다.

정적 공고·고정 기준 시각·메모리 상태·로컬 원문 참고 링크는 운영 수집·등록·외부 URL 검증이나 실제 현재 시각 기반 서버 집계를 구현한 것이 아닙니다. 운영 날짜·API·등록 전 확인의 구현과 검증은 별도입니다.

## 공식 참가 인원과 팀 연결

[#77의 F05·F11 결정](https://github.com/wejo-team/sku-dreamon/issues/77)에 따라 **개인/팀 참가 유형을 따로 관리하지 않고 공식 최소·최대 인원 조건으로 표현**합니다. `숫자 범위`·`제한 없음`·`미확인`을 구분하고 누락을 제한 없음으로 간주하지 않습니다. 정확히 1명인 조건은 최소·최대 모두 1, 정확히 N명인 조건은 둘 다 N으로 표현합니다. 상한이 없다고 확인된 경우에도 확인된 최소 인원 조건은 유지합니다.

모든 팀은 [공식 인원 조건과 목표 정원](team-recruitment.md#official-capacity)을 따릅니다. 준비 모임의 별도 정원 예외와 개인 전용 공고의 공동 준비 팀 구분은 제거합니다. 공식 인원이 1명이면 목표 정원은 1명이며 추가 모집하지 않습니다. 고정 N명은 정원을 N명으로 고정하고, 범위·상한 없음 조건에서는 팀장이 기본값 없이 직접 목표 정원을 입력합니다.

공식 원문 확인과 로그인 후 팀 생성·지원은 기존 [접근 정책](authentication.md#access-policy)을 따릅니다. 주최 측의 접수·출품을 대행하거나 원문 참가 조건을 변경하지 않으며, 팀 생성·목록·상세·팀 공간에서 같은 인원 조건을 사용합니다. 과거 #37의 준비 모임 허용은 이번 결정으로 대체합니다.

## 마감과 정보 변경

[#77에 기록한 #36 최신 결정](https://github.com/wejo-team/sku-dreamon/issues/77)에 따라 아래 기준을 적용합니다. 이전 ‘날짜만 있는 마감은 TBD’ 보류를 대체합니다.

1. 원문 시간대와 마감 시각을 우선합니다. 시간대가 없으면 한국시간(`Asia/Seoul`)을 사용합니다.
2. 시각이 없으면 위 시간대의 해당 날짜가 끝나는 **다음 날 00:00**을 마감 경계로 사용합니다. 경계 시각부터 신규 지원을 접수하지 않고 신규 지원 가능한 추천 후보에서도 제외합니다.
3. 날짜만 `10월 21일 마감`이면 한국시간 10월 22일 00:00부터 마감입니다. `10월 21일 17:00`이고 시간대만 없으면 한국시간 10월 21일 17:00을 적용합니다. 다른 시간대가 명시돼 있으면 원문 시간대를 우선합니다.
4. 시각이나 시간대를 기본값으로 보완했으면 **서비스 기준으로 보완한 값임을 안내**합니다. 원문 표기·확인된 시각과 서비스 해석을 구분하며 주최 측이 확인한 정확한 시각처럼 안내하지 않습니다.
5. 목록·상세·팀 모집 기한 판단·지원 접수·신규 지원 가능한 추천에서 같은 경계를 사용합니다. 시간대가 있는 날짜·시간의 저장·전송은 [기술 기준](../development/conventions.md)을 따릅니다. 마감 계산을 확정한 것이 마감 알림 도입을 뜻하지 않으며 [알림 범위](notifications.md)를 유지합니다.

등록된 공고는 마감 후에도 열람할 수 있습니다. 신규 지원 가능한 추천과 [기존 지원자의 AI 검토](matching.md#eligibility)는 구분하며, 마감·정원 충족만으로 팀장의 기존 지원자 검토 결과 확인·재요청을 막지 않습니다.

공고 변경은 관리자가 관리합니다. 변경·마감 반영의 방법·실행 주기와 변경 정보의 재확인·노출 절차는 #50의 후속 결정입니다. 공고 자격·일정 변경이 기존 지원·선발·팀에 미치는 영향은 아래 [보류 정책](#eligibility-changes)을 유지합니다.

개별 참가 자격은 원문 확인을 안내하고 [비즈니스 로직에서 지원·선발을 제한하지 않습니다](team-recruitment.md#recruitment-conditions). 자격 충족을 보장하지 않으며 공고 자체의 등록 전 확인이나 마감·공식 정원·프로필 공개·중복·소속 등 기존 서비스 조건은 그대로 적용합니다.

### 마감 후 상세 열람

[이슈 #39의 결정](https://github.com/wejo-team/sku-dreamon/issues/39#issuecomment-6234731790)에 따라 **이미 공개된 공고는 마감 후에도 로그인 없이 누구나 상세 정보와 공식 원문 링크를 확인**할 수 있습니다. 상세에 마감 상태를 명확히 표시하고, 직접 URL과 팀 공간의 공고 링크에서도 동일하게 열람할 수 있습니다.

| 상황 | 결과 |
| --- | --- |
| 비로그인 사용자가 마감 공고의 상세 URL로 접근 | 마감 표시와 함께 상세 정보·공식 원문 링크 열람 가능 |
| 현재 팀장·확정 팀원이 팀 공간에서 마감 공고 확인 | 상세 정보·공식 원문 링크 열람 가능 |
| 팀 공간 접근 권한이 없는 사용자가 해당 팀 공간에 접근 | 기존 [팀 공간 접근 정책](team-recruitment.md#team-workspace-access)에 따라 거부. 공개 공고 상세는 별도로 열람 가능 |
| 마감 공고의 상세를 본 뒤 신규 지원을 시도 | 접수 불가. 마감 공고는 신규 지원 대상 추천에서도 제외 |

상세 열람 허용은 공고 접수의 재개나 팀 공간 권한 확대를 뜻하지 않습니다. 기존 지원자의 마감 후 AI 검토 결과 열람·재요청은 [추천 정책](matching.md#eligibility)에 따라 허용합니다. 일반 목록에서 마감 공고를 배치·정렬·필터하는 방식, 별도 삭제 사유와 보존 기간은 CONTEST-05에서 후속으로 정합니다.

### 주최 측 조건 변경과 기존 지원·팀원 처리

2026-10-19 사용자 결정에 따라 공고 조건 변경은 **주최 측의 책임**으로 두며, 참가 자격·인원·일정 등의 변경이 기존 지원·선발·팀에 미치는 세부 영향은 아직 정의하지 않고 TBD로 유지합니다. [이슈 #51의 보류 판단](https://github.com/wejo-team/sku-dreamon/issues/51#issuecomment-6234732341)과 연결하며 관리자 정보 수정이나 참가 자격 비차단 정책으로 이 영향을 대신 확정하지 않습니다.

이번 보류는 변경 전 조건을 유지하거나, 현재 조건으로 자동 재확인하거나, 지원을 일괄 취소하거나, 확정 팀원을 자동 제외하는 결정이 아닙니다. 현재 정의하지 않은 소급 처리를 구현에 추가하지 않습니다. 신규 행동의 마감·공식 정원 등 명시된 서비스 제한은 유지하되, 참가 자격 자체로 후보·지원·선발을 차단하지 않습니다.

## 완료 조건

- [ ] AC-01: 관리자가 공고의 필수 정보와 공식 URL을 등록·수정·관리하고 일반 회원·팀장은 이를 변경할 수 없다. 수집·적재·변경 경로와 관리자 페이지·권한 부여/회수 절차는 CONTEST-01에서 정한 뒤 검증한다.
- [ ] AC-02: 공고 목록에서는 포스터·D-day·제목·동등한 복수 분야·주최자·연결된 전체 팀 수를 확인하고, 상세에서 참가 대상·원문 참가 조건·일정·인원 조건·확인된 제출물·공식 링크를 확인할 수 있다.
- [ ] AC-03: AI 요약을 사용하는 경우에도 필수 공고 자료는 등록 전에 확인한다. 등록된 공고는 모두 공개하며 공개/비공개 설정을 제공하지 않는다. 등록 전 확인은 관리자가 담당하며 확인 방법·도구는 CONTEST-03에서 정한 뒤 검증한다.
- [ ] AC-04: 미확인 정보를 임의의 확정값으로 표시하지 않는다. 참가 인원의 숫자 범위·제한 없음·미확인을 구분하고 누락을 제한 없음으로 처리하지 않는다.
- [ ] AC-05: 마감 경계부터 신규 지원과 신규 지원 대상 추천을 허용하지 않는다. 원문 시각·시간대를 우선하고 누락된 시간대는 한국시간, 누락된 시각은 해당 날짜 종료로 보완하며 서비스 보완 사실을 안내한다.
- [ ] AC-06: 공모전에서 팀 탐색·생성으로 이동하며 개인/팀 유형이나 준비 모임을 별도 선택하지 않는다. 모든 경로에서 공식 최소·최대 인원 조건을 적용한다.
- [ ] AC-07: 시연의 실제 AI API 연동 여부를 사실대로 안내하며, 요약을 제공하는 경우 결정된 생성·표시 방식과 일치한다. 요약 화면·내용·제공 방식의 검증은 [요약 범위](#summary-scope) 결정 후 진행하며, 이 조건만으로 요약 제공이나 AI 연동을 필수화하지 않는다.
- [ ] AC-08: 필수 공고 자료가 미확인인 경우 등록 전에 원문을 확인하며, 미확인 공고를 등록한 뒤 공개 전환하는 흐름을 제공하지 않는다.
- [ ] AC-09: 등록된 공고는 선택 정보가 미확인이거나 접수가 마감돼도 공개한다. 공개 여부와 접수 예정·접수 중·접수 마감 상태를 구분한다.
- [ ] AC-10: 공식 인원이 정확히 1명이면 팀 목표 정원은 1명이고 추가 모집하지 않는다. 준비 모임 예외로 공식 인원을 초과하는 팀을 생성하지 않는다. 고정 인원·범위·상한 없음의 목표 정원은 팀 명세를 따른다.
- [ ] AC-11: 이미 공개된 공고가 마감되어도 비로그인 사용자는 직접 URL로 마감 표시·상세 정보·공식 원문 링크를 확인할 수 있고, 현재 팀장·확정 팀원은 팀 공간의 공고 링크에서도 확인할 수 있다. 팀 공간 접근 권한은 확대되지 않으며, 상세 열람 이후에도 신규 지원은 접수되지 않고 신규 지원 대상 추천에서 제외된다.
- [ ] AC-12: 목록 카드는 왼쪽 세로 포스터·D-day와 오른쪽 제목·분야·주최자·팀 아이콘/숫자를 제공한다. 이미지 아래 문구·별도 상세보기·참가 대상·접수 마감 행을 두지 않으며 키보드로 상세에 이동한다. 팀 수는 모집 상태와 관계없는 해당 공모전의 모든 팀을 세며 현재 지원 가능한 팀 수로 안내하지 않는다.
- [ ] AC-13: 공모전 검색·분야 선택·정렬로 목록이 바뀌고, 필터 팝업의 미적용 초안은 취소 시 버려진다. 정렬만 변경한 경우를 포함해 조건을 초기화할 수 있고, 변경 시 1페이지로 이동하며 상세 복귀 시 검색·탭·필터·정렬·페이지를 유지한다. 전체 결과 수·총페이지와 페이지 번호 이동, 결과 없음·잘못된 페이지 보정, 검색어 지우기·초기화·AI 아이콘의 접근성 이름을 확인한다.
- [ ] AC-14: 포스터가 없거나 로드에 실패하면 기본 이미지가 표시되고 제목·상세 이동은 유지된다. 긴 제목과 모바일 폭에서도 포스터 비율과 정보 구분을 유지한다.
- [ ] AC-15: 공모전 상세에 현재 공모전의 공개 팀을 모집 상태와 관계없이 표시하고 카드로 모집글을 연다. 생성·AI 아이콘은 로그인·접수·소속 정책을 유지하며 접수 중 빈 목록에는 생성 권유, 마감 공고에는 정보 안내만 제공한다.
- [ ] AC-16: 참가 대상에서 대학생·일반인은 복수 선택을 허용하고 제한 없음·미확인은 단독으로만 저장·표시한다. 대학생의 대학원생 포함 의미를 정밀한 자동 자격 판정으로 사용하지 않는다.
- [ ] AC-17: 공고 분야는 대표 구분 없이 공통 목록의 최대 3개를 표시하고, 일반 검색·분야 필터·연결된 팀 정보에서 동일한 분야를 사용한다.

구현과 검증 전에는 체크하지 않습니다. 등록 전 확인과 공개 원칙은 위 정책을 적용하고, 수집·적재·관리자 권한 부여/회수·확인 방법 등 미정 사항에 의존하는 검증은 해당 결정을 먼저 진행합니다.
