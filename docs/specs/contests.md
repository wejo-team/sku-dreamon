# 공모전 공고 탐색과 관리

- 구현 상태: 예정
- 명세 검토: 이 변경의 PR에서 검토
- 구현 작업: 미등록

공고의 출처·등록·검수·공개·마감과 사용자 탐색을 정의합니다. 추천 후보와 점수는 [추천 매칭](matching.md), 공고를 선택한 뒤의 팀 생성·지원은 [팀 모집과 지원](team-recruitment.md)에서 관리합니다.

## 목적과 사용자

교내 사용자가 신뢰할 수 있는 공모전의 참가 자격·일정·원문을 확인하고 참여할 팀을 찾을 수 있게 합니다. 운영자는 프로젝트 팀이 확인한 공고를 직접 입력하고 원문 변경과 마감을 반영합니다.

## 범위

| 포함 | 제외·미정 |
| --- | --- |
| 교내 공모전·지원 프로그램 및 공식 공모전 공고 | 외부 사이트 자동 수집은 초기 범위에서 제외 |
| 운영자 직접 등록·수정·관리 | 운영자 권한 부여 방법과 전용 관리 화면의 범위는 미정 |
| 공모전 목록·상세·공식 링크 | 원문을 대신하는 공모전 접수·제출 기능은 정의되지 않음 |
| 등록 공고의 요약·조건 정리와 운영자 검수 | AI 입력 형식·실제 사용 여부·API 연동은 미정 |
| 마감 상태 반영과 신규 지원 제한 | 상태별 공개·보존·재개 동작의 세부 규칙은 미정 |

초기 시연은 소수의 신뢰할 수 있는 공고로 전체 흐름을 보여 줄 수 있습니다. 자동 수집이나 많은 공고 수를 완료 조건으로 삼지 않습니다.

<a id="data"></a>

## 공고 데이터

| 구분 | 항목 |
| --- | --- |
| 필수 | 공모전명, 주최 기관, 참가 자격, 모집·마감 일정 |
| 필수 | 참가 방식(개인·팀), 팀 인원 조건, 공식 원문 URL |
| 확인 가능한 경우 추가 | 분야, 제출물, 시상 내용, 문의처, 마지막 확인일, 공고 상태 |

공식 URL은 공고별로 저장합니다. 불명확한 정보는 임의로 채우지 않고 미확인으로 표시하거나 원문 확인을 안내합니다. 원문은 위 필수 항목과 미확인 안내를 함께 요구하지만, 필수 정보가 확인되지 않은 공고를 공개할 수 있는지는 정하지 않았습니다. 추천에서는 자격 미확인을 자동 통과시키지 않는 [필수 조건](matching.md#eligibility)을 적용합니다.

원문 데이터 표의 ‘확인 가능한 경우 추가하는 공고 상태’와 서비스가 신규 지원을 제어하는 모집·마감 상태의 구체적인 구분·값은 미정입니다. 마감 공고의 신규 지원 금지 원칙은 유지합니다.

<a id="operation-flow"></a>

## 운영 흐름

1. 운영자가 프로젝트 팀이 확인한 공고와 공식 링크를 입력합니다.
2. 등록된 공고를 요약하고 참가 조건을 정리합니다. 생성형 AI를 사용할 대상이며 실제 사용 여부와 입력 형식은 먼저 결정합니다.
3. 운영자가 요약·조건을 공식 원문과 대조합니다. 특히 참가 자격과 마감일은 AI 결과를 검토한 뒤 공개합니다.
4. 검수한 공고를 사용자가 탐색할 수 있도록 공개합니다.
5. 원문이 바뀌거나 마감되면 공고를 수정하고 신규 지원 가능 상태를 갱신합니다.

AI 요약은 긴 공고를 읽기 쉬운 문장으로 제공하기 위한 수단입니다. 필수 자격·마감의 판단과 후보 순위는 규칙으로 처리하며, 요약이 원문 확인을 대신하지 않습니다. AI를 사용하지 않는 시연의 요약 제공 방식과 AI 호출 실패 시 공개·재시도 동작은 미정입니다. 실제 API 사용 여부는 [시연 기준](sprint-1.md#web-demo)에 따라 명확히 표시합니다.

## 사용자 탐색 흐름

1. 사용자는 홈·공모전 목록에서 모집 중 공고와 자신에게 매칭된 공모전을 확인합니다.
2. 공모전 상세에서 참가 자격, 마감일, 제출물 등 확인된 정보를 읽고 공식 링크로 원문을 확인합니다.
3. 선택한 공모전의 팀을 탐색하거나 팀 모집글 작성으로 이동합니다.

추천 표시 정보·실행 시점·순위는 [추천 매칭](matching.md)에 둡니다. 공고에 개인 참가 방식이 있다는 사실이 서비스 내 개인 접수 기능을 포함한다는 뜻은 아닙니다.

## 마감과 정보 변경

- 마감된 공고는 신규 지원이 불가능하도록 상태를 변경합니다. 모집 중이며 마감 전인 공고만 추천 후보가 됩니다.
- 공고 변경·마감은 운영자가 관리합니다. 자동 마감 처리 방식·실행 주기와 수동 수정의 관계는 원문에 없으므로 구현 계획 전에 결정합니다.
- 자격이나 일정이 바뀌었을 때 기존 지원·선발·팀에 미치는 영향은 미정입니다. 변경 전 정보를 근거로 이후 지원까지 허용한다고 가정하지 않습니다.
- 불명확한 자격은 ‘확인 필요’로 구분하며, 지원 시 검증 범위와 원문 정보 보완 흐름은 관련 미정 사항에서 정합니다.

<a id="acceptance-criteria"></a>

## 완료 조건

- [ ] AC-01: 운영자가 확인한 공고의 필수 정보와 공식 URL을 등록하고 변경 내용을 수정할 수 있다.
- [ ] AC-02: 공개한 공고의 목록과 상세에서 사용자가 참가 자격·일정·확인된 제출물·공식 링크를 확인할 수 있다.
- [ ] AC-03: AI 요약을 사용하는 경우 운영자가 참가 자격·마감일을 원문과 대조한 뒤 공개한다.
- [ ] AC-04: 확인되지 않은 정보가 임의의 확정값으로 표시되지 않고 미확인 또는 원문 확인 안내로 구분된다.
- [ ] AC-05: 마감된 공고에 신규 지원할 수 없고 신규 추천 후보에서도 제외된다.
- [ ] AC-06: 사용자가 선택한 공모전에서 팀 탐색 또는 모집글 작성 흐름으로 이동할 수 있다.
- [ ] AC-07: 시연에서 공고 요약의 실제 AI API 연동 여부를 확인할 수 있다.

구현과 검증 전에는 체크하지 않습니다. 공개 가능 조건·운영자 권한 등 미정 사항을 먼저 결정하고 실패 경로의 완료 조건을 보완합니다.
