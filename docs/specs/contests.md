# 공모전 공고 탐색과 관리

- 구현 상태: 예정
- 명세 검토: [PR #17](https://github.com/wejo-team/sku-dreamon/pull/17)
- 구현 작업: 미등록

공고의 출처·등록·검수·공개·마감과 사용자 탐색을 정의합니다. 추천 후보와 점수는 [추천 매칭](matching.md), 공고를 선택한 뒤의 팀 생성·지원은 [팀 모집과 지원](team-recruitment.md)에서 관리합니다.

## 목적과 사용자

교내 사용자가 신뢰할 수 있는 공모전의 참가 자격·일정·원문을 확인하고 참여할 팀을 찾을 수 있게 합니다. 공고의 수집·DB 적재·갱신 방식과 관리 담당·권한·화면은 TBD입니다.

## 범위

| 포함 | 제외·미정 |
| --- | --- |
| 교내 공모전·지원 프로그램 및 공식 공모전 공고 | 수동 입력·크롤링 등 수집·DB 적재 방식은 TBD |
| 공고 데이터 제공·변경 반영 | 관리자 화면의 범위, 등록·수정·확인·공개 주체와 권한 부여·회수 책임은 TBD |
| 공모전 목록·상세·공식 링크, 개인 참가 전용 공고의 준비 팀 연결 | 원문을 대신하는 공모전 접수·제출 기능은 정의되지 않음 |
| 참가 조건 정리와 최초 공개 전 필수 정보 확인 | 확인 방법·담당자, 별도 요약의 사용처·필요성·MVP 포함 여부와 AI 연동은 [TBD](#summary-scope) |
| 마감 상태 반영·신규 지원 제한과 마감 후 공개 상세 열람 | 마감 공고의 목록 배치·정렬·필터, 별도 삭제·비공개·보존 기간과 재개 세부 규칙은 미정 |

초기 시연은 소수의 신뢰할 수 있는 공고로 전체 흐름을 보여 줄 수 있습니다. 자동 수집이나 많은 공고 수를 완료 조건으로 삼지 않습니다. 실제·시연 공고와 계정·팀의 추천·지원·선발은 [시연 데이터 정책](sprint-1.md#demo-data-scope)에 따라 서로 허용하며, 시연 표시와 최초 공개 조건을 유지합니다.

[이슈 #34의 보류 판단](https://github.com/wejo-team/sku-dreamon/issues/34#issuecomment-6232606000)에 따라 원문의 운영자 직접 등록·관리와 자동 수집 초기 제외는 확정된 전제로 사용하지 않습니다. 크롤링 후 DB 적재도 검토 가능한 선택지이며, 채택 여부는 아직 정하지 않았습니다.

## 공고 데이터

| 구분 | 항목 |
| --- | --- |
| 필수 | 공모전명, 주최 기관, 참가 자격, 모집·마감 일정 |
| 필수 | 참가 방식(개인·팀), 팀 인원 조건, 공식 원문 URL |
| 확인 가능한 경우 추가 | 분야, 제출물, 시상 내용, 문의처, 마지막 확인일, 공고 상태 |

공식 URL은 공고별로 저장합니다. 불명확한 정보는 임의로 채우지 않습니다. 필수 정보의 미확인은 [최초 공개 조건](#publication-policy)에 따라 공개를 막고, 선택 정보의 미확인은 구분해 안내합니다. 추천에서 개별 사용자의 참가 자격을 확인할 수 없는 경우에는 별도로 [필수 조건](matching.md#eligibility)을 적용합니다.

원문 데이터 표의 ‘확인 가능한 경우 추가하는 공고 상태’와 서비스가 신규 지원을 제어하는 모집·마감 상태의 구체적인 구분·값은 미정입니다. 마감 공고의 신규 지원 금지 원칙은 유지합니다.

## 최초 공개 조건

[이슈 #35의 결정](https://github.com/wejo-team/sku-dreamon/issues/35#issuecomment-6232606316)에 따라 **필수 정보가 확인될 때까지 공고를 비공개로 둡니다.** 필수 항목은 위 공고 데이터 표를 따릅니다. 확인 방법·담당자·도구는 TBD이며, 이 조건만으로 관리자 화면이나 별도 사람 승인 단계를 요구하지 않습니다.

| 정보 상태 | 최초 공개 판정 |
| --- | --- |
| 모든 필수 정보가 확인됨 | 공개 가능. 공개 담당·실행 방식은 TBD |
| 필수 정보가 하나라도 미확인 | 비공개 유지. 사용자의 목록·상세 탐색과 추천 대상으로 제공하지 않음 |
| 조건부 항목이 원문상 적용되지 않음이 확인됨 | 해당 항목을 “해당 없음”으로 구분. 나머지 필수 정보도 확인되면 공개 가능 |
| 필수 정보는 확인됐으나 선택 정보가 미확인 | 공개 가능. 선택 정보는 미확인 또는 원문 확인 안내로 구분 |

예를 들어 마감일을 아직 확인하지 못한 공고는 비공개로 둡니다. 마감일을 포함한 필수 정보를 확인하면 공개할 수 있으며, 선택 항목인 시상 내용의 미확인은 공개를 막지 않습니다. 개인 참가 전용임이 확인된 공고의 팀 인원 조건은 “해당 없음”으로 기록할 수 있습니다. 아직 모르는 값을 임의로 “해당 없음”으로 처리하지 않습니다.

이 조건은 최초 공개를 대상으로 합니다. 공개 후 정보 변경 시 재확인 여부와 확인 중 기존 값 유지·비공개 여부는 [이슈 #50의 보류 판단](https://github.com/wejo-team/sku-dreamon/issues/50#issuecomment-6232606670)에 따라 TBD로 남깁니다.

## 운영 흐름

현재는 공고 데이터와 최초 공개 조건을 정의하며, 세부 운영 절차는 확정하지 않습니다.

1. 공고 정보와 공식 원문 URL을 준비합니다. 수동 입력·크롤링 등 수집·DB 적재 경로는 TBD입니다.
2. 참가 자격·일정·제출물 등 확인된 정보를 정리합니다. 별도 요약의 사용처·필요성과 MVP 포함 여부는 [요약 범위](#summary-scope)에서 먼저 결정하고, AI 연동 여부는 그 뒤에 정합니다.
3. [최초 공개 조건](#publication-policy)을 충족한 공고를 공개할 수 있습니다. 정보 확인과 공개를 수행할 방법·담당자·화면은 TBD입니다.
4. 공개 후 정보 갱신·재확인·노출 순서는 수집·갱신 방식을 정할 때 논의합니다. 현재 단계에서 관리자 승인이나 기존 공개본 유지 절차를 확정하지 않습니다.

### 공고 요약의 사용처와 MVP 범위

[이슈 #38의 보류 판단](https://github.com/wejo-team/sku-dreamon/issues/38#issuecomment-6235004516)에 따라 **별도 요약의 사용처·필요성과 MVP 포함 여부는 TBD**입니다. 기존 명세에는 긴 공고를 읽기 쉽게 정리하려는 목적은 있으나, 요약을 표시할 화면·내용·완료 조건은 정의되어 있지 않습니다. [주요 화면](sprint-1.md#screens)의 공모전 상세는 참가 자격·마감일·제출물·공식 링크를 제공하며, 별도 요약 영역을 확정하지 않습니다.

화면 기획 때 요약이 필요한지와 어디서 사용하는지를 먼저 정하고, 포함하기로 한 경우 내용·생성 방식·표시 기준을 구체화합니다. 실제 AI API 호출·수동 작성·사전 생성 중 어느 방식도 기본값으로 채택하지 않으며, AI 연동 여부는 사용처를 정한 뒤 결정합니다. 이번 보류는 요약의 MVP 제외 결정이 아닙니다.

필수 자격·마감 판단과 후보 순위·추천 근거의 기존 규칙 및 [최초 공개 조건](#publication-policy)은 유지합니다. 요약을 제공하더라도 원문 확인을 대신하지 않습니다. [이슈 #52](https://github.com/wejo-team/sku-dreamon/issues/52)는 실제 AI 사용을 선택했을 때만 실패 시 공개·대체 요약 정책을 논의하는 조건부 대기이며, 재시도 동작도 미정입니다. 실제 API 사용 여부는 [시연 기준](sprint-1.md#web-demo)에 따라 사실대로 안내하되, 표시 기준만으로 AI 연동을 필수화하지 않습니다.

## 사용자 탐색 흐름

1. 사용자는 [로그인 없이 공개 공고](authentication.md#access-policy)를 목록·상세에서 탐색할 수 있습니다. 개인화 추천의 노출·계산은 [추천 매칭](matching.md)을 따르며 비로그인 제공 여부는 별도입니다.
2. 공모전 상세에서 참가 자격, 마감일, 제출물 등 확인된 정보를 읽고 공식 링크로 원문을 확인합니다.
3. 선택한 공모전의 공개 팀 모집 정보를 탐색할 수 있습니다. 개인 참가 전용 공고에서는 아래 정책에 따라 함께 준비하는 팀임을 안내합니다. 팀 모집글 작성·지원은 로그인 후 이용하고 지원 직전 [누락된 필수 정보를 보완](profile.md#before-application)합니다.

추천 표시 정보·실행 시점·순위는 [추천 매칭](matching.md)에 둡니다. 공고에 개인 참가 방식이 있다는 사실이 서비스 내 개인 접수 기능을 포함한다는 뜻은 아닙니다.

## 참가 방식과 팀의 목적

[이슈 #37의 결정](https://github.com/wejo-team/sku-dreamon/issues/37#issuecomment-6233302698)에 따라 **개인 참가 전용 공고에서도 함께 준비하는 팀 생성·모집을 허용**합니다. 준비 팀에 속해 있다는 사실은 해당 공모전의 공동 출전 자격을 뜻하지 않습니다.

| 공고의 공식 참가 방식 | 상세 화면에서 제공할 행동 | 서비스에서 만드는 팀의 목적 |
| --- | --- | --- |
| 개인 전용 | 공식 원문 확인, 준비 팀 탐색·생성·지원 | 각자 개인으로 참가하는 사용자가 함께 준비하는 팀. 공동 출전 팀과 구분해 안내 |
| 팀 전용 | 공식 원문 확인, 팀 탐색·생성·지원 | 공식 팀 참가 조건을 따르는 공동 출전 팀 |
| 개인·팀 모두 허용 | 공식 원문 확인, 팀 탐색·생성·지원 | 팀을 만드는 경우 공식 팀 참가 조건을 따르는 공동 출전 팀. 개인 참가 가능 여부도 공고에 안내 |

공개 정보 탐색과 로그인 후 팀 생성·지원의 구분은 [접근 정책](authentication.md#access-policy)을 따릅니다. 개인 전용 공고 상세에서 팀으로 이동할 때, 팀 생성·모집 정보와 지원 흐름에서 준비 목적임을 확인할 수 있어야 합니다. 직접 URL 등 다른 경로로 진입해도 같은 구분을 적용하며, 준비 팀을 공식 공동 출전이 가능한 팀으로 안내하지 않습니다.

공동 출전 팀의 목표 총 정원은 [확인된 공식 팀 인원 범위](team-recruitment.md#official-capacity)를 따릅니다. 개인 전용 공고의 공식 참가 인원 1명이나 “팀 인원 조건 해당 없음”을 준비 팀의 정원 상한으로 해석하지 않습니다. 준비 팀 자체의 정원 제한 세부 기준은 [팀 명세의 TEAM-07](team-recruitment.md#open-questions)에서 정하며, 기존 [팀장 포함 정원·선발](team-recruitment.md#membership-capacity)과 [공모전별 소속 제한](team-recruitment.md#membership-limit)은 유지합니다.

준비 팀 생성·지원은 서비스 안의 팀 참여입니다. 주최 측에 개인 접수·출품을 대행하는 기능이나 공식 참가 방식의 변경을 포함하지 않습니다.

## 마감과 정보 변경

- 마감된 공고는 신규 지원이 불가능하도록 상태를 변경합니다. 모집 중이며 마감 전인 공고만 추천 후보가 됩니다.
- [이슈 #36의 마지막 답변](https://github.com/wejo-team/sku-dreamon/issues/36#issuecomment-6233303254)에 따라 날짜만 있는 마감일의 기본 시각·시간대와 정확한 지원·추천 경계는 **TBD**입니다. 앞서 검토한 한국시간 날짜 종료 기준은 채택하지 않습니다. 시각 확인 전 일괄 지원 금지나 운영자가 종료 시각을 정하는 방식도 확정하지 않으며, 공고 일정 처리 방식을 구체화할 때 함께 정합니다.
- 공고 변경·마감 반영의 담당·방법, 자동 처리 방식·실행 주기와 수동 수정의 관계는 TBD입니다. 변경된 정보의 재확인 대상·순서와 사용자에게 보여 줄 값은 #50의 후속 결정입니다.
- 자격 변경이 기존 지원·선발·팀에 미치는 영향은 아래 [보류 정책](#eligibility-changes)을 따릅니다. 일정 변경의 영향도 미정이며, 변경 전 정보를 근거로 이후 지원까지 허용한다고 가정하지 않습니다.
- 불명확한 자격은 ‘확인 필요’로 구분합니다. 실제 지원의 접수 정책·판정 기준은 [이슈 #33](https://github.com/wejo-team/sku-dreamon/issues/33#issuecomment-6233084109)에 따라 TBD이며, 원문 정보 보완 흐름은 관련 미정 사항에서 정합니다.

### 마감 후 상세 열람

[이슈 #39의 결정](https://github.com/wejo-team/sku-dreamon/issues/39#issuecomment-6234731790)에 따라 **이미 공개된 공고는 마감 후에도 로그인 없이 누구나 상세 정보와 공식 원문 링크를 확인**할 수 있습니다. 상세에 마감 상태를 명확히 표시하고, 직접 URL과 팀 공간의 공고 링크에서도 동일하게 열람할 수 있습니다.

| 상황 | 결과 |
| --- | --- |
| 비로그인 사용자가 마감 공고의 상세 URL로 접근 | 마감 표시와 함께 상세 정보·공식 원문 링크 열람 가능 |
| 현재 팀장·확정 팀원이 팀 공간에서 마감 공고 확인 | 상세 정보·공식 원문 링크 열람 가능 |
| 팀 공간 접근 권한이 없는 사용자가 해당 팀 공간에 접근 | 기존 [팀 공간 접근 정책](team-recruitment.md#team-workspace-access)에 따라 거부. 공개 공고 상세는 별도로 열람 가능 |
| 마감 공고의 상세를 본 뒤 신규 지원을 시도 | 접수 불가. 마감 공고는 신규 추천 후보에서도 제외 |

상세 열람 허용은 공고 접수의 재개나 팀 공간 권한 확대를 뜻하지 않습니다. 기존 지원자의 마감 후 추천·순위 열람은 #46의 TBD를 유지합니다. 일반 목록에서 마감 공고를 배치·정렬·필터하는 방식, 별도 삭제·비공개 사유와 보존 기간은 CONTEST-05에서 후속으로 정합니다.

<a id="eligibility-changes"></a>

### 자격 변경 후 기존 지원·팀원 처리

[이슈 #51의 보류 판단](https://github.com/wejo-team/sku-dreamon/issues/51#issuecomment-6234732341)에 따라 공고 참가 자격이 바뀐 뒤 **기존 지원자·확정 팀원의 재확인, 결과 표시, 선발·소속 처리는 TBD**입니다. #33의 실제 접수·자격 판정과 #50의 공고 갱신·재확인·노출 방식을 구체화할 때 함께 정합니다.

이번 보류는 변경 전 조건을 유지하거나, 현재 조건으로 자동 재확인하거나, 지원을 일괄 취소하거나, 확정 팀원을 자동 제외하는 결정이 아닙니다. 신규 추천에서 적용하는 자격 필터를 기존 지원·팀원 처리에 그대로 확대하지 않습니다.

<a id="acceptance-criteria"></a>

## 완료 조건

- [ ] AC-01: 공고의 필수 정보와 공식 URL을 저장·관리할 수 있다. 수집·적재·변경 경로와 권한은 CONTEST-01에서 정한 뒤 검증한다.
- [ ] AC-02: 공개한 공고의 목록과 상세에서 사용자가 참가 자격·일정·확인된 제출물·공식 링크를 확인할 수 있다.
- [ ] AC-03: AI 요약을 사용하는 경우에도 참가 자격·마감일을 포함한 필수 정보가 확인되기 전에는 공고를 최초 공개하지 않는다. 확인 방법·담당자는 CONTEST-03에서 정한 뒤 검증한다.
- [ ] AC-04: 확인되지 않은 정보가 임의의 확정값으로 표시되지 않는다. 공개된 공고의 선택 정보가 미확인이면 미확인 또는 원문 확인 안내로 구분하며, 공식적으로 확인된 “해당 없음”과 혼동하지 않는다.
- [ ] AC-05: 마감된 공고에 신규 지원할 수 없고 신규 추천 후보에서도 제외된다.
- [ ] AC-06: 사용자가 선택한 공모전에서 팀 탐색 또는 모집글 작성 흐름으로 이동할 수 있다. 개인 전용 공고는 준비 팀, 팀 전용·개인/팀 허용 공고는 공동 출전 팀으로 목적을 구분해 안내하며, 직접 URL 진입에도 같은 정책을 적용한다.
- [ ] AC-07: 시연의 실제 AI API 연동 여부를 사실대로 안내하며, 요약을 제공하는 경우 결정된 생성·표시 방식과 일치한다. 요약 화면·내용·제공 방식의 검증은 [요약 범위](#summary-scope) 결정 후 진행하며, 이 조건만으로 요약 제공이나 AI 연동을 필수화하지 않는다.
- [ ] AC-08: 필수 정보가 하나라도 미확인인 공고는 최초 공개되지 않고 사용자의 목록·상세 탐색 및 추천 대상에도 노출되지 않는다. 누락 정보를 보완해 필수 정보가 모두 확인되면 공개 가능한 상태가 된다.
- [ ] AC-09: 필수 정보가 확인된 공고는 선택 정보의 미확인만으로 공개가 차단되지 않는다. 개인 참가 전용 공고의 팀 인원 조건처럼 적용되지 않음이 확인된 조건부 항목은 “해당 없음”으로 판정하되, 단순 미확인을 같은 상태로 처리하지 않는다.
- [ ] AC-10: 개인 전용 공고에서도 준비 팀을 생성·모집하고 지원할 수 있다. 공고에서 팀으로 이동할 때와 팀 생성·모집 정보·지원 흐름에서 준비 목적임을 확인할 수 있고, 공동 출전이 허용된다는 의미로 표시하지 않는다. 공식 개인 참가 인원 1명 때문에 준비 팀 정원을 1명으로 제한하지 않으며, 준비 팀의 정원 제한 세부 검증은 [팀 명세의 TEAM-07](team-recruitment.md#open-questions) 결정 후 진행한다.
- [ ] AC-11: 이미 공개된 공고가 마감되어도 비로그인 사용자는 직접 URL로 마감 표시·상세 정보·공식 원문 링크를 확인할 수 있고, 현재 팀장·확정 팀원은 팀 공간의 공고 링크에서도 확인할 수 있다. 팀 공간 접근 권한은 확대되지 않으며, 상세 열람 이후에도 신규 지원은 접수되지 않고 신규 추천 후보에서 제외된다.

구현과 검증 전에는 체크하지 않습니다. 최초 공개 조건은 위 정책을 적용하고, 수집·적재·권한·확인 방법 등 미정 사항에 의존하는 검증은 해당 결정을 먼저 진행합니다.
