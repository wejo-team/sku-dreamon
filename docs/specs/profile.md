# 프로필과 공개 범위

- 구현 상태: 예정
- 명세 검토: [PR #14](https://github.com/wejo-team/wejo-app/pull/14), PDF 대조·명세 연결 보완 [PR #17](https://github.com/wejo-team/wejo-app/pull/17)
- 구현 작업: 미등록

기획 문서의 프로필 정책을 옮긴 초안입니다. 본문의 닉네임·파일 업로드 가능성은 정책 부록에서 구체화한 실명 입력·외부 URL 정책으로 정리했습니다.
학교 이메일 필수 요구는 [이슈 #20의 자체 로그인 결정](authentication.md#login-decision)에 따라 이번 범위에서 제외합니다.
선택지나 코드가 바뀔 때는 [공통 선택지](profile-options.md), 학사 계층이 바뀔 때는 [학사 분류](academic-structure.md)의 해당 절만 읽습니다.

## 목적과 사용자

교내 사용자가 참가 자격, 관심 분야, 희망 역할과 협업 가능 정보를 작성하고 수정할 수 있게 합니다. 다른 사용자와 지원 팀장은 자신의 관계와 동의 범위에 맞는 정보만 확인합니다.

## 범위

| 포함 | 제외 |
| --- | --- |
| 실명 입력, 필수·선택 프로필 작성과 수정 | 신분증 등을 통한 실명 진위 확인 |
| 관심 분야·경험·자기소개 공개 설정, 대상별 최소 공개와 프로필 단위 포트폴리오 공개·비공개 설정 | 모든 교내 사용자에게 전체 프로필 일괄 공개 |
| 외부 포트폴리오 URL과 선택 제목 | 포트폴리오 파일 업로드·AI 분석 |
| 계정 삭제 시 프로필·포트폴리오 처리 정책 | 삭제·비식별 처리 중 세부 방식의 임의 확정 |

추천 점수와 순위는 [추천 매칭](matching.md)에서 정의합니다. 전체 개발 범위와 본문·부록의 적용 기준은 [스프린트 1](sprint-1.md#source-priority)을 따릅니다.

## 사용자 흐름과 동작

1. 가입한 사용자가 프로필 설정 화면에서 필수 정보를 작성합니다.
2. 학사 정보·경험·역량·가능 시간·자기소개·포트폴리오를 필요한 만큼 보완합니다.
3. 관심 분야·경험·자기소개의 공개 범위를 설정합니다. 포트폴리오는 프로필에서 공개·비공개를 설정하고, 모든 지원 팀에 동일하게 적용된다는 안내를 확인합니다. 상세 정책은 [포트폴리오 공개 설정](#portfolio-visibility), 아직 정하지 않은 기본값 등은 아래 미정 사항을 따릅니다.
4. 저장한 프로필을 조회하고 수정할 수 있습니다.
5. 교내 사용자·지원 팀장·확정 팀원은 아래 공개 정책에 따라 정보를 확인합니다.

## 입력 항목

필수 여부와 입력 방식의 원본은 이 표입니다. 실제 선택지는 [프로필 선택지](profile-options.md#choices)와 [학사 선택 목록](academic-structure.md#catalog)에 둡니다.

| 이름 | 실명 입력 필수 | 사용자 화면과 팀 모집·지원 화면의 표시 이름 |
| 학적 상태 | 단일 선택·조건부 필수 | 공고에 명시된 참가 자격 확인 |
| 학년 | 단일 선택·조건부 필수 | 공고 또는 팀의 명시적 학년 조건 확인 |

| 세부전공 | 해당 학부에만 표시·조건부 단일 선택 | 학사 계층과 전공 미배정 상태는 [학사 입력 흐름](academic-structure.md#selection-flow) 참조 |
| 관심 분야 | 복수 선택·필수 | 공모전·팀 주제 적합도 판단 |

| 보유 역량 | 복수 선택·권장 | 팀 역할 관련 역량 평가 |
| 관련 경험 | 프로젝트·공모전 경험 선택 또는 기술·선택 입력 | 경험 분야 분류와 자유서술의 관계는 미정; 경험이 적다는 이유만으로 후보 제외하지 않음 |
| 활동 가능 시간 | 요일별 시간 구간 복수 선택·권장 | 매칭에 필요한 시간 겹침 계산; 상세 개인 일정 공개하지 않음 |
| 자기소개 | 선택 입력 | 지원 검토·팀원 탐색 참고 |
| 포트폴리오 | 외부 URL과 선택 제목·선택 입력 | [포트폴리오 정책](#portfolio) 적용 |

본문의 활동 가능 시간 필수 여부 표현인 ‘필수 권장’은 정책 부록의 ‘권장’을 적용합니다. 학적·학년의 조건부 필수 입력을 언제 요청할지는 미정입니다.

## 이름과 계정 식별

- 실명 입력을 필수로 하며 사용자 화면과 팀 모집·지원 화면에는 등록된 실명을 표시합니다.
- 별도의 닉네임을 기본 표시 이름으로 사용하지 않습니다.
- 동명이인을 허용합니다. 계정은 내부 고유 사용자 ID로 구분하며 이름을 계정 식별자로 사용하지 않습니다.
- 자체 로그인과 실명 입력을 교내 구성원·실명 진위 확인으로 취급하지 않습니다. 후속 학교 인증의 한계도 [교내 인증의 의미](authentication.md#verification-meaning)를 따릅니다.

## 공개 범위

아래 표는 원문에서 확인된 대상과 항목입니다. ‘미정’은 공개 허용을 뜻하지 않습니다. 원문의 공개 설정과 부록의 최소 정보 공개가 만나는 부분은 임의로 확대하지 않습니다.

스프린트 1에는 교내 인증 사용자가 없으므로 아래 ‘교내 인증 사용자’ 열을 자체 로그인 사용자 전체에게 자동 적용하지 않습니다. 로그인 사용자의 공개 범위는 [이슈 #22](https://github.com/wejo-team/wejo-app/issues/22), 접근 권한과의 관계는 [이슈 #40](https://github.com/wejo-team/wejo-app/issues/40)에서 정합니다. 관계별 열람이 허용되는 화면에 교내 인증 여부를 표시할 때는 ‘미인증’으로 표시합니다.

| 정보 | 교내 인증 사용자 | 지원한 팀의 팀장 | 확정 팀원 |
| --- | --- | --- | --- |
| 이름 | 실명 표시 | 실명 표시 | 사용자 화면의 실명 표시 원칙 적용 |
| 이메일 주소 | 공개하지 않음 | 공개하지 않음 | 공개하지 않음 |
| 교내 인증 여부 | 표시 | 표시 | 표시 |
| 관심 분야·희망 역할 | 팀 탐색에 필요한 최소 정보 | 지원 검토에 사용 | 협업에 필요한 범위의 구체 항목 미정 |
| 학적 상태·학년·전공 | 필요 시 제한 공개; 대상·조건 미정 | 필요 시 제한 공개; 대상·조건 미정 | 구체 항목 미정 |
| 역량·경험·자기소개 | 본문의 사용자 공개 설정과 적용 관계 미정 | 지원 검토에 필요한 정보 확인 | 협업에 필요한 범위의 구체 항목 미정 |
| 활동 가능 시간 | 구체 개인 일정 대신 매칭에 필요한 겹침 정보만 노출; 대상별 범위 미정 | 구체 개인 일정 대신 매칭에 필요한 겹침 정보만 노출 | 구체 개인 일정 대신 매칭에 필요한 겹침 정보만 노출 |
| 포트폴리오 | 전체 교내 사용자에 대한 공개 동작은 정의되지 않음 | [프로필의 포트폴리오 공개 설정](#portfolio-visibility)에 따라 모든 지원 팀에 동일하게 표시·비표시 | 상세 포트폴리오는 별도 동의 후 공유 |
| 연락처 | 공개 동작은 정의되지 않음 | 공개 동작은 정의되지 않음 | 별도 동의 후 공유 |

관심 분야·경험·자기소개에는 사용자가 공개 범위를 설정하는 기능을 제공합니다. 설정의 대상·기본값, 부록의 대상별 최소 공개와 충돌할 때의 적용 관계, 동의 철회 시 동작은 미정입니다. 연락처는 공유 정책만 있으며 수집 필드·방식은 정의되지 않았습니다.

## 외부 포트폴리오

| 항목 | 정책 |
| --- | --- |
| 입력 | Notion, GitHub, 개인 웹사이트 등의 외부 URL을 선택적으로 등록 |
| 저장 | URL과 선택 입력 제목만 저장; 본문의 설명 입력은 최종 저장 범위에 포함하지 않음 |
| 선택 등록 | 포트폴리오 없이도 공모전 탐색·팀 모집·지원·추천을 동일하게 이용 |
| 파일 업로드 | 스프린트 1에서 제외 |
| AI 분석 | 스프린트 1에서 제외; 포트폴리오 AI 분석 결과를 추천 점수에 사용하지 않음 |
| 공개 | [프로필 단위 공개·비공개 설정](#portfolio-visibility)에 따라 지원 팀장에게 표시; 확정 팀원 공유는 별도 동의 필요 |
| 링크 접근 | 사용자가 공유 권한·접근 가능 여부를 확인하도록 안내; 비공개·삭제된 외부 내용은 서비스가 보장하지 않음 |
| 수정·삭제 | 사용자가 등록 정보를 수정·삭제할 수 있음 |

파일 업로드는 형식·크기·저장소·접근 권한·악성 파일 관리 부담을 줄이고 핵심 흐름에 집중하기 위해 제외합니다. 포트폴리오 AI 분석은 문서 처리와 정확도·평가 기준 검증이 필요하므로 후속 고도화에서 검토하며, 도입을 확정한 것은 아닙니다.

외부 링크의 허용 형식·검증 방법·등록 개수는 원문에 없습니다.

### 포트폴리오 공개 설정

[이슈 #23](https://github.com/wejo-team/wejo-app/issues/23)의 공개 동의 적용 단위는 **프로필**로 정합니다. 프로필에서 포트폴리오 공개·비공개를 한 번 설정하고 모든 지원 팀에 동일하게 적용합니다.

- 지원 팀장에게 포트폴리오를 공개할지에 대한 동의는 프로필의 공개 설정에서 받습니다. 설정 화면에는 현재 및 이후 지원하는 모든 팀에 공통으로 적용됨을 안내합니다.
- `공개`에 동의하면 열람 권한이 있는 모든 지원 팀장에게 등록한 포트폴리오 URL과 선택 제목을 표시합니다. `비공개`이거나 공개 동의가 없으면 표시하지 않습니다.
- 지원 팀·지원 건·URL별로 공개 설정을 따로 두지 않습니다. A팀에만 공개하고 B팀에는 비공개로 두는 설정은 제공하지 않으며, 등록한 모든 포트폴리오 URL에 같은 설정을 적용합니다. URL 등록 개수는 PROFILE-05에서 별도로 정합니다.
- 지원 제출만으로 비공개 설정을 공개로 바꾸거나 팀별 공개 동의를 추가로 받지 않습니다. 포트폴리오를 비공개로 두어도 탐색·모집·지원·추천을 동일하게 이용합니다.
- 이 설정으로 일반 사용자의 포트폴리오 열람 권한을 부여하지 않습니다. 확정 팀원의 상세 포트폴리오 공유는 별도 동의가 필요하며, 지원 팀장 대상 공개 동의로 대체하지 않습니다.
- 설정 변경도 모든 지원 팀에 공통으로 적용합니다. 기존 지원에 반영되는 시점과 동의 철회 세부 동작, 지원 취소·미선발 후 열람 권한은 PROFILE-02에서 정합니다.

다음 사례는 지원한 팀의 팀장이 지원자 열람 권한을 가지며, 모든 지원 팀에 같은 프로필 설정이 적용된 상태를 기준으로 합니다. 일반 사용자는 해당 사용자의 지원 팀장·확정 팀원이 아닌 사람을 뜻합니다.

| 설정과 지원 관계 | A팀 팀장 | B팀 팀장 | 일반 사용자 | 확정 팀원 |
| --- | --- | --- | --- | --- |
| 비공개, A·B팀에 지원, 확정 팀원 공유 동의 없음 | 표시하지 않음 | 표시하지 않음 | 이 설정으로 공개하지 않음 | 표시하지 않음 |
| 공개 동의, A·B팀에 지원, 확정 팀원 공유 동의 없음 | URL·제목 표시 | URL·제목 표시 | 이 설정으로 공개하지 않음 | 표시하지 않음 |
| 공개 동의, A팀에만 지원, 확정 팀원 공유 동의 없음 | URL·제목 표시 | 표시하지 않음 | 이 설정으로 공개하지 않음 | 표시하지 않음 |
| 공개 동의, A·B팀에 지원, 확정 팀원 공유에 별도 동의 | URL·제목 표시 | URL·제목 표시 | 이 설정으로 공개하지 않음 | 별도 동의 범위에서 공유 |

## 수정·삭제와 미입력

- 사용자는 프로필을 수정할 수 있으며, 수정·삭제 방법과 공개 범위를 안내합니다.
- 계정 삭제 시 프로필과 포트폴리오 URL을 삭제하거나 비식별 처리하는 정책을 적용합니다. 두 방식 중 선택과 대상·시점은 미정입니다.
- 미입력·미확인과 명시적 값의 차이는 [공통 데이터 관리](profile-options.md#catalog-management)를 따릅니다.
- 본문은 정보 삭제를 안내하라고 요구하지만 개별 필드 삭제 시 필수값·기존 지원에 미치는 영향은 정의하지 않았습니다.

<a id="acceptance-criteria"></a>

## 완료 조건

- [ ] AC-01: 사용자가 필수 프로필을 작성하고 저장한 정보를 조회·수정할 수 있다.
- [ ] AC-02: 이름이 같은 두 사용자가 서로 다른 계정으로 유지되고, 사용자·모집·지원 화면에는 각 계정의 등록된 실명이 표시된다.
- [ ] AC-03: 이메일 주소가 다른 사용자에게 노출되지 않고, 관계별 열람이 허용되는 화면의 교내 인증 상태는 ‘미인증’으로 표시된다.
- [ ] AC-04: 지원 팀장은 검토에 필요한 역량·경험·자기소개를 확인하며, 구체적인 개인 일정 대신 매칭에 필요한 시간 겹침 정보만 확인한다.
- [ ] AC-05: 포트폴리오를 등록하지 않거나 비공개로 두어도 탐색·모집·지원·추천을 이용할 수 있고, 등록한 URL·제목은 프로필의 공개 설정에서 동의하지 않으면 지원 팀장에게 표시되지 않는다.
- [ ] AC-06: 사용자가 포트폴리오 URL·선택 제목을 수정·삭제할 수 있으며 파일 업로드·AI 분석 기능은 제공되지 않는다.
- [ ] AC-07: 확정 팀원에게 상세 포트폴리오·연락처를 공유하려면 별도 동의가 필요하다.
- [ ] AC-08: 사용자가 관심 분야·경험·자기소개의 공개 범위를 설정할 수 있으며, PROFILE-01에서 확정한 대상·기본값·최소 공개 적용 관계에 따라 실제 열람 범위가 달라진다.
- [ ] AC-09: 프로필에서 포트폴리오 공개·비공개를 설정하고 모든 지원 팀에 공통으로 적용된다는 안내를 확인할 수 있다. A·B팀에 지원한 사용자의 URL·제목은 [공개 설정 사례](#portfolio-visibility)에 따라 두 팀장에게 동일하게 표시·비표시된다.
- [ ] AC-10: 지원 팀·지원 건·URL별로 독립된 포트폴리오 공개 설정이 없고, 지원 제출만으로 공개 상태가 바뀌지 않는다. 공개 설정만으로 일반 사용자·미지원 팀장·별도 공유 동의가 없는 확정 팀원에게 URL·제목이 표시되지 않는다.

AC-08의 대상별 검증 사례는 PROFILE-01을 결정한 뒤 구체화합니다. 계정 삭제·조건부 필수 입력의 상세 완료 조건은 관련 미정 사항을 결정한 뒤 추가합니다.
