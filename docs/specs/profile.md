# 프로필과 공개 범위

- 구현 상태: 예정
- 명세 검토: [PR #14](https://github.com/wejo-team/sku-dreamon/pull/14), PDF 대조·명세 연결 보완 [PR #17](https://github.com/wejo-team/sku-dreamon/pull/17)
- 구현 작업: 미등록
- 변경 근거: 2026-10-19 [#77 최신 사용자 결정](https://github.com/wejo-team/sku-dreamon/issues/77#issuecomment-6260435650)의 입력 계약·신규 지원 공개 필수·기존 지원 최신 프로필 AI 검토 반영. 명세 반영과 디자인·서버 구현 완료는 구분

기획 문서의 프로필 정책을 옮긴 초안입니다. 본문의 닉네임·파일 업로드 가능성은 정책 부록에서 구체화한 실명 입력·외부 URL 정책으로 정리했습니다.
학교 이메일 필수 요구는 [이슈 #20의 자체 로그인 결정](authentication.md#login-decision)에 따라 이번 범위에서 제외합니다.
추천은 [LLM 기반 추천 정책](matching.md#policy-decisions)을 따르며 내부 아키텍처는 TBD입니다. 기존 고정 점수와 시간 기반 계산 규칙은 사용하지 않습니다.
선택지나 코드가 바뀔 때는 [공통 선택지](profile-options.md), 학사 계층이 바뀔 때는 [학사 분류](academic-structure.md)의 해당 절만 읽습니다.

## 목적과 사용자

교내 사용자가 참가 자격, 관심 분야, 희망 역할과 협업 가능 정보를 작성하고 수정할 수 있게 합니다. 다른 사용자는 공개 프로필을, 지원받은 팀장은 지원자의 공개 상태와 관계없이 등록된 전체 프로필을 확인합니다. 인증·계정 정보는 공개 프로필에 포함하지 않습니다.

## 범위

| 포함 | 제외 |
| --- | --- |
| 실명 입력, 필수·선택 프로필 작성과 수정 | 신분증 등을 통한 실명 진위 확인 |
| 제공된 파워프렌즈 캐릭터 중 프로필 이미지 선택 | 사용자 사진 파일 업로드 |
| 프로필 전체의 공개·비공개 설정, 전환 안내·확인, 지원 팀장 열람 예외 | 항목별·포트폴리오별 공개 설정, 비로그인 프로필 열람 |
| 외부 포트폴리오 URL과 선택 제목 | 포트폴리오 파일 업로드·AI 분석 |
| MVP 계정 탈퇴의 soft delete·데이터 보존 방향 | 실제 삭제·비식별·보존 기간·복구·탈퇴 후 표시와 접근 효력의 세부 정책은 TBD |

LLM 추천의 동작·근거·미정 내부 설계는 [추천 매칭](matching.md)에서 정의합니다. 전체 개발 범위와 본문·부록의 적용 기준은 [스프린트 1](sprint-1.md#source-priority)을 따릅니다.

## 사용자 흐름과 동작

1. 로그인한 사용자가 프로필 설정 화면에서 필수 정보를 작성합니다. 공개 공고·팀 모집 정보 탐색은 [비로그인 접근 정책](authentication.md#access-policy)을 따릅니다.
2. 학사 정보·경험·역량·주당 참여 가능 시간·자기소개·포트폴리오를 필요한 만큼 보완합니다.
3. 기본 비공개인 프로필 전체를 공개할지 설정합니다. 전환 안내 팝업에서 검색·항목 노출 범위와 지원 팀장 예외를 확인한 뒤 변경을 확정합니다. [사람 탐색과 공개 설정](#people-directory)과 [전환 절차](#visibility-changes)를 따릅니다.
4. 저장한 프로필을 조회하고 수정할 수 있습니다. 기존 지원의 검토·추천에도 [현재 프로필 기준](#application-profile)을 적용하며, MVP에서는 프로필 변경 사실을 별도로 알리지 않습니다.
5. 교내 사용자·지원 팀장·확정 팀원은 아래 공개 정책에 따라 정보를 확인합니다.
6. 신규 지원은 공개 프로필에서만 제출합니다. 비공개이면 설명 팝업으로 공개 전환을 확인하고 저장한 뒤 [제출 직전 필수 정보 점검](#before-application)과 현재 모집 조건을 확인합니다. 공개 전환·필수 정보 저장만으로 지원을 자동 접수하지 않습니다.

## 입력 항목

필수 여부와 입력 방식의 원본은 이 표입니다. 선택 가능한 값은 [프로필 선택지](profile-options.md#choices), 학사 소속의 새 선택과 저장된 과거값 유지는 [학사 선택 정책](academic-structure.md#selection-policy)을 따릅니다. 학사 이관 목록의 공식 검증 상태는 [학사 목록](academic-structure.md#catalog)에서 구분합니다.

| 항목 | 입력 방식·필수 여부 | 사용 목적·정책 |
| --- | --- | --- |
| 학교 이메일 | 스프린트 1 수집·인증 제외 | 가입·프로필 필수값으로 요구하지 않음. 주소·인증 완료 시각의 저장 필드만 설계하며 기능은 [후속 학교 인증](authentication.md#verification-meaning) 범위 |
| 이름 | 실명 1~50자·필수 | 사용자 화면과 팀 모집·지원 화면의 표시 이름 |
| 프로필 이미지 | 제공된 캐릭터 중 단일 선택·선택 입력 | 미선택 시 기본 스콘 사용. [프로필 이미지 선택](#profile-image) 적용 |
| 학적 상태 | 단일 선택·선택 입력 | 미입력이어도 지원 가능. 세부 참가 자격은 원문에서 확인하며 입력만으로 자격 검증을 보장하지 않음 |
| 학년 | 단일 선택·선택 입력 | 미입력이어도 지원 가능. 공고·팀의 조건 확인을 위한 참고 정보 |
| 단과대학 | 단일 선택·선택 입력 | 명시적 참가 자격·팀 조건 확인 |
| 학부·학과 | 단일 선택·선택 입력 | 단과대학에 속한 학부·학과 선택 |
| 세부전공 | 해당 학부에만 표시·단일 선택·선택 입력 | 학부·학과까지만 선택해도 해당 소속을 저장·표시. [학사 입력 흐름](academic-structure.md#selection-flow) 참조 |
| 관심 분야 | 1~3개 선택·필수 | 공모전·팀 주제 적합도 판단 |
| 희망 역할 | 1~2개 선택·필수 | [기타를 제외한 6개 역할](profile-options.md#role-policy) 중 선택. 모집 역할과의 적합도 판단; 불일치만으로 추천 후보를 제외하지 않음 |
| 보유 역량 | 선택 입력·목록 안에서 별도 개수 상한 없음 | 팀 역할 관련 참고 정보 |
| 관련 경험 | 3상태·분야 선택 없는 자유서술·본문 최대 500자·선택 입력 | [경험 등록 상태](#experience)를 구분하며 경험이 적다는 이유만으로 후보를 제외하지 않음 |
| 주당 참여 가능 시간 | 네 구간 중 단일 선택·권장 입력·필수 아님 | 참여 중인 모든 프로젝트를 합산한 자기신고 예상 총량으로 팀장의 지원자 검토에 참고. [5시간 미만 / 5~10시간 미만 / 10~20시간 미만 / 20시간 이상](profile-options.md#weekly-availability) 중 선택하며 미입력은 낮은 구간으로 간주하지 않음. 전체 프로필 공개 범위 유지 |
| 자기소개 | 최대 300자·선택 입력 | 지원 검토·팀원 탐색 참고 |
| 포트폴리오 | 외부 URL 1개와 최대 50자 선택 제목·선택 입력 | [포트폴리오 정책](#portfolio) 적용 |

원문의 활동 가능 시간 필수 여부 표현인 ‘필수 권장’에는 정책 부록의 ‘권장’을 적용했으며, 2026-10-19 주당 참여 가능 시간으로 바꾼 뒤에도 권장 입력을 유지합니다. 지원 시 필수 입력 점검·보완은 아래 제출 직전 정책을 따르며, 이 결정으로 주당 총량을 필수로 만들지 않습니다.

<a id="input-validation"></a>

### 입력 검증과 저장

- 프로필의 텍스트는 앞뒤 공백을 제거한 뒤 남은 공백·줄바꿈을 포함해 글자 수를 계산합니다. 이름은 1~50자, 자기소개는 최대 300자, 경험 본문은 최대 500자, 포트폴리오 제목은 최대 50자입니다. Unicode 계수의 구체 구현 계약은 PROFILE-07에 남기며 화면과 서버에서 같은 기준을 사용해야 합니다.
- 길이·개수를 초과한 입력은 유지하고 수정할 항목을 안내합니다. 조용히 잘라 저장하거나 초과 선택을 몰래 버리지 않습니다. 필수값이 비거나 제약을 충족하지 못하면 저장하지 않습니다.
- 관심 분야 1~3개·희망 역할 1~2개를 선택합니다. 보유 역량은 선택 입력이며 목록 안에서 별도 개수 상한을 두지 않습니다. 기타 선택지·보충 설명은 [공통 목록](profile-options.md#choices)에서 제거합니다.
- 학적 상태·학년은 비워도 저장·지원할 수 있습니다. 입력한 학사 소속의 상위값을 바꾸면 [유효하지 않은 하위 선택만 초기화](academic-structure.md#dependent-selection)합니다.
- 편집은 초안이며 저장에 성공해야 현재 프로필에 반영합니다. 편집 취소는 기존 저장값으로 돌아갑니다. 오류가 나면 입력을 보존하고 수정할 수 있게 안내합니다.

<a id="experience"></a>

### 경험 등록 상태

| 상태 | 저장·표시 규칙 |
| --- | --- |
| 미입력 | 경험이 있는지 없는지 추정하지 않음. 본문을 비워 저장하면 이 상태 |
| 관련 경험 없음 | 사용자가 직접 선택. 이 상태로 저장하면 이전 경험 본문을 제거 |
| 경험 작성 | 분야 선택 없이 최대 500자 자유서술. 공백 제거 후 본문이 비면 미입력으로 저장 |

경험 상태 변경도 편집 초안에 적용하며 취소하면 기존 저장 상태·본문을 유지합니다. 경험이 적거나 없다는 이유만으로 추천 후보에서 제외하지 않습니다.

<a id="profile-image"></a>

### 프로필 이미지 선택

- 프로필 수정에서 파워프렌즈 **스콘·아티·디모·비아트·컨버** 중 하나를 선택합니다. 선택은 필수가 아니며 별도 선택값이 없으면 스콘을 표시합니다. 사용자 사진 업로드나 외부 이미지 URL 입력은 현재 범위에 포함하지 않습니다.
- `프로필 이미지 변경` 팝업에는 `마음에 드는 파워프렌즈를 골라보세요.` 설명과 캐릭터 선택·미리보기를 제공합니다. 선택을 적용하면 편집 중인 프로필에 반영되고, 최종 프로필 저장을 해야 현재 값이 바뀝니다.
- 팝업을 취소·닫으면 팝업에서 선택한 초안을 버립니다. 팝업에서 적용했더라도 프로필 편집을 취소하면 기존 저장 이미지를 유지합니다.
- 저장한 이미지는 본인 프로필과 열람이 허용된 공개 프로필·팀 화면에서 같은 사용자 이미지로 표시합니다. 캐릭터 선택이 이름·교내 인증·공개 상태·팀 소속을 변경하지 않습니다.

<a id="before-application"></a>

### 지원 직전 필수 정보 점검

[이슈 #54의 결정](https://github.com/wejo-team/sku-dreamon/issues/54#issuecomment-6233083862)에 따라 **모든 지원의 제출 직전** 필수 프로필을 점검합니다. [#77 최신 결정](https://github.com/wejo-team/sku-dreamon/issues/77#issuecomment-6260435650)에 따라 학적 상태·학년은 선택 입력이며, 공고에 학사 조건이 있다는 이유로 필수 보완 항목으로 바꾸지 않습니다.

- 신규 지원은 [공개 상태 전환](#visibility-priority)에 성공한 공개 프로필에서만 제출합니다. 비공개 상태로 시작했다면 확인 팝업을 거치며 지원 버튼만으로 공개하거나 접수하지 않습니다.
- 이름·관심 분야·희망 역할 등 적용되는 필수값이 누락되거나 입력 제약을 충족하지 못하면 보완을 요청합니다. 이미 입력된 유효값은 다시 받지 않습니다.
- 보완을 취소하거나 필수값 오류가 남으면 접수하지 않습니다. 보완·공개 저장 후에도 원래 지원 흐름에서 현재 마감·정원·중복 지원·공모전별 소속 등 조건을 다시 확인합니다. 취소 후 재지원도 신규 지원으로 같은 규칙을 적용합니다.
- 사용자 자격 정보가 부족하면 **공고 원문에서 직접 확인하도록 안내한 뒤 일반 팀 지원으로 접수**합니다. 별도 자격 확인 대기 상태를 만들지 않습니다. 이는 #33의 이전 보류를 대체하며 접수 성공·필수 프로필 완성을 공식 참가 자격 충족으로 표시하지 않습니다.
- 2026-10-19 추가 사용자 결정에 따라 참가 자격은 [비즈니스 로직의 지원·선발 제한으로 사용하지 않습니다](team-recruitment.md#recruitment-conditions). 정보 부족 여부와 관계없이 원문 확인을 안내하며 학적·학년·전공·팀별 추가 자격 제한을 두지 않습니다. 공고의 등록 전 확인과 공개·필수값·마감·정원·중복·소속 조건은 그대로 유지합니다.

| 상황 | 제출 직전 동작 |
| --- | --- |
| 프로필이 비공개 | 공개 전환의 일반 검색·전체 항목 노출 범위를 설명하고 확인·저장 요청. 취소·실패 시 접수하지 않음 |
| 필수 이름·관심 분야·희망 역할이 누락되거나 제약 위반 | 항목 보완 요청, 보완 전 접수하지 않음 |
| 학적·학년 미입력 | 선택 입력이므로 이 누락만으로 지원을 막거나 필수 보완을 요구하지 않음 |
| 자격을 확인할 사용자 정보가 부족 | 원문 확인 안내 후 일반 지원으로 접수하되 공개·마감·정원 등 나머지 조건 적용 |
| 공개·필수 입력·나머지 지원 조건 충족 | 별도 자격 확인 대기 없이 일반 지원 접수, 자격 충족 보장은 아님 |

팀 생성·개인화 추천에서 요구할 프로필 완성 범위는 이 지원 정책으로 확대하지 않습니다.

## 이름과 계정 식별

- 실명 입력을 필수로 하며 사용자 화면과 팀 모집·지원 화면에는 등록된 실명을 표시합니다.
- 별도의 닉네임을 기본 표시 이름으로 사용하지 않습니다.
- 동명이인을 허용합니다. 계정은 내부 고유 사용자 ID로 구분하며 이름을 계정 식별자로 사용하지 않습니다.
- 자체 로그인과 실명 입력을 교내 구성원·실명 진위 확인으로 취급하지 않습니다. 후속 학교 인증의 한계도 [교내 인증의 의미](authentication.md#verification-meaning)를 따릅니다.

## 공개 범위

2026-10-19 [최신 사용자 결정](https://github.com/wejo-team/sku-dreamon/issues/77#issuecomment-6260435650)에 따라 **하나의 공개·비공개 상태를 프로필 전체에 적용**합니다. 공개 상태는 로그인한 사용자의 일반 검색·AI 사람 탐색에서 발견되고 등록된 모든 프로필 항목이 보이며, 비공개 상태는 모든 일반 검색·AI 사람 탐색과 일반 상세 주소에서 제공하지 않습니다. **지원한 팀의 팀장은 공개 상태와 관계없이 지원자의 전체 현재 프로필을 확인**할 수 있습니다.

‘전체 프로필’은 이름·프로필 이미지·교내 인증 상태, 학적·학년·단과대학·학부·학과·세부전공, 관심 분야·희망 역할·역량·경험·자기소개·주당 참여 가능 시간, 등록한 포트폴리오 URL·제목을 뜻합니다. 미입력 값은 만들어 내지 않습니다. 로그인 아이디·비밀번호·세션 등 인증 정보나 스프린트 1에서 수집하지 않는 학교 이메일·연락처를 새로 공개·수집하는 정책이 아닙니다. 지원 메시지는 프로필 항목이 아니며 [본인·지원 팀장만 열람](team-recruitment.md#application-message)합니다.

스프린트 1에는 교내 인증 사용자가 없습니다. 관계별 열람이 허용되는 화면에는 교내 인증 여부를 ‘미인증’으로 표시합니다. 비로그인은 공개 상태인 사람도 목록·상세에서 볼 수 없습니다.

| 열람자·경로 | 공개 프로필 | 비공개 프로필 |
| --- | --- | --- |
| 본인 | 전체 현재 프로필 조회·수정 | 전체 현재 프로필 조회·수정 |
| 로그인한 일반 사용자·미지원 팀장 | 일반 검색·AI 사람 탐색의 후보가 되며, 상세에서 등록된 모든 항목 열람 | 모든 일반 검색·AI 사람 탐색에서 제외, 일반 상세 직접 주소도 제공하지 않음 |
| 지원한 팀의 팀장 | 지원자 조회에서 전체 현재 프로필 열람·해당 지원의 AI 검토 | 기존 지원의 전체 현재 프로필 직접 열람·최신 프로필 기반 AI 검토 유지. 일반 사람 검색·AI 사람 추천에는 포함하지 않음 |
| 같은 팀의 일반 확정 팀원 | 일반 로그인 사용자와 같은 공개 프로필 열람 | 팀원 관계만으로 전체 프로필을 열람할 수 없음 |
| 비로그인 사용자 | 사람 목록·상세 접근 불가 | 사람 목록·상세 접근 불가 |

팀장과 현재 확정 팀원의 [팀 공간 접근 권한](team-recruitment.md#team-workspace-access)은 별도로 판단합니다. 팀 공간의 실명·역할 등 소속 표시와 전체 프로필 상세의 접근 권한을 구분하고, 일반 팀원에게 지원 팀장 예외를 적용하지 않습니다. 팀에서 이탈한 사용자의 팀 공간 접근 종료와 [지원 취소 후 팀장의 프로필 열람](#former-applicant-visibility)도 구분합니다.

주당 참여 가능 시간은 [모든 프로젝트 합산의 자기신고 예상 총량](profile-options.md#weekly-availability)이며 요일별 일정이 아닙니다. 외부 개인 캘린더를 추가 수집하지 않습니다. 기존 지원을 받은 팀장의 AI 검토는 비공개 전환 후에도 최신 프로필을 반영할 수 있습니다. 이 권한은 해당 지원 관계에 한정되며 일반 AI 사람 추천·일반 대화의 비공개 프로필 자동 열람이나 모든 항목의 무조건 전송으로 확대하지 않습니다. 실제 AI 입력 필드·모델·보존·삭제 방식은 [MATCH-10](matching.md#open-questions)의 후속 설계 범위입니다.

### 사람 탐색과 공개 설정

- **프로필 공개** 스위치는 기본 꺼짐입니다. 항목별 또는 포트폴리오별 공개 스위치를 두지 않습니다.
- 공개하면 로그인한 사용자의 사람 목록·일반 검색·AI 사람 탐색 모두에서 검색 조건에 맞는 후보가 되며, 상세에 등록된 모든 프로필 항목을 표시합니다. 공개는 모든 검색어에 반드시 결과로 표시한다는 뜻이 아닙니다.
- 비공개로 전환하면 일반 사용자·미지원 팀장에게 목록·검색·AI 사람 탐색 결과·직접 상세 주소로 프로필을 제공하지 않습니다. 공개 여부만으로 기존 지원·팀 소속을 바꾸지 않으며, 비공개 상태에서도 팀 탐색과 로그인 후 일반 AI 기능을 이용할 수 있으나 신규 지원 제출은 공개 전환 후 가능합니다.
- 지원한 팀장은 공개·비공개와 관계없이 기존 지원의 전체 현재 프로필을 확인하고 해당 지원의 AI 검토에 최신 프로필을 반영할 수 있습니다. 이 예외를 일반 사람 검색·AI 사람 추천에 비공개 후보를 포함하거나 다른 팀원에게 정보를 공유하는 근거로 사용하지 않습니다.
- 공개된 모습 미리보기는 일반 로그인 사용자에게 보이는 현재 공개 상태와 항목 범위를 확인하는 기능이며, 비공개 프로필을 실제로 일반 공개하거나 설정을 저장하지 않습니다.

사람 탐색의 제목은 `함께할 사람`으로 표시합니다. 목록은 [탐색 공통 페이지 이동 정책](sprint-1.md#exploration-pagination)에 따라 페이지 번호로 조회하며, 현재 검색·필터와 공개 정책에 맞는 전체 검색 결과 수·총페이지를 표시합니다. 서비스 전체 회원 수나 지원 팀장 예외로만 열람하는 비공개 사용자를 일반 탐색 결과 수에 포함하지 않습니다. 검색·필터·탭 변경 시 1페이지로 이동하고 사람 상세에서 복귀할 때는 조건과 페이지를 유지합니다. 비로그인 사용자에게는 목록뿐 아니라 사람 검색 결과 수도 제공하지 않습니다.

### 프로필 단위 공개와 지원 팀장 예외

이 앵커는 과거 문서·PR 링크의 호환을 위해 유지합니다. [이슈 #22](https://github.com/wejo-team/sku-dreamon/issues/22)의 ‘항목별 비공개가 지원 팀장 열람보다 우선’ 결정은 2026-10-19 사용자 요청으로 대체합니다. 관심 분야·경험·자기소개·포트폴리오를 각각 숨기는 설정은 제공하지 않습니다.

**신규 지원은 프로필 공개 상태에서만 제출**합니다. 비공개이면 기존 공개 전환 팝업으로 일반 검색·AI 사람 추천의 후보가 되고 전체 항목이 공개됨을 설명합니다. 사용자가 확인해 공개 저장에 성공한 뒤 필수 입력·현재 모집 조건을 다시 확인하며, 지원 버튼만으로 공개하거나 자동 접수하지 않습니다. 지원 후 비공개로 전환해도 기존 지원·팀 소속과 해당 팀장의 직접 열람·최신 프로필 기반 AI 검토는 유지합니다.

이 예외는 해당 지원을 받은 팀장의 검토 권한입니다. 일반 팀원·미지원 팀장·비로그인 사용자나 일반 AI 사람 추천으로 확대하지 않습니다. 별도 공개 동의나 지원 심사 상태를 추가하지 않으며, 구체 AI 입력 필드·제공자·보존 방식은 후속 설계로 구분합니다. 인증 정보나 외부 포트폴리오 내용을 수집·분석하도록 허용한 것이 아닙니다.

### 공개·비공개 전환과 적용 시점

공개와 비공개 어느 방향으로 바꾸든 **설명 팝업에서 변경 후 범위와 기존 지원의 직접 열람·AI 검토 유지 예외를 확인**한 뒤 확정합니다.

| 전환 | 팝업에서 안내할 내용 |
| --- | --- |
| 비공개 → 공개 | 로그인한 사용자의 일반 검색·AI 사람 탐색에 나타나며, 등록한 모든 프로필 항목과 주당 참여 가능 시간·포트폴리오가 보임 |
| 공개 → 비공개 | 일반 검색·AI 사람 추천·일반 상세에서 숨김. 기존 지원·팀 소속, 지원받은 팀장의 전체 현재 프로필 직접 열람·최신 프로필 기반 AI 검토는 유지. 신규 지원은 다시 공개한 뒤 가능 |

- 팝업은 확인과 취소를 제공합니다. 취소·닫기·Escape로 빠져나오면 기존 공개 상태를 유지합니다. 팝업을 열거나 스위치를 누른 것만으로 공개 범위를 바꾸지 않습니다.
- 확인 후 저장에 성공해야 새 상태를 적용합니다. 실패하면 기존 상태를 유지하고 재시도할 수 있게 안내합니다.
- 저장 성공 즉시 바뀐 설정을 열람 기준으로 사용합니다. 이후 일반 목록·검색·AI 사람 추천·일반 상세 조회에 이전 공개 상태를 적용하지 않으며, 지원서·요약·직접 링크·과거 공개 정보·대화·캐시를 일반 추천의 우회 노출 경로로 사용하지 않습니다. 구현 방식은 후속 설계에서 정합니다.
- 다시 공개하면 현재 등록된 항목이 공개되며, 삭제한 이전 값을 복원하지 않습니다. 지원 팀장의 전체 현재 프로필 열람은 어느 방향의 전환에서도 유지합니다.
- 설정 변경 자체로 지원 취소·미선발·팀원 이탈을 처리하지 않습니다. 지원받은 팀장의 AI 검토는 최신 프로필을 반영하되 과거 AI 답변의 실시간 자동 재작성이나 과거 모델 입력의 즉시 삭제·되돌리기를 의미하지 않습니다. 일반 프로필 변경 알림·실시간 화면 갱신 제외 정책과 공개 권한의 적용 시점을 구분합니다.

[이슈 #41](https://github.com/wejo-team/sku-dreamon/issues/41#issuecomment-6232924566)의 저장 성공 즉시 적용·지원 상태와 분리 원칙은 유지합니다. 항목별 동의 철회가 지원 팀장의 열람도 차단하던 부분은 이번 프로필 단위 정책과 팀장 예외로 대체합니다.

<a id="former-applicant-visibility"></a>

### 취소·미선발·폐기 후 팀장의 프로필 열람

[이슈 #55](https://github.com/wejo-team/sku-dreamon/issues/55#issuecomment-6232925011)의 **지원 취소·미선발만으로 팀장의 열람 관계를 종료하지 않는 원칙**을 유지합니다. 선발·확정 후 지원을 취소해 팀에서 이탈한 경우에도 같습니다. 같은 공모전의 다른 팀 선발 또는 본인 팀 생성으로 기존 대기 지원이 [폐기](team-recruitment.md#parallel-applications)된 경우에도 지원받은 팀장의 최신 프로필 직접 열람·기존 지원서 AI 검토 관계를 유지합니다. 열람 범위는 이번 정책에 따라 공개 상태와 관계없이 **전체 현재 프로필**로 변경합니다.

| 지원 관계 | 팀장의 상세 프로필 열람 |
| --- | --- |
| 선발 전 지원 취소 | 열람 관계 유지; 전체 현재 프로필 표시 |
| 미선발 | 열람 관계 유지; 전체 현재 프로필 표시 |
| 다른 팀 선발·본인 팀 생성에 따른 지원 폐기 | 열람 관계 유지; 전체 현재 프로필 표시. 새 선발 후보에서는 제외 |
| 선발·확정 후 지원 취소 | 열람 관계 유지; 전체 현재 프로필 표시 |
| 위 상태에서 프로필을 비공개로 전환 | 일반 검색·상세는 숨김; 지원 팀장 열람은 유지 |

이 정책으로 일반 사용자·미지원 팀장·다른 팀원의 권한을 확대하지 않습니다. 취소한 사용자의 [팀 공간 접근 종료](team-recruitment.md#team-workspace-access)를 유지하며, 팀장의 프로필 열람을 지원자 추천 대상 포함으로 해석하지 않습니다. 팀장 변경·위임 기능은 제공하지 않습니다. 지원 이력의 저장·보관 기간과 계정 삭제 시 처리 방식은 기존 미정 사항을 따릅니다.

## 외부 포트폴리오

| 항목 | 정책 |
| --- | --- |
| 입력 | Notion, GitHub, 개인 웹사이트 등의 HTTP(S) 외부 URL 1개를 선택적으로 등록. 최대 50자 선택 제목 입력 가능 |
| 저장 | URL과 선택 입력 제목만 저장; 본문의 설명 입력은 최종 저장 범위에 포함하지 않음 |
| 선택 등록 | 포트폴리오 없이도 공모전 탐색·팀 모집·지원·추천을 동일하게 이용 |
| 파일 업로드 | 스프린트 1에서 제외 |
| AI 분석 | 스프린트 1에서 제외. URL 등록·프로필 공개를 외부 내용 수집·LLM 분석 동의로 취급하지 않음 |
| 공개 | [전체 프로필 공개 정책](#portfolio-visibility)에 포함. 공개 프로필이면 일반 로그인 사용자, 비공개여도 지원 팀장에게 등록된 URL·제목 표시 |
| 링크 접근 | 사용자가 공유 권한·접근 가능 여부를 확인하도록 안내; 비공개·삭제된 외부 내용은 서비스가 보장하지 않음 |
| 수정·삭제 | 사용자가 등록 정보를 수정·삭제할 수 있음 |

파일 업로드는 형식·크기·저장소·접근 권한·악성 파일 관리 부담을 줄이고 핵심 흐름에 집중하기 위해 제외합니다. 포트폴리오 AI 분석은 문서 처리와 정확도·평가 기준 검증이 필요하므로 후속 고도화에서 검토하며, 도입을 확정한 것은 아닙니다.

URL은 앞뒤 공백을 제거하고 `http:` 또는 `https:`의 유효한 주소만 등록합니다. 잘못된 주소는 오류를 표시하고 외부 링크로 제공하지 않습니다. URL을 삭제하면 이후 조회에서 링크·제목을 제공하지 않습니다. 유효한 URL을 새로 저장하면 현재 프로필 공개 상태와 지원 관계에 따라 표시하며, URL 입력·수정·삭제로 프로필의 공개 상태를 바꾸지 않습니다. 외부 사이트의 내용·접근 권한까지 검증된 것으로 표시하지 않습니다.

### 포트폴리오와 전체 프로필 공개

이 앵커는 과거 문서·PR 링크의 호환을 위해 유지합니다. [이슈 #23](https://github.com/wejo-team/sku-dreamon/issues/23)의 별도 포트폴리오 공개 동의는 2026-10-19 사용자 요청으로 대체합니다. 포트폴리오 URL·선택 제목은 다른 등록 항목과 함께 [전체 프로필 공개 상태와 지원 관계](#visibility)를 따릅니다.

- 별도 포트폴리오 스위치, 팀별·지원 건별·URL별 동의는 제공하지 않습니다.
- 공개 프로필의 유효한 URL·제목은 일반 로그인 사용자에게 표시합니다. 비공개 프로필은 일반 사용자에게 표시하지 않지만 지원 팀장은 현재 URL·제목을 확인할 수 있습니다.
- 일반 확정 팀원은 프로필이 공개일 때 같은 일반 로그인 사용자 권한으로 확인하며, 비공개 프로필의 링크를 팀원 관계만으로 열람하지 않습니다.
- 포트폴리오 미등록을 탐색·모집·지원·추천 제한 사유로 사용하지 않습니다. 등록 링크 표시와 외부 웹사이트 접근 권한은 별개이며, 프로필 공개가 외부 내용 수집·LLM 분석 동의는 아닙니다.

## 수정·삭제와 미입력

- 사용자는 프로필을 수정할 수 있으며, 수정·삭제 방법과 공개 범위를 안내합니다.
- MVP의 계정 탈퇴는 아래 [soft delete와 데이터 보존 방향](#account-withdrawal)을 적용합니다. 실제 삭제·비식별·보존 기간·복구와 탈퇴 처리 세부는 후속으로 정합니다.
- 미입력·미확인과 명시적 값의 차이는 [공통 데이터 관리](profile-options.md#catalog-management)를 따릅니다.
- 필수값을 비우거나 [입력 계약](#input-validation)을 위반하면 저장하지 않습니다. 학적·학년은 선택 입력이며 비워도 지원을 막지 않습니다. 경험·포트폴리오의 지우기 처리는 담당 절, 학사 종속값 처리는 [학사 명세](academic-structure.md#dependent-selection)를 따릅니다. 저장된 변경은 아래 현재 프로필 기준으로 기존 지원 조회에 반영합니다. 나머지 미정 입력 계약은 PROFILE-07에서 정합니다.

### MVP 계정 탈퇴와 데이터 보존

[이슈 #25의 사용자 판단](https://github.com/wejo-team/sku-dreamon/issues/25#issuecomment-6234890281)에 따라 MVP에서는 **soft delete로 탈퇴 상태를 관리하고 계정·프로필·포트폴리오 데이터를 즉시 물리 삭제하지 않는 방향**을 적용합니다. 복구 가능성을 고려하며, 기존 원문의 즉시 삭제 또는 비식별 처리를 이번 단계의 확정 동작으로 사용하지 않습니다.

데이터를 보존한다는 사실은 복구 기능 제공·재가입 시 자동 복구·무기한 보존을 확정한 것이 아닙니다. 실제 삭제·비식별 대상과 시점, 보존 기간, 복구 가능 조건·기간·절차는 PROFILE-04에서 후속으로 정합니다.

탈퇴 후 보관 중인 데이터를 어떻게 표시·접근 제한할지도 별도 정책입니다. 탈퇴 처리의 완료 시점, 로그인·세션·프로필 접근 효력, 기존 팀·지원 화면의 표시 방식은 아직 정하지 않았습니다. 보존 방향만으로 기존 프로필 공개를 계속 허용하거나 즉시 비표시·‘탈퇴 사용자’ 치환을 확정하지 않습니다. 이러한 효력을 정하기 전에는 데이터 보관만으로 탈퇴 기능 전체의 완료를 판단하지 않습니다.

팀장 변경·위임 기능은 제공하지 않습니다. 탈퇴 시 팀원 소속·정원 반환·지원 상태 전환과 전체 활동 이력의 보존은 기존 미정 사항으로 유지합니다. 계정 탈퇴를 [지원 취소](team-recruitment.md#application-cancellation)와 같은 처리로 간주하지 않습니다. 저장 구조와 구체적인 상태값은 개발 계획에서 정합니다.

### 기존 지원의 검토·추천 기준

[이슈 #24](https://github.com/wejo-team/sku-dreamon/issues/24)는 **현재 저장된 프로필**을 기준으로 정합니다. 지원 검토 화면과 지원자 추천의 기준 시점을 현재 프로필로 맞추되, 실제 추천 입력은 허용된 데이터 범위만 사용합니다. MVP에서는 변경 사실을 별도로 알리지 않습니다.

- 지원 당시 프로필 사본을 검토·추천의 기준으로 고정하지 않습니다. 사용자가 프로필 변경을 저장하면 기존 지원에도 반영하며, 지원자가 별도로 지원 갱신을 요청할 필요가 없습니다. 비공개 전환 후에도 해당 지원을 받은 팀장의 AI 검토는 다음 요청에서 최신 프로필을 사용합니다.
- 주당 참여 가능 시간은 여러 팀에 지원해도 같은 프로필 값을 사용합니다. 저장 후 다음 지원 검토 조회에는 현재 총량을 표시하지만, 팀별로 이미 정한 일정·약속을 자동 변경하지 않습니다. 팀 공간의 세부 일정 기능은 후속 구상으로 아직 미구현이며 구체 명세는 TBD입니다.
- 저장 후 다음 조회·갱신에서 검토 정보와 추천 근거를 같은 현재 프로필 기준으로 맞춥니다. 현재 프로필에 이전 프로필의 근거를 섞어 표시하지 않습니다. LLM 추천의 실행·갱신은 [추천 이용 흐름](matching.md#recommendation-types)을 따르며, 고정 점수나 특정 필드 변경에 따른 결과 불변을 보장하지 않습니다.
- MVP에서는 프로필 변경 알림, 변경 배지, 변경 전후 비교 안내를 제공하지 않습니다. 일반 프로필 값 변경에 대해 이미 열어 둔 팀장 화면의 실시간 자동 갱신도 요구하지 않으며, 다시 조회하거나 새로고침하면 현재 기준으로 확인합니다. 공개 설정의 효력은 [저장 성공 즉시](#visibility-changes) 적용합니다.
- 현재 프로필을 사용해도 [공개 범위](#visibility)에서 열람이 허용된 정보만 표시합니다. 삭제된 포트폴리오 URL·제목을 지원 당시 값으로 복원해 표시하지 않습니다. 공개 상태 변경에도 [현재 설정과 지원 팀장 예외](#visibility-changes)를 적용합니다.
- 이 결정은 정보의 기준 시점을 정합니다. 취소·미선발·폐기 후 열람은 [열람 관계 유지 정책](#former-applicant-visibility)을 따르며, 추천 대상은 별도 정책입니다. 프로필 값·공개 설정 변경만으로 지원 취소·미선발·선발 취소를 자동 처리하지 않습니다.

다음은 열람·추천 대상인 기존 지원에서 전체 현재 프로필과 별도의 추천 데이터 사용 범위를 적용하고, 다른 입력·모집 조건은 같을 때의 예시입니다. 변경을 저장한 뒤 팀장이 다시 조회하는 시점을 기준으로 합니다.

| 저장한 변경 | 지원 검토 화면 | 추천 결과 |
| --- | --- | --- |
| 희망 역할을 디자인에서 개발로 변경 | 현재 희망 역할 표시 | 현재 역할에 근거하며 모집 역할 불일치만으로 자동 제외하지 않음 |
| 주당 참여 가능 시간 입력·변경 | 모든 프로젝트를 합산한 현재 자기신고 예상 총량 표시. 팀별 확정 일정·약속은 자동 변경하지 않음 | 모델 전송·추천 사용 범위는 별도 정책을 따르며 잔여 시간이나 확인되지 않은 일정·시간 겹침을 생성하지 않음 |
| 자기소개 문구 수정 | 현재 자기소개 표시 | 사용할 수 있는 범위의 현재 정보를 기준으로 하고 이전 내용을 현재 사실로 설명하지 않음 |
| 포트폴리오 URL 삭제 | 삭제한 URL·제목을 표시하지 않음 | 삭제한 링크를 다시 노출하거나 외부 내용을 수집·분석하지 않음 |
| 프로필을 비공개로 변경 | 기존 지원·소속과 지원 팀장의 전체 현재 프로필 표시 유지 | 일반 AI 사람 탐색에서는 제외. 해당 지원을 받은 팀장의 AI 검토는 최신 프로필을 반영해 유지 |
| 프로필을 다시 공개 | 지원 팀장에게 전체 현재 프로필 표시 유지 | 일반 AI 사람 탐색 후보에 현재 프로필 반영. 외부 포트폴리오 수집·분석은 계속 제외 |

모든 사례에서 프로필 변경 사실을 팀장에게 별도로 알리지 않습니다. 새 선발 후보는 [지원 완료·검토 중인 유효 지원자](matching.md#recommendation-types)이며 기존 지원자가 비공개로 전환했다는 이유만으로 제외하지 않습니다. 선발·미선발·지원 취소·폐기는 새 선발 후보에서 제외하고, 모집 마감·정원 충족만으로 기존 지원자 AI 결과 확인·재요청을 막지 않습니다. 새 기능이나 일반 사람 추천 권한으로 확대하지 않으며 구체 모델 입력·보존 방식은 MATCH-10에 남깁니다.

| 이름·희망 역할·관심 분야와 선택 텍스트 검증 | 이름 1~50자, 역할 1~2개, 관심 분야 1~3개, 자기소개 300자·경험 500자·포트폴리오 제목 50자 상한을 검사합니다. 초과 입력은 유지하고 오류를 표시합니다. 일반 텍스트의 운영 Unicode 계수 계약은 미정이며 화면의 임시 계수와 구분합니다. |
| 학사·역량·경험·주당 참여 가능 시간·포트폴리오 편집 | 학사 선택과 종속 초안은 [학사 레퍼런스](academic-structure.md#prototype-reference), 기타 제거와 주당 시간 단일 선택은 [선택지 레퍼런스](profile-options.md#prototype-reference)를 따릅니다. 학적·학년이 비어 있어도 지원할 수 있습니다. |
| 경험 등록 상태 | 미입력·관련 경험 없음·경험 작성을 구분합니다. 경험 없음은 본문을 비우고 입력을 비활성화하며, 경험 작성의 빈 본문은 미입력으로 저장합니다. |
| 포트폴리오 URL·제목 | HTTP(S) 주소를 검사하고 URL을 삭제해 저장하면 제목도 비웁니다. 링크 수정·삭제 자체가 공개 설정을 바꾸지 않습니다. |
| 공개 범위와 신규 지원 | 비공개 프로필은 일반 사람 검색·AI 사람 추천에서 제외합니다. 신규 지원은 공개 확인·저장 후 나머지 조건을 재확인하고 별도로 제출합니다. 기존 지원·소속은 비공개 전환으로 취소되지 않습니다. |
| 지원받은 팀장의 현재 프로필 검토 | 공개 설정과 관계없이 현재 전체 프로필을 사용합니다. 지원자 AI 검토는 최신 값을 사용한 로컬 참고 응답이며 실제 모델 전송·분석이 아닙니다. |
| 등록 항목 조회 | 공개 프로필·본인 공개 모습·지원자 검토에서 같은 상세 계층을 사용합니다. 비어 있는 학사 항목·포트폴리오는 생략하고 나머지 빈 항목은 미입력으로 표시하며 값을 추정하지 않습니다. |

현재 저장은 브라우저 실행 중 메모리에 반영됩니다. 서버 저장 실패·계정 간 권한·새로고침 뒤 보존은 이 레퍼런스로 검증되지 않습니다. 계정 탈퇴 화면과 soft delete 처리는 제공하지 않으며 [탈퇴 정책의 미정 범위](#account-withdrawal)는 유지합니다.

## 완료 조건

- [ ] AC-01: 사용자가 필수 프로필을 작성하고 저장한 정보를 조회·수정할 수 있다.
- [ ] AC-02: 이름이 같은 두 사용자가 서로 다른 계정으로 유지되고, 사용자·모집·지원 화면에는 각 계정의 등록된 실명이 표시된다.
- [ ] AC-03: 이메일 주소가 다른 사용자에게 노출되지 않고, 관계별 열람이 허용되는 화면의 교내 인증 상태는 ‘미인증’으로 표시된다.
- [ ] AC-04: 지원 팀장은 지원자의 공개·비공개 상태와 관계없이 등록된 모든 현재 프로필 항목을 확인한다. 주당 참여 가능 시간과 포트폴리오 URL·제목을 포함하되 인증 정보는 제공하지 않는다.
- AC-05(폐기): 포트폴리오 미등록과 비공개 상태를 함께 지원 허용 조건으로 보던 기준은 #77의 신규 지원 공개 필수 결정으로 대체합니다. 포트폴리오 선택 등록은 유지하며 새 조건은 AC-29를 사용합니다.
- [ ] AC-06: 사용자가 포트폴리오 URL·선택 제목을 수정·삭제할 수 있으며 파일 업로드·외부 내용 AI 분석 기능은 제공되지 않는다.
- [ ] AC-07: 일반 확정 팀원은 공개 프로필을 일반 로그인 사용자와 같은 범위로 확인하며, 비공개 프로필은 팀원 관계만으로 열람하지 못한다.
- [ ] AC-08: 사용자가 하나의 프로필 공개·비공개 상태를 설정하며, 항목별·포트폴리오별 공개 스위치가 없다.
- [ ] AC-09: 공개 프로필은 일반 검색·AI 사람 탐색의 후보가 되고 상세에서 등록된 모든 항목을 확인할 수 있다. 비공개 프로필은 모든 일반 검색·AI 사람 탐색·일반 상세 직접 주소에서 제공하지 않는다.
- AC-10(폐기): 비공개 상태의 신규 지원을 허용하던 조건은 #77의 공개 필수 결정으로 대체합니다. 번호는 과거 참조용으로 남기며 새 조건은 AC-29를 사용합니다.
- [ ] AC-11: 공개 프로필의 포트폴리오 URL·제목은 일반 로그인 사용자에게 표시되고, 비공개 프로필의 URL·제목도 지원한 A·B팀 팀장에게는 동일하게 표시된다.
- [ ] AC-12: 지원 팀·지원 건·URL별 독립된 공개 설정이 없으며, 지원 팀장 예외가 미지원 팀장·일반 팀원에게 적용되지 않는다.
- [ ] AC-13: 지원 후 역할·주당 참여 가능 시간·자기소개 변경을 저장하면 다음 조회에서 현재 프로필을 확인하며, 추천은 허용된 데이터 범위에서 현재 근거를 사용한다. 역할 불일치만으로 추천 후보에서 제외하지 않으며, 기존 지원의 AI 검토 권한을 일반 AI 사람 추천의 비공개 데이터 사용 권한으로 확대하지 않는다.
- [ ] AC-14: 프로필 변경 후 팀장에게 변경 알림·배지·전후 비교 안내를 제공하지 않으며, 다시 조회하면 현재 정보를 확인할 수 있다.
- [ ] AC-15: 기존 지원을 다시 조회할 때 삭제한 포트폴리오 URL·제목을 지원 당시 값으로 표시하지 않는다.
- [ ] AC-16: 공개·비공개 전환을 저장한 즉시 일반 검색·AI 사람 탐색·일반 상세 조회에 새 상태를 적용한다. 비공개로 바꾸어도 기존 지원을 받은 팀장은 전체 현재 프로필을 직접 확인하고 해당 지원의 AI 검토에 최신 정보를 반영한다.
- [ ] AC-17: 다시 공개하면 현재 등록된 항목이 공개되고 삭제된 값은 복원되지 않는다. 공개 상태 전환만으로 지원·팀원 상태가 바뀌지 않는다.
- [ ] AC-18: 선발 전 취소·미선발·폐기·선발 후 취소 각각에서 지원 팀장의 열람 관계를 유지하고, 프로필 공개 상태와 관계없이 전체 현재 프로필을 표시한다.
- [ ] AC-19: 취소·미선발·폐기 후 팀장 열람 허용을 일반 사용자·미지원 팀장·다른 팀원의 추가 권한으로 사용하지 않는다. 인증 정보를 공개하지 않으며 취소로 이탈한 사용자의 팀 공간 접근 종료를 유지한다.
- [ ] AC-20: 팀의 학년 조건 유무와 관계없이 모든 지원의 제출 직전 필수 정보 입력 여부를 점검하고, 필수 항목이 누락됐다면 보완을 요청한다. 이미 입력한 필수값은 다시 요청하지 않으며 선택 입력인 학적·학년을 강제하지 않는다.
- [ ] AC-21: 보완 입력을 취소하거나 누락된 필수값이 남아 있으면 지원이 접수되지 않는다. 보완 저장 후 원래 지원 흐름에서 현재 조건을 다시 확인하며, 입력 완성을 자격 확인 완료나 지원 완료로 표시하지 않는다. 재지원에도 같은 점검을 적용한다.
- [ ] AC-22: MVP의 soft delete에서 탈퇴 상태를 기록해도 계정·프로필·포트폴리오 데이터를 즉시 물리 삭제하거나 비식별 값으로 치환하지 않는다. 보존을 실제 삭제 완료나 복구 기능 제공으로 취급하지 않으며, 탈퇴 완료·접근·표시·보존 기간 등 전체 흐름은 PROFILE-04를 결정한 뒤 검증한다.

- [ ] AC-23: 프로필은 기본 비공개이며 로그인한 사용자만 공개 프로필을 탐색한다. 비로그인은 공개 프로필의 목록·상세도 열람하지 못한다.
- [ ] AC-24: 공개·비공개 양방향 전환 시 일반 검색·AI 사람 추천 범위와 기존 지원의 직접 열람·최신 프로필 기반 AI 검토 유지 예외를 설명하는 팝업이 나타난다. 확인 후 저장 성공 시에만 상태가 바뀌며, 취소·닫기·Escape 또는 저장 실패는 기존 상태를 유지한다.
- [ ] AC-25: HTTP(S) URL 1개와 선택 제목을 등록·수정·삭제할 수 있고, 유효하지 않은 주소는 링크로 제공하지 않는다. URL 변경은 프로필 공개 상태를 변경하지 않으며, 현재 저장된 링크에 같은 프로필 정책을 적용한다.
- [ ] AC-26: 제공된 5종 캐릭터 중 프로필 이미지를 선택할 수 있고 미선택 시 스콘을 표시한다. 팝업 적용만으로 최종 저장하지 않으며 팝업 취소·프로필 편집 취소 시 기존 저장 이미지를 유지한다. 최종 저장 후에는 열람이 허용된 프로필·팀 화면에 같은 이미지가 반영된다.
- [ ] AC-27: 로그인한 사용자는 `함께할 사람`에서 현재 조건과 공개 범위에 맞는 전체 결과 수·총페이지를 확인하고 페이지 번호로 이동한다. 비공개 사용자는 일반 목록과 집계에서 제외하고 비로그인에게 결과 수를 제공하지 않는다. 조건·탭 변경 시 1페이지, 상세 복귀 시 조건·페이지 유지, 빈 결과·잘못된 페이지 보정을 확인한다.
- [ ] AC-28: 여러 팀에 지원한 사용자의 주당 참여 가능 시간은 하나의 공통 프로필 값이며, 변경 저장 후 각 팀장이 다시 조회하면 현재 자기신고 총량을 확인한다. 이 변경으로 팀별 확정 일정·약속·소속 상태를 자동 변경하지 않는다.

- [ ] AC-29: 신규 지원은 공개 프로필만 제출할 수 있다. 비공개이면 공개 범위를 설명하고 사용자의 확인·저장 성공 후 현재 지원 조건을 다시 확인한다. 팝업 취소·닫기·저장 실패 시 공개·지원 접수가 발생하지 않으며 지원 버튼만으로 자동 공개하거나 접수하지 않는다. 포트폴리오 미등록은 지원 제한 사유가 아니며 비공개 회원의 탐색·팀 생성·일반 AI 이용은 유지한다.
- [ ] AC-30: 지원 후 비공개 전환만으로 기존 지원·팀 소속을 바꾸지 않으며 해당 팀장의 AI 검토는 최신 프로필을 사용한다. 새 선발 후보는 지원 완료·검토 중인 유효 지원자로 제한하되 비공개 전환만으로 제외하지 않는다. 모집 마감·정원 충족 후 기존 결과 확인·재요청은 허용하며 신규 지원·정원 초과 선발을 허용하지 않는다. 일반 AI 사람 추천에는 지원서·요약·링크·과거 공개 정보로 비공개 사용자를 우회 노출하지 않는다.
- [ ] AC-31: 이름 1~50자, 자기소개 최대 300자, 포트폴리오 제목 최대 50자, 관심 분야 1~3개·희망 역할 1~2개를 검증하고 보유 역량은 목록 내에서 별도 개수 상한을 두지 않는다. 앞뒤 공백을 제거한 뒤 남은 공백·줄바꿈도 길이에 포함한다. 필수 누락·길이 초과 입력은 잘라 버리지 않고 보존하여 수정하도록 안내하며 저장하지 않는다.
- [ ] AC-32: 관련 경험은 미입력·경험 없음·경험 작성의 3상태를 구분하고 분야 선택 없이 최대 500자 자유서술을 제공한다. 빈 본문 저장은 미입력이며 경험 없음 저장 시 이전 본문을 비운다. 미입력을 경험 없음으로 추정하지 않고 편집 취소 시 저장값을 유지한다.
- [ ] AC-33: 학적·학년 미입력만으로 지원을 막거나 필수 보완을 요구하지 않는다. 개별 참가 자격은 원문 확인을 안내하고 비즈니스 로직에서 지원·선발을 차단하지 않으며 별도 자격 확인 대기 상태·팀별 추가 학사 제한·자격 충족 보장을 표시하지 않는다. 공개 필수·마감·정원·중복·소속 제한은 그대로 확인한다.

계정 탈퇴·삭제와 나머지 입력 계약의 상세 검증은 관련 미정 사항을 결정한 뒤 보완합니다. 주당 참여 가능 시간의 네 구간·단일 선택·미입력 구분은 [선택지 완료 조건](profile-options.md#acceptance-criteria)을 따릅니다. 저장 ID와 기존 슬롯 데이터 전환은 [OPTIONS-07](profile-options.md#open-questions)에 남기며, 주당 시간 참고 화면만으로 서버 저장·기존 데이터 전환까지 완료했다고 판단하지 않습니다.
