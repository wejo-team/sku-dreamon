# 프로필과 공개 범위

- 구현 상태: 예정
- 명세 검토: [PR #14](https://github.com/wejo-team/sku-dreamon/pull/14), PDF 대조·명세 연결 보완 [PR #17](https://github.com/wejo-team/sku-dreamon/pull/17)
- 구현 작업: 미등록
- 변경 검토: 2026-10-18 공식 디자인·LLM 추천 반영, 이 변경 PR에서 사람 검토 대기

기획 문서의 프로필 정책을 옮긴 초안입니다. 본문의 닉네임·파일 업로드 가능성은 정책 부록에서 구체화한 실명 입력·외부 URL 정책으로 정리했습니다.
학교 이메일 필수 요구는 [이슈 #20의 자체 로그인 결정](authentication.md#login-decision)에 따라 이번 범위에서 제외합니다.
추천은 [LLM 기반 추천 정책](matching.md#policy-decisions)을 따르며 내부 아키텍처는 TBD입니다. 기존 고정 점수와 시간 기반 계산 규칙은 사용하지 않습니다.
선택지나 코드가 바뀔 때는 [공통 선택지](profile-options.md), 학사 계층이 바뀔 때는 [학사 분류](academic-structure.md)의 해당 절만 읽습니다.

## 목적과 사용자

교내 사용자가 참가 자격, 관심 분야, 희망 역할과 협업 가능 정보를 작성하고 수정할 수 있게 합니다. 다른 사용자와 지원 팀장은 자신의 관계와 동의 범위에 맞는 정보만 확인합니다.

## 범위

| 포함 | 제외 |
| --- | --- |
| 실명 입력, 필수·선택 프로필 작성과 수정 | 신분증 등을 통한 실명 진위 확인 |
| 제공된 마스코트 중 프로필 이미지 선택 | 개인 사진 파일 업로드·편집 |
| 로그인한 사람 탐색의 공개 동의, 관심 분야·경험·자기소개 공개 설정, 프로필 단위 포트폴리오 공개·비공개 | 비로그인 프로필 열람, 모든 사용자에게 전체 프로필 일괄 공개 |
| 외부 포트폴리오 URL과 선택 제목 | 포트폴리오 파일 업로드·AI 분석 |
| MVP 계정 탈퇴의 soft delete·데이터 보존 방향 | 실제 삭제·비식별·보존 기간·복구·탈퇴 후 표시와 접근 효력의 세부 정책은 TBD |

LLM 추천의 동작·근거·미정 내부 설계는 [추천 매칭](matching.md)에서 정의합니다. 전체 개발 범위와 본문·부록의 적용 기준은 [스프린트 1](sprint-1.md#source-priority)을 따릅니다.

## 사용자 흐름과 동작

1. 로그인한 사용자가 프로필 설정 화면에서 필수 정보를 작성합니다. 공개 공고·팀 모집 정보 탐색은 [비로그인 접근 정책](authentication.md#access-policy)을 따릅니다.
2. 학사 정보·경험·역량·가능 시간·자기소개·포트폴리오를 필요한 만큼 보완합니다.
3. 관심 분야·경험·자기소개의 공개 범위를 설정합니다. 비공개 항목은 지원한 팀의 팀장에게도 표시하지 않습니다. 포트폴리오는 프로필에서 공개·비공개를 설정하고, 모든 지원 팀에 동일하게 적용된다는 안내를 확인합니다. 공개 스위치의 대상·기본값은 [사람 탐색과 공개 설정](#people-directory), 포트폴리오는 [포트폴리오 공개 설정](#portfolio-visibility)을 따릅니다.
4. 저장한 프로필을 조회하고 수정할 수 있습니다. 기존 지원의 검토·추천에도 [현재 프로필 기준](#application-profile)을 적용하며, MVP에서는 프로필 변경 사실을 별도로 알리지 않습니다.
5. 교내 사용자·지원 팀장·확정 팀원은 아래 공개 정책에 따라 정보를 확인합니다.
6. 지원하려면 [제출 직전 필수 정보 점검](#before-application)을 거칩니다. 누락된 필수 항목을 보완하기 전에는 지원을 접수하지 않습니다.

필수 여부와 입력 방식의 원본은 이 표입니다. 선택 가능한 값은 [프로필 선택지](profile-options.md#choices), 학사 소속의 새 선택과 저장된 과거값 유지는 [학사 선택 정책](academic-structure.md#selection-policy)을 따릅니다. 학사 이관 목록의 공식 검증 상태는 [학사 목록](academic-structure.md#catalog)에서 구분합니다.

| 항목 | 입력 방식·필수 여부 | 사용 목적·정책 |
| --- | --- | --- |
| 학교 이메일 | 스프린트 1 수집·인증 제외 | 가입·프로필 필수값으로 요구하지 않음. 후속 학교 인증 도입 시 재검토하며 현재는 [자체 로그인](authentication.md) 적용 |

| 학년 | 단일 선택·조건부 필수 | 공고 또는 팀의 명시적 학년 조건 확인 |

| 학부·학과 | 단일 선택·선택 입력 | 단과대학에 속한 학부·학과 선택 |

### 지원 직전 필수 정보 점검

[이슈 #54의 결정](https://github.com/wejo-team/sku-dreamon/issues/54#issuecomment-6233083862)에 따라 **모든 지원의 제출 직전**에 필수 정보가 입력됐는지 점검합니다. 학년 조건이 있는 팀에 지원하는 경우에만 점검하는 방식은 사용하지 않습니다.

- 적용되는 필수 항목이 누락됐다면 보완 입력을 요청합니다. 필수 여부의 원본은 위 입력 항목 표이며, 이번 결정으로 학적·학년이나 선택 항목을 모두 무조건 필수로 바꾸지는 않습니다. 조건부 필수의 구체 적용 기준은 PROFILE-03에 남깁니다.
- 이미 입력된 필수값은 다시 받지 않습니다. 보완 입력을 취소하거나 필요한 값이 계속 누락돼 있으면 지원을 접수하지 않으며 공개 정보 탐색은 계속할 수 있습니다.
- 보완을 저장하면 원래 지원 흐름으로 이어가고, 현재 모집 상태·마감·정원 등 적용 조건을 다시 확인합니다. 입력 저장 자체로 지원 완료를 만들지 않습니다. 취소 후 재지원에도 같은 점검을 적용합니다.
- 입력 완성과 참가 자격 확인은 별개입니다. [이슈 #33의 보류 결정](https://github.com/wejo-team/sku-dreamon/issues/33#issuecomment-6233084109)에 따라 자격이 `확인 필요`인 사용자의 접수 정책·판정 방식은 TBD이며, 입력을 끝냈다는 이유만으로 자격 충족이나 접수 성공을 보장하지 않습니다.

| 상황 | 제출 직전 동작 |
| --- | --- |
| 학년 조건이 없는 팀에 지원하며 필수 정보 누락 | 누락된 필수 정보 보완 요청, 보완 전 접수하지 않음 |
| 학년 조건이 있는 팀에 지원하며 필수 정보 누락 | 동일하게 필수 정보 보완 요청, 보완 전 접수하지 않음 |
| 적용되는 필수 정보가 이미 입력됨 | 같은 값을 다시 요청하지 않고 나머지 지원 조건 확인으로 진행 |
| 보완 입력을 취소 | 지원을 접수하지 않고 탐색으로 복귀 가능 |
| 보완 저장 뒤에도 자격이 확인 필요 | 접수 여부는 #33의 후속 결정 대상; 자동 통과하지 않음 |

이 절은 지원 직전의 점검 시점을 정의합니다. 팀 생성·개인화 추천에서 요구할 프로필 완성 범위는 이번 지원 정책으로 확대하지 않습니다.

## 이름과 계정 식별

- 실명 입력을 필수로 하며 사용자 화면과 팀 모집·지원 화면에는 등록된 실명을 표시합니다.
- 별도의 닉네임을 기본 표시 이름으로 사용하지 않습니다.
- 동명이인을 허용합니다. 계정은 내부 고유 사용자 ID로 구분하며 이름을 계정 식별자로 사용하지 않습니다.
- 자체 로그인과 실명 입력을 교내 구성원·실명 진위 확인으로 취급하지 않습니다. 후속 학교 인증의 한계도 [교내 인증의 의미](authentication.md#verification-meaning)를 따릅니다.

<a id="profile-avatar"></a>

## 프로필 이미지

- 프로필 수정에서 서경대학교 파워프렌즈 스콘·아티·디모·비아트·컨버 중 하나를 선택합니다. 이미지 선택은 필수 정보 점검 대상이 아니며 기본값은 스콘입니다.
- 선택창의 미리보기와 선택 적용은 수정 중인 프로필에만 반영합니다. 프로필의 저장 버튼을 눌러야 최종 적용되며, 선택창 취소는 직전 선택을, 프로필 수정 취소는 저장 전 값을 유지합니다.
- 저장한 이미지는 내 프로필, 공개가 허용된 프로필, 지원자와 확정 팀원 화면에서 일관되게 표시합니다. 이미지 선택 자체로 사람 탐색 공개나 다른 항목의 공개 설정을 변경하지 않습니다.
- 개인 사진 업로드·자르기·외부 이미지 URL 입력은 이번 범위에 포함하지 않습니다. 이미지 로드 실패 시 표시 이름의 일부를 대체 표시합니다.
- 공식 디자인의 원본 이미지는 [서경대학교 마스코트 안내](https://www.skuniv.ac.kr/mascot)를 참조합니다. 이름·캐릭터는 사용자 계정의 신원·소속 인증을 의미하지 않습니다.

## 공개 범위

아래 표는 [비공개 설정 우선 결정](#visibility-priority)과 공식 디자인의 로그인·공개 동의 기준을 적용한 범위입니다. ‘미정’은 공개 허용을 뜻하지 않습니다.

스프린트 1에는 교내 인증 사용자가 없습니다. 로그인한 사용자는 아래 사람 탐색 정책에 따라 공개에 동의한 프로필의 허용된 항목만 확인합니다. 로그인 성공만으로 전체 프로필을 공개하지 않으며, 비로그인은 타인 프로필 목록·상세를 볼 수 없습니다. 관계별 열람이 허용되는 화면에는 교내 인증 여부를 ‘미인증’으로 표시합니다.

| 정보 | 로그인한 일반 사용자 · 사람 탐색 공개 동의 시 | 지원한 팀의 팀장 | 확정 팀원 |
| --- | --- | --- | --- |
| 이름 | 실명 표시 | 실명 표시 | 사용자 화면의 실명 표시 원칙 적용 |
| 선택한 프로필 이미지 | 사람 탐색 공개 동의 시 표시 | 지원자와 함께 표시 | 팀원과 함께 표시 |
| 이메일 주소 | 공개하지 않음 | 공개하지 않음 | 공개하지 않음 |
| 교내 인증 여부 | 표시 | 표시 | 표시 |
| 관심 분야 | 공개가 허용된 경우 팀 탐색에 필요한 최소 정보; 비공개 항목은 표시하지 않음 | 공개가 허용된 항목만 지원 검토에 사용; 비공개 항목은 표시하지 않음 | 비공개 항목은 표시하지 않음; 그 외 구체 항목 미정 |
| 희망 역할 | 팀 탐색에 필요한 최소 정보 | 지원 검토에 사용 | 협업에 필요한 범위의 구체 항목 미정 |
| 학적 상태·학년·전공 | 필요 시 제한 공개; 대상·조건 미정 | 필요 시 제한 공개; 대상·조건 미정 | 구체 항목 미정 |
| 보유 역량 | 공개 범위 미정 | 지원 검토에 필요한 정보 확인 | 협업에 필요한 범위의 구체 항목 미정 |
| 경험·자기소개 | 해당 항목 공개 동의 시만 표시; 기본 비공개 | 공개가 허용된 항목만 지원 검토에 표시; 비공개 항목은 표시하지 않음 | 비공개 항목은 표시하지 않음; 그 외 구체 항목 미정 |
| 활동 가능 시간 | 상세 개인 일정 비공개; 그 외 표시 범위 미정 | 상세 개인 일정 비공개; 그 외 표시 범위 미정 | 상세 개인 일정 비공개; 그 외 표시 범위 미정 |
| 포트폴리오 | 사람 탐색에 공개하지 않음 | [프로필의 포트폴리오 공개 설정](#portfolio-visibility)에 따라 모든 지원 팀에 동일하게 표시·비표시 | 상세 포트폴리오는 별도 동의 후 공유 |
| 연락처 | 공개 동작은 정의되지 않음 | 공개 동작은 정의되지 않음 | 별도 동의 후 공유 |

관심 분야·경험·자기소개의 공개 스위치는 각각 기본 비공개입니다. 필수 입력인 관심 분야도 입력 의무와 다른 사용자에 대한 공개 여부는 별개입니다. 공개 설정 변경·동의 철회는 [기존 지원에도 즉시 적용](#visibility-changes)합니다. 연락처는 공유 정책만 있으며 수집 필드·방식은 정의되지 않았습니다.

팀장과 현재 확정 팀원의 [팀 공간 접근 권한](team-recruitment.md#team-workspace-access)은 프로필 항목의 공개 동의를 대신하지 않습니다. 팀 공간에서도 비공개 항목을 표시하지 않으며, 상세 포트폴리오·연락처 공유에 필요한 별도 동의를 유지합니다. 팀에서 이탈한 사용자의 팀 공간 접근 종료와 [지원 취소 후 팀장의 프로필 열람](#former-applicant-visibility)은 구분합니다.

활동 가능 시간의 권장 입력과 상세 개인 일정의 비공개 제한은 유지합니다. 현재 확인되지 않은 시간 겹침을 추천 이유로 표시하지 않으며, LLM 전환으로 원시 시간 정보의 열람·모델 전송 권한을 새로 부여하지 않습니다. 추가 활용 범위는 [추천의 미정 사항](matching.md#open-questions)에서 정합니다.

### 사람 탐색과 공개 설정

- **사람 탐색 공개** 스위치는 기본 꺼짐입니다. 켜면 로그인한 일반 사용자의 사람 목록·상세에 이름·희망 역할·교내 미인증 상태와 공개한 항목이 나타납니다. 비로그인 목록·상세와 무제한 공개 프로필은 제공하지 않습니다.
- 관심 분야·경험·자기소개 공개 스위치는 각각 기본 꺼짐이며 프로필 전체에 공통 적용합니다. 켜진 항목만 열람 관계에 맞게 표시하고, 사람 탐색 공개를 켠 것만으로 항목별 설정을 켜지 않습니다.
- 사람 탐색 공개는 일반 사용자의 발견·열람 여부를 정합니다. 이를 꺼도 지원한 팀장의 기존 열람 관계가 사라지지는 않으며, 그 팀장은 글로벌 항목별 공개 설정에 따라 허용된 정보만 봅니다.
- 사람 탐색을 끄면 일반 사용자에게 목록·검색·AI 사람 탐색 결과·직접 상세 주소로 프로필을 제공하지 않습니다. 본인 조회와 지원 관계에 따른 팀장 조회는 별도의 권한으로 판단합니다.
- 포트폴리오 스위치는 지원 팀장에게만 적용하며 사람 탐색에는 URL·제목을 노출하지 않습니다. 상세 개인 일정·이메일은 어느 공개 스위치로도 일반 공개하지 않습니다.
- 설정 화면은 사람 탐색 대상과 항목별 공개 대상, 포트폴리오의 모든 지원 팀 공통 적용을 구분해 안내합니다. 공개를 끄거나 항목을 비공개로 유지한 것만으로 지원을 막지 않습니다.

### 비공개 설정 우선

[이슈 #22](https://github.com/wejo-team/sku-dreamon/issues/22)는 **A · 사용자 설정 우선**을 적용합니다. 관심 분야·경험·자기소개 중 사용자가 비공개로 설정한 항목은 지원 검토용 최소 공개보다 사용자 설정을 우선하며, 지원한 팀의 팀장에게도 표시하지 않습니다. 지원·선발·팀원 확정만으로 비공개 항목을 공개로 전환하지 않습니다. 사용자가 정한 공개 범위를 유지하기 위한 결정이며, 팀장은 공개가 허용된 정보로 지원자를 검토합니다.

같은 사용자가 자기소개를 비공개로 설정한 뒤 팀에 지원하고, 그 설정을 유지하는 경우의 예시입니다.

| 열람자 | 자기소개 표시 |
| --- | --- |
| 작성자 본인 | 본인의 프로필에서 확인·수정 가능 |
| 일반 교내 사용자 | 표시하지 않음 |
| 지원한 팀의 팀장 | 지원 검토에 필요하더라도 표시하지 않음 |
| 확정 팀원 | 팀원 관계만으로 표시하지 않음 |

이 원칙은 공개된 항목의 열람 대상을 새로 허용하지 않습니다. 실제 화면 접근과 공개 항목의 열람 범위는 위 표와 관련 미정 사항을 함께 따릅니다.

지원 제출 전에는 팀장에게 표시되는 항목과 비공개 유지 원칙을 안내합니다. 비공개 항목의 공개 동의를 지원 제출 조건으로 요구하지 않으며, 해당 항목을 공개하지 않는다는 이유로 지원 제출을 막지 않습니다. 필수 프로필 입력과 모집·지원 조건은 각 명세를 따릅니다.

포트폴리오의 공개 동의는 [프로필 단위 공개 설정](#portfolio-visibility)을 따릅니다. 기존 지원의 프로필 정보는 [현재 프로필 기준](#application-profile), 공개 설정 변경·동의 철회의 효력은 아래 [즉시 적용 정책](#visibility-changes)을 따릅니다. [이슈 #49의 보류 판단](https://github.com/wejo-team/sku-dreamon/issues/49#issuecomment-6234827892)에 따라 타인 비공개 정보의 모델 전송·추천 사용과 결과를 통한 간접 노출은 **TBD**이며, [MATCH-10](matching.md#open-questions)에서 설계·동의 범위와 함께 정합니다. 미정을 사용 허가로 해석하지 않으며 공식 디자인은 열람이 허용된 정보만 사용합니다.

### 공개 설정 변경·철회와 재동의

[이슈 #41](https://github.com/wejo-team/sku-dreamon/issues/41#issuecomment-6232924566)에 따라 공개·비공개 설정 변경과 공개 동의 철회는 저장에 성공한 즉시 기존 지원에도 적용합니다. 지원 당시의 공개 설정이나 프로필 사본을 근거로 이전 공개 내용을 계속 제공하지 않습니다.

- 관심 분야·경험·자기소개를 비공개로 바꾸면 기존 지원을 조회하는 팀장에게도 해당 항목을 표시하지 않습니다. 포트폴리오를 비공개로 바꾸거나 공개 동의를 철회하면 URL·제목을 표시하지 않습니다.
- 다시 공개로 설정하거나 공개에 재동의하면 현재 열람 권한이 있는 모든 지원 팀에 같은 설정을 적용합니다. 포트폴리오의 동의는 프로필에서 한 번 받으며 팀별 재동의를 요구하지 않습니다. [취소·미선발 후에도 열람 관계가 유지되는 팀장](#former-applicant-visibility)에게도 현재 설정을 동일하게 적용합니다.
- 설정 변경·철회·재동의 자체로 지원 취소·미선발·팀원 이탈을 처리하지 않습니다. 지원·팀원 상태와 공개 여부는 별개입니다.
- 저장 성공 즉시 바뀐 설정을 열람 기준으로 사용하며, 이후 조회·새로고침에서 이전 설정으로 정보를 제공하지 않습니다. 일반 프로필 변경에 대한 알림·실시간 화면 갱신 제외 정책과 공개 권한의 효력 시점을 구분합니다.
- 일반 사용자나 미지원 팀장에게 새 열람 권한을 부여하지 않습니다. 확정 팀원 대상 상세 포트폴리오·연락처 공유에 필요한 별도 동의도 이 설정으로 대체하지 않습니다.

다음은 A·B팀에 지원한 사용자가 프로필 설정을 변경하는 사례입니다. 두 팀장 모두 해당 지원자의 프로필 열람 권한이 있고, 각 변경을 저장한 이후 조회를 기준으로 합니다.

| 저장한 변경 | A·B팀 팀장의 표시 | 지원·팀원 상태 |
| --- | --- | --- |
| 공개한 자기소개를 비공개로 변경 | 두 팀장 모두 현재 자기소개를 표시하지 않음 | 변경 없음 |
| 포트폴리오 공개 동의 철회 | 두 팀장 모두 URL·제목을 표시하지 않음 | 변경 없음 |
| 자기소개를 다시 공개 | 두 팀장 모두 현재 자기소개 표시 | 변경 없음 |
| 포트폴리오 공개에 다시 동의 | 두 팀장 모두 현재 등록된 URL·제목 표시; 삭제된 이전 값은 복원하지 않음 | 변경 없음 |

### 취소·미선발 후 팀장의 프로필 열람

[이슈 #55](https://github.com/wejo-team/sku-dreamon/issues/55#issuecomment-6232925011)에 따라 지원 취소·미선발만으로 해당 팀장의 상세 프로필 열람 관계를 종료하지 않습니다. 선발·확정 후 지원을 취소해 팀에서 이탈한 경우에도 같습니다. 팀장은 [현재 프로필](#application-profile)의 현재 공개 설정에 따라 허용된 항목만 확인합니다.

| 지원 관계 | 팀장의 상세 프로필 열람 |
| --- | --- |
| 선발 전 지원 취소 | 열람 관계 유지; 현재 공개 항목만 표시 |
| 미선발 | 열람 관계 유지; 현재 공개 항목만 표시 |
| 선발·확정 후 지원 취소 | 열람 관계 유지; 현재 공개 항목만 표시 |
| 위 상태에서 비공개 전환·동의 철회 | 변경한 항목은 즉시 비표시 기준 적용; 지원 당시 공개본을 대신 표시하지 않음 |

이 정책은 지원한 적 없는 팀장이나 일반 사용자에게 프로필을 공개하는 결정이 아닙니다. 이메일·상세 개인 일정의 비공개와 확정 팀원 대상 상세 포트폴리오·연락처의 별도 공유 동의를 유지합니다. 취소한 사용자의 [팀 공간 접근 종료](team-recruitment.md#team-workspace-access)도 유지하며, 팀장의 프로필 열람을 지원자 추천 대상 포함으로 해석하지 않습니다. 지원 이력의 저장·보관 기간과 계정 삭제 시 처리 방식은 별도 미정 사항입니다.

## 외부 포트폴리오

| 항목 | 정책 |
| --- | --- |
| 입력 | Notion, GitHub, 개인 웹사이트 등의 HTTP(S) 외부 URL 1개를 선택적으로 등록. 선택 제목 입력 가능 |
| 저장 | URL과 선택 입력 제목만 저장; 본문의 설명 입력은 최종 저장 범위에 포함하지 않음 |
| 선택 등록 | 포트폴리오 없이도 공모전 탐색·팀 모집·지원·추천을 동일하게 이용 |
| 파일 업로드 | 스프린트 1에서 제외 |
| AI 분석 | 스프린트 1에서 제외. URL 등록·공개 동의를 외부 내용 수집·LLM 분석 동의로 취급하지 않음 |
| 공개 | [프로필 단위 공개·비공개 설정](#portfolio-visibility)에 따라 지원 팀장에게 표시; 확정 팀원 공유는 별도 동의 필요 |
| 링크 접근 | 사용자가 공유 권한·접근 가능 여부를 확인하도록 안내; 비공개·삭제된 외부 내용은 서비스가 보장하지 않음 |
| 수정·삭제 | 사용자가 등록 정보를 수정·삭제할 수 있음 |

파일 업로드는 형식·크기·저장소·접근 권한·악성 파일 관리 부담을 줄이고 핵심 흐름에 집중하기 위해 제외합니다. 포트폴리오 AI 분석은 문서 처리와 정확도·평가 기준 검증이 필요하므로 후속 고도화에서 검토하며, 도입을 확정한 것은 아닙니다.

URL은 앞뒤 공백을 제거하고 `http:` 또는 `https:`의 유효한 주소만 등록합니다. 잘못된 주소는 오류를 표시하고 외부 링크로 제공하지 않습니다. URL을 삭제하거나 유효하지 않은 값으로 수정하면 공개 동의를 해제하며, 유효한 URL을 다시 넣어도 자동으로 공개하지 않습니다. 외부 사이트의 내용·접근 권한까지 검증된 것으로 표시하지 않습니다.

### 포트폴리오 공개 설정

[이슈 #23](https://github.com/wejo-team/sku-dreamon/issues/23)의 공개 동의 적용 단위는 **프로필**로 정합니다. 프로필에서 포트폴리오 공개·비공개를 한 번 설정하고 모든 지원 팀에 동일하게 적용합니다.

- 포트폴리오 공개 스위치는 기본 비공개이며 유효한 URL을 등록한 경우에만 켤 수 있습니다. 지원 팀장에게 공개할지에 대한 동의는 프로필의 공개 설정에서 받습니다. 설정 화면에는 현재 및 이후 지원하는 모든 팀에 공통으로 적용됨을 안내합니다.
- `공개`에 동의하면 열람 권한이 있는 모든 지원 팀장에게 등록한 포트폴리오 URL과 선택 제목을 표시합니다. `비공개`이거나 공개 동의가 없으면 표시하지 않습니다.
- 지원 팀·지원 건·URL별로 공개 설정을 따로 두지 않습니다. A팀에만 공개하고 B팀에는 비공개로 두는 설정은 제공하지 않으며, 등록한 단일 포트폴리오 URL과 선택 제목에 같은 설정을 적용합니다.
- 지원 제출만으로 비공개 설정을 공개로 바꾸거나 팀별 공개 동의를 추가로 받지 않습니다. 포트폴리오를 비공개로 두어도 탐색·모집·지원·추천을 동일하게 이용합니다.
- 이 설정으로 일반 사용자의 포트폴리오 열람 권한을 부여하지 않습니다. 확정 팀원의 상세 포트폴리오 공유는 별도 동의가 필요하며, 지원 팀장 대상 공개 동의로 대체하지 않습니다.
- 설정 변경·동의 철회·재동의는 [기존 지원에도 즉시 적용](#visibility-changes)합니다. 취소·미선발 후에도 [팀장의 열람 관계](#former-applicant-visibility)는 유지하며 현재 설정에 따라 표시·비표시합니다.

다음 사례는 지원한 팀의 팀장이 지원자 열람 권한을 가지며, 모든 지원 팀에 같은 프로필 설정이 적용된 상태를 기준으로 합니다. 일반 사용자는 해당 사용자의 지원 팀장·확정 팀원이 아닌 사람을 뜻합니다.

| 설정과 지원 관계 | A팀 팀장 | B팀 팀장 | 일반 사용자 | 확정 팀원 |
| --- | --- | --- | --- | --- |
| 비공개, A·B팀에 지원, 확정 팀원 공유 동의 없음 | 표시하지 않음 | 표시하지 않음 | 이 설정으로 공개하지 않음 | 표시하지 않음 |
| 공개 동의, A·B팀에 지원, 확정 팀원 공유 동의 없음 | URL·제목 표시 | URL·제목 표시 | 이 설정으로 공개하지 않음 | 표시하지 않음 |
| 공개 동의, A팀에만 지원, 확정 팀원 공유 동의 없음 | URL·제목 표시 | 표시하지 않음 | 이 설정으로 공개하지 않음 | 표시하지 않음 |
| 공개 동의, A·B팀에 지원, 확정 팀원 공유에 별도 동의 | URL·제목 표시 | URL·제목 표시 | 이 설정으로 공개하지 않음 | 별도 동의 범위에서 공유 |

## 수정·삭제와 미입력

- 사용자는 프로필을 수정할 수 있으며, 수정·삭제 방법과 공개 범위를 안내합니다.
- MVP의 계정 탈퇴는 아래 [soft delete와 데이터 보존 방향](#account-withdrawal)을 적용합니다. 실제 삭제·비식별·보존 기간·복구와 탈퇴 처리 세부는 후속으로 정합니다.
- 미입력·미확인과 명시적 값의 차이는 [공통 데이터 관리](profile-options.md#catalog-management)를 따릅니다.
- 개별 필드 삭제를 허용하는 조건과 필수값 검증은 미정입니다. 저장이 완료된 수정·삭제의 기존 지원 조회 반영은 아래 현재 프로필 기준을 따릅니다.

### MVP 계정 탈퇴와 데이터 보존

[이슈 #25의 사용자 판단](https://github.com/wejo-team/sku-dreamon/issues/25#issuecomment-6234890281)에 따라 MVP에서는 **soft delete로 탈퇴 상태를 관리하고 계정·프로필·포트폴리오 데이터를 즉시 물리 삭제하지 않는 방향**을 적용합니다. 복구 가능성을 고려하며, 기존 원문의 즉시 삭제 또는 비식별 처리를 이번 단계의 확정 동작으로 사용하지 않습니다.

데이터를 보존한다는 사실은 복구 기능 제공·재가입 시 자동 복구·무기한 보존을 확정한 것이 아닙니다. 실제 삭제·비식별 대상과 시점, 보존 기간, 복구 가능 조건·기간·절차는 PROFILE-04에서 후속으로 정합니다.

탈퇴 후 보관 중인 데이터를 어떻게 표시·접근 제한할지도 별도 정책입니다. 탈퇴 처리의 완료 시점, 로그인·세션·프로필 접근 효력, 기존 팀·지원 화면의 표시 방식은 아직 정하지 않았습니다. 보존 방향만으로 기존 프로필 공개를 계속 허용하거나 즉시 비표시·‘탈퇴 사용자’ 치환을 확정하지 않습니다. 이러한 효력을 정하기 전에는 데이터 보관만으로 탈퇴 기능 전체의 완료를 판단하지 않습니다.

팀장 위임·팀원 소속·정원 반환·지원 상태 전환과 전체 활동 이력의 보존은 기존 미정 사항으로 유지합니다. 계정 탈퇴를 [지원 취소](team-recruitment.md#application-cancellation)와 같은 처리로 간주하지 않습니다. 저장 구조와 구체적인 상태값은 개발 계획에서 정합니다.

### 기존 지원의 검토·추천 기준

[이슈 #24](https://github.com/wejo-team/sku-dreamon/issues/24)는 **현재 저장된 프로필**을 기준으로 정합니다. 지원 검토 화면과 지원자 추천이 같은 정보를 사용하도록 하며, MVP에서는 변경 사실을 별도로 알리지 않습니다.

- 지원 당시 프로필 사본을 검토·추천의 기준으로 고정하지 않습니다. 사용자가 프로필 변경을 저장하면 기존 지원에도 반영하며, 지원자가 별도로 지원 갱신을 요청할 필요가 없습니다.
- 저장 후 다음 조회·갱신에서 검토 정보와 추천 근거를 같은 현재 프로필 기준으로 맞춥니다. 현재 프로필에 이전 프로필의 근거를 섞어 표시하지 않습니다. LLM 추천의 실행·갱신은 [추천 이용 흐름](matching.md#recommendation-types)을 따르며, 고정 점수나 특정 필드 변경에 따른 결과 불변을 보장하지 않습니다.
- MVP에서는 프로필 변경 알림, 변경 배지, 변경 전후 비교 안내를 제공하지 않습니다. 일반 프로필 값 변경에 대해 이미 열어 둔 팀장 화면의 실시간 자동 갱신도 요구하지 않으며, 다시 조회하거나 새로고침하면 현재 기준으로 확인합니다. 공개 설정의 효력은 [저장 성공 즉시](#visibility-changes) 적용합니다.
- 현재 프로필을 사용해도 [공개 범위](#visibility)에서 열람이 허용된 정보만 표시합니다. 삭제된 포트폴리오 URL·제목을 지원 당시 값으로 복원해 표시하지 않습니다. 공개 설정 변경·동의 철회·재동의에도 [현재 설정](#visibility-changes)을 적용합니다.
- 이 결정은 정보의 기준 시점을 정합니다. 취소·미선발 후 열람은 [열람 관계 유지 정책](#former-applicant-visibility)을 따르며, 추천 대상은 별도 정책입니다. 프로필 값·공개 설정 변경만으로 지원 취소·미선발·선발 취소를 자동 처리하지 않습니다.

다음은 열람·추천 대상인 기존 지원에서 각 항목에 현재 공개 설정을 적용하고, 다른 입력·모집 조건은 같을 때의 예시입니다. 변경을 저장한 뒤 팀장이 다시 조회하는 시점을 기준으로 합니다.

| 저장한 변경 | 지원 검토 화면 | 추천 결과 |
| --- | --- | --- |
| 희망 역할을 디자인에서 개발로 변경 | 현재 희망 역할 표시 | 현재 역할에 근거하며 모집 역할 불일치만으로 자동 제외하지 않음 |
| 활동 가능 시간 입력·변경 | 상세 개인 일정 비공개 유지 | 비공개 상세 일정을 다른 사용자에게 전달하거나 확인되지 않은 시간 겹침을 생성하지 않음 |
| 자기소개 문구 수정 | 공개가 허용된 현재 자기소개 표시 | 사용할 수 있는 범위의 현재 정보를 기준으로 하고 이전 내용을 현재 사실로 설명하지 않음 |
| 포트폴리오 URL 삭제 | 삭제한 URL·제목을 표시하지 않고 공개 동의 해제 | 삭제한 링크를 다시 노출하거나 외부 내용을 수집·분석하지 않음 |
| 관심 분야·경험을 비공개로 변경 | 기존 지원에도 즉시 비표시 기준 적용; 취소·미선발 후에도 동일 | 비공개 내용을 추천 이유에 표시하지 않음. 모델 전송·추천 사용·간접 노출은 MATCH-10의 TBD이며 사용 허가가 아님 |
| 포트폴리오 공개 동의 철회 후 재동의 | 철회 시 비표시, 재동의 시 현재 열람 권한이 있는 모든 지원 팀에 현재 URL·제목 표시 | 링크 열람 동의를 외부 내용 수집·LLM 분석 동의로 취급하지 않음 |

모든 사례에서 프로필 변경 사실을 팀장에게 별도로 알리지 않습니다. 타인 비공개 정보의 모델 전송·추천 사용 범위는 MATCH-10의 별도 결정 사항입니다.

## 완료 조건

- [ ] AC-01: 사용자가 필수 프로필을 작성하고 저장한 정보를 조회·수정할 수 있다.
- [ ] AC-02: 이름이 같은 두 사용자가 서로 다른 계정으로 유지되고, 사용자·모집·지원 화면에는 각 계정의 등록된 실명이 표시된다.
- [ ] AC-03: 이메일 주소가 다른 사용자에게 노출되지 않고, 관계별 열람이 허용되는 화면의 교내 인증 상태는 ‘미인증’으로 표시된다.
- [ ] AC-04: 지원 팀장은 공개가 허용된 범위의 역량·경험·자기소개를 확인하며, 비공개 경험·자기소개와 상세 개인 일정은 표시되지 않는다. 추천용 시간 겹침 정보의 자동 계산·표시는 요구하지 않는다.
- [ ] AC-05: 포트폴리오를 등록하지 않거나 비공개로 두어도 탐색·모집·지원·추천을 이용할 수 있고, 등록한 URL·제목은 프로필의 공개 설정에서 동의하지 않으면 지원 팀장에게 표시되지 않는다.
- [ ] AC-06: 사용자가 포트폴리오 URL·선택 제목을 수정·삭제할 수 있으며 파일 업로드·AI 분석 기능은 제공되지 않는다.
- [ ] AC-07: 확정 팀원에게 상세 포트폴리오·연락처를 공유하려면 별도 동의가 필요하다.
- [ ] AC-08: 사용자가 관심 분야·경험·자기소개의 공개 범위를 설정할 수 있으며, 비공개 설정이 대상별 최소 공개보다 우선한다. 공개 대상·기본값은 [사람 탐색과 공개 설정](#people-directory)을 따른다.
- [ ] AC-09: 관심 분야·경험·자기소개를 비공개로 설정한 뒤 그 설정을 유지하면, 본인은 확인·수정할 수 있고 일반 교내 사용자·지원 팀장·확정 팀원에게는 해당 항목이 표시되지 않는다.
- [ ] AC-10: 지원 제출 전에 팀장에게 표시되는 항목과 비공개 유지 원칙을 안내하며, 비공개 항목의 공개 동의를 필수로 요구하거나 비공개 유지 자체를 이유로 지원 제출을 차단하지 않는다.
- [ ] AC-11: 프로필에서 포트폴리오 공개·비공개를 설정하고 모든 지원 팀에 공통으로 적용된다는 안내를 확인할 수 있다. A·B팀에 지원한 사용자의 URL·제목은 [공개 설정 사례](#portfolio-visibility)에 따라 두 팀장에게 동일하게 표시·비표시된다.
- [ ] AC-12: 지원 팀·지원 건·URL별로 독립된 포트폴리오 공개 설정이 없고, 지원 제출만으로 공개 상태가 바뀌지 않는다. 공개 설정만으로 일반 사용자·미지원 팀장·별도 공유 동의가 없는 확정 팀원에게 URL·제목이 표시되지 않는다.
- [ ] AC-13: 지원 후 역할·시간·자기소개 변경을 저장하면, 지원 갱신 요청 없이 다음 조회·새로고침에서 [현재 프로필 사례](#application-profile)에 맞는 검토 정보와 추천 결과가 함께 표시된다. 현재 역할이 모집 역할과 다르다는 이유만으로 추천 후보에서 제외하지 않으며, 추천 결과에 이전 프로필 근거나 비공개 정보를 노출하지 않는다.
- [ ] AC-14: 프로필 변경 후 팀장에게 변경 알림·배지·전후 비교 안내를 제공하지 않으며, 다시 조회하면 현재 정보를 확인할 수 있다.
- [ ] AC-15: 기존 지원을 다시 조회할 때 삭제한 포트폴리오 URL·제목을 지원 당시 값으로 표시하지 않고, 현재 정보에도 프로필 공개 정책을 적용한다.
- [ ] AC-16: 공개 설정 변경·동의 철회를 저장한 즉시 기존 지원에도 현재 설정을 적용한다. 이후 A·B팀 팀장이 조회하면 비공개로 바꾼 항목과 공개 동의를 철회한 포트폴리오 URL·제목이 표시되지 않으며, 지원 당시 공개본으로 대체하지 않는다.
- [ ] AC-17: 다시 공개하거나 포트폴리오 공개에 재동의하면 현재 열람 권한이 있는 모든 지원 팀에 현재 설정이 동일하게 적용된다. 팀별 재동의를 요구하지 않고 설정 변경·철회·재동의만으로 지원·팀원 상태가 바뀌지 않는다.
- [ ] AC-18: 선발 전 취소·미선발·선발 후 취소 각각에서 팀장의 프로필 열람 관계를 유지하되 현재 공개 항목만 표시한다. 취소 후에도 비공개 전환·동의 철회·재동의가 같은 기준으로 적용된다.
- [ ] AC-19: 취소·미선발 후 팀장 열람 허용으로 일반 사용자·미지원 팀장의 접근이나 이메일·상세 개인 일정 공개를 허용하지 않는다. 확정 팀원 대상 상세 포트폴리오·연락처의 별도 동의와 취소로 이탈한 사용자의 팀 공간 접근 종료를 유지한다.
- [ ] AC-20: 팀의 학년 조건 유무와 관계없이 모든 지원의 제출 직전 필수 정보 입력 여부를 점검하고, 적용되는 필수 항목이 누락됐다면 보완을 요청한다. 이미 입력한 필수값은 다시 요청하지 않는다.
- [ ] AC-21: 보완 입력을 취소하거나 누락된 필수값이 남아 있으면 지원이 접수되지 않는다. 보완 저장 후 원래 지원 흐름에서 현재 조건을 다시 확인하며, 입력 완성을 자격 확인 완료나 지원 완료로 표시하지 않는다. 재지원에도 같은 점검을 적용한다.
- [ ] AC-22: MVP의 soft delete에서 탈퇴 상태를 기록해도 계정·프로필·포트폴리오 데이터를 즉시 물리 삭제하거나 비식별 값으로 치환하지 않는다. 보존을 실제 삭제 완료나 복구 기능 제공으로 취급하지 않으며, 탈퇴 완료·접근·표시·보존 기간 등 전체 흐름은 PROFILE-04를 결정한 뒤 검증한다.

- [ ] AC-23: 사람 탐색과 관심 분야·경험·자기소개·포트폴리오 공개 스위치는 기본 비공개다. 로그인한 사용자만 탐색 공개에 동의한 사람 목록·상세를 보며, 목록 비공개 전환 후 일반 사용자에게 직접 주소로도 제공하지 않는다.
- [ ] AC-24: 사람 탐색을 끈 지원자의 현재 공개 항목은 지원한 팀장이 확인할 수 있으며, 항목별 비공개는 팀장에게도 적용된다. 사람 탐색 공개만으로 포트폴리오를 일반 사용자에게 노출하지 않는다.
- [ ] AC-25: HTTP(S) URL 1개와 선택 제목을 등록·수정·삭제할 수 있고, 유효하지 않은 주소는 링크로 제공하지 않는다. URL 삭제·무효화 시 공개 동의가 해제되며 유효한 URL 재입력만으로 다시 공개되지 않는다.
- [ ] AC-26: 이미지 선택 없이 기본 스콘으로 이용할 수 있고, 제공된 다섯 캐릭터를 선택·미리보기할 수 있다. 선택창 취소와 프로필 수정 취소는 저장값을 변경하지 않으며, 저장한 이미지는 공개가 허용된 프로필·지원자·확정 팀원 화면에 동일하게 적용된다. 이미지 변경으로 공개 범위를 변경하지 않는다.

비공개 항목의 대상별 검증 기준은 AC-09를 따릅니다. 계정 탈퇴·삭제와 조건부 필수 적용 기준의 상세 검증은 관련 미정 사항을 결정한 뒤 보완합니다.
