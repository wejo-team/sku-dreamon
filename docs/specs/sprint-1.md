# 스프린트 1 범위와 완료 기준

- 구현 상태: 예정
- 명세 검토: [PR #17](https://github.com/wejo-team/sku-dreamon/pull/17)
- 구현 작업: 미등록

`스프린트1_기능정의_및_개발범위_정책확정본.pdf`의 전체 범위, 화면, 일정과 시연 기준을 관리합니다. 기능별 정책은 아래 담당 명세에서 정의합니다. 이 문서의 일정과 완료 조건은 계획이며, 구현·검증·배포 완료 기록이 아닙니다.

## 목적과 사용자

AI 기반 교내 공모전 도전 지원 서비스의 첫 흐름을 만듭니다. 사용자는 로그인 없이 공개 공고·팀 모집 정보를 탐색하고, 자체 로그인 후 팀을 만들거나 기존 팀에 지원합니다. 모든 지원의 제출 직전에 누락된 필수 정보를 보완하며, 이번 범위에서는 교내 구성원 여부를 검증하지 않습니다. 팀장은 실제 지원자를 검토·선발하고, 사용자는 추천과 자신의 지원 결과를 확인합니다. 공고는 [최초 공개 조건](contests.md#publication-policy)을 따르며 수집·적재·관리 방식은 TBD입니다.

## 원문 적용 기준

- PDF 1~6쪽은 기능 정의 본문, 7~9쪽은 정책 확정 부록입니다. 같은 항목이 달라진 경우 부록의 구체화된 기준을 적용합니다.
- 닉네임 우선 표시는 실명 입력·표시로, 포트폴리오 파일 업로드 가능성은 외부 URL만 제공하는 정책으로 정리합니다. 본문의 시간 입력 ‘필수 권장’은 부록의 ‘권장’을 적용합니다.
- 본문의 팀 매칭 가중치는 예시입니다. 현재는 [추천 정책 결정](matching.md#policy-decisions)에 따라 모집 역할 강제 필터와 시간 점수를 사용하지 않으며, 팀·지원자 최종 가중치·산식은 후속 정의합니다. 공모전 추천의 부록 가중치는 유지합니다.
- 원문에서 정하지 않은 동작을 이관 과정에서 확정하지 않습니다. 기능별 미정 사항은 해당 명세에 남깁니다. 기존 `추가 리스트 최종.md`와의 선택지 차이는 [선택지 차이](profile-options.md#source-differences)에서 관리합니다.
- 원문 이관 이후 [이슈 #20](https://github.com/wejo-team/sku-dreamon/issues/20)에서 변경한 가입 경로는 [자체 로그인 결정](authentication.md#login-decision)을 적용합니다. 원문의 학교 이메일 필수·실제/시연 인증 선택은 이번 범위에서 대체합니다.

팀장이 선발하면 해당 지원자가 즉시 확정 팀원이 되며 별도 수락은 없습니다. 팀장 포함 정원과 선발 시 차감은 [팀원 확정과 정원 정책](team-recruitment.md#membership-capacity)을 따릅니다. [지원자 검토를 시작해도 현재 접수 조건을 충족하면 신규 지원을 받으며](team-recruitment.md#recruitment-review), 나머지 팀 전체 모집 상태 전이·종료는 [팀 명세의 미정 사항](team-recruitment.md#open-questions)에서 별도로 결정합니다.

개인 참가 전용 공고에서도 [함께 준비하는 팀](contests.md#participation-policy)을 만들 수 있으며 공식 공동 출전 팀과 구분해 안내합니다. 공동 출전 팀의 목표 총 정원은 [확인된 공식 팀 인원 범위](team-recruitment.md#official-capacity) 안에서만 저장합니다. 날짜만 있는 마감일의 기본 시각·시간대는 [TBD](contests.md#deadline-policy)로 두고 일정 처리 구체화 때 결정합니다.

팀 생성·선발에는 팀장을 포함한 [공모전별 한 팀 소속 제한](team-recruitment.md#membership-limit)을 적용합니다. 지원자는 선발·확정 후에도 [지원을 취소해 팀에서 빠지고 한 자리를 반환](team-recruitment.md#application-cancellation)할 수 있으며, 현재 모집 조건을 충족하면 [즉시 재지원](team-recruitment.md#reapplication)할 수 있습니다. 동시 지원·다른 지원의 자동 취소·미선발 후 재지원·팀장 탈퇴와 위임은 이번 결정에 포함하지 않습니다.

## AI와 알고리즘의 역할

조건 비교는 재현 가능한 규칙으로 처리합니다. 긴 문서를 읽기 쉽게 정리하는 요약은 생성형 AI의 활용 후보이나, [#38의 보류 판단](contests.md#summary-scope)에 따라 요약의 사용처·필요성과 MVP 포함 여부를 화면 기획 때 먼저 정하고 AI 연동 여부는 그 뒤에 결정합니다.

| 기능 | 처리 기준 | 담당 명세 |
| --- | --- | --- |
| 참가 자격 확인 | 규칙 기반 필터링 | [추천 매칭](matching.md) |
| 마감 여부 확인 | 날짜와 상태 기반 처리 | [공고](contests.md), [팀 모집과 지원](team-recruitment.md) |
| 공모전·팀·지원자 후보 순위 | 필수 조건 확인 후 규칙 기반 점수 계산 | [추천 매칭](matching.md) |
| 공고 요약 | 사용처·필요성·MVP 포함 여부는 TBD. 포함 시 내용·생성 방식·표시 기준을 정하고 실제 AI 연동은 이후 결정. 참가 조건 정리와 최초 공개 조건은 유지 | [요약 범위](contests.md#summary-scope) |
| 매칭 이유 | 점수에 실제 반영된 데이터에 근거한 설명 | [추천 매칭](matching.md) |

작업 분해·역할 초안과 회의 시간 계산은 위 후속 범위에 둡니다. AI가 확인되지 않은 자격·경험·역량을 추정하거나 추천 점수를 대신 정하는 정책은 포함하지 않습니다.

## 모바일 웹과 시연 기준

- **모바일 우선 반응형 웹 서비스**로 제공합니다. 문서와 발표에서도 이 표현을 사용합니다.
- 브라우저에서 URL로 접속하며 별도 설치 없이 시연합니다. 모바일 화면을 먼저 설계하고 데스크톱에서도 레이아웃이 깨지지 않도록 합니다.
- 로그인, 프로필, 공고 탐색, 팀 모집·지원, 팀장 관리를 웹 페이지로 제공하고 버튼·입력창·목록·상태 표시가 실제로 동작해야 합니다.
- 구체적인 모바일 UI 개발 기준은 [프론트엔드 가이드](../development/frontend.md)의 「모바일 UI」 절을 따릅니다.

| 시연 항목 | 기준 |
| --- | --- |
| 접속 | 배포된 웹 URL 또는 개발 서버 |
| 기본 시연 | 스마트폰 브라우저 |
| 보조 시연 | 데스크톱 브라우저의 모바일 화면 |

| 로그인 | 동일한 자체 로그인 경로를 사용하며 학교 인증 미제공·시연 계정 여부를 안내. [시연 계정 안내](authentication.md#demo-auth)를 따름 |
| AI | 실제 API 연동 여부를 사실대로 안내. 요약의 사용처·필요성과 MVP 포함 여부를 먼저 결정하며, 이 표시 기준이 요약 제공·AI 연동을 필수화하지 않음 |

### 실제·시연 데이터의 상호작용

[이슈 #53의 결정](https://github.com/wejo-team/sku-dreamon/issues/53#issuecomment-6234951428)에 따라 **실제·시연 계정·공고·팀을 서로 추천·지원·선발할 수 있게 허용**합니다. 시연 데이터라는 이유만으로 별도 후보 집합으로 분리하거나 상호작용을 차단하지 않습니다.

| 이용 계정 | 대상 공고·팀 | 추천·지원 |
| --- | --- | --- |
| 실제 계정 | 실제 공고·팀 | 기존 추천·접수 조건을 충족하면 허용 |
| 실제 계정 | 시연 공고·팀 | 기존 추천·접수 조건을 충족하면 허용 |
| 시연 계정 | 실제 공고·팀 | 기존 추천·접수 조건을 충족하면 허용 |
| 시연 계정 | 시연 공고·팀 | 기존 추천·접수 조건을 충족하면 허용 |

실제·시연 팀의 팀장은 해당 팀에 지원한 실제·시연 계정을 모두 검토·선발할 수 있습니다. 명세의 ‘실제 지원자’는 해당 팀에 지원한 후보를 뜻하며, 시연 계정을 제외한다는 의미로 사용하지 않습니다.

- [최초 공개 조건](contests.md#publication-policy), 마감·정원·자격·공모전별 소속 제한과 기존 추천·접수·선발 조건을 동일하게 적용합니다. 혼합 허용으로 현재 TBD인 자격 판정이나 추천 산식을 확정하지 않습니다.
- [자체 로그인·시연 계정 안내](authentication.md#demo-auth), 프로필 공개 범위와 팀 공간 접근 권한을 유지합니다. 시연 계정이라는 이유로 인증이나 관계별 권한을 우회하지 않습니다.
- 사용자에게 계정·공고·팀을 보여 주고 추천·지원·선발하는 흐름에서 시연용임을 구분해 안내합니다. 시연 데이터를 실제 모집이나 교내 인증 완료로 오해하게 표시하지 않습니다. 구체적인 표시 위치·문구·UI는 후속으로 정합니다.

데이터 저장 구조, 사용할 계정·공고·팀의 수와 선정, 준비·정리 절차 및 새 데이터의 시연 분류 기준은 미정입니다. 혼합 허용은 특정 DB 구성이나 시연 계정의 별도 로그인 기능을 채택하는 결정이 아닙니다.

## 전체 흐름의 완료 조건

기능별 예외·정책의 상세 완료 조건은 담당 명세에서 관리합니다. 아래 체크는 문서 이관 여부가 아닌 실제 구현과 검증 결과를 뜻합니다.

| 기존 조건 | 이슈 #20에 따른 변경 |
| --- | --- |
| AC-01 · 실제 교내 인증 또는 시연용 인증 가입 | 자체 로그인 경로로 대체; 새 조건은 AC-11 |
| AC-10 · 실제/시연 인증과 AI 연동 구분 | 인증 경로 변경으로 대체; 새 조건은 AC-12 |

- [ ] AC-02: 사용자가 필수 프로필을 작성하고 저장된 정보를 수정할 수 있다.
- [ ] AC-03: 사용자가 등록된 공모전 목록과 상세 정보를 확인할 수 있다.
- [ ] AC-04: 사용자가 공모전을 선택해 팀을 탐색하거나 모집글을 작성할 수 있다.
- [ ] AC-05: 사용자가 모집글에 지원하고 팀장은 해당 지원자 목록을 확인할 수 있다.
- [ ] AC-06: 시스템이 조건에 맞는 팀 또는 실제 지원자 후보를 근거와 함께 보여 준다.
- [ ] AC-07: 팀장이 지원자를 선발하고 지원자는 본인의 결과를 확인할 수 있다.
- [ ] AC-08: 팀장과 현재 확정 팀원만 팀 공간에서 공모전 정보·팀원·모집 및 매칭 상태를 확인할 수 있다. [팀 공간 접근 정책](team-recruitment.md#team-workspace-access)에 따라 팀장은 생성 시, 팀원은 선발·확정 즉시 접근하며, 지원 취소로 팀에서 이탈하면 접근이 종료된다. 공개 모집글·상세 열람과 구분하며 프로필의 비공개·별도 동의 정책을 유지한다.
- [ ] AC-09: 스마트폰 브라우저에서 주요 흐름을 설치 없이 이용하고, 데스크톱에서도 화면과 주요 동작을 사용할 수 있다.
- [ ] AC-11: 사용자가 학교 이메일·소셜 계정 없이 자체 아이디·비밀번호로 가입·로그인·로그아웃하고, 교내 미인증 상태를 확인할 수 있다. 상세 조건은 [인증 AC-04~09](authentication.md#acceptance-criteria)를 따른다.
- [ ] AC-12: 시연에서 자체 로그인 제공·학교 인증 미제공·시연 계정 여부와 실제 AI API 연동 여부가 사실에 맞게 표시된다. 요약 제공·AI 연동의 필수 여부는 이 표시 조건으로 정하지 않고 [#38의 요약 범위 결정](contests.md#summary-scope)을 먼저 따른다.
- [ ] AC-13: [시연 데이터 정책](#demo-data-scope)의 네 조합에서 기존 조건을 충족하면 추천·지원할 수 있고, 팀장은 실제·시연 구분과 무관하게 해당 팀의 지원자를 선발할 수 있다. 시연 데이터임을 확인할 수 있으며, 마감·정원·소속 제한이나 접근 권한 위반은 기존 정책대로 처리한다.
