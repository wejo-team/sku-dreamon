# 스프린트 1 범위와 완료 기준

- 구현 상태: 예정
- 명세 검토: [PR #17](https://github.com/wejo-team/wejo-app/pull/17)
- 구현 작업: 미등록

`스프린트1_기능정의_및_개발범위_정책확정본.pdf`의 전체 범위, 화면, 일정과 시연 기준을 관리합니다. 기능별 정책은 아래 담당 명세에서 정의합니다. 이 문서의 일정과 완료 조건은 계획이며, 구현·검증·배포 완료 기록이 아닙니다.

## 목적과 사용자

AI 기반 교내 공모전 도전 지원 서비스의 첫 흐름을 만듭니다. 교내 사용자는 인증과 프로필 작성을 마치고 공모전을 탐색해 팀을 만들거나 기존 팀에 지원합니다. 팀장은 실제 지원자를 검토·선발하고, 사용자는 추천과 자신의 지원 결과를 확인합니다. 운영자는 확인한 공고를 직접 등록·관리합니다.

## 원문 적용 기준

- PDF 1~6쪽은 기능 정의 본문, 7~9쪽은 정책 확정 부록입니다. 같은 항목이 달라진 경우 부록의 구체화된 기준을 적용합니다.
- 닉네임 우선 표시는 실명 입력·표시로, 포트폴리오 파일 업로드 가능성은 외부 URL만 제공하는 정책으로 정리합니다. 본문의 시간 입력 ‘필수 권장’은 부록의 ‘권장’을 적용합니다.
- 본문 팀 매칭 가중치는 예시이며, 실제 기준은 [추천 매칭](matching.md)의 부록 기반 확정 가중치입니다.
- 원문에서 정하지 않은 동작을 이관 과정에서 확정하지 않습니다. 기능별 미정 사항은 해당 명세에 남깁니다. 기존 `추가 리스트 최종.md`와의 선택지 차이는 [선택지 차이](profile-options.md#source-differences)에서 관리합니다.

## AI와 알고리즘의 역할

조건 비교는 재현 가능한 규칙으로 처리하고, 긴 문서를 읽기 쉬운 문장으로 바꾸는 요약에 생성형 AI를 활용하는 범위를 둡니다.

| 기능 | 처리 기준 | 담당 명세 |
| --- | --- | --- |
| 참가 자격 확인 | 규칙 기반 필터링 | [추천 매칭](matching.md) |
| 마감 여부 확인 | 날짜와 상태 기반 처리 | [공고](contests.md), [팀 모집과 지원](team-recruitment.md) |
| 공모전·팀·지원자 후보 순위 | 필수 조건 확인 후 규칙 기반 점수 계산 | [추천 매칭](matching.md) |
| 공고 요약·조건 정리 | 생성형 AI 활용 대상. 입력 형식·실제 사용 및 API 연동 여부는 미정이고 운영자가 원문 검수 | [공고](contests.md) |
| 매칭 이유 | 점수에 실제 반영된 데이터에 근거한 설명 | [추천 매칭](matching.md) |

작업 분해·역할 초안과 회의 시간 계산은 위 후속 범위에 둡니다. AI가 확인되지 않은 자격·경험·역량을 추정하거나 추천 점수를 대신 정하는 정책은 포함하지 않습니다.

## 모바일 웹과 시연 기준

- **모바일 우선 반응형 웹 서비스**로 제공합니다. 문서와 발표에서도 이 표현을 사용합니다.
- 브라우저에서 URL로 접속하며 별도 설치 없이 시연합니다. 모바일 화면을 먼저 설계하고 데스크톱에서도 레이아웃이 깨지지 않도록 합니다.
- 로그인, 프로필, 공고 탐색, 팀 모집·지원, 팀장 관리를 웹 페이지로 제공하고 버튼·입력창·목록·상태 표시가 실제로 동작해야 합니다.
- 구체적인 모바일 UI 개발 기준은 [프론트엔드 가이드](../development/frontend.md)의 「모바일 UI」 절을 따릅니다.

| 시연 항목 | 기준 |
| --- | --- |
| 접속 | 배포된 웹 URL 또는 개발 서버 |
| 기본 시연 | 스마트폰 브라우저 |
| 보조 시연 | 데스크톱 브라우저의 모바일 화면 |
| 데이터 | 확인된 공고 또는 시연용 공고·계정; 사용할 범위는 시연 전에 결정 |
| 인증 | 실제 교내 인증과 시연용 인증을 구분해 안내. [시연 인증 안내](authentication.md#demo-auth)를 따름 |
| AI | 실제 API 연동 여부를 명확히 표시 |

## 전체 흐름의 완료 조건

기능별 예외·정책의 상세 완료 조건은 담당 명세에서 관리합니다. 아래 체크는 문서 이관 여부가 아닌 실제 구현과 검증 결과를 뜻합니다.

- [ ] AC-01: 사용자가 실제 교내 인증 또는 시연용 인증을 거쳐 가입하고 두 방식의 차이를 확인할 수 있다.
- [ ] AC-02: 사용자가 필수 프로필을 작성하고 저장된 정보를 수정할 수 있다.
- [ ] AC-03: 사용자가 등록된 공모전 목록과 상세 정보를 확인할 수 있다.
- [ ] AC-04: 사용자가 공모전을 선택해 팀을 탐색하거나 모집글을 작성할 수 있다.
- [ ] AC-05: 사용자가 모집글에 지원하고 팀장은 해당 지원자 목록을 확인할 수 있다.
- [ ] AC-06: 시스템이 조건에 맞는 팀 또는 실제 지원자 후보를 근거와 함께 보여 준다.
- [ ] AC-07: 팀장이 지원자를 선발하고 지원자는 본인의 결과를 확인할 수 있다.
- [ ] AC-08: 팀 공간에서 공모전 정보·팀원·모집 및 매칭 상태를 확인할 수 있다. 팀원 확정 기준은 팀 명세에서 먼저 결정한다.
- [ ] AC-09: 스마트폰 브라우저에서 주요 흐름을 설치 없이 이용하고, 데스크톱에서도 화면과 주요 동작을 사용할 수 있다.
- [ ] AC-10: 시연에서 실제·시연 인증과 실제 AI API 연동 여부가 구분되어 표시된다.
