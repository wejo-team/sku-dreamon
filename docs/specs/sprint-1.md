# 스프린트 1 제품 개요와 범위

- 구현 상태: 예정
- 명세 검토: [PR #15](https://github.com/wejo-team/wejo-app/pull/15)
- 구현 작업: 미등록

이 문서는 간결한 PRD(제품 요구사항 문서) 개요로서 대상 사용자·제공 가치·스프린트 범위·화면·검증 기준을 관리합니다. 개별 기능의 정책·미정 사항·완료 조건은 해당 명세에서만 정의합니다. 제품 목적과 범위를 판단하거나 전체 흐름을 검토할 때 읽습니다.

<a id="product-context"></a>

## 대상 사용자와 제공 가치

교내 구성원이 공모전을 탐색하고 함께 참여할 팀을 만들거나 기존 팀에 지원하도록 돕는 서비스입니다. 스프린트 1은 교내 인증·프로필 설정부터 팀 모집·지원·매칭·선발 결과 확인까지 제공합니다.

| 대상·역할 | 제공할 가치 |
| --- | --- |
| 공모전 참여를 원하는 교내 사용자 | 공고의 자격·일정·공식 원문과 추천 근거를 확인하고, 참여할 팀을 탐색·지원하며 결과를 확인 |
| 팀을 모집하는 팀장 | 필요한 역할·인원·조건을 알리고, 실제 지원자 정보와 추천 근거를 바탕으로 검토·선발 |
| 공고를 관리하는 운영자 | 확인한 공고를 등록하고 요약·자격·마감 정보를 원문과 대조해 공개·수정 |

대상과 제공 가치는 원문 기능을 요약한 것입니다. 사용자 문제의 조사 근거와 제품 성과 기준은 원문에 없으며 [제품 성과 검토](#product-validation)에서 확인할 항목으로 남깁니다. 실제 가입 허용 대상은 [인증의 미정 사항](authentication.md#open-questions)을 따릅니다.

## 핵심 사용자 흐름

1. [가입·교내 인증](authentication.md)을 거쳐 인증 상태를 확인합니다.
2. [프로필](profile.md)을 작성하고 공개 범위를 확인합니다.
3. [공모전 공고](contests.md)를 탐색하고 자격·마감·공식 원문을 확인합니다.
4. 공모전을 선택해 [팀을 생성하거나 모집 중인 팀에 지원](teams.md)합니다.
5. [추천](matching.md)에서 조건에 맞는 공모전·팀·지원자 후보와 실제 데이터에 근거한 추천 이유를 확인합니다.
6. 팀장은 지원자를 검토·선발하고 지원자는 자신의 결과를 확인합니다. 팀원 확정 시점은 팀 명세에서 검토합니다.

## 포함 범위와 이후 검토

| 영역 | 스프린트 1 범위 | 이후 검토 또는 제외 |
| --- | --- | --- |
| 가입·인증 | 실제 교내 인증 또는 명확히 구분한 시연용 인증 | 신분증 등 별도 실명 본인확인 |
| 프로필 | 필수 정보 작성·수정, 공개 범위, 선택적 외부 포트폴리오 URL | 포트폴리오 파일 업로드·AI 분석 |
| 공모전 | 운영자 직접 등록·관리, 목록·상세, 공식 원문 확인, 요약 검토 | 외부 사이트 자동 수집 |
| 팀 모집·지원 | 공모전·목표·역할·인원 등록, 지원·취소·현황 확인 | 자체 채팅 |
| 추천 | 공모전·팀·실제 지원자를 대상으로 조건 필터·점수·근거 표시 | 자연어 대화형 매칭 |
| 팀원 확정·팀 공간 | 선발·결과 확인, 공모전 정보·팀원·모집 및 매칭 상태 표시 | 작업 분해·역할 초안·일정 조율 |
| 알림 | 서비스 화면 안에서 상태·결과 표시 | 푸시 알림 |
| 제공 형태 | 모바일 우선 반응형 웹, 데스크톱 사용 | 네이티브 앱·앱스토어 배포·설치 기능 |

필요하면 외부 메신저 링크를 제공할 수 있습니다. 링크 제공을 필수 기능이나 자체 채팅 구현으로 확대하지 않습니다.

후속 범위의 원문 방향은 작업 분해·역할 초안에 생성형 AI를, 회의 시간 계산에 일반 알고리즘으로 시간대 교집합을 사용하는 것입니다. 스프린트 1 요구사항이나 후속 구현 확정으로 취급하지 않습니다.

## 모바일 웹과 시연 기준

- 모바일 화면을 우선 설계하고 데스크톱에서도 사용할 수 있는 반응형 웹을 제공합니다.
- 모바일의 목록·상세·입력 화면은 단순하게 구성하고, 사용자와 팀장에게 각각 필요한 상태와 행동을 표시합니다.
- 버튼·입력창·목록·상태 표시와 핵심 사용자 흐름은 실제로 동작해야 합니다.
- 기본 시연은 스마트폰 브라우저, 보조 시연은 데스크톱 브라우저의 모바일 화면으로 진행합니다.
- 배포된 웹 URL 또는 개발 서버로 접속합니다. 운영 배포 플랫폼은 이 문서에서 확정하지 않습니다.
- 확인된 공고 또는 시연용 공고·계정을 사용하며 실제 정보와 시연 데이터를 구분합니다.
- 실제 교내 인증과 시연용 인증을 구분해 안내하고, 시연용 인증을 실제 보안 인증이 구현된 것으로 설명하지 않습니다.
- AI API 실제 연동 여부를 명확히 표시합니다. 규칙 기반 추천을 생성형 AI 추론으로 설명하지 않습니다.
- 문서와 발표에서는 제공 형태를 '모바일 우선 반응형 웹 서비스'로 표기합니다.

## 전체 흐름 검증

기능별 완료 조건은 [인증](authentication.md#acceptance-criteria), [프로필](profile.md#acceptance-criteria), [공고](contests.md#acceptance-criteria), [팀](teams.md#acceptance-criteria), [추천](matching.md#acceptance-criteria)에서 확인합니다. 선택지 구현을 검증할 때는 [공통 선택지](profile-options.md#acceptance-criteria)·[학사 구조](academic-structure.md#acceptance-criteria)의 조건도 확인합니다. 이 문서에는 조건의 사본이나 별도 구현 체크를 만들지 않습니다.

시연에서는 인증 → 프로필 → 공고 → 팀 모집·지원 → 추천·선발 결과 확인 흐름을 연결해 검증합니다. 실제 인증·AI 연동 여부와 시연 데이터 범위를 함께 기록합니다. 명세 이관·합의만으로 구현 완료나 배포 완료를 표시하지 않습니다.

## 제품 성과 검토

위 흐름의 동작 검증과 별도로, 실제 사용자가 가치를 얻는지 판단할 기준은 아직 정하지 않았습니다. 다음은 원문에 없는 기획 보완 질문이며, 이관 과정에서 새 기능이나 수치 목표를 확정한 것이 아닙니다.

| ID | 검토할 내용 |
| --- | --- |
| PRODUCT-01 | 우선 해결할 사용자 문제, 현재 공고·팀을 찾는 방법과 그 불편을 확인한 조사 근거 |
| PRODUCT-02 | 제공 가치를 확인할 사용자·팀장 대상 검증 방법과 대상 범위 |
| PRODUCT-03 | 공고 선택·팀 지원·선발 흐름에서 확인할 성과 지표·목표값·수집 방법 |

지표 수집이 새 기능이나 개인정보 처리를 요구한다면 별도 범위·정책 검토가 필요합니다. 성과 지표가 미정이라는 이유로 기능별 완료 조건을 충족한 것으로 간주하지 않습니다.

## 범위 확정 전에 확인할 사항

- 실제 인증과 시연 인증의 선택·시연 계정 및 데이터 범위를 정합니다. 인증 동작은 [인증의 미정 사항](authentication.md#open-questions)에서 검토합니다.
- 대상별 공개 범위와 설정·동의의 적용 관계는 [프로필의 미정 사항](profile.md#open-questions)의 PROFILE-01·02에서 검토합니다.
- 공고 요약의 입력 형식과 실제 AI API 연동 여부를 정합니다. 처리 범위는 [공고의 미정 사항](contests.md#open-questions)에서 검토합니다.
- 팀 확정 시점과 지원 상태 전이는 [팀의 미정 사항](teams.md#open-questions)에서 검토합니다.
- 추천 수식의 입력·동점·미입력 처리에서 남은 결정은 [추천의 미정 사항](matching.md#open-questions)에서 검토합니다.
