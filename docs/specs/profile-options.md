목록 변경 작업에는 아래 필요한 분류와 관리 원칙만 읽습니다.

## 목적과 범위

사용자 입력, 추천, 검색 필터, 통계가 같은 분류와 코드 의미를 사용하도록 합니다.
이 문서는 선택 가능한 값과 공통 데이터 관리 원칙을 정의합니다. 공개 범위는 [프로필](profile.md#visibility), LLM 추천의 동작·미정 내부 설계는 [추천 매칭](matching.md)에서 관리합니다.

## 공통 선택지

아래 선택지 표시는 `추가 리스트 최종.md`에서 이관했으며, 희망 역할은 아래 [역할 목록 결정](#role-policy)에 따라 6개를 제공합니다. 원문에 코드값은 없으며 아래 이름을 코드로 사용한다는 뜻이 아닙니다. 원문의 요일별 시간 구간은 2026-10-19 [주당 참여 가능 시간 정책](#weekly-availability)으로 대체합니다.

| 항목 | 선택지 |
| --- | --- |
| 관심 분야 | IT·기술 / 경영·창업 / 디자인 / 사회·문화 / 환경 / 교육 / 미디어·콘텐츠 / 보건·의료 / 정책 / 공공 |
| 희망 역할 | 기획 / 디자인 / 개발 / 마케팅 / 자료조사 / 발표 |
| 보유 역량 | 프로그래밍 / UI/UX / 데이터분석 / 영상 편집 / 문서 작성 / 서비스 기획 / 시장 조사 / 그래픽 디자인 / PPT 제작 / 데이터 시각화 / SNS 마케팅 / 콘텐츠 기획 / 발표·스피치 |
| 주당 참여 가능 시간 | 5시간 미만 / 5~10시간 미만 / 10~20시간 미만 / 20시간 이상. 참여 중인 모든 프로젝트를 합산한 자기신고 예상 총량이며 단일 선택 |
| 학적 상태 | 재학 / 휴학 / 졸업 |
| 학년 | 1학년 / 2학년 / 3학년 / 4학년 이상 / 해당 없음 |

[#77 최신 결정](https://github.com/wejo-team/sku-dreamon/issues/77#issuecomment-6260435650)에 따라 관심 분야·보유 역량·학적 상태에서도 기타와 보충 설명 입력을 제거합니다. 희망 역할의 기타 미제공은 유지합니다. 실제 기존 기타 값·설명 데이터의 전환은 OPTIONS-08에서 별도로 정하며 임의 삭제·자동 분류하지 않습니다.

프로필은 관심 분야 1~3개, 희망 역할 1~2개를 필수로 선택하고 보유 역량은 정해진 목록 안에서 별도 개수 상한 없이 선택할 수 있습니다. 학적 상태·학년은 선택 입력입니다. 관련 경험은 분야 선택 없이 3상태와 자유서술을 사용합니다. 필수 여부·본문 길이 등 입력 계약의 원본은 [프로필 입력 항목](profile.md#fields)입니다. 포트폴리오는 정해진 선택지 목록이 아닙니다.

### 희망 역할 목록

[이슈 #26의 결정](https://github.com/wejo-team/sku-dreamon/issues/26#issuecomment-6234780296)에 따라 희망 역할은 **기획·디자인·개발·마케팅·자료조사·발표의 6개만 제공**하고 ‘기타’는 포함하지 않습니다. 희망 역할용 기타 선택지·보충 설명 입력은 제공하지 않습니다. 이후 #77의 결정으로 관심 분야·보유 역량·학적 상태의 기타도 제거합니다.

필수·복수 선택 여부는 [프로필 입력 항목](profile.md#fields)을 따릅니다. 이 결정은 선택 가능한 역할의 범위를 정하며, [모집 역할 불일치만으로 추천·지원을 제한하지 않는 정책](matching.md#policy-decisions)을 바꾸지 않습니다. LLM 기반 추천으로 전환하며 기존 역할 점수·가중치 산식은 제외합니다.

## 주당 참여 가능 시간

2026-10-19 사용자 결정([#77](https://github.com/wejo-team/sku-dreamon/issues/77))에 따라 프로필의 요일별 3시간 가능 구간을 폐기하고, **참여 중인 모든 프로젝트를 합산한 주당 참여 가능 시간**을 받습니다. 팀장이 지원자를 검토할 때 참고하는 자기신고 예상 총량이며, 특정 팀에 제공하기로 약정한 시간이 아닙니다.

- [프로필 입력 항목](profile.md#fields)의 권장 입력을 유지하며 필수로 강제하지 않습니다. 아래 네 구간 중 하나를 선택하며 숫자를 직접 입력하지 않습니다. 미입력은 별도 상태이며 가장 낮은 구간으로 간주하지 않습니다. 미입력 총량이나 구체적인 요일·시각을 추정하지 않습니다.
- 여러 팀에 지원해도 프로필의 같은 값을 사용합니다. 변경을 저장하면 [현재 프로필을 사용하는 지원 검토](profile.md#application-profile)에 반영하며, 팀별 확정 일정이나 약속을 자동 수정하지 않습니다.
- 팀장이 이 값을 각 팀에 각각 사용할 수 있는 시간, 다른 활동을 차감한 잔여 시간, 일정 확보 또는 팀원 간 일정 교집합의 보장으로 해석하지 않도록 의미를 안내합니다.
- 등록값은 [전체 프로필 공개 상태와 지원 팀장 예외](profile.md#visibility)에 따라 표시합니다. 기존 지원을 받은 팀장의 최신 프로필 기반 AI 검토 허용과 일반 AI 사람 추천의 비공개 제외는 [프로필 정책](profile.md#application-profile)을 따릅니다. 실제 AI 입력 필드·모델·보존 방식은 추천 명세의 후속 설계 범위입니다. 시간 점수·겹침 비율·미입력 대체 점수는 제공하지 않습니다.
- 팀의 구체적인 일정 조율은 팀 공간의 후속 기능 구상입니다. 현재 미구현이며 상세 입력·동의·변경·시간대 정책은 TBD입니다. 프로필의 주당 총량 입력을 팀 일정 기능의 구현이나 약속으로 간주하지 않습니다.

2026-10-19 추가 사용자 결정으로 입력 구간과 경계를 다음과 같이 정합니다.

| 선택지 | 경계 의미 |
| --- | --- |
| 5시간 미만 | 예상 총량이 5시간보다 적음 |
| 5~10시간 미만 | 5시간 이상, 10시간 미만. 정확히 5시간이면 이 구간 |
| 10~20시간 미만 | 10시간 이상, 20시간 미만. 정확히 10시간이면 이 구간 |
| 20시간 이상 | 20시간 이상. 정확히 20시간이면 이 구간 |

한 프로필에는 한 구간만 선택합니다. 구간은 자기신고 참고 정보의 표현이며 실제 투입 시간 측정값이나 약정이 아닙니다. 구간별 고유 저장 ID와 기존 요일별 슬롯 데이터의 전환·재입력 처리는 OPTIONS-07에 남깁니다.

이 정책은 #77의 앞선 F10 한국시간·요일별 3시간 슬롯 합의를 **프로필 입력에 한해 대체**합니다. 그 합의를 팀 일정 시간대 정책으로 자동 적용하지 않습니다. 기존 `time-slots` 앵커는 과거 링크 호환을 위해 유지합니다.

## 코드와 공통 데이터 관리

2026-10-22 사용자 결정으로 MVP의 분야·역할·역량·학적 상태·학년·주당 참여 가능 시간·프로필 이미지 선택지는 **애플리케이션의 공통 enum과 그 메타데이터**로 관리합니다. 코드·표시명·표시 순서·선택 가능 여부를 서버의 한 정의에서 제공하고, 화면별 목록이나 공통코드 DB 테이블을 따로 두지 않습니다. 목록 변경은 코드 수정·검토·배포로 반영합니다. 대학·학부·학과·전공의 계층과 소속 경로는 별도 [학사 설계](../database/catalogs.md#academic-tables)를 유지합니다.

| 원칙 | 정책 |
| --- | --- |
| 식별자·표시명 분리 | 공통 선택지는 고유 코드, 학사 항목은 증가형 ID로 식별하고 화면에는 표시명을 출력. 동일 의미의 표기만 통일하며 기존 식별자·선택값 연결을 보존. 실제로 다른 학과·전공은 비슷한 이름만으로 합치지 않음 |
| 단일 관리 | 공통 선택지 7종은 서버의 같은 enum 정의를 조회·입력 검증·검색에서 사용하고 목록 API로 제공. 학사 계층은 학사 테이블을 원본으로 사용. 화면별 별도 목록 금지 |
| 관심 분야 정의 | 서비스가 정한 공통 분류를 코드로 관리. MVP에서 관리자 화면이나 DB 수정으로 선택지를 편집하는 기능은 제공하지 않음 |
| 입력 형태 | 필드별 단일·복수 값 구분은 프로필 명세를 따름. 주당 참여 가능 시간은 정해진 네 구간 중 단일 선택이며 미입력을 허용 |
| 기타 제거 | 관심 분야·보유 역량·학적 상태의 기타 선택지·보충 설명 입력 제거, 희망 역할 기타 미제공 유지. 실제 기존 데이터의 전환 방식은 OPTIONS-08에서 결정 |
| 미입력·미확인 | 명시적 불일치·경험 없음·최저 시간 구간과 구분. 사용자 자격 정보가 부족하면 원문 확인을 안내하고 일반 팀 지원으로 접수하되 자격 충족을 보장하지 않는 [지원 정책](profile.md#before-application)을 따름 |
| 공통 활용 | 공모전·팀·지원자 추천, 검색 필터, 통계 집계에서 동일한 표준 코드와 분류 의미를 사용 |
| 학사 정보 갱신 | 학교 공식 학사 정보를 기준으로 갱신. [학사 선택 정책](academic-structure.md#selection-policy)에 따라 새 선택은 현행 목록만 허용하고 폐지·통합 항목은 비활성화하여 저장된 과거 기록과 연결 유지 |
| 변경 근거 | enum 목록의 추가·수정·비활성화 날짜와 사유는 Git·PR 기록에 남김. 학사 목록도 시드·마이그레이션으로 반영하고 공식 출처·적용 대상·변경 사유는 문서·PR에서 관리하며 별도 DB 변경 이력은 두지 않음. 추천 내부 설계는 [LLM 추천의 TBD](matching.md#open-questions)로 구분 |

사용자가 고른 코드는 프로필 컬럼·연결 테이블에 저장하고, 서버가 해당 종류의 enum 값과 새 선택 가능 여부를 검사합니다. 이미 저장된 코드는 enum 정의에서 삭제하거나 다른 의미로 재사용하지 않고 비활성 상태로 남겨 기존 값의 표시·유지를 지원합니다.

공식 학사 목록의 이관 값과 출처 검증 상태는 [학사 목록](academic-structure.md#catalog)에서 관리하며, 실제 목록의 ID 대응은 해당 명세의 미정 사항을 따릅니다. 이 문서의 공통 선택지 표는 표시 정책이며, 실제 기술 코드 사전은 [서버 enum](../../backend/app/domains/catalogs/codes.py)에 명시적인 영문 `snake_case`로 정의합니다. 기존 운영 데이터 전환과 공식 학사 원장은 별도 범위입니다.

| 참고 화면 | 동작과 정책 구분 |
| --- | --- |
| 관심 분야·희망 역할·역량 | 공통 체크박스를 사용하고 관심 분야 1~3개·희망 역할 1~2개를 검사합니다. 관심 분야·역량의 기타 선택과 보충 설명 입력은 제공하지 않습니다. |
| 주당 참여 가능 시간 | [확정한 네 구간](#weekly-availability) 중 하나를 고르거나 미입력으로 둘 수 있습니다. 모든 참여 프로젝트를 합산한 자기신고 참고값이라는 설명을 함께 표시합니다. |
| 시간 수정·저장·취소 | 프로필 편집의 선택값은 초안이며 최종 `변경사항 저장`으로 적용합니다. 편집을 취소하면 기존 저장값을 유지합니다. 별도의 요일·시간 슬롯 팝업은 제공하지 않습니다. |
| 초기 데이터 | 기존 요일·슬롯 문자열을 합산하거나 추정해 새 시간 값으로 바꾸지 않고 초기 주당 시간을 미입력으로 둡니다. 실제 기존 데이터 전환은 별도 계약입니다. |

표시 문자열과 메모리 상태는 운영용 고유 코드·목록 버전·API·DB 저장 형식이나 기존 데이터 전환 구현이 아닙니다. 시간 겹침 점수·비율, 팀별 배정·잔여 시간·확정 일정은 제공하지 않습니다.

<a id="acceptance-criteria"></a>

## 완료 조건

- [ ] AC-01: 같은 분류 항목을 프로필·추천·검색에서 조회할 때 동일한 코드 의미와 표시명을 사용한다.
- [ ] AC-02: 표시명을 변경해도 기존 사용자 선택값의 의미와 연결이 유지된다.
- AC-03(폐기): 요일별 3시간 구간 선택·자정 경계 확인 조건은 2026-10-19 주당 참여 가능 시간 정책으로 대체합니다. 번호는 과거 참조용으로 남기며 새 조건은 AC-08을 사용합니다.
- AC-04(폐기): 기타 보충 설명 입력 조건은 #77의 기타 제거 결정으로 대체합니다. 번호는 과거 참조용으로 남기며 새 조건은 AC-10을 사용합니다.
- [ ] AC-05: 미입력·미확인 값이 명시적인 불일치 값과 구분된다.
- [ ] AC-06: 학사 항목이 폐지·통합되어 비활성화돼도 과거 사용자 기록과의 연결을 유지하고, 관련 문서·PR에서 변경 사유·공식 근거를 확인할 수 있다.
- [ ] AC-07: 희망 역할로 기획·디자인·개발·마케팅·자료조사·발표만 선택·저장할 수 있고 ‘기타’를 추가로 선택·저장할 수 없다. 모집 역할과 다르다는 이유만으로 추천 후보를 제외하거나 지원을 막지 않는다.
- [ ] AC-08: 주당 참여 가능 시간은 참여 중인 모든 프로젝트를 합산한 자기신고 예상 총량으로 안내하며, 특정 팀의 약정·잔여 시간이나 일정 확보·교집합 보장으로 표시하지 않는다. 미입력을 허용하고 이를 가장 낮은 구간으로 취급하지 않는다.
- [ ] AC-09: 주당 참여 가능 시간은 `5시간 미만`, `5~10시간 미만`, `10~20시간 미만`, `20시간 이상` 중 하나만 선택한다. 정확히 5시간·10시간·20시간은 각각 두 번째·세 번째·네 번째 구간으로 안내하며 숫자 직접 입력은 제공하지 않는다.
- [ ] AC-10: 관심 분야·보유 역량·학적 상태에 기타와 보충 설명 입력을 제공하지 않는다. 기존 실제 데이터의 전환은 별도 결정 없이 삭제·재분류하지 않는다.
- [ ] AC-11: 같은 의미의 이전 표기를 정규화해도 기존 식별자와 선택 연결을 유지하고, 이름이 비슷하지만 다른 학과·전공을 합치지 않는다.

## 미정 사항

| ID | 결정할 내용 |
| --- | --- |
| OPTIONS-02 | 초기 기술 코드는 서버 enum에 정의. 기존 운영 코드·선택 연결의 이관 적용 여부는 별도 확인하며, 기존 식별자 보존 원칙과 폐기한 요일·시간 슬롯 제외를 유지 |
| OPTIONS-07 | 주당 참여 가능 시간 구간의 초기 코드는 서버 enum에 정의. 기존 요일별 슬롯 데이터의 전환·재입력 처리. 기존 구간을 합산해 자기신고 주당 총량이 입력된 것으로 자동 취급하지 않음 |
| OPTIONS-08 | 제거된 기타 선택지·보충 설명을 사용하는 실제 기존 데이터의 전환·보존·재입력 방식 |

OPTIONS-01은 [희망 역할 6개·기타 제외](#role-policy), OPTIONS-03은 기타 선택지·설명 입력 제거, OPTIONS-04는 [경험 3상태·분야 선택 없는 500자 자유서술](profile.md#experience)로 반영했습니다. 실제 코드 사전과 기존 데이터 전환은 위 후속 항목에서 정합니다.

기존 OPTIONS-05의 프로필 슬롯 시간대·주 경계·팀 슬롯 일치 여부는 주당 총량 정책으로 대체해 프로필 입력 요구에서 제외합니다. 팀 공간의 후속 일정 기능은 여전히 미구현·상세 TBD이며, 이 변경으로 시간대나 일정 입력 방식을 확정하지 않습니다.

OPTIONS-06의 입력 형태·허용값은 2026-10-19 [주당 참여 가능 시간의 네 구간 단일 선택](#weekly-availability)으로 반영했습니다. 권장 입력을 유지하며 미입력을 낮은 구간과 구분합니다. 이 결정이 구간 저장 ID나 기존 슬롯 데이터 전환 방식까지 확정하지는 않습니다.
