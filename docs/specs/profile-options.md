# 프로필 선택지와 공통 코드

- 구현 상태: 예정
- 명세 검토: [PR #14](https://github.com/wejo-team/wejo-app/pull/14)
- 구현 작업: 미등록

공통 선택지와 코드 관리 원칙을 옮긴 초안입니다. 필드의 필수 여부·단일/복수 입력은 [프로필 입력 항목](profile.md#fields), 대학·학부·전공 관계는 [학사 분류](academic-structure.md)에서 정의합니다.
목록 변경 작업에는 아래 필요한 분류와 관리 원칙만 읽습니다.

## 목적과 범위

사용자 입력, 추천, 검색 필터, 통계가 같은 분류와 코드 의미를 사용하도록 합니다.
이 문서는 선택 가능한 값과 공통 데이터 관리 원칙을 정의하며, 프로필 공개 범위와 추천 계산식을 정의하지 않습니다.

<a id="choices"></a>

## 공통 선택지

아래 선택지 표시는 `추가 리스트 최종.md`의 값을 그대로 보존했습니다. 원문에 코드값은 없으며 아래 이름을 코드로 사용한다는 뜻이 아닙니다.

| 항목 | 선택지 |
| --- | --- |
| 관심 분야 | IT·기술 / 경영·창업 / 디자인 / 사회·문화 / 환경 / 교육 / 미디어·콘텐츠 / 보건·의료 / 정책 / 공공 / 기타 |
| 희망 역할 | 기획 / 디자인 / 개발 / 마케팅 / 자료조사 / 발표 |
| 보유 역량 | 프로그래밍 / UI/UX / 데이터분석 / 영상 편집 / 문서 작성 / 서비스 기획 / 시장 조사 / 그래픽 디자인 / PPT 제작 / 데이터 시각화 / SNS 마케팅 / 콘텐츠 기획 / 발표·스피치 / 기타 |
| 활동 가능 요일 | 월/화/수/목/금/토/일 |
| 활동 가능 시간 | 00:00~03:00 / 03:00~06:00 / 06:00~09:00 / 09:00~12:00 / 12:00~15:00 / 15:00~18:00 / 18:00~21:00 / 21:00~24:00 |
| 학적 상태 | 재학 / 휴학 / 졸업 / 기타 |
| 학년 | 1학년 / 2학년 / 3학년 / 4학년 이상 / 해당 없음 |

원문 공통 표의 포트폴리오·관련 경험은 정해진 선택지 목록이 아니므로 [프로필 입력 항목](profile.md#fields)에서 입력 정책을 관리합니다.

### 문서 간 선택지 차이

| 항목 | 정책 부록 | 추가 리스트 | 이관 처리 |
| --- | --- | --- | --- |
| 희망 역할 ‘기타’ | 기획·디자인·개발·마케팅·자료 조사·발표·기타 | 기타 없음 | 누락인지 제외 결정인지 미정; 위 이관 표에 조용히 추가하지 않음 |
| 자료 조사 | 띄어 씀 | 자료조사 | 같은 의미의 표기인지 코드 확정 때 정규화 여부 확인 |
| 데이터 분석 | 띄어 씀 | 데이터분석 | 같은 의미의 표기인지 코드 확정 때 정규화 여부 확인 |
| 관심 분야·보유 역량 | 대표 분류를 ‘등’으로 제시 | 구체 목록 제공 | 구체 목록을 이관하되 공식 코드 부여·검토 완료로 취급하지 않음 |
| 기타 보충 설명 | 기타 선택 때만 보충 설명 입력 가능 | 직접 입력 여부를 개발 시 확인 사항으로 둠 | 부록의 조건부 입력 원칙 보존; 적용 항목·필수 여부는 미정 |

<a id="time-slots"></a>

## 활동 가능 시간

- 요일별로 3시간 단위 구간을 복수 선택합니다.
- `24:00`은 다음 날 `00:00`을 의미합니다.
- 활동 가능 시간은 요일과 시간 구간의 집합으로 저장합니다.
- 구체적인 개인 일정의 공개 대신 매칭에 필요한 겹침 정보만 노출하는 정책은 [프로필 공개 범위](profile.md#visibility)에 둡니다.
- 팀 활동 시간에도 동일 구간을 사용할지, 시간대 기준과 주 경계에서 어떻게 처리할지는 원문에 없어 미정입니다.

이 절은 입력 슬롯을 정의합니다. 겹치는 구간의 비율·점수·미입력 점수는 추천 정책의 책임입니다.

<a id="catalog-management"></a>

## 코드와 공통 데이터 관리

| 원칙 | 정책 |
| --- | --- |
| 코드·표시명 분리 | 각 항목은 변경되지 않는 고유 코드로 저장하고 화면에는 표시명을 출력. 표시명 변경으로 기존 데이터 의미가 바뀌지 않아야 함 |
| 단일 관리 | 학적 상태·학년·단과대학·전공·학과·관심 분야·희망 역할·보유 역량을 공통 기준 목록으로 관리. 화면별 별도 목록 금지 |
| 관심 분야 정의 | 관리자가 정의한 공통 분류를 사용. 관리자 편집 화면·관리 기능의 구현 범위는 원문에 정의되지 않음 |
| 입력 형태 | 필드별 단일·복수 값 구분은 프로필 명세를 따름. 시간은 요일·구간의 집합 |
| 기타 | 기타를 선택한 경우에만 보충 설명을 입력할 수 있음. 표준 코드와 분리해 저장하며 자동으로 새 표준 분류로 취급하지 않음 |
| 미입력·미확인 | 불일치로 간주하지 않고 별도 상태로 저장. 필수 자격의 통과 여부는 추천·지원 정책에서 판단 |
| 공통 활용 | 공모전·팀·지원자 추천, 검색 필터, 통계 집계에서 동일한 표준 코드와 계산 규칙을 사용 |
| 학사 정보 갱신 | 학교 공식 학사 정보를 기준으로 갱신. 폐지·통합 항목을 즉시 삭제하지 않고 비활성화하여 과거 기록과 연결 유지 |
| 변경 이력 | 목록의 추가·수정·비활성화 날짜와 변경 사유 기록. 점수 가중치의 버전·적용일은 추천 정책에서 관리 |

공식 학사 목록의 이관 값과 출처 검증 상태는 [학사 목록](academic-structure.md#catalog)에서 관리합니다. 현재 표는 코드가 부여된 운영 데이터나 구현된 설정 파일이 아닙니다.

<a id="acceptance-criteria"></a>

## 완료 조건

- [ ] AC-01: 같은 분류 항목을 프로필·추천·검색에서 조회할 때 동일한 코드 의미와 표시명을 사용한다.
- [ ] AC-02: 표시명을 변경해도 기존 사용자 선택값의 의미와 연결이 유지된다.
- [ ] AC-03: 사용자가 요일별 3시간 구간을 복수 선택하고 `21:00~24:00` 구간의 끝을 다음 날 `00:00`으로 구분할 수 있다.
- [ ] AC-04: 기타 보충 설명은 표준 코드와 분리되며 설명을 입력해도 공통 선택지에 자동 추가되지 않는다.
- [ ] AC-05: 미입력·미확인 값이 명시적인 불일치 값과 구분된다.
- [ ] AC-06: 학사 항목이 폐지·통합되어 비활성화돼도 과거 사용자 기록과의 연결, 변경 날짜·사유를 확인할 수 있다.
