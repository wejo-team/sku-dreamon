# 팀 모집·지원·선발과 팀 공간

- 구현 상태: 예정
- 명세 검토: [PR #17](https://github.com/wejo-team/sku-dreamon/pull/17)
- 구현 작업: 미등록
- 변경 검토: 2026-10-19 배포 프로토타입 v12의 팀 탐색·생성·워크스페이스·지원 흐름 대조, 이 변경 PR에서 사람 검토 대기

스프린트 1의 팀 생성부터 지원 결과 확인까지를 정의합니다. LLM 추천 후보·추천 이유는 [추천 매칭](matching.md), 공고 정보와 마감 관리는 [공모전 공고](contests.md), 전체 개발 범위는 [스프린트 1](sprint-1.md)을 따릅니다.

## 목적과 사용자

교내 사용자가 선택한 공모전에 참여할 팀을 만들거나 모집 중인 팀에 지원할 수 있게 합니다. 팀장은 실제 지원자를 검토하고 선발하며, 지원자는 자신의 상태와 결과를 확인합니다. 확정된 팀은 최소 팀 공간에서 공모전과 팀원 정보를 확인합니다.

## 범위

| 항목 | 스프린트 1 범위 |
| --- | --- |
| 팀 생성 | 공모전, 팀 목표, 필요한 역할, 모집 인원 등록 |
| 팀 탐색 | 선택한 공모전의 팀 목록·상세, 모집 조건·모집글 조회 |
| 모집글 작성 | 공모전, 역할, 인원, 마감 설정 |
| 지원 | 모집글에 지원·선발 후를 포함한 지원 취소·조건 충족 시 재지원, 내 지원 현황과 결과 확인 |
| 팀장 관리 | 지원자 목록·매칭 후보 조회, 지원자 검토·선발 |
| 팀원 확정 | 팀장 선발 즉시 팀원 확정·정원 차감, 지원자는 결과 확인 |
| 팀 공간 | 팀장·현재 확정 팀원이 접근해 공모전 기본 정보, 확정된 팀원, 모집·매칭 상태 확인 |
| 작업 분해·역할 제안·일정 조율 | 스프린트 2 이후 검토 |
| 사용자 간 자체 채팅 | 초기 범위 제외; 필요하면 외부 메신저 링크 제공. AI 탐색 대화와 구분 |

지원자의 별도 수락 단계는 제공하지 않습니다. 외부 메신저 링크 제공 여부와 방식은 확정되지 않았습니다.

## 사용자 흐름과 동작

### 공모전 선택과 팀 탐색

1. 사용자가 공개 공모전 목록·상세에서 참여할 공모전을 확인합니다. 공개 공고·팀 모집 정보는 [로그인 없이 탐색](authentication.md#access-policy)할 수 있습니다.
2. 공모전 상세에 바로 표시한 해당 공모전의 공개 팀 목록이나 탐색의 팀 탭에서 팀 조건과 모집글을 확인합니다. 팀 목록의 일반 검색·필터와 AI 추천을 구분하고, 탐색 검색창·공모전 상세의 AI 아이콘을 통해 팀 추천으로 이동합니다.
3. 사용자는 [로그인](authentication.md#access-policy) 후 참여할 팀에 지원하거나 새 팀과 모집글을 작성합니다. 지원 직전에는 [필수 정보 누락 점검·보완](profile.md#before-application)을 거칩니다. 추천 표시 정보와 실행 시점은 [추천 매칭](matching.md)을 따릅니다.

자체 로그인 성공은 교내 인증 완료를 뜻하지 않지만 교내 미인증 자체로 참여를 막지는 않습니다. 팀 공간·지원자 관리·타인 프로필은 기존 관계별 권한을 적용합니다. 팀 생성에 필요한 프로필 완성 범위와 자격 확인 필요의 실제 지원 접수는 각 [프로필](profile.md#open-questions)·[추천](matching.md#open-questions)의 미정 사항에 남깁니다.

팀 탐색은 팀명·소개/목표·모집 역할·공모전명으로 검색하고, 역할 하나와 `모집중만` 조건으로 좁힙니다. 역할 필터는 탐색 조건이며 [역할 불일치 지원 허용](#recruitment-information)을 바꾸지 않습니다. 필터 팝업은 선택 초안을 적용한 때에만 목록을 변경하고 취소·닫기는 기존 조건을 유지합니다. 탐색의 팀 탭은 [공통 페이지 이동 정책](sprint-1.md#exploration-pagination)에 따라 현재 조건의 전체 결과 수·총페이지와 페이지 번호 이동을 제공합니다. 조건·탭 변경 시 1페이지로 이동하며 상세에서 돌아오면 검색·필터·페이지를 유지합니다. 조건 초기화는 현재 탐색 탭을 유지하고 검색어·역할·모집 조건·공모전 조건을 해제합니다. 검색 결과가 없으면 조건 변경·초기화를 안내합니다.

공모전 상세의 팀 목록은 [상세 안의 팀 목록과 행동](contests.md#contest-teams)을 따릅니다. 현재 공모전과 연결된 공개 팀만 바로 보여 주며 별도 팀 찾기 버튼은 두지 않습니다. 생성·AI 진입은 아이콘으로 제공하고 팀이 없는 열린 공고에는 생성을 권유합니다. 마감 공고의 신규 생성·추천 행동은 제공하지 않으며, 공개 목록 열람과 실제 지원 접수 조건은 구분합니다.

공개 팀 카드는 모집 상태·확정 인원·팀명·소개·모집 역할·공모전명을 제공하고 카드 전체로 공개 모집글에 이동합니다. 공모전 상세 안의 팀 카드에서는 상위 화면에 표시한 공모전명을 반복하지 않습니다. 이 공개 카드로 지원자 목록이나 팀 공간을 노출하지 않습니다. 목록의 상태 필터와 실제 접수 가능 여부를 구분하며, 신규 접수는 [검토 중 접수](#recruitment-review)와 [마감·정원](#recruitment-conditions) 정책을 따릅니다. 현재 집계·필터의 제한과 최종 표시 기준의 후속 항목은 아래 [대조 범위](#reference-scope)에 남깁니다.

### 팀 생성과 모집글 작성

팀을 만드는 사용자는 공모전, 팀 목표, 필요한 역할, 모집 인원을 등록하고 모집 마감을 설정합니다. 팀장은 이 모집 조건을 바탕으로 지원자를 확인하고 선발합니다.

공모전은 검색 가능한 하단 팝업에서 선택합니다. 공모전명·주최자·분야로 찾고 결과에 제목·주최자·분야·마감을 함께 보여 같은 이름의 공고도 구분합니다. 항목을 선택하면 입력에 반영하고 팝업을 닫습니다. 선택하지 않고 닫거나 결과가 없더라도 기존에 선택한 공모전을 지우지 않으며, 검색어 지우기·결과 추가 표시·키보드 선택을 제공합니다. 공모전 상세에서 진입한 경우 해당 공모전을 미리 선택합니다.

개인 참가 전용 공고에서도 [함께 준비하는 팀을 생성](contests.md#participation-policy)할 수 있으며, 공동 출전하는 팀과 구분해 안내합니다. 준비 목적의 팀에도 이 문서의 공모전별 소속 제한·팀장 포함 정원·선발·지원 정책을 적용합니다.

팀 생성 시 생성자는 확정 팀장 소속을 갖습니다. 이미 같은 공모전의 팀에 소속되어 있으면 새 팀 생성을 허용하지 않으며, [공모전별 소속 제한](#membership-limit)을 적용합니다.

| 정보 | 사용 목적·확인된 요구사항 |
| --- | --- |
| 팀명 | 팀 추천 결과에서 팀을 구분해 표시 |
| 공모전 | 참여 대상 공모전 연결, 목록·상세·팀 공간의 공모전 정보 표시 |
| 팀 목표 | 팀 생성 시 등록하는 목표 |
| 필요한 역할 | 팀장이 현재 모집하는 역할을 안내하고 지원자 선발 시 판단. 역할 불일치만으로 추천·지원을 강제 제한하지 않음 |
| 모집 인원 | 팀장을 포함한 전체 정원. 생성·목록·상세·팀 공간에서 같은 계산 의미를 유지하되 워크스페이스 요약은 `확정 인원 / 정원`으로 간결하게 표시하고 “팀장 포함 총 N명” 반복 문구는 생략. 생성 입력·모집 상세에서는 정원의 의미를 안내. 공동 출전 팀의 목표 정원은 [확인된 공식 인원 조건](#official-capacity)을 적용 |
| 모집 마감 | 모집글 작성 시 설정, 지원 가능 여부 판단 |
| 팀 관심 분야 | 팀 주제 설명과 탐색·추천의 근거 정보 |
| 활동 시간 구간 | 입력 범위·활용은 후속 검토. 확인되지 않은 시간 겹침 수치를 만들거나 개인 상세 일정을 노출하지 않음 |
| 명시적 참가·모집 조건 | 학년·전공 등 실제로 요구하는 조건만 필수 필터에 사용 |

팀명·팀 관심 분야·활동 시간은 원문에서 팀의 설명·입력으로 다루는 정보입니다. 입력 필수 여부, 입력 제약, 공모전 정보에서 가져오는 범위는 원문에 없으므로 임의로 확정하지 않습니다. 추천은 [LLM 기반](matching.md#policy-decisions)으로 변경하며, 원문의 ‘필수 활동 시간’이라는 명칭만으로 모든 구간의 참석을 지원 필수 조건으로 추가하지 않습니다.

### 모집 정보 관리

[이슈 #30의 결정](https://github.com/wejo-team/sku-dreamon/issues/30#issuecomment-6232752606)에 따라 모집 역할은 팀장의 판단과 안내를 위한 정보입니다. 팀장은 이미 모집된 분야 때문에 지원자가 혼동하지 않도록 프로젝트 워크스페이스(팀 공간)의 모집 정보·현재 필요한 역할 안내를 갱신하는 방향으로 관리합니다.

역할 불일치 자체로 추천 후보에서 제외하거나 지원을 차단하지 않고 실제 선발은 팀장이 판단합니다. 참가 자격·마감·전체 정원 등 다른 정책은 유지합니다. 역할별 자동 정원 차감이나 역할 충족 판정은 추가하지 않으며, 수정 가능한 항목·화면·시점·표시 반영 방식은 TEAM-07·TEAM-08에서 후속 정의합니다.

### 지원·취소와 내 지원 현황

1. 사용자가 팀 상세에서 모집 조건과 지원 가능 상태를 확인합니다. 지원은 로그인 후 가능하며, 모든 지원의 제출 직전에 [누락된 필수 정보를 보완](profile.md#before-application)하도록 요청합니다. 제출 전에는 **비공개 프로필도 지원받은 팀장에게는 등록된 모든 항목이 보인다**는 [지원 팀장 예외](profile.md#visibility-priority)를 안내합니다. 활동 가능 시간·포트폴리오 URL·제목도 포함하며, 일반 사람 탐색의 공개 상태는 바꾸지 않습니다.
2. 지원자는 내 지원 현황에서 지원 상태를 확인합니다.
3. 사용자는 지원 완료·검토 중·선발 후에도 [지원 취소](#application-cancellation)를 할 수 있습니다. 선발 후 취소는 확정 팀원 관계를 해제하고 자리를 반환합니다.
4. 팀장의 검토·선발 이후 지원자는 자신의 결과를 확인합니다.
5. 취소 후에는 [현재 모집 조건을 충족하면 즉시 재지원](#reapplication)할 수 있습니다. 재지원만으로 이전 선발 결과가 복원되지는 않습니다.

지원할 역할을 선택하고 선택 메시지를 입력한 뒤 제출합니다. 모집글에 안내한 역할 외의 역할도 선택할 수 있습니다. 지원 중에는 중복 제출을 막고 실패하면 입력을 유지하며 재시도할 수 있게 합니다. 지원 취소는 확인 팝업을 거치며, 선발 후 취소에서는 팀원 제외·팀 공간 접근 종료와 현재 모집 조건에 따른 재지원 제한을 먼저 설명합니다. 확인하지 않고 닫으면 취소하지 않습니다.

<a id="application-message"></a>

지원 전 선택 입력으로 “팀에 전할 말”을 최대 1,000자까지 작성할 수 있습니다. 비워도 지원할 수 있고 초과 입력은 접수 전에 안내합니다. 메시지는 해당 지원의 본인과 지원 팀장에게만 표시하며 공개 사람 프로필에 노출하지 않습니다. 제출 후 메시지 수정·이력 정책은 TEAM-09에 남깁니다.

초기 알림은 [서비스 알림함](notifications.md)과 각 화면의 현재 상태 표시로 처리합니다. 푸시 알림은 후속 검토 범위입니다. 프로필 변경 사실에 대한 별도 알림·배지·전후 비교 안내는 MVP에서 제공하지 않습니다.

### 팀장 검토·선발과 팀 공간

1. 팀장은 관리 화면에서 자신의 팀에 접수된 지원자 목록을 확인합니다.
2. 실제 지원자 중 조건에 맞는 매칭 후보와 근거를 확인합니다. 지원하지 않은 사용자 전체를 지원자 추천 대상으로 삼지 않습니다.
3. 지원 검토에 필요한 프로필 정보를 [공개 범위](profile.md#visibility)에 따라 확인하고 지원자를 선발합니다. 지원자의 공개·비공개 상태와 관계없이 등록된 전체 현재 프로필을 확인합니다. 지원 후 프로필이 바뀌면 다음 조회·새로고침에서 검토 정보와 추천을 [현재 프로필 기준](profile.md#application-profile)으로 함께 확인합니다.
4. 선발 시 정원과 [공모전별 소속 제한](#membership-limit)을 함께 확인합니다. 선발 처리가 성공하면 해당 지원자가 즉시 확정 팀원에 포함되고 남은 정원이 한 자리 줄어듭니다. 지원자는 내 지원 현황에서 선발·팀원 확정 결과를 확인하며, 별도로 수락하지 않습니다.
5. 팀 공간에는 공모전 기본 정보, 확정된 팀원, 모집·매칭 상태를 표시합니다.

[팀원 확정과 정원 정책](#membership-capacity)은 개별 지원자가 팀원이 되는 시점을 정합니다. 검토 중 접수는 [모집과 검토의 병행](#recruitment-review), 팀 공간 접근 대상·시점은 [팀 공간 접근](#team-workspace-access)을 따릅니다. 나머지 팀 전체 모집 상태의 전이·종료는 TEAM-02에서 별도로 결정합니다.

선발 확인 팝업에는 즉시 팀원 확정·자리 한 개 차감·별도 수락 단계가 없음을 설명합니다. 팀장이 모집을 종료할 때도 확인 팝업에서 신규 지원 중단과 기존 지원·확정 팀원 유지를 안내하며, 확인하지 않고 닫으면 변경하지 않습니다. 처리 실패 시 현재 상태를 다시 확인하도록 안내하고 성공으로 표시하지 않습니다.

<a id="workspace-ui"></a>

### 워크스페이스와 내 지원 표시

워크스페이스에는 본인이 팀장이거나 현재 확정 팀원인 팀만 표시합니다. 지원 완료·검토 중이라는 이유만으로 내 팀에 포함하지 않습니다. `내 팀` 또는 `내 지원` 제목과 개수를 보여 주고, 옆에 내 지원 목록 아이콘과 팀 만들기 더하기 아이콘을 배치합니다. 아이콘은 각각 `내 지원`, `팀 만들기`라는 접근성 이름을 가지며 내 지원 화면에서는 선택 상태와 내 팀 복귀를 제공합니다. 목록이 비어 있으면 팀 탐색으로 연결합니다.

내 팀 카드에는 모집 상태·팀명·공모전·내 역할·확정 인원/정원, 팀장의 경우 검토 대기 지원자 수를 표시합니다. 모집 중은 녹색 배경, 모집 마감·정원 충족은 회색 배경 배지로 구분하고 상태 문구를 함께 제공합니다. 카드 전체가 팀 공간 링크이며 우하단 화살표로 이동을 안내합니다. 카드 안의 `팀 공간으로` 문구와 반복 정원 설명은 생략하되 접근성 이름에는 팀명과 목적지를 포함합니다.

내 지원은 지원한 팀·공모전·역할·지원 상태를 보여 주고, 선발된 현재 팀원은 팀 공간으로, 나머지는 공개 모집글로 연결합니다. 취소 가능한 상태에서는 확인 팝업을 거쳐 취소합니다. 지원자 관리에서는 해당 팀에 실제 접수된 지원서·역할·상태와 검토 대기 수를 확인하고 지원서 상세로 이동합니다. 이 표시 동작은 아래 [관계별 접근 정책](#team-workspace-access)과 전체 프로필의 [지원 팀장 예외](profile.md#visibility-priority)를 유지합니다.

### 팀 공간 접근

[이슈 #48의 결정](https://github.com/wejo-team/sku-dreamon/issues/48#issuecomment-6232873381)에 따라 **해당 팀의 팀장과 현재 확정 팀원만 팀 공간에 접근**합니다. 공개 모집글·팀 상세 화면과 팀 공간을 구분하며, 모집 정보를 보기 위해 지원자에게 팀 공간 접근을 부여하지 않습니다. 일반 화면의 로그인·공개 범위는 [인증 정책](authentication.md#open-questions)을 따릅니다.

| 해당 팀과의 관계 | 팀 공간 접근 |
| --- | --- |
| 현재 팀장 | 팀 생성 성공부터 가능 |
| 미지원자 | 불가 |
| 지원 완료·검토 중 | 불가 |
| 선발·현재 확정 팀원 | 선발 성공 즉시 가능 |
| 선발 대기·별도 수락 대기 | 별도 단계 없음 |
| 미선발 | 불가 |
| 지원 취소 | 불가. 선발 후 취소도 취소 성공으로 소속이 해제되면 접근 종료 |
| 취소 후 재지원 완료·검토 중 | 불가. 다시 선발돼 확정 팀원이 되어야 접근 가능 |

취소 성공 이후에는 팀 공간 링크를 알고 있거나 화면을 열어 두었어도 새 조회·요청에서 접근을 허용하지 않습니다. 팀 공간 접근은 일반 팀원에게 지원자 검토·선발·모집 정보 편집 등 팀장 권한을 부여하는 결정이 아닙니다.

표시 항목에는 [프로필 공개 정책](profile.md#visibility)을 계속 적용합니다. 일반 확정 팀원에게는 프로필이 공개일 때만 등록된 전체 항목을 제공하며, 비공개 프로필은 팀원 관계만으로 열람하지 못합니다. 지원받은 팀장의 예외는 일반 팀원에게 적용하지 않고 연락처 수집·공유를 추가하지 않습니다. 팀 공간의 ‘매칭 상태’ 표시는 [#46의 보류 결정](https://github.com/wejo-team/sku-dreamon/issues/46#issuecomment-6232873014)을 대체하지 않으며, 마감 후 추천 결과나 추가 선발을 새로 허용하지 않습니다. 팀장 탈퇴·위임·팀 삭제와 외부 메신저 링크 방식은 후속으로 정합니다.

[마감 공고 공개 정책](contests.md#closed-visibility)에 따라 이미 공개된 공고는 마감 후에도 팀 공간에서 마감 표시와 함께 공고 상세·공식 원문 링크로 연결합니다. 해당 공고 상세는 비로그인 사용자도 직접 주소로 열람할 수 있지만, 팀 공간 자체는 계속 해당 팀의 팀장·현재 확정 팀원만 접근합니다. 공고 열람이 신규 지원·신규 추천을 다시 허용하는 것은 아닙니다.

## 모집·지원 상태

### 팀 모집 상태

| 상태 | 원문에서 정한 의미 |
| --- | --- |
| 모집 중 | 지원 가능, 팀 정보 확인 가능 |
| 지원자 검토 | 팀장이 지원자 목록을 확인하고 선발 진행. 신규 접수 조건을 충족하면 추가 지원도 허용 |
| 팀원 확정 | 팀원 구성이 확정된 상태 |
| 모집 마감 | 정원 충족 또는 팀장 종료 처리로 신규 지원 불가 |

이 표는 상태의 의미를 정의하며 반드시 표 순서대로 전이한다는 뜻은 아닙니다. ‘지원자 검토’ 중에도 조건을 충족하면 신규 접수를 허용합니다. 팀원 확정과 모집 마감의 관계, 자동·수동 전이와 재개 가능 여부는 후속으로 정합니다. 기존 지원자 추천 결과의 마감 후 제공 여부는 [추천 매칭](matching.md#open-questions)의 미정 사항으로 유지합니다.

### 지원자 상태

| 상태 | 화면에서 구분해야 하는 정보 |
| --- | --- |
| 지원 완료 | 사용자가 팀에 지원한 상태 |
| 검토 중 | 지원 검토가 진행 중인 상태 |
| 선발 | 팀장의 선발 성공으로 해당 지원자가 즉시 확정 팀원이 된 결과 |
| 미선발 | 선발되지 않은 결과 |
| 지원 취소 | 사용자가 지원을 취소한 상태. 선발 후 취소라면 현재 확정 팀원에서 제외되고 자리를 반환한 결과 |

선발 성공과 지원자 본인의 취소·재지원은 아래 정책을 따릅니다. 나머지 전환 동작·시점, 미선발 처리 방식, 팀장의 선발 취소, 취소 이후 기록의 보존·상세 이력 표시는 미정입니다. 취소·미선발 후 팀장의 전체 현재 프로필 열람은 [열람 관계 유지 정책](profile.md#former-applicant-visibility)을 따르며, 개별 지원자의 팀원 확정을 팀 전체의 모집 종료로 취급하지 않습니다.

## 정책과 예외

### 팀원 확정과 정원

| 결정 항목 | 정책 | 결정 기록 |
| --- | --- | --- |
| TEAM-01 · 팀원 확정 | 팀장의 선발 처리가 성공하는 즉시 해당 지원자를 확정 팀원에 포함합니다. 지원자의 별도 수락은 없습니다. | [이슈 #27](https://github.com/wejo-team/sku-dreamon/issues/27#issuecomment-6232505226) |
| TEAM-05 · 정원의 의미 | 모집 인원은 팀장을 포함한 전체 정원입니다. 팀 생성·목록·상세·팀 공간에서 같은 의미로 표시하고 현재 확정 인원·남은 자리와 구분합니다. | [이슈 #28](https://github.com/wejo-team/sku-dreamon/issues/28#issuecomment-6232505533) |
| TEAM-05 · 정원 차감 | 지원 접수·검토 시에는 차감하지 않습니다. 선발 성공 시 팀원 확정과 정원 차감을 함께 반영하며, 임시 예약이나 수락 대기 자리는 두지 않습니다. | [이슈 #44](https://github.com/wejo-team/sku-dreamon/issues/44#issuecomment-6232505836) |

남은 자리는 **전체 정원 − 팀장을 포함한 현재 확정 팀원 수**입니다. 정원이 없으면 추가 선발을 허용하지 않습니다. 마지막 한 자리에 대한 선발이 겹치면 먼저 선발 처리가 완료된 한 명만 확정합니다. 나머지 선발은 정원이 찼음을 안내하고 실패하며, 해당 지원자를 확정 팀원에 추가하거나 실패한 요청 때문에 정원을 차감하지 않습니다. 구체적인 동시 처리 구현은 개발 계획에서 정합니다.

| 사례 | 관찰할 결과 |
| --- | --- |
| 팀장 1명, 팀장 포함 총 4명으로 생성 | 현재 확정 인원 1명, 추가 선발 가능한 자리 3명 |
| 위 팀에 지원자 여러 명이 접수·검토 중 | 확정 팀원 목록은 팀장 1명이며 남은 자리는 계속 3명 |
| 위 팀에서 지원자 한 명을 선발 | 별도 수락 없이 확정 팀원 목록에 팀장·선발자 총 2명 표시, 남은 자리 2명 |
| 총 4명 팀에 이미 3명이 확정된 상태에서 두 명을 동시에 선발 | 한 명만 선발·확정되고 총인원은 4명 유지, 나머지 선발은 정원 부족 안내와 함께 실패 |

수락·거절 응답·응답 기한·미응답에 따른 자리 예약·해제는 적용하지 않습니다. 지원자 본인의 [선발 후 취소와 자리 반환](#application-cancellation), [공모전별 소속 제한](#membership-limit)은 아래 결정을 따릅니다. 공동 출전 팀의 목표 정원에는 [확인된 공식 인원 조건](#official-capacity)을 적용합니다. 팀장에 의한 선발 취소와 모집 재개는 TEAM-02·TEAM-03에서 별도로 정합니다.

<a id="official-capacity"></a>

### 공동 출전 팀의 목표 정원과 공식 인원 조건

[이슈 #47](https://github.com/wejo-team/sku-dreamon/issues/47#issuecomment-6233303001)에 따라 공동 출전 팀의 **팀장 포함 목표 총 정원**이 확인된 공식 최소·최대 인원 범위를 벗어나면 저장을 허용하지 않습니다. 팀 생성과 이미 허용되는 정원 저장에 같은 기준을 적용합니다. 정원 편집을 허용하는 시점·화면·권한을 이 결정으로 새로 추가하지 않습니다.

공식 인원 조건이 **2~4명**으로 확인된 공동 출전 팀의 예시입니다. 다른 팀 생성·저장 조건을 충족한다고 가정합니다.

| 입력·현재 인원 | 결과 |
| --- | --- |
| 목표 총 정원 1명 | 공식 최소 인원 미만이므로 저장 실패 |
| 목표 총 정원 2명 | 공식 최소 인원과 같으므로 저장 허용 |
| 목표 총 정원 4명 | 공식 최대 인원과 같으므로 저장 허용 |
| 목표 총 정원 5명 | 공식 최대 인원 초과이므로 저장 실패 |
| 팀장 1명으로 목표 총 정원 4명인 팀 생성 | 생성 허용. 현재 확정 인원 1명·남은 자리 3명으로 모집 시작 |

검증 대상은 목표 정원이며, 모집 중 현재 확정 인원이 공식 최소보다 적다는 이유로 팀 생성·모집을 막지 않습니다. 범위 밖 값을 입력해 저장에 실패하면 새 팀·팀장 소속을 만들거나 기존 정원을 해당 값으로 바꾸지 않습니다. 미확인된 공식 인원 조건을 임의로 추정하지 않으며, 최초 공고 공개는 [필수 정보 확인 정책](contests.md#publication-policy)을 따릅니다. 공식 조건 변경 후 기존 팀·지원·선발에 미치는 영향은 TEAM-06, 정원 편집의 세부 범위는 TEAM-07에서 후속으로 정합니다.

개인 전용 공고의 준비 팀은 [참가 방식별 정책](contests.md#participation-policy)을 따릅니다. 출전 팀이 아니므로 공식 개인 1명 조건이나 공동 출전 팀의 인원 범위를 준비 팀 정원의 상한으로 사용하지 않습니다. 준비 팀도 자체 목표 정원을 팀장 포함 총인원으로 표시하고 남은 자리·선발 시 차감 정책을 유지하며, 준비 팀 자체의 정원 제한 상세는 TBD입니다.

<a id="membership-limit"></a>

### 공모전별 확정 소속

[이슈 #43의 결정](https://github.com/wejo-team/sku-dreamon/issues/43#issuecomment-6232822511)에 따라 **한 사용자는 공모전마다 하나의 팀에만 확정 소속**을 가질 수 있습니다. 팀장과 선발된 팀원에게 동일하게 적용하며, 다른 공모전의 팀에는 동시에 소속될 수 있습니다.

| 현재 소속과 시도 | 결과 |
| --- | --- |
| 공모전 A의 팀원 또는 팀장이 같은 공모전의 다른 팀에서 선발됨 | 선발 실패·기존 소속 안내. 두 번째 팀원 추가나 정원 차감 없음 |
| 공모전 A의 팀원 또는 팀장이 같은 공모전에 새 팀 생성 | 생성 실패·기존 소속 안내. 새 팀이나 팀장 소속을 만들지 않음 |
| 공모전 A에 소속된 사용자가 공모전 B에서 선발되거나 팀 생성 | 소속 제한 자체로는 막지 않음. 다른 적용 조건은 별도 확인 |
| 같은 공모전의 두 팀이 한 사용자를 동시에 선발 | 먼저 성공한 한 팀에만 확정. 다른 선발은 실패하며 해당 팀 정원은 차감하지 않음 |
| 기존 소속의 지원 취소가 성공한 뒤 같은 공모전의 다른 팀에서 선발 | 이전 소속으로 차단하지 않고 현재 조건을 다시 확인 |

팀 생성과 선발이 겹칠 때도 같은 공모전의 확정 소속은 하나만 유지합니다. 여러 팀에 동시 지원할 수 있는지, 한 팀에서 확정될 때 다른 지원을 자동 취소하는지, 이미 소속된 사용자의 추천 후보 처리 방식은 이번 결정으로 확정하지 않습니다. 팀장 본인의 탈퇴·위임·팀 삭제도 별도 정책입니다.

<a id="application-cancellation"></a>

### 선발 전후의 지원 취소

[이슈 #45의 결정](https://github.com/wejo-team/sku-dreamon/issues/45#issuecomment-6232822752)에 따라 지원자는 **선발·팀원 확정 후에도 자신의 지원을 취소**할 수 있습니다. 선발·확정 시점을 취소의 마감으로 삼지 않습니다.

| 취소 전 지원 상태 | 취소 결과 | 팀원·정원 변화 |
| --- | --- | --- |
| 지원 완료 | 지원 취소 | 확정 전이므로 변화 없음 |
| 검토 중 | 지원 취소 | 확정 전이므로 변화 없음 |
| 선발·팀원 확정 | 지원 취소 | 확정 팀원에서 제거하고 남은 자리 1개 반환 |
| 이미 지원 취소 | 취소 결과 유지 | 중복 반환 없음 |
| 미선발 | 미선발 후 취소 전환 여부는 TEAM-03에서 별도 정의 | 이번 결정으로 정원 변화 추가하지 않음 |

취소 성공 시 지원자의 내 지원 현황과 팀장 화면에 취소 결과를 표시합니다. 선발 후 취소라면 현재 확정 팀원 목록·인원·남은 자리를 함께 갱신하고 공모전별 소속 제한에서도 해당 소속을 해제합니다. 취소한 사용자의 팀 공간 접근은 종료하지만, 팀장의 현재 프로필 열람은 [취소·미선발 후 공개 정책](profile.md#former-applicant-visibility)에 따라 공개 상태와 관계없이 유지합니다. 과거 프로필 사본이나 상세 이력의 보존·표시를 새로 허용하는 결정은 아닙니다.

취소와 선발이 겹치더라도 취소가 성공한 지원을 확정 팀원으로 남겨 두지 않습니다. 취소가 먼저 성공하면 해당 지원의 뒤늦은 선발은 실패합니다. 선발이 먼저 성공한 뒤 취소가 성공하면 팀원 관계를 해제하고 차감했던 자리 한 개를 반환합니다. 재요청으로 자리나 소속을 중복 변경하지 않으며, 구체적인 동시 처리 방식은 개발 계획에서 정합니다.

자리 반환이 모집 마감 상태의 자동 재개를 뜻하지는 않습니다. 마감 후 재개 방식은 TEAM-02에서 정하고, 지원 이력이 없는 팀장의 탈퇴·위임·팀 삭제는 이 지원 취소 정책에 포함하지 않습니다.

<a id="reapplication"></a>

### 취소 후 재지원

[이슈 #56의 결정](https://github.com/wejo-team/sku-dreamon/issues/56#issuecomment-6232823013)에 따라 본인의 지원 취소가 성공한 뒤 **현재 모집 조건을 충족하면 같은 팀에 즉시 재지원**할 수 있습니다. 별도의 대기 기간은 두지 않으며 선발 후 취소한 경우에도 같습니다.

- [지원 직전 필수 정보 점검](profile.md#before-application)과 현재 공고·팀 모집 상태, 마감, 정원 및 적용되는 자격 조건을 다시 확인합니다. 자격 미확인·미충족의 실제 제출 제한 범위는 TEAM-06의 후속 결정을 따릅니다.
- 취소된 이전 지원과 새로 접수한 현재 지원을 구분합니다. 현재 유효한 지원은 중복 생성하지 않으며, 재지원은 `지원 완료`로 접수하고 이전 선발·팀원 확정을 자동 복원하지 않습니다. 이전 지원에 대한 뒤늦은 선발·취소 요청으로 새 지원을 변경하지 않습니다.
- 취소 이력만을 이유로 재지원을 영구 차단하지 않습니다. 이전 지원의 보존 기간·상세 열람과 저장 구조는 별도 정의합니다.
- 모집이 마감됐거나 현재 정원이 차면 재지원도 접수하지 않습니다. 선발 후 취소로 자리가 생겨도 모집 마감 상태가 유지되고 있다면 바로 재지원할 수 없습니다.
- 팀장의 미선발 처리 후 재지원 허용 여부는 TEAM-04에 남깁니다. 본인 취소에 대한 이번 결정을 미선발 이력에 그대로 적용하지 않습니다.

### 모집 마감·정원·자격

- 모집 상태와 지원 기간을 확인해 신규 접수가 가능한 공고·팀에만 지원할 수 있게 합니다. 팀의 ‘지원자 검토’ 상태 자체는 접수 종료가 아니며, 공고가 마감되거나 팀 모집이 종료되면 신규 지원을 허용하지 않습니다.
- 정원이 찬 팀은 신규 지원을 허용하지 않고, 신규 지원자 후보 및 신규 지원 대상 팀 후보에서도 제외합니다.
- 팀장이 모집을 종료하면 ‘모집 마감’ 상태로 신규 지원을 막습니다.
- 참가 자격이 충족되지 않는 것으로 확인되면 추천 후보에서 제외합니다. 자격 정보가 없거나 확인되지 않으면 자동 통과시키지 않고 ‘확인 필요’로 분리합니다.
- 모집 역할이 일치하지 않는다는 이유만으로 추천 후보를 제외하거나 지원을 차단하지 않습니다. 팀장은 [최신 모집 정보](#recruitment-information)를 안내하고 실제 지원자를 검토·선발합니다.
- 경험이 적다는 이유만으로 초보자를 자동 제외하지 않습니다. 학적·학년·단과대학·전공 조건은 공고나 팀이 실제로 명시한 경우에만 필수 필터에 사용합니다.

추천의 참가 자격 필터를 실제 지원 제출 제한으로 적용할 범위는 미정입니다. ‘확인 필요’ 사용자의 지원 처리는 [이슈 #33의 보류 결정](https://github.com/wejo-team/sku-dreamon/issues/33#issuecomment-6233084109)에 따라 자격 판단 기준·제출 정책을 구체화할 때 함께 정합니다. 필수 입력 보완을 완료한 것만으로 자격 확인 완료·접수 허용을 결정하지 않습니다. 필터의 세부 기준은 [추천 매칭](matching.md)을 따릅니다. 모집 마감·정원 충족 후 기존 지원자의 추천 결과 열람은 [이슈 #46에서 TBD로 보류](https://github.com/wejo-team/sku-dreamon/issues/46#issuecomment-6232873014)했으며, LLM 추천의 동작·내부 설계를 구체화할 때 함께 논의합니다. 신규 지원 대상 제외만으로 기존 추천 결과의 유지나 종료를 정하지 않습니다.

[이슈 #51의 보류 결정](https://github.com/wejo-team/sku-dreamon/issues/51#issuecomment-6234732341)에 따라 공고의 참가 자격이 변경된 뒤 기존 지원·확정 팀원을 다시 확인할지, 이후 선발과 팀 소속을 어떻게 처리할지는 **TBD**입니다. [자격 변경 정책](contests.md#eligibility-changes)은 공고 수집·갱신 방식과 자격 판정 기준을 구체화할 때 함께 정하며, 이번에는 이전 조건 유지나 자동 취소·팀원 제외 중 어느 처리도 확정하지 않습니다.

<a id="recruitment-review"></a>

### 모집과 검토의 병행

[이슈 #29의 결정](https://github.com/wejo-team/sku-dreamon/issues/29#issuecomment-6232872773)에 따라 **검토 시작 자체로 신규 접수를 종료하지 않습니다.** 팀장이 기존 지원자를 검토하는 동안에도 현재 마감·정원·적용 조건을 충족하면 신규 지원을 받습니다.

| 상황 | 신규 지원과 팀 추천의 모집 상태 판단 |
| --- | --- |
| 검토 전, 마감 전·여석 있음·다른 접수 조건 충족 | 접수 가능. 팀 추천에서도 모집 상태만으로 제외하지 않음 |
| 검토 시작 후, 나머지 조건 동일 | 접수 가능. ‘지원자 검토’ 상태만으로 팀 추천에서 제외하지 않음 |
| 검토 중 정원 충족·마감 도달·팀장 모집 종료 | 신규 접수 불가. 신규 지원 대상 팀 추천에서도 제외 |

추가 접수가 성공하면 현재 지원자 목록에 포함합니다. 이 결정은 팀의 모집 상태를 해석하는 기준이며, 개별 지원자의 ‘검토 중’ 상태를 추천 평가에 포함할지는 별도입니다. 마감 후 기존 지원자 추천 결과는 #46의 TBD를 유지하고, 마감 후 추가 선발 가능 여부·모집 재개 등은 TEAM-02·TEAM-03에서 정합니다.

### 중복 지원과 추천 대상

- 같은 팀에 현재 유효한 지원을 중복 생성하지 않습니다.
- 취소된 이전 지원을 현재 유효한 지원으로 평가하지 않습니다. 취소 후 새 지원은 [재지원 정책](#reapplication)에 따라 접수하며, 원문의 취소 상태 제외 문구를 재지원 금지로 적용하지 않습니다.
- 실제 지원자 매칭은 해당 팀에 지원 완료한 사용자만 평가합니다. 미지원자를 신규 지원자처럼 보여 주지 않습니다.

미선발 이후 재지원 허용 여부는 TEAM-04, 지원자 추천에서 ‘검토 중’ 상태를 포함하는지 등 세부 상태 해석은 [추천 매칭](matching.md)의 미정 사항에서 결정합니다.

### 표시 정보와 공개 범위

- 사용자 화면과 팀 모집·지원 화면의 표시 이름은 [프로필의 실명 입력 정책](profile.md)을 따릅니다. 원문 본문의 닉네임 표현은 정책 확정 부록의 실명 표시로 대체합니다.
- 지원받은 팀장은 [팀장 예외](profile.md#visibility-priority)에 따라 공개·비공개 상태와 관계없이 지원자의 전체 현재 프로필을 확인합니다. 학사 정보·역량·경험·자기소개·활동 가능 시간·포트폴리오 URL·제목을 포함하며 인증 정보는 제공하지 않습니다. 일반 확정 팀원은 이 예외를 갖지 않습니다.
- 포트폴리오 미등록이나 프로필 비공개 상태로 팀 탐색·모집·지원과 로그인 후 AI 이용을 제한하지 않습니다. 포트폴리오별 공개 설정은 없으며, URL 접근 안내는 [외부 포트폴리오](profile.md#portfolio)를 따릅니다.
- [공개 상태 전환](profile.md#visibility-changes)은 설명·확인 후 저장 성공 시 적용합니다. 일반 검색·상세의 노출 여부가 바뀌어도 지원 팀장의 전체 현재 프로필 열람과 기존 지원·팀 소속은 유지합니다.
- 지원 취소·미선발·선발 후 취소만을 이유로 팀장의 현재 프로필 열람을 차단하지 않습니다. [열람 관계 유지 정책](profile.md#former-applicant-visibility)에 따라 전체 현재 프로필을 표시합니다. 계정 삭제 시 기존 지원·팀 기록 처리와 상세 이력 보존은 [프로필의 미정 사항](profile.md#open-questions)에 남깁니다.

## 완료 조건

체크는 구현·검증 결과를 뜻하며, 문서 이관이나 명세 검토만으로 체크하지 않습니다.

- [ ] AC-01: 사용자가 공모전을 선택해 관련 팀 목록·상세와 모집 조건을 확인할 수 있다.
- [ ] AC-02: 사용자가 공모전, 팀 목표, 필요한 역할, 모집 인원을 등록하고 모집 마감을 설정해 팀·모집글을 작성할 수 있다.
- [ ] AC-03: 신규 접수 조건을 충족하는 팀에 지원한 사용자의 지원 내역이 내 지원 현황과 팀장의 지원자 목록에 표시된다. 팀의 ‘지원자 검토’ 상태만으로 접수를 차단하지 않는다.
- [ ] AC-04: 지원 완료·검토 중·선발 후 자신의 지원을 취소하면 본인과 팀장에게 취소 결과가 표시된다. 선발 전에는 정원이 변하지 않고, 선발 후에는 확정 팀원 제거·소속 해제·자리 한 개 반환을 함께 확인할 수 있다.
- [ ] AC-05: 팀장이 실제 지원자 목록과 조건에 맞는 매칭 후보·근거를 확인하고 지원자를 선발하면, 선발 성공 즉시 해당 지원자가 확정 팀원에 포함되고 정원이 차감된다. 지원자는 별도 수락 없이 그 결과를 확인할 수 있다.
- [ ] AC-06: 공고 마감, 팀 모집 마감 또는 정원 충족 상태에서 신규 지원이 접수되지 않는다.
- [ ] AC-07: 같은 팀에 현재 유효한 지원이 중복 생성되지 않는다. 취소된 이전 지원을 현재 지원으로 평가하지 않으며, 취소 후 재지원은 [현재 모집 조건](#reapplication)을 확인해 접수한다. 미선발 후 재지원은 TEAM-04 결정 후 검증한다.
- [ ] AC-08: 팀 모집 상태 네 가지와 지원자 상태 다섯 가지를 구분해 표시하고 사용자·팀장에게 필요한 상태와 행동을 제공한다. 허용 행동은 TEAM-02·TEAM-03 결정 후 검증한다.
- [ ] AC-09: 팀 공간의 확정 팀원 목록에 [선발 즉시 확정 정책](#membership-capacity)을 적용하고 공모전 기본 정보·모집·매칭 상태를 표시한다. [관계별 접근 표](#team-workspace-access)에 따라 팀장과 현재 확정 팀원만 접근하며 프로필 공개 정책을 유지한다. 마감 후 추천 결과는 #46 결정 후 검증한다.
- [ ] AC-10: 팀 모집·지원 화면에 실명이 표시되고 팀장·팀원의 프로필 열람 범위가 [프로필 정책](profile.md#visibility)에 맞게 적용된다. 지원 팀장은 공개 상태와 관계없이 등록된 전체 현재 프로필을 확인하고, 일반 확정 팀원은 공개 프로필만 일반 로그인 사용자와 같은 범위로 열람한다.
- [ ] AC-11: 포트폴리오를 등록하지 않거나 프로필을 비공개로 둔 사용자도 팀 탐색·모집·지원과 로그인 후 AI 기능을 이용할 수 있다.
- [ ] AC-12: 지원자가 프로필 변경을 저장한 뒤 팀장이 지원자 목록·상세와 추천을 다시 조회하면 [현재 프로필 기준](profile.md#application-profile)이 적용되며, 프로필 변경 사실을 알리는 별도 알림·배지·전후 비교 안내는 제공되지 않는다.
- [ ] AC-13: 팀 생성·목록·상세·팀 공간에서 정원은 팀장을 포함한 총인원을 뜻한다. 워크스페이스 카드에서는 반복 안내 없이 `확정 인원 / 정원`으로 요약하고, 생성 입력·모집 상세에서는 의미를 안내한다. 총 4명 팀에 팀장만 있으면 확정 인원 1명·남은 자리 3명이며, 지원 접수·검토는 이 수치를 바꾸지 않는다.
- [ ] AC-14: 마지막 한 자리에 대한 동시 선발은 한 명만 성공하며, 성공한 지원자만 확정 팀원에 포함되고 남은 자리는 0명이 된다. 다른 선발은 정원 부족 안내와 함께 실패하여 정원을 초과하지 않고, 이후 신규 지원도 접수되지 않는다.
- [ ] AC-15: 다른 참가 조건을 만족하는 지원자는 모집 역할 불일치만으로 추천에서 제외되거나 지원이 차단되지 않으며, 팀장이 선발 여부를 판단한다. 모집 정보 수정·표시의 세부 검증은 TEAM-07·TEAM-08 결정 후 진행한다.
- [ ] AC-16: 팀장·선발된 팀원 모두 같은 공모전에서 두 번째 선발·팀 생성이 차단되고, 다른 공모전의 소속은 이 제한만으로 차단되지 않는다. 같은 사용자의 동시 선발·팀 생성에서도 공모전별 확정 소속은 하나만 유지된다.
- [ ] AC-17: 취소가 먼저 성공한 지원의 선발은 실패하고, 선발이 먼저 성공한 뒤 취소하면 팀원 제거와 자리 한 개 반환이 반영된다. 반복 취소로 자리 수가 늘어나지 않는다.
- [ ] AC-18: 취소 후 현재 모집 조건을 충족하면 대기 기간 없이 새 지원이 `지원 완료`로 접수되고, 이전 선발 결과는 복원되지 않는다. 이전 지원에 대한 뒤늦은 선발·취소 요청은 새 지원을 변경하지 않는다. 현재 마감·정원 조건을 충족하지 않으면 재지원도 차단된다.
- [ ] AC-19: 마감·정원 등 조건이 같으면 검토 시작 전후 모두 신규 지원을 접수하고 팀 추천의 모집 상태 판단도 같다. 이후 정원 충족·마감·팀장 종료가 발생하면 신규 지원 및 신규 지원 대상 팀 추천에서 제외된다.
- [ ] AC-20: 선발 성공으로 팀 공간 접근이 시작되고 선발 후 취소 성공으로 종료된다. 취소한 사용자의 직접 링크·열린 화면에서 새 조회·요청이 거부되며, 재지원 접수만으로는 접근이 복원되지 않는다. 일반 팀원에게 팀장 관리 권한이나 비공개 정보 열람 권한이 추가되지 않는다.
- [ ] AC-21: 취소·미선발·선발 후 취소 이후에도 지원받은 팀장은 공개 상태와 관계없이 전체 현재 프로필을 확인한다. 일반 검색에서 비공개로 전환하거나 팀 공간 접근이 종료되어도 이 관계는 유지되며, 공개 상태 변경 자체로 지원 상태·팀 소속을 변경하지 않는다.
- [ ] AC-22: 공식 인원이 2~4명인 공동 출전 팀의 목표 총 정원을 1명·5명으로 저장할 수 없고, 2명·4명은 다른 조건을 충족하면 저장할 수 있다. 팀 생성과 이미 허용되는 정원 저장에서 같은 기준을 적용하고, 실패한 저장은 새 팀·소속 생성이나 기존 정원 변경으로 반영되지 않는다.
- [ ] AC-23: 공식 최소 인원이 2명이어도 팀장 1명으로 목표 총 정원 4명인 팀을 생성할 수 있으며, 현재 확정 인원 1명·남은 자리 3명을 표시한다. 목표 정원 검증과 모집 중 현재 인원을 구분한다.
- [ ] AC-24: 개인 전용 공고에서도 준비 목적 팀을 생성할 수 있고 공동 출전 팀과 구분해 안내한다. 공식 개인 1명 조건이나 공동 출전 인원 범위를 준비 팀 정원 상한으로 적용하지 않으며, 기존 공모전별 소속 제한·팀장 포함 정원·선발 정책을 유지한다. 준비 팀 자체 정원 제한의 세부 검증은 TEAM-07 결정 후 진행한다.
- [ ] AC-25: 이미 공개된 공고가 마감되면 팀장·현재 확정 팀원이 팀 공간에서 마감 표시를 확인하고 공고 상세·공식 원문 링크로 이동할 수 있다. 비로그인 사용자의 마감 공고 상세 직접 열람은 허용하되, 이를 근거로 팀 공간 접근이나 신규 지원·신규 추천을 허용하지 않는다.
- [ ] AC-26: 지원 메시지 없이 제출할 수 있고, 입력한 경우 최대 1,000자를 허용하며 초과하면 접수하지 않는다. 본인·지원 팀장만 메시지를 확인하고 일반 사람 탐색에는 노출하지 않는다.
- [ ] AC-27: 팀 탐색에서 검색어·역할·모집 상태·공모전으로 결과를 좁히고, 현재 조건의 전체 결과 수·총페이지를 확인하며 페이지 번호로 이동한다. 조건·탭 변경 시 1페이지로 이동하고 상세 복귀 시 조건·페이지를 유지한다. 필터 초안을 취소하면 적용되지 않으며 초기화 후 현재 탭은 유지한다. 빈 결과와 잘못된 페이지를 처리하고, 상태 필터와 실제 접수 가능 여부를 구분해 지원 제출 시 검토 중 접수 허용·기한·정원 정책을 적용한다.
- [ ] AC-28: 팀 생성에서 검색 가능한 팝업으로 공모전을 선택하고 주최자·분야·마감으로 동명 공고를 구분한다. 결과 없음·검색어 지우기·추가 표시·키보드 선택을 제공하며, 선택 없이 닫거나 검색해도 기존 선택은 지워지지 않는다. 생성 성공 후 해당 팀 공간으로 이동한다.
- [ ] AC-29: 워크스페이스의 내 팀/내 지원 수, 작업 아이콘의 접근성 이름·선택 상태, 팀 카드의 역할·확정 인원·모집 배지를 확인할 수 있다. 선발·지원 취소·모집 종료는 결과를 설명하는 확인 팝업을 거치고 취소·닫기 시 상태를 변경하지 않는다.

TEAM-01·TEAM-05는 [팀원 확정과 정원](#membership-capacity)·[공동 출전 팀의 공식 인원 조건](#official-capacity), TEAM-03·TEAM-04 중 이번 결정은 [취소](#application-cancellation)·[재지원](#reapplication)·[소속 제한](#membership-limit)에 반영했습니다. 나머지 미정 정책에 의존하는 조건은 해당 결정을 먼저 확정한 뒤 검증합니다.

| --- | --- |
| TEAM-02 | 모집 상태의 나머지 전이 동작·권한·시점, 팀 전체의 팀원 확정 상태와 모집 마감의 관계, 마감 후 재개·추가 선발 가능 여부. 검토 중 신규 접수는 현재 조건 충족 시 허용. 마감·정원 충족 후 기존 지원자 추천 결과는 #46에 따라 LLM 추천 설계 구체화 때 논의 |
| TEAM-03 | 선발·본인 취소·재지원 외 지원 상태 전이, 미선발 처리와 미선발 후 취소 전환, 팀장의 선발 취소·변경 및 자리 반환, 팀장 탈퇴·위임·팀 삭제. 본인 지원 취소는 선발 후에도 허용하고 팀원 제거·자리 반환 |
| TEAM-04 | 미선발 후 재지원 허용 여부·시점, 여러 팀 동시 지원의 허용 범위, 한 팀 확정 시 다른 지원의 자동 처리. 확정 소속은 공모전마다 한 팀이며 본인 취소 후에는 현재 조건 충족 시 즉시 재지원 |
| TEAM-06 | 참가 자격 미충족·확인 필요를 실제 지원 제출 제한에 적용하는 범위, 공고·모집 조건 변경이나 마감이 기존 지원·선발에 미치는 영향. 공고 자격 변경 후 기존 지원·확정 팀원의 재확인·선발·소속 처리는 [#51에서 TBD로 보류](https://github.com/wejo-team/sku-dreamon/issues/51#issuecomment-6234732341)했으며 갱신·자격 판정 방식과 함께 결정. 확인 필요 접수는 #33의 TBD를 유지하고 필수 입력 보완과 구분. 모집 역할 불일치 자체는 지원 제한으로 사용하지 않음 |
| TEAM-07 | 팀명·팀 관심 분야·활동 시간 등 입력 항목의 필수 여부·제약·기본값, 공모전에서 가져오는 범위와 모집글 수정·삭제 범위. 팀장이 최신 모집 정보를 안내할 편집 항목·시점·화면별 반영 방식, 준비 팀 자체의 정원 제한 상세. 공동 출전 팀의 정원 저장 기준은 [공식 인원 조건](#official-capacity)으로 결정 |
| TEAM-08 | 팀 공간 세부 표시·편집 범위, 외부 메신저 링크 제공 여부·등록·공개 방식. 접근 대상·시점은 [팀장·현재 확정 팀원](#team-workspace-access)으로 결정하며, 프로필 공개 정책과 마감 후 추천 TBD를 유지 |
| TEAM-09 | 제출 후 지원 메시지 수정 가능 여부·이력 보존. 선택 입력·최대 1,000자와 본인·지원 팀장 열람은 위 정책 적용 |
