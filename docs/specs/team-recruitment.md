# 팀 모집·지원·선발과 팀 공간

- 구현 상태: 예정
- 명세 검토: [PR #17](https://github.com/wejo-team/sku-dreamon/pull/17)
- 구현 작업: 미등록
- 변경 근거: 2026-10-21 사용자 승인으로 팀 모집 상태 단순화, 검토·미선발·선발 기한, 재지원·소속 경계와 MVP 제외 행동 확정. 2026-10-19 사용자 결정과 [#77](https://github.com/wejo-team/sku-dreamon/issues/77)의 팀 입력·공식 정원·프로필 공개·참가 자격 정책은 유지. 디자인·배포 검증 상태는 [대조 기록](prototype-alignment.md)에서 별도 관리

스프린트 1의 팀 생성부터 지원 결과 확인까지를 정의합니다. LLM 추천 후보·추천 이유는 [추천 매칭](matching.md), 공고 정보와 마감 관리는 [공모전 공고](contests.md), 전체 개발 범위는 [스프린트 1](sprint-1.md)을 따릅니다.

## 목적과 사용자

교내 사용자가 선택한 공모전에 참여할 팀을 만들거나 모집 중인 팀에 지원할 수 있게 합니다. 팀장은 실제 지원자를 검토하고 선발하며, 지원자는 자신의 상태와 결과를 확인합니다. 확정된 팀은 최소 팀 공간에서 공모전과 팀원 정보를 확인합니다.

## 범위

| 항목 | 스프린트 1 범위 |
| --- | --- |
| 팀 생성 | 공모전, 팀 목표, 필요한 역할, 모집 인원 등록 |
| 팀 탐색 | 선택한 공모전의 팀 목록·상세, 모집 조건·모집글 조회 |
| 모집글 작성 | 공모전, 역할, 인원, 마감 설정 |
| 지원 | 모집글에 지원·선발 후를 포함한 지원 취소·조건 충족 시 재지원, 내 지원 현황과 결과 확인 |
| 팀장 관리 | 지원자 목록·매칭 후보 조회, 명시적 검토 시작·선발·미선발·조건 충족 시 모집 재개 |
| 팀원 확정 | 팀장 선발 즉시 팀원 확정·정원 차감, 지원자는 결과 확인 |
| 팀 공간 | 팀장·현재 확정 팀원이 접근해 공모전 기본 정보, 확정된 팀원, 모집·매칭 상태 확인 |
| 팀장·팀 해제 행동 | 팀장 변경·위임·선발 취소·강퇴·팀장 탈퇴·팀 삭제는 MVP에서 제외. 일반 팀원의 본인 지원 취소는 유지 |
| 작업 분해·역할 제안·일정 조율 | 스프린트 2 이후 검토. 구체적인 일정 조율은 팀 공간 안의 후속 기능 구상이며 현재 구현·MVP 범위로 확정하지 않음 |
| 사용자 간 자체 채팅 | 초기 범위 제외; 필요하면 외부 메신저 링크 제공. AI 탐색 대화와 구분 |

지원자의 별도 수락 단계는 제공하지 않습니다. 외부 메신저 링크 제공 여부와 방식은 확정되지 않았습니다.

## 사용자 흐름과 동작

### 공모전 선택과 팀 탐색

1. 사용자가 공개 공모전 목록·상세에서 참여할 공모전을 확인합니다. 공개 공고·팀 모집 정보는 [로그인 없이 탐색](authentication.md#access-policy)할 수 있습니다.
2. 공모전 상세에 바로 표시한 해당 공모전의 공개 팀 목록이나 탐색의 팀 탭에서 팀 조건과 모집글을 확인합니다. 팀 목록의 일반 검색·필터와 AI 추천을 구분하고, 탐색 검색창·공모전 상세의 AI 아이콘을 통해 팀 추천으로 이동합니다.
3. 사용자는 [로그인](authentication.md#access-policy) 후 참여할 팀에 지원하거나 새 팀과 모집글을 작성합니다. 지원 직전에는 [필수 정보 누락 점검·보완](profile.md#before-application)을 거칩니다. 추천 표시 정보와 실행 시점은 [추천 매칭](matching.md)을 따릅니다.

자체 로그인 성공은 교내 인증 완료를 뜻하지 않지만 교내 미인증 자체로 참여를 막지는 않습니다. 팀 공간·지원자 관리·타인 프로필은 관계별 권한을 적용합니다. 신규 지원은 [프로필 공개와 필수 입력 조건](profile.md#before-application)을 따르며, 개별 자격 정보 부족만으로 접수를 차단하지 않는 [지원 정책](#recruitment-conditions)을 적용합니다. 팀 생성에 필요한 나머지 프로필 완성 범위는 프로필 명세에서 관리합니다.

팀 탐색은 팀명·소개/목표·모집 역할·공모전명으로 검색하고, 역할 하나와 `모집중만` 조건으로 좁힙니다. 역할 필터는 탐색 조건이며 [역할 불일치 지원 허용](#recruitment-information)을 바꾸지 않습니다. 필터 팝업은 선택 초안을 적용한 때에만 목록을 변경하고 취소·닫기는 기존 조건을 유지합니다. 탐색의 팀 탭은 [공통 페이지 이동 정책](sprint-1.md#exploration-pagination)에 따라 현재 조건의 전체 결과 수·총페이지와 페이지 번호 이동을 제공합니다. 조건·탭 변경 시 1페이지로 이동하며 상세에서 돌아오면 검색·필터·페이지를 유지합니다. 조건 초기화는 현재 탐색 탭을 유지하고 검색어·역할·모집 조건·공모전 조건을 해제합니다. 검색 결과가 없으면 조건 변경·초기화를 안내합니다.

공모전 상세의 팀 목록은 [상세 안의 팀 목록과 행동](contests.md#contest-teams)을 따릅니다. 현재 공모전과 연결된 공개 팀만 바로 보여 주며 별도 팀 찾기 버튼은 두지 않습니다. 생성·AI 진입은 아이콘으로 제공하고 팀이 없는 접수 중 공고에는 생성을 권유합니다. 마감 공고의 신규 생성·신규 지원 대상 추천 행동은 제공하지 않으며, 공개 목록 열람과 실제 지원 접수 조건은 구분합니다.

공개 팀 카드는 모집 상태·확정 인원·팀명·소개·모집 역할·공모전명을 제공하고 카드 전체로 공개 모집글에 이동합니다. 공모전 상세 안의 팀 카드에서는 상위 화면에 표시한 공모전명을 반복하지 않습니다. 이 공개 카드로 지원자 목록이나 팀 공간을 노출하지 않습니다. 모집 중 표시·필터는 [공통 모집 가능 기준](#recruitment-conditions)을 적용하며 개인별 자격이나 현재 지원·소속에 따른 제출 가능 보장과 구분합니다. 공모전 카드·상세의 팀 수는 이 필터와 달리 모집 상태와 관계없이 해당 공모전에 연결된 모든 팀을 셉니다.

### 팀 생성과 모집글 작성

팀을 만드는 사용자는 공모전, 팀명·소개/목표, 공식 인원 조건에 맞는 목표 정원과 해당하는 모집 역할을 입력하고 모집 마감을 설정합니다. 팀장은 이 모집 조건을 바탕으로 지원자를 확인하고 선발합니다.

공모전은 검색 가능한 하단 팝업에서 선택합니다. 공모전명·주최자·분야로 찾고 결과에 제목·주최자·분야·마감을 함께 보여 같은 이름의 공고도 구분합니다. 항목을 선택하면 입력에 반영하고 팝업을 닫습니다. 선택하지 않고 닫거나 결과가 없더라도 기존에 선택한 공모전을 지우지 않으며, 검색어 지우기·결과 추가 표시·키보드 선택을 제공합니다. 공모전 상세에서 진입한 경우 해당 공모전을 미리 선택합니다.

개인/팀 유형이나 준비 모임을 별도로 만들지 않습니다. [공고의 공식 참가 인원](contests.md#participation-policy)을 모든 팀에 적용하며, 정확히 1명인 공고의 팀은 정원 1명으로 만들고 추가 모집하지 않습니다.

팀 생성 시 생성자는 확정 팀장 소속을 갖고, 같은 공모전의 다른 팀에 남아 있는 본인의 대기 지원은 함께 [폐기](#parallel-applications)합니다. 이미 같은 공모전의 팀에 소속되어 있으면 새 팀 생성을 허용하지 않으며, [공모전별 소속 제한](#membership-limit)을 적용합니다. 생성 후 팀장은 MVP에서 팀을 나가거나 삭제할 수 없다는 [제한](#membership-exclusions)을 생성 전에 안내합니다.

| 정보 | 입력·표시 계약 |
| --- | --- |
| 팀명 | 필수, 2~40자 |
| 공모전 | 필수, 해당 공모전의 공식 인원·분야와 연결 |
| 팀 소개·목표 | 필수, 10~1,000자 |
| 모집 역할 | 목표 정원 2명 이상이면 [공통 6개 역할](profile-options.md#role-policy) 중 1~6개 필수. 정원 1명이면 생략 |
| 목표 정원 | 팀장을 포함한 전체 인원. [공식 인원 조건](#official-capacity)에 따라 고정하거나 기본값 없이 직접 입력. 워크스페이스는 `확정 인원 / 정원`으로 표시 |
| 모집 마감 | 필수, 신규 접수 가능 여부 판단에 사용. [공고 마감 기준](contests.md#deadline-policy)과 같은 시각·시간대 보완을 적용하고 공고 접수 종료 이후 신규 지원을 허용하지 않음 |
| 팀 관심 분야 | 공모전의 동등한 복수 분야를 그대로 사용. 별도 입력·편집 없음 |
| 팀 활동 요일·시간 구간 | 팀 생성 폼에서 입력하지 않음. 개인 주당 참여 가능 시간은 [프로필 공통 정보](profile.md#fields)를 참고 |

글자수는 앞뒤 공백 제거 후 공백·줄바꿈을 포함해 계산하고, 초과 입력은 유지한 채 수정하도록 안내합니다. 조용히 잘라 저장하지 않습니다. 구체적인 Unicode 계수 계약은 공통 입력 정책의 후속 구현에서 정합니다. 모집 역할 불일치만으로 지원을 막지 않는 정책은 유지합니다. 원문의 ‘필수 활동 시간’을 특정 시간 참석이나 지원 필수 조건으로 사용하지 않습니다.

팀장은 지원자를 선별할 때 [프로필의 주당 참여 가능 시간](profile.md#fields)을 참고합니다. 이 값은 참여 중인 **모든 프로젝트를 합산한 자기신고 참고 총량**이며 팀별 배정 시간·확정 일정·남은 시간을 뜻하지 않습니다. [공통 선택지](profile-options.md#weekly-availability)에 정한 네 구간 중 등록된 하나를 표시하며, 미입력을 가장 낮은 구간으로 간주하지 않습니다.

프로필 공통값을 수정하면 여러 팀이 현재 프로필로 진행하는 지원자 검토에 함께 영향을 줄 수 있습니다. 그러나 이 변경이 팀별 확정 일정이나 약속을 자동으로 변경하지는 않습니다. 팀별 구체적인 일정 조율은 팀 공간 안의 후속 기능 구상으로 남기며, 주당 참여 가능 시간 변경으로 일정 조율 기능의 구현이나 MVP 포함을 확정하지 않습니다.

### 모집 정보 관리

[이슈 #30의 결정](https://github.com/wejo-team/sku-dreamon/issues/30#issuecomment-6232752606)에 따라 모집 역할은 팀장의 판단과 안내를 위한 정보입니다. 팀장은 이미 모집된 분야 때문에 지원자가 혼동하지 않도록 프로젝트 워크스페이스(팀 공간)의 모집 정보·현재 필요한 역할 안내를 갱신하는 방향으로 관리합니다.

역할 불일치 자체로 추천 후보에서 제외하거나 지원을 차단하지 않고 실제 선발은 팀장이 판단합니다. 마감·전체 정원·공개 상태·중복·소속 등 다른 정책은 유지합니다. 참가 자격은 원문 확인 안내로 제공하며 비즈니스 로직의 차단 조건으로 사용하지 않습니다. 역할별 자동 정원 차감이나 역할 충족 판정은 추가하지 않으며, 수정 가능한 항목·화면·시점·표시 반영 방식은 TEAM-07·TEAM-08에서 후속 정의합니다.

### 지원·취소와 내 지원 현황

1. 사용자가 팀 상세에서 모집 조건과 지원 가능 상태를 확인합니다. 신규 지원은 로그인한 사용자의 **프로필이 공개 상태일 때만 제출**할 수 있습니다. 비공개이면 [공개 전환 안내·확인](profile.md#visibility-changes)을 거쳐 저장 성공 후 지원 조건을 다시 확인합니다. 버튼을 누른 것만으로 자동 공개하거나 접수하지 않습니다. 모든 지원 직전에는 [필수 입력 보완](profile.md#before-application)을 적용하되 선택인 학적·학년 미입력이나 개별 자격 정보 부족만으로 차단하지 않습니다.
2. 지원자는 내 지원 현황에서 지원 상태를 확인합니다.
3. 사용자는 지원 완료·검토 중·선발 후에도 [지원 취소](#application-cancellation)를 할 수 있습니다. 선발 후 취소는 확정 팀원 관계를 해제하고 자리를 반환합니다.
4. 팀장의 검토·선발 이후 지원자는 자신의 결과를 확인합니다.
5. 취소 후에는 [현재 모집 조건을 충족하면 즉시 재지원](#reapplication)할 수 있습니다. 재지원도 신규 접수이므로 공개 상태 조건을 적용하며, 이전 선발 결과가 복원되지는 않습니다.

제출 전에는 [원문 참가 조건 확인 안내](#recruitment-conditions)와 [지원받은 팀의 현재 프로필 직접 열람·AI 검토 범위](profile.md#visibility-priority)를 안내합니다. 지원 후 비공개 전환이 기존 지원·팀 소속을 없애지 않는다는 점도 구분합니다.

지원할 역할을 선택하고 선택 메시지를 입력한 뒤 제출합니다. 모집글에 안내한 역할 외의 역할도 선택할 수 있습니다. 지원 중에는 중복 제출을 막고 실패하면 입력을 유지하며 재시도할 수 있게 합니다. 지원 취소는 확인 팝업을 거치며, 선발 후 취소에서는 팀원 제외·팀 공간 접근 종료와 현재 모집 조건에 따른 재지원 제한을 먼저 설명합니다. 확인하지 않고 닫으면 취소하지 않습니다.

<a id="application-message"></a>

지원 전 선택 입력으로 “팀에 전할 말”을 최대 1,000자까지 작성할 수 있습니다. 비워도 지원할 수 있고 초과 입력은 접수 전에 안내합니다. 메시지는 해당 지원의 본인과 지원 팀장에게만 표시하며 공개 사람 프로필에 노출하지 않습니다. 제출 후 메시지 수정·이력 정책은 TEAM-09에 남깁니다.

초기 알림은 [서비스 알림함](notifications.md)과 각 화면의 현재 상태 표시로 처리합니다. 푸시 알림은 후속 검토 범위입니다. 프로필 변경 사실에 대한 별도 알림·배지·전후 비교 안내는 MVP에서 제공하지 않습니다.

### 팀장 검토·선발과 팀 공간

1. 팀장은 관리 화면에서 자신의 팀에 접수된 지원자 목록을 확인합니다. 조회만으로 상태를 바꾸지 않으며, 개별 지원의 `검토 시작`을 실행한 경우에만 `검토 중`으로 변경합니다.
2. 자기 팀의 현재 유효한 `지원 완료`·`검토 중` 지원자만 새 선발 후보 추천에 포함합니다. `선발`·`미선발`·`지원 취소`·`폐기`나 미지원자를 새 후보로 추천하지 않습니다. 기존 기록 열람과 후보 추천 범위는 구분합니다.
3. 지원 검토에 필요한 프로필 정보를 [공개 범위](profile.md#visibility)에 따라 확인하고 선발 또는 미선발을 결정합니다. `지원 완료`에서도 검토 시작을 거치지 않고 바로 결정할 수 있습니다. 지원자의 공개·비공개 상태와 관계없이 등록된 전체 현재 프로필을 확인합니다. 지원 후 프로필이 바뀌면 다음 조회·새로고침에서 검토 정보와 추천을 [현재 프로필 기준](profile.md#application-profile)으로 함께 확인합니다.
4. 선발 시 [선발 기한](#selection-window)·정원과 [공모전별 소속 제한](#membership-limit)을 함께 확인합니다. 선발 처리가 성공하면 해당 지원자가 즉시 확정 팀원에 포함되고 남은 정원이 한 자리 줄어듭니다. 지원자는 내 지원 현황에서 선발·팀원 확정 결과를 확인하며, 별도로 수락하지 않습니다. 같은 공모전의 다른 팀에 남아 있는 지원 완료·검토 중 지원은 함께 `폐기`로 전환하며 [동시 지원 정책](#parallel-applications)을 적용합니다.
5. 팀 공간에는 공모전 기본 정보, 확정된 팀원, 모집·매칭 상태를 표시합니다. 모집 마감·정원 충족 후에도 팀장은 기존 지원자의 AI 검토 결과를 확인하고 현재 정보로 다시 요청할 수 있습니다. 신규 지원과 정원 초과 선발은 허용하지 않으며, 추천은 자동 선발·정원 변경을 수행하지 않습니다.

[팀원 확정과 정원 정책](#membership-capacity)은 개별 지원자가 팀원이 되는 시점을 정합니다. 검토 중 접수는 [모집과 검토의 병행](#recruitment-review), 팀 공간 접근 대상·시점은 [팀 공간 접근](#team-workspace-access), 팀 전체 모집은 [두 상태의 전이](#team-state-transitions)를 따릅니다. 팀 전체를 별도로 확정하는 단계는 두지 않습니다.

선발 확인 팝업에는 즉시 팀원 확정·자리 한 개 차감·별도 수락 단계가 없으며 해당 지원자의 같은 공모전 내 다른 대기 지원이 폐기됨을 설명합니다. 팀장이 모집을 종료할 때도 확인 팝업에서 신규 지원 중단과 기존 지원·확정 팀원 유지를 안내하며, 확인하지 않고 닫으면 변경하지 않습니다. 처리 실패 시 현재 상태를 다시 확인하도록 안내하고 성공으로 표시하지 않습니다.

<a id="workspace-ui"></a>

### 워크스페이스와 내 지원 표시

워크스페이스에는 본인이 팀장이거나 현재 확정 팀원인 팀만 표시합니다. 지원 완료·검토 중이라는 이유만으로 내 팀에 포함하지 않습니다. `내 팀` 또는 `내 지원` 제목과 개수를 보여 주고, 옆에 내 지원 목록 아이콘과 팀 만들기 더하기 아이콘을 배치합니다. 아이콘은 각각 `내 지원`, `팀 만들기`라는 접근성 이름을 가지며 내 지원 화면에서는 선택 상태와 내 팀 복귀를 제공합니다. 목록이 비어 있으면 팀 탐색으로 연결합니다.

내 팀 카드에는 모집 상태·팀명·공모전·내 역할·확정 인원/정원, 팀장의 경우 검토 대기 지원자 수를 표시합니다. 모집 중은 녹색 배경, 모집 마감·정원 충족은 회색 배경 배지로 구분하고 상태 문구를 함께 제공합니다. 카드 전체가 팀 공간 링크이며 우하단 화살표로 이동을 안내합니다. 카드 안의 `팀 공간으로` 문구와 반복 정원 설명은 생략하되 접근성 이름에는 팀명과 목적지를 포함합니다.

내 지원은 지원한 팀·공모전·역할·지원 상태를 보여 주고, 선발된 현재 팀원은 팀 공간으로, 나머지는 공개 모집글로 연결합니다. 취소 가능한 상태에서는 확인 팝업을 거쳐 취소합니다. 지원자 관리에서는 해당 팀에 실제 접수된 지원서·역할·상태와 검토 대기 수를 확인하고 지원서 상세로 이동합니다. 이 표시 동작은 아래 [관계별 접근 정책](#team-workspace-access)과 전체 프로필의 [지원 팀장 예외](profile.md#visibility-priority)를 유지합니다.

### 팀 공간 접근

[이슈 #48의 결정](https://github.com/wejo-team/sku-dreamon/issues/48#issuecomment-6232873381)에 따라 **해당 팀의 팀장과 현재 확정 팀원만 팀 공간에 접근**합니다. 공개 모집글·팀 상세 화면과 팀 공간을 구분하며, 모집 정보를 보기 위해 지원자에게 팀 공간 접근을 부여하지 않습니다. 일반 화면의 로그인·공개 범위는 [인증 정책](authentication.md#open-questions)을 따릅니다.

| 해당 팀과의 관계 | 팀 공간 접근 |
| --- | --- |
| 현재 팀장 | 팀 생성 성공부터 가능 |
| 미지원자 | 불가 |
| 지원 완료·검토 중 | 불가 |
| 선발·현재 확정 팀원 | 선발 성공 즉시 가능 |
| 선발 대기·별도 수락 대기 | 별도 단계 없음 |
| 미선발·폐기 | 불가 |
| 지원 취소 | 불가. 선발 후 취소도 취소 성공으로 소속이 해제되면 접근 종료 |
| 취소 후 재지원 완료·검토 중 | 불가. 다시 선발돼 확정 팀원이 되어야 접근 가능 |

취소 성공 이후에는 팀 공간 링크를 알고 있거나 화면을 열어 두었어도 새 조회·요청에서 접근을 허용하지 않습니다. 팀 공간 접근은 일반 팀원에게 지원자 검토·선발·모집 정보 편집 등 팀장 권한을 부여하는 결정이 아닙니다.

표시 항목에는 [프로필 공개 정책](profile.md#visibility)을 계속 적용합니다. 일반 확정 팀원에게는 프로필이 공개일 때만 등록된 전체 항목을 제공하며, 비공개 프로필은 팀원 관계만으로 열람하지 못합니다. 지원받은 팀장의 직접 열람·AI 검토 예외는 일반 팀원에게 적용하지 않고 연락처 수집·공유를 추가하지 않습니다. [#46·#49의 결정](https://github.com/wejo-team/sku-dreamon/issues/77)에 따라 모집 마감·정원 충족이나 지원 후 비공개 전환 자체로 기존 지원자의 AI 검토 결과 확인·재요청을 차단하지 않습니다. 현재 권한·지원 관계를 적용하며, AI 검토 허용과 [실제 선발 기한](#selection-window)을 구분합니다. 팀장 변경·탈퇴·팀 삭제 등은 [MVP 제외 행동](#membership-exclusions)을 따르며 외부 메신저 링크 방식은 후속으로 정합니다.

[마감 공고 공개 정책](contests.md#closed-visibility)에 따라 이미 공개된 공고는 마감 후에도 팀 공간에서 마감 표시와 함께 공고 상세·공식 원문 링크로 연결합니다. 해당 공고 상세는 비로그인 사용자도 직접 주소로 열람할 수 있지만, 팀 공간 자체는 계속 해당 팀의 팀장·현재 확정 팀원만 접근합니다. 공고 열람이 신규 지원·신규 지원 대상 추천을 다시 허용하는 것은 아닙니다.

## 모집·지원 상태

<a id="team-state-transitions"></a>

### 팀 모집 상태와 전이

2026-10-21 사용자 승인에 따라 MVP의 팀 모집 상태는 **모집 중(`open`)·모집 마감(`closed`) 두 가지**로 단순화합니다. 원문의 팀 전체 `지원자 검토`·`팀원 확정` 상태는 MVP에서 사용하지 않습니다. `검토 중`은 개별 지원의 상태이며, 개별 팀원은 선발 성공 즉시 확정됩니다.

| 상태·행동 | 의미와 결과 |
| --- | --- |
| 모집 중 | 팀장이 접수를 열어 둔 상태. 현재 공고·팀 기한·정원 등 [접수 조건](#recruitment-conditions)을 충족할 때 신규 지원 가능 |
| 모집 마감 | 팀장 종료 또는 정원 충족으로 접수를 닫은 상태. 기존 지원·소속은 유지 |
| 팀 생성 | 모집 중으로 시작. 정원 1명 팀은 팀장만으로 정원이 차므로 모집 마감으로 시작 |
| 팀장 모집 종료·정원 충족 | 모집 마감으로 변경. 남은 대기 지원을 자동 미선발로 바꾸지 않음 |
| 모집 마감 뒤 자리 반환 | 모집 마감 유지. [명시적 재개](#recruitment-reopening) 전에는 신규 지원을 받지 않음 |
| 팀장 모집 재개 | 공고·팀 기한과 여석 조건을 확인한 뒤 모집 중으로 변경 |

저장한 모집 상태와 현재 접수 가능 여부를 구분합니다. 기한이 지나면 저장 상태가 모집 중이어도 신규 접수를 막고 화면에는 마감을 표시합니다. 시각 경과만으로 별도 상태 변경 작업이나 대기 지원 일괄 종료를 요구하지 않습니다. 정원이 찬 것은 팀 전체 확정 버튼이나 취소 불가 상태를 뜻하지 않습니다. 모집이 닫혀 있어도 [기한과 조건을 충족한 기존 지원 선발](#selection-window), 현재 소속과 기존 AI 검토는 별도로 유지합니다.

<a id="recruitment-reopening"></a>

### 팀장의 모집 재개

2026-10-19 사용자 결정에 따라 팀장은 모집을 닫은 뒤에도 **직접 `모집 중`으로 변경하여 다시 모집**할 수 있습니다. 현재 공고가 접수 중이고 공고·팀 모집 기한이 지나지 않았으며 잔여 정원이 있는 경우에만 재개합니다. 재개 성공 이후 신규 지원·모집 중 표시·필터·신규 지원 대상 추천에 같은 기준을 적용합니다.

- 정원 충족이나 팀장 종료로 모집이 닫혔다는 사실은 유지합니다. 이후 팀원 취소 등으로 자리가 생겨도 신규 지원·모집 필터·신규 추천을 자동 재개하지 않습니다. 팀장이 재개하기 전에는 신규 지원을 받지 않습니다. 개별 지원 검토 중에 정원이 찬 경우도 같습니다. 저장 상태·사유 등 구체적인 표현은 DB 설계에서 정합니다.
- 정원 1명 팀은 팀장으로 정원이 차 있으므로 재개할 수 없습니다. 공식 정원을 늘리거나 1인 공고에서 추가 모집하는 예외는 제공하지 않습니다.
- 재개 시 확인 팝업에서 신규 지원을 다시 받을 수 있음을 설명합니다. 취소·닫기나 처리 실패 시 기존 상태를 유지합니다. 기한·정원 조건이 맞지 않으면 사유를 안내하고 재개하지 않습니다.
- 재개는 기존 지원 상태·확정 소속을 되돌리거나 폐기된 지원을 복원하지 않습니다. 마감일 연장·정원 변경은 허용하지 않으며, 기존 지원 선발은 재개 여부와 별개로 [선발 기한](#selection-window)을 적용합니다.
- 일반 팀원·지원자는 모집을 재개할 수 없습니다. 팀장 변경·위임 기능은 제공하지 않습니다.

### 지원자 상태

| 상태 | 화면에서 구분해야 하는 정보 |
| --- | --- |
| 지원 완료 | 사용자가 팀에 지원한 상태 |
| 검토 중 | 지원 검토가 진행 중인 상태 |
| 선발 | 팀장의 선발 성공으로 해당 지원자가 즉시 확정 팀원이 된 결과 |
| 미선발 | 선발되지 않은 결과 |
| 지원 취소 | 사용자가 지원을 취소한 상태. 선발 후 취소라면 현재 확정 팀원에서 제외되고 자리를 반환한 결과 |
| 폐기 | 같은 공모전의 다른 팀에서 선발되거나 직접 팀을 만들어 소속이 생겨 이 팀의 대기 지원이 종료된 결과. 기록 삭제·미선발·본인 취소와 구분 |

<a id="application-transitions"></a>

### 개별 지원의 상태 전이

| 행동 | 실행 주체·전이 | 적용 범위 |
| --- | --- | --- |
| 검토 시작 | 해당 팀장, 지원 완료 → 검토 중 | 명시적 행동으로만 변경. 목록·상세 조회, AI 검토 요청·결과 열람만으로 변경하지 않음 |
| 선발 | 해당 팀장, 지원 완료 또는 검토 중 → 선발 | 검토 시작을 먼저 할 필요 없음. [선발 기한](#selection-window)과 소속·정원 조건 확인 |
| 미선발 | 해당 팀장, 지원 완료 또는 검토 중 → 미선발 | 검토 시작을 먼저 할 필요 없음. 모집 종료·공고 마감 뒤에도 미처리 지원을 수동 정리할 수 있음 |
| 본인 취소 | 지원자, 지원 완료·검토 중·선발 → 지원 취소 | 선발 후에는 소속·자리를 함께 반환. 이미 취소한 요청은 상태·자리를 다시 바꾸지 않음 |
| 다른 소속 확정 | 선발 또는 팀 생성 성공과 함께, 같은 공모전의 다른 지원 완료·검토 중 → 폐기 | [동시 지원 정책](#parallel-applications)의 원인·범위를 적용 |

`미선발`·`지원 취소`·`폐기`는 해당 지원 시도의 종료 상태입니다. 다시 검토·선발하거나 다른 종료 상태로 바꾸지 않습니다. 미선발을 지원 취소로 바꿔 같은 팀의 재지원 제한을 우회할 수 없습니다. 허용된 재지원은 별도 새 지원으로 접수합니다.

모집 종료·정원 충족·기한 경과만으로 대기 지원을 자동 미선발 처리하지 않습니다. 공고가 마감되어도 미처리 지원은 기존 지원 상태와 함께 마감·선발 불가를 안내하며, 팀장이 필요하면 미선발로 정리합니다. 팀장의 선발 취소·강퇴는 [MVP 범위 밖](#membership-exclusions)입니다. 기존 기록의 보존 기간·상세 이력 표시는 후속 정책으로 남깁니다. 취소·미선발·폐기 후 팀장의 전체 현재 프로필 열람은 [열람 관계 유지 정책](profile.md#former-applicant-visibility)을 따릅니다.

<a id="selection-window"></a>

### 기존 지원자의 선발 기한

신규 지원 접수 마감과 이미 접수한 지원의 선발 기한을 구분합니다. 팀 모집 기한이 지났거나 팀장이 모집을 종료했어도 **공고 접수 마감 전이며 여석이 있으면 기존 지원 완료·검토 중 지원자를 선발**할 수 있습니다. 해당 팀장 권한·현재 지원 상태·공모전별 소속·정원을 다시 확인하고, 기존 지원자를 선발하기 위해 모집을 재개할 필요는 없습니다.

| 현재 상황 | 기존 유효 지원의 새 선발 |
| --- | --- |
| 팀 모집 중·공고 접수 중·여석 있음 | 허용 |
| 팀 모집 기한 경과 또는 팀장 종료·공고 접수 중·여석 있음 | 허용. 신규 지원은 계속 불가 |
| 정원 충족 | 불가 |
| 정원 충족 뒤 본인 취소로 여석 발생·공고 접수 중 | 허용. 새 지원 접수는 팀장 재개 전까지 계속 불가 |
| 공고 접수 마감 시각과 같거나 지난 시점 | 불가. 미처리 지원을 자동 미선발로 바꾸지는 않음 |

공고 접수 마감 뒤에도 본인의 지원 취소·소속 및 자리 반환, 현재 권한에 따른 기록 열람과 기존 지원자 AI 검토·재요청은 유지합니다. AI 검토·후보 제시는 실제 선발 허용이나 공고 접수 완료를 뜻하지 않습니다. 선발 시점의 공고 마감 검사는 [공고 마감 기준](contests.md#deadline-policy)을 따릅니다.

### 팀원 확정과 정원

| 결정 항목 | 정책 | 결정 기록 |
| --- | --- | --- |
| TEAM-01 · 팀원 확정 | 팀장의 선발 처리가 성공하는 즉시 해당 지원자를 확정 팀원에 포함합니다. 지원자의 별도 수락은 없습니다. | [이슈 #27](https://github.com/wejo-team/sku-dreamon/issues/27#issuecomment-6232505226) |
| TEAM-05 · 정원의 의미 | 모집 인원은 팀장을 포함한 전체 정원입니다. 팀 생성·목록·상세·팀 공간에서 같은 의미로 표시하고 현재 확정 인원·남은 자리와 구분합니다. | [이슈 #28](https://github.com/wejo-team/sku-dreamon/issues/28#issuecomment-6232505533) |
| TEAM-05 · 정원 차감 | 지원 접수·검토 시에는 차감하지 않습니다. 선발 성공 시 팀원 확정과 정원 차감을 함께 반영하며, 임시 예약이나 수락 대기 자리는 두지 않습니다. | [이슈 #44](https://github.com/wejo-team/sku-dreamon/issues/44#issuecomment-6232505836) |

남은 자리는 **전체 정원 − 팀장을 포함한 현재 확정 팀원 수**입니다. 정원이 없으면 추가 선발을 허용하지 않습니다. 마지막 한 자리에 대한 선발이 겹치면 먼저 선발 처리가 완료된 한 명만 확정합니다. 나머지 선발은 정원이 찼음을 안내하고 실패하며, 해당 지원자를 확정 팀원에 추가하거나 실패한 요청 때문에 정원을 차감하지 않습니다. 구체적인 동시 처리 구현은 개발 계획에서 정합니다.

| 사례 | 관찰할 결과 |
| --- | --- |
| 팀장 1명, 팀장 포함 총 4명으로 생성 | 현재 확정 인원 1명, 추가 선발 가능한 자리 3명 |
| 위 팀에 지원자 여러 명이 접수·검토 중 | 확정 팀원 목록은 팀장 1명이며 남은 자리는 계속 3명 |
| 위 팀에서 지원자 한 명을 선발 | 별도 수락 없이 확정 팀원 목록에 팀장·선발자 총 2명 표시, 남은 자리 2명 |
| 총 4명 팀에 이미 3명이 확정된 상태에서 두 명을 동시에 선발 | 한 명만 선발·확정되고 총인원은 4명 유지, 나머지 선발은 정원 부족 안내와 함께 실패 |

수락·거절 응답·응답 기한·미응답에 따른 자리 예약·해제는 적용하지 않습니다. 지원자 본인의 [선발 후 취소와 자리 반환](#application-cancellation), [공모전별 소속 제한](#membership-limit)은 아래 결정을 따릅니다. 모든 팀의 목표 정원에는 [확인된 공식 인원 조건](#official-capacity)을 적용합니다. 모집 재개는 [팀장의 명시적 변경](#recruitment-reopening)을 따르며, 팀장에 의한 선발 취소는 [MVP에서 제공하지 않습니다](#membership-exclusions).

<a id="official-capacity"></a>

### 모든 팀의 목표 정원과 공식 인원 조건

[#77의 F05·F11 결정](https://github.com/wejo-team/sku-dreamon/issues/77)에 따라 **모든 팀의 팀장 포함 목표 총 정원**에 [공고의 공식 인원 조건](contests.md#participation-policy)을 적용합니다. 준비 모임의 별도 예외·서비스 자체 상한·초기 정원 4명은 적용하지 않습니다.

| 확인된 공식 인원 | 팀 생성의 목표 정원 |
| --- | --- |
| 정확히 1명(최소·최대 1) | 1명으로 고정. 팀장만으로 정원이 차므로 모집 역할을 입력하지 않고 추가 지원을 받지 않음 |
| 정확히 N명(최소·최대 N) | N명으로 고정 |
| 최소·최대 범위 | 기본값 없이 팀장이 범위 안의 정수를 직접 입력 |
| 상한 없음 | 기본값 없이 팀장이 목표 정원을 직접 입력. 확인된 최소 조건을 지키되 서비스 자체 상한을 추가하지 않음 |
| 인원 미확인 | 누락을 무제한으로 해석하지 않으며 [등록 전 원문 확인](contests.md#publication-policy)을 적용 |

예를 들어 공식 인원이 2~4명이면 목표 정원 1명·5명은 저장할 수 없고, 2명·4명은 다른 조건을 충족하면 저장할 수 있습니다. **모집 중 현재 확정 인원과 목표 정원은 다릅니다.** 공식 최소가 2명이어도 팀장 1명으로 목표 정원 4명인 팀을 만들 수 있으며 현재 확정 인원 1명·남은 자리 3명으로 시작합니다.

생성과 이미 허용되는 정원 저장에 같은 기준을 적용합니다. 실패한 저장은 새 팀·소속이나 기존 정원 변경으로 반영하지 않습니다. 정원 편집 시점·화면·권한을 새로 허용하는 것은 아니며 TEAM-07에서 후속으로 정합니다. 공식 조건 변경 후 기존 팀·지원·선발에 미치는 영향은 TEAM-06으로 남깁니다.

<a id="membership-limit"></a>

### 공모전별 확정 소속

[이슈 #43의 결정](https://github.com/wejo-team/sku-dreamon/issues/43#issuecomment-6232822511)에 따라 **한 사용자는 공모전마다 하나의 팀에만 확정 소속**을 가질 수 있습니다. 팀장과 선발된 팀원에게 동일하게 적용하며, 다른 공모전의 팀에는 동시에 소속될 수 있습니다.

| 현재 소속과 시도 | 결과 |
| --- | --- |
| 공모전 A의 팀원 또는 팀장이 같은 공모전의 다른 팀에서 선발됨 | 선발 실패·기존 소속 안내. 두 번째 팀원 추가나 정원 차감 없음 |
| 공모전 A의 팀원 또는 팀장이 같은 공모전에 새 팀 생성 | 생성 실패·기존 소속 안내. 새 팀이나 팀장 소속을 만들지 않음 |
| 공모전 A의 팀원 또는 팀장이 같은 공모전의 팀에 신규 지원 | 접수 불가. 현재 소속을 유지한 채 다른 팀의 선발을 기다리는 지원을 만들지 않음 |
| 공모전 A에 소속된 사용자가 공모전 B에서 선발되거나 팀 생성 | 소속 제한 자체로는 막지 않음. 다른 적용 조건은 별도 확인 |
| 공모전 A에 소속된 사용자가 공모전 B의 팀에 신규 지원 | 소속 제한 자체로는 막지 않음. 현재 모집·공개 프로필·중복 등 조건은 별도 확인 |
| 같은 공모전의 두 팀이 한 사용자를 동시에 선발 | 먼저 성공한 한 팀에만 확정. 다른 선발은 실패하며 해당 팀 정원은 차감하지 않음 |
| 기존 소속의 지원 취소가 성공한 뒤 같은 공모전의 다른 팀에서 선발 | 이전 소속으로 차단하지 않고 현재 조건을 다시 확인 |

팀 생성과 선발이 겹칠 때도 같은 공모전의 확정 소속은 하나만 유지합니다. 새 지원과 소속 생성이 겹쳐도 소속 확정 뒤 같은 공모전의 대기 지원이 남지 않도록 아래 [폐기 정책](#parallel-applications)을 함께 적용합니다. 일반 팀원은 본인 지원 취소로 소속을 끝낸 뒤 다른 팀에 새로 지원할 수 있으나, 팀장은 [MVP 제외 행동](#membership-exclusions)에 따라 같은 방식으로 팀을 나갈 수 없습니다.

<a id="membership-exclusions"></a>

### MVP에서 제공하지 않는 팀 해제 행동

팀장의 선발 취소·팀원 강퇴, 팀장 변경·위임, 팀장 본인의 팀 탈퇴와 팀 삭제는 MVP에서 제공하지 않습니다. 선발된 일반 팀원은 기존 [본인 지원 취소](#application-cancellation)로 소속을 종료할 수 있습니다. 미선발 처리는 아직 선발하지 않은 지원에만 적용하며, 확정 팀원을 미선발로 바꿔 강퇴하는 우회 경로를 두지 않습니다.

따라서 팀장은 팀 생성 뒤 같은 공모전의 다른 팀으로 이동할 수 없고, 잘못 만든 팀도 MVP에서 삭제할 수 없습니다. 모집 종료는 팀이나 소속을 삭제하는 행동이 아닙니다. 팀 생성 전에 이 제한을 안내합니다. 계정 탈퇴·데이터 보존의 후속 정책은 [프로필 미정 사항](profile.md#open-questions)을 유지하며, 이번 결정으로 계정 탈퇴 처리를 임의 확정하지 않습니다.

<a id="parallel-applications"></a>

### 동시 지원과 다른 대기 지원의 폐기

2026-10-19 사용자 결정에 따라 같은 공모전의 **서로 다른 팀에 동시 지원**할 수 있습니다. 같은 팀의 현재 유효 지원 중복 금지는 유지하고, 2026-10-21 승인에 따라 같은 공모전의 현재 확정 소속이 없어야 새로 지원할 수 있습니다. 한 팀의 선발이 성공하면 즉시 해당 팀 소속을 확정하고, 같은 지원자의 같은 공모전 내 다른 팀에 남아 있는 `지원 완료`·`검토 중` 지원을 `폐기`로 전환합니다. 본인이 새 팀을 만들어 팀장 소속이 생길 때도 같은 범위의 대기 지원을 함께 폐기합니다.

| 상황 | 처리 |
| --- | --- |
| 같은 공모전 A의 팀 1·2에 지원 완료 또는 검토 중 | 동시 지원 허용. 접수만으로 정원·확정 소속을 차지하지 않음 |
| 팀 1에서 선발 성공 | 팀 1은 선발·즉시 소속 확정, 팀 2의 대기 지원은 폐기 |
| 공모전 A에 직접 새 팀 생성 성공 | 새 팀·팀장 소속을 만들고, 같은 사용자의 공모전 A 다른 대기 지원은 폐기 |
| 같은 사용자의 다른 공모전 B 지원 | 변경하지 않음 |
| 이미 미선발·지원 취소·폐기된 이전 지원 | 상태와 기록을 다시 변경하지 않음 |
| 선발 또는 팀 생성 실패 | 다른 지원을 폐기하지 않음 |
| 선발된 팀에서 이후 본인이 지원 취소 | 소속·한 자리를 반환하지만 다른 팀의 폐기 지원은 자동 복원하지 않음 |

폐기는 지원 기록을 삭제하는 동작이 아닙니다. 내 지원과 해당 팀의 지원자 목록에 상태와 `다른 팀 선발` 또는 `직접 팀 생성` 사유를 표시하며, 대기 수·새 AI 선발 후보·선발 대상에서는 제외합니다. 지원받은 팀장의 최신 프로필 직접 열람·기존 지원서 AI 검토 범위는 [기존 지원 열람 정책](profile.md#former-applicant-visibility)을 유지합니다. 폐기로 팀 공간 접근 권한을 부여하지 않습니다.

선발에서는 팀원 확정·정원 차감·다른 대기 지원 폐기를 함께 반영하고, 팀 생성에서는 새 팀·팀장 소속·다른 대기 지원 폐기를 함께 반영합니다. 겹친 처리나 재시도로 두 소속·중복 차감·중복 상태 변경을 만들지 않습니다. 폐기된 지원에 대한 늦은 선발은 실패합니다. 알림은 기존 [본인 지원 상태 변경 계열](notifications.md#generation-policy)을 사용합니다. 이후 소속이 종료되어도 이전 폐기를 복원하지 않으며 새 지원은 [종료 사유별 재지원 정책](#reapplication)을 따릅니다.

<a id="application-cancellation"></a>

### 선발 전후의 지원 취소

[이슈 #45의 결정](https://github.com/wejo-team/sku-dreamon/issues/45#issuecomment-6232822752)에 따라 지원자는 **선발·팀원 확정 후에도 자신의 지원을 취소**할 수 있습니다. 선발·확정 시점을 취소의 마감으로 삼지 않습니다.

| 취소 전 지원 상태 | 취소 결과 | 팀원·정원 변화 |
| --- | --- | --- |
| 지원 완료 | 지원 취소 | 확정 전이므로 변화 없음 |
| 검토 중 | 지원 취소 | 확정 전이므로 변화 없음 |
| 선발·팀원 확정 | 지원 취소 | 확정 팀원에서 제거하고 남은 자리 1개 반환 |
| 이미 지원 취소 | 취소 결과 유지 | 중복 반환 없음 |
| 미선발·폐기 | 취소로 전환하지 않으며 기존 종료 상태 유지 | 변화 없음 |

취소 성공 시 지원자의 내 지원 현황과 팀장 화면에 취소 결과를 표시합니다. 선발 후 취소라면 현재 확정 팀원 목록·인원·남은 자리를 함께 갱신하고 공모전별 소속 제한에서도 해당 소속을 해제합니다. 취소한 사용자의 팀 공간 접근은 종료하지만, 팀장의 현재 프로필 열람은 [취소·미선발 후 공개 정책](profile.md#former-applicant-visibility)에 따라 공개 상태와 관계없이 유지합니다. 과거 프로필 사본이나 상세 이력의 보존·표시를 새로 허용하는 결정은 아닙니다.

취소와 선발이 겹치더라도 취소가 성공한 지원을 확정 팀원으로 남겨 두지 않습니다. 취소가 먼저 성공하면 해당 지원의 뒤늦은 선발은 실패합니다. 선발이 먼저 성공한 뒤 취소가 성공하면 팀원 관계를 해제하고 차감했던 자리 한 개를 반환합니다. 재요청으로 자리나 소속을 중복 변경하지 않으며, 구체적인 동시 처리 방식은 개발 계획에서 정합니다.

자리 반환이 모집 마감 상태의 자동 재개를 뜻하지는 않습니다. 재개는 [팀장의 명시적 모집 중 변경](#recruitment-reopening)을 따릅니다. 공고 마감 뒤에도 본인 취소·자리 반환은 허용하지만 새 선발은 [선발 기한](#selection-window)에 따라 막습니다. 지원 이력이 없는 팀장의 탈퇴·팀 삭제는 이 지원 취소 정책에 포함하지 않으며 [MVP에서 제공하지 않습니다](#membership-exclusions).

<a id="reapplication"></a>

### 종료 사유별 재지원

[이슈 #56의 결정](https://github.com/wejo-team/sku-dreamon/issues/56#issuecomment-6232823013)에 따라 본인의 지원 취소가 성공한 뒤 **현재 모집 조건을 충족하면 같은 팀에 즉시 재지원**할 수 있습니다. 별도의 대기 기간은 두지 않으며 선발 후 취소한 경우에도 같습니다.

- [지원 직전 필수 정보 점검](profile.md#before-application)과 현재 공고·팀 모집 상태, 마감, 정원·중복·소속 조건을 다시 확인합니다. 개별 참가 자격은 원문 확인을 안내하되 비즈니스 로직으로 지원을 차단하지 않습니다. 비공개 상태의 재지원은 공개 전환 후에만 접수합니다.
- 취소된 이전 지원과 새로 접수한 현재 지원을 구분합니다. 현재 유효한 지원은 중복 생성하지 않으며, 재지원은 `지원 완료`로 접수하고 이전 선발·팀원 확정을 자동 복원하지 않습니다. 이전 지원에 대한 뒤늦은 선발·취소 요청으로 새 지원을 변경하지 않습니다.
- 취소 이력만을 이유로 재지원을 영구 차단하지 않습니다. 이전 지원의 보존 기간·상세 열람과 저장 구조는 별도 정의합니다.
- 모집이 마감됐거나 현재 정원이 차면 재지원도 접수하지 않습니다. 선발 후 취소로 자리가 생겨도 모집 마감 상태가 유지되고 있다면 바로 재지원할 수 없습니다.
- 팀장의 미선발 처리 이력이 있는 같은 팀에는 MVP에서 재지원할 수 없습니다. 다른 팀에는 현재 모집·소속·공개 프로필 등 조건을 충족하면 지원할 수 있습니다. 미선발 지원을 취소로 바꿔 제한을 우회하지 않습니다.
- 다른 팀의 선발 또는 직접 팀 생성으로 폐기된 지원은 현재 소속이 종료되고 현재 모집 조건을 충족하면 같은 팀에 새로 제출할 수 있습니다. 단, 팀장 탈퇴·팀 삭제가 없는 MVP에서는 직접 팀 생성으로 얻은 팀장 소속을 해제하는 경로를 제공하지 않습니다.
- 지원 취소·폐기 뒤 재지원은 새 지원 ID의 `지원 완료`로 시작합니다. 기존 종료 기록·선발·소속을 복원하지 않으며 다른 공모전의 지원에는 영향을 주지 않습니다.

<a id="recruitment-conditions"></a>

### 모집과 지원 조건

공모전의 팀 수와 모집 가능 표시는 서로 다른 정보를 나타냅니다. 공모전 카드·상세의 팀 수는 모집 상태와 관계없이 **해당 공모전에 연결된 모든 팀**을 셉니다. `모집 중` 표시·필터와 신규 지원 대상 추천은 다음 팀 차원의 공통 기준을 적용합니다.

- 팀 상태가 `모집 중`이고 공고가 접수 중이며, 공고·팀 모집 기한이 지나지 않았고 잔여 정원이 있어야 합니다. 정원 충족·팀장 종료로 닫힌 모집은 [명시적으로 재개](#recruitment-reopening)한 뒤에만 이 조건을 충족합니다. 개별 지원의 검토 시작 자체로 팀 모집을 닫지 않습니다.
- 기한은 [공고 마감 시각·시간대 기준](contests.md#deadline-policy)을 적용하며 정확한 경계부터 접수를 제한합니다. 팀장이 종료했거나 정원이 찬 팀에도 신규 지원을 받지 않습니다.
- 이 표시는 개인의 자격 충족을 보장하거나 중복 지원·공모전별 소속을 확인한 결과가 아닙니다. 제출 시 프로필 공개 상태·현재 유효 지원·소속 등 기존 조건을 다시 확인합니다.
- 모집 역할 불일치나 경험 부족만으로 후보를 제외하거나 지원을 차단하지 않습니다. 공통 참가 대상은 넓은 분류이며 학적·학년의 선택 입력을 정밀한 자동 자격 판정으로 바꾸지 않습니다.

2026-10-19 사용자 결정에 따라 **개별 참가 자격은 비즈니스 로직에서 지원·선발을 제한하는 조건으로 사용하지 않습니다.** 공고 원문 확인을 안내하고 참가 자격 판단은 사용자·주최 측에 맡깁니다. 정보 부족·학적·학년·전공·모집 역할 불일치나 서비스가 해석한 자격 미충족을 이유로 접수를 차단하지 않으며, 팀별 추가 학사 자격 제한이나 별도 자격 확인 대기 지원 상태를 만들지 않습니다. 접수 성공·필수 입력 완료를 공식 자격 충족 보장으로 표시하지 않습니다. 신규 지원의 공개 프로필·필수 입력·공고 및 팀 기한과 공식 정원·중복·공모전별 소속 제한, 공고 등록 전 확인은 유지합니다. 기존 지원의 선발에는 별도의 [선발 기한](#selection-window)을 적용합니다. 이는 #33의 정보 부족 시 접수 허용을 확장한 정책입니다.

[#49의 최신 결정](https://github.com/wejo-team/sku-dreamon/issues/77)에 따른 신규 지원의 공개 상태 조건은 [프로필 정책](profile.md#before-application)을 따릅니다. 지원 후 비공개로 바꾸어도 기존 지원·소속과 지원받은 팀장의 최신 프로필 직접 열람·AI 검토는 유지하며, 일반 사람 검색·AI 사람 추천에는 노출하지 않습니다. AI 입력의 구체 필드·외부 포트폴리오·인증 정보 등 제한은 [추천 정책](matching.md#result-display)을 따릅니다.

모집 마감·정원 충족 후에도 팀장은 기존 지원자의 AI 검토 결과를 확인하고 재요청할 수 있습니다. 새 선발 후보 추천은 현재 유효한 `지원 완료`·`검토 중`만 대상으로 하며 `선발`·`미선발`·`지원 취소`·`폐기`는 제외합니다. 후보 제외가 기존 지원 기록·직접 열람 권한의 삭제를 뜻하지 않으며 별도 개별 재검토 모드를 추가하지 않습니다. 신규 지원 제한·정원 초과 선발 금지는 유지하고, 실제 LLM 내부 구조는 [추천 명세](matching.md)의 TBD로 남깁니다.

공고 조건 변경은 주최 측의 책임으로 두고 기존 지원·선발·팀 소속에 미치는 세부 영향은 [TBD](contests.md#eligibility-changes)로 유지합니다. 자격 제한을 두지 않는 정책이나 관리자 정보 수정만으로 자동 취소·팀원 제외·기존 관계 변경을 추가하지 않습니다.

<a id="recruitment-review"></a>

### 모집과 검토의 병행

[이슈 #29의 결정](https://github.com/wejo-team/sku-dreamon/issues/29#issuecomment-6232872773)에 따라 **검토 시작 자체로 신규 접수를 종료하지 않습니다.** 2026-10-21 상태 단순화에 따라 검토 중은 개별 지원에만 표시합니다. 팀장이 기존 지원자를 검토하는 동안에도 팀 모집이 열려 있고 현재 마감·정원·적용 조건을 충족하면 신규 지원을 받습니다.

| 상황 | 신규 지원과 팀 추천의 모집 상태 판단 |
| --- | --- |
| 검토 전, 마감 전·여석 있음·다른 접수 조건 충족 | 접수 가능. 팀 추천에서도 모집 상태만으로 제외하지 않음 |
| 개별 지원 검토 시작 후, 나머지 조건 동일 | 접수 가능. 지원의 검토 상태로 팀 추천에서 제외하지 않음 |
| 검토 중 정원 충족·마감 도달·팀장 모집 종료 | 신규 접수 불가. 신규 지원 대상 팀 추천에서도 제외 |

추가 접수가 성공하면 현재 지원자 목록에 포함합니다. 새 선발 후보 추천에는 유효한 `지원 완료`·`검토 중` 지원자를 포함합니다. 마감·정원 충족 후 기존 지원자 AI 검토 결과 확인·재요청은 허용하며, 신규 접수를 위한 재개는 [팀장의 명시적 변경](#recruitment-reopening), 실제 선발은 [선발 기한](#selection-window)을 따릅니다.

### 중복 지원과 추천 대상

- 같은 팀에 현재 유효한 지원을 중복 생성하지 않습니다.
- 취소된 이전 지원을 현재 유효한 지원으로 평가하지 않습니다. 취소 후 새 지원은 [재지원 정책](#reapplication)에 따라 접수하며, 원문의 취소 상태 제외 문구를 재지원 금지로 적용하지 않습니다.
- 실제 지원자 매칭은 해당 팀에 지원 완료한 사용자만 평가합니다. 미지원자를 신규 지원자처럼 보여 주지 않습니다.

미선발 이후 같은 팀 재지원은 허용하지 않으며 취소·폐기 뒤 새 지원은 [종료 사유별 정책](#reapplication)을 따릅니다. 현재 새 선발 후보는 유효한 지원 완료·검토 중만 포함하며 선발·미선발·취소·폐기를 제외하는 [추천 정책](matching.md#eligibility)을 따릅니다.

### 표시 정보와 공개 범위

- 사용자 화면과 팀 모집·지원 화면의 표시 이름은 [프로필의 실명 입력 정책](profile.md)을 따릅니다. 원문 본문의 닉네임 표현은 정책 확정 부록의 실명 표시로 대체합니다.
- 지원받은 팀장은 [팀장 예외](profile.md#visibility-priority)에 따라 공개·비공개 상태와 관계없이 지원자의 전체 현재 프로필을 확인합니다. 학사 정보·역량·경험·자기소개·주당 참여 가능 시간·포트폴리오 URL·제목을 포함하며 인증 정보는 제공하지 않습니다. 일반 확정 팀원은 이 예외를 갖지 않습니다.
- 포트폴리오 미등록만으로 팀 탐색·모집·지원을 제한하지 않습니다. 비공개 사용자도 로그인 후 일반 AI를 이용할 수 있지만 신규 팀 지원은 [프로필 공개 상태](profile.md#before-application)에서만 가능합니다. 포트폴리오별 공개 설정은 없으며 URL 접근 안내는 [외부 포트폴리오](profile.md#portfolio)를 따릅니다.
- [공개 상태 전환](profile.md#visibility-changes)은 설명·확인 후 저장 성공 시 적용합니다. 비공개 전환 설명에는 일반 검색·AI 사람 추천 제외와 기존 지원·소속·지원 팀장의 현재 프로필 직접 열람·AI 검토 유지를 함께 안내합니다. 다음 검토는 최신 프로필을 사용하되 과거 AI 답변의 실시간 자동 재작성은 요구하지 않습니다.
- 지원 취소·미선발·폐기·선발 후 취소만을 이유로 팀장의 현재 프로필 열람을 차단하지 않습니다. [열람 관계 유지 정책](profile.md#former-applicant-visibility)에 따라 전체 현재 프로필을 표시합니다. 계정 삭제 시 기존 지원·팀 기록 처리와 상세 이력 보존은 [프로필의 미정 사항](profile.md#open-questions)에 남깁니다.

## 디자인 레퍼런스와 대조 범위

[공식 디자인 PR](https://github.com/wejo-team/sku-dreamon/pull/74)의 참고 앱 동작입니다. 소스·배포 버전과 수행한 검증은 [프로토타입·명세 대조 기록](prototype-alignment.md)에서 관리하며, 아래 화면 동작을 실제 서버 기능의 완료로 취급하지 않습니다.

| 참고 흐름 | 현재 동작 |
| --- | --- |
| 공모전 선택·팀 생성 | 접수 중인 공고를 검색해 고르고 공식 인원 조건을 적용합니다. 고정 N명은 정원을 고정하며 범위·상한 없음은 기본값 없이 입력합니다. 1명은 역할 입력 없이 생성하고 2명 이상은 모집 역할 1~6개를 요구합니다. |
| 입력·분야 | 팀명 2~40자·소개 10~1,000자와 모집 마감을 검사하고 초과 입력을 잘라내지 않습니다. 팀 관심 분야는 공모전에서 상속합니다. 준비 모임 예외·별도 팀 분야·요일/시간 슬롯 입력은 제공하지 않습니다. |
| 목록·지원 | 전체 연결 팀 수와 지원 가능한 모집 필터를 구분합니다. 신규 지원은 공개 프로필·필수 입력·모집 상태·기한·정원·동일 팀 지원 이력을 확인하며 자격 정보 부족은 원문 확인 안내 후 접수합니다. |
| 선발·취소 | 선발 성공 시 확정 팀원과 정원을 함께 갱신합니다. 같은 공모전의 중복 확정 소속과 정원 초과 선발을 막고, 선발 후 본인 취소는 소속·한 자리를 반환합니다. |
| 기존 지원 검토 | 지원받은 팀장의 직접 열람은 현재 프로필을 사용합니다. 모집 마감·정원 충족 후에도 유효한 기존 지원자의 AI 검토 요청을 제공하며 실제 LLM 처리는 하지 않습니다. 자세한 결과·재요청 동작은 [추천 레퍼런스](matching.md#current-reference)를 따릅니다. |

생성·지원·선발·취소는 한 브라우저의 메모리 상태입니다. 서버 권한·동시 요청·영구 저장·계정 간 데이터 공유를 검증한 것이 아닙니다. 공모전 선택창의 로컬 20개씩 더보기는 운영 검색 API·페이지 크기를 확정하지 않습니다.

위 표는 참고 앱에서 확인했던 동작이며 새 제품 정책의 구현 완료를 뜻하지 않습니다. 모집 재개·동시 지원/폐기·참가 자격 비차단과 2026-10-21에 확정한 두 모집 상태·명시적 검토 시작·미선발·선발 기한·재지원 및 소속 경계는 제품 정책입니다. 디자인 반영·검증은 [후속 대조 항목](prototype-alignment.md#policy-follow-up)에서 별도로 확인합니다. 모집 정보 편집·외부 메신저·구체 일정 조율은 관련 미정 사항을 유지합니다.

## 완료 조건

체크는 구현·검증 결과를 뜻하며, 문서 이관이나 명세 검토만으로 체크하지 않습니다.

- [ ] AC-01: 사용자가 공모전을 선택해 관련 팀 목록·상세와 모집 조건을 확인할 수 있다.
- [ ] AC-02: 공모전과 팀명 2~40자·소개/목표 10~1,000자를 입력하고 공식 조건에 맞는 정원과 모집 마감을 설정해 팀을 만든다. 정원 2명 이상은 공통 6개 역할 중 1~6개, 정원 1명은 역할 생략을 적용한다. 팀 분야는 공고에서 가져오고 별도 입력·편집하지 않는다.
- [ ] AC-03: 신규 접수 조건을 충족하는 팀에 지원한 사용자의 지원 내역이 내 지원 현황과 팀장의 지원자 목록에 표시된다. 다른 지원의 검토 시작만으로 팀의 신규 접수를 차단하지 않는다.
- [ ] AC-04: 지원 완료·검토 중·선발 후 자신의 지원을 취소하면 본인과 팀장에게 취소 결과가 표시된다. 선발 전에는 정원이 변하지 않고, 선발 후에는 확정 팀원 제거·소속 해제·자리 한 개 반환을 함께 확인할 수 있다.
- [ ] AC-05: 팀장이 실제 지원자 목록과 조건에 맞는 매칭 후보·근거를 확인하고 지원자를 선발하면, 선발 성공 즉시 해당 지원자가 확정 팀원에 포함되고 정원이 차감된다. 지원자는 별도 수락 없이 그 결과를 확인할 수 있다.
- [ ] AC-06: 공고 마감, 팀 모집 마감 또는 정원 충족 상태에서 신규 지원이 접수되지 않는다.
- [ ] AC-07: 같은 팀에 현재 유효한 지원이 중복 생성되지 않는다. 취소된 이전 지원을 현재 지원으로 평가하지 않으며, 취소 후 재지원은 [현재 모집 조건](#reapplication)을 확인해 접수한다. 미선발 이력이 있는 같은 팀에는 재지원할 수 없다.
- [ ] AC-08: 팀 모집은 모집 중·모집 마감 두 상태, 개별 지원은 지원 완료·검토 중·선발·미선발·지원 취소·폐기 여섯 상태로 구분한다. 팀 전체 검토 중·팀원 확정 상태나 팀 전체 확정 버튼을 제공하지 않는다.
- [ ] AC-09: 선발 즉시 팀원과 정원이 반영되고 팀 공간에 공모전·확정 팀원·모집·매칭 상태를 표시한다. 접근은 팀장·현재 확정 팀원으로 제한한다. 모집 마감·정원 충족 후에도 팀장은 기존 지원자 AI 검토 결과 확인·재요청을 할 수 있으나 신규 지원·정원 초과 선발은 불가하다.
- [ ] AC-10: 팀 모집·지원 화면에 실명이 표시되고 팀장·팀원의 프로필 열람 범위가 [프로필 정책](profile.md#visibility)에 맞게 적용된다. 지원 팀장은 공개 상태와 관계없이 등록된 전체 현재 프로필을 확인하고, 일반 확정 팀원은 공개 프로필만 일반 로그인 사용자와 같은 범위로 열람한다.
- [ ] AC-11: 포트폴리오 미등록자는 팀 이용에서 차별하지 않는다. 비공개 사용자도 탐색·로그인 후 일반 AI를 이용하지만 신규 지원은 공개 전환을 확인·저장한 뒤 제출한다. 자동 공개·자동 접수하지 않는다.
- [ ] AC-12: 지원자가 프로필 변경을 저장한 뒤 팀장이 지원자 목록·상세와 추천을 다시 조회하면 [현재 프로필 기준](profile.md#application-profile)이 적용되며, 프로필 변경 사실을 알리는 별도 알림·배지·전후 비교 안내는 제공되지 않는다.
- [ ] AC-13: 팀 생성·목록·상세·팀 공간에서 정원은 팀장을 포함한 총인원을 뜻한다. 워크스페이스 카드에서는 반복 안내 없이 `확정 인원 / 정원`으로 요약하고, 생성 입력·모집 상세에서는 의미를 안내한다. 총 4명 팀에 팀장만 있으면 확정 인원 1명·남은 자리 3명이며, 지원 접수·검토는 이 수치를 바꾸지 않는다.
- [ ] AC-14: 마지막 한 자리에 대한 동시 선발은 한 명만 성공하며, 성공한 지원자만 확정 팀원에 포함되고 남은 자리는 0명이 된다. 다른 선발은 정원 부족 안내와 함께 실패하여 정원을 초과하지 않고, 이후 신규 지원도 접수되지 않는다.
- [ ] AC-15: 다른 참가 조건을 만족하는 지원자는 모집 역할 불일치만으로 추천에서 제외되거나 지원이 차단되지 않으며, 팀장이 선발 여부를 판단한다. 모집 정보 수정·표시의 세부 검증은 TEAM-07·TEAM-08 결정 후 진행한다.
- [ ] AC-16: 팀장·선발된 팀원 모두 같은 공모전에서 두 번째 선발·팀 생성이 차단되고, 다른 공모전의 소속은 이 제한만으로 차단되지 않는다. 같은 사용자의 동시 선발·팀 생성에서도 공모전별 확정 소속은 하나만 유지된다.
- [ ] AC-17: 취소가 먼저 성공한 지원의 선발은 실패하고, 선발이 먼저 성공한 뒤 취소하면 팀원 제거와 자리 한 개 반환이 반영된다. 반복 취소로 자리 수가 늘어나지 않는다.
- [ ] AC-18: 취소 후 현재 모집 조건을 충족하면 대기 기간 없이 새 지원이 `지원 완료`로 접수되고, 이전 선발 결과는 복원되지 않는다. 이전 지원에 대한 뒤늦은 선발·취소 요청은 새 지원을 변경하지 않는다. 현재 마감·정원 조건을 충족하지 않으면 재지원도 차단된다.
- [ ] AC-19: 마감·정원 등 조건이 같으면 검토 시작 전후 모두 신규 지원을 접수하고 팀 추천의 모집 상태 판단도 같다. 이후 정원 충족·마감·팀장 종료가 발생하면 신규 지원 및 신규 지원 대상 팀 추천에서 제외된다.
- [ ] AC-20: 선발 성공으로 팀 공간 접근이 시작되고 선발 후 취소 성공으로 종료된다. 취소한 사용자의 직접 링크·열린 화면에서 새 조회·요청이 거부되며, 재지원 접수만으로는 접근이 복원되지 않는다. 일반 팀원에게 팀장 관리 권한이나 비공개 정보 열람 권한이 추가되지 않는다.
- [ ] AC-21: 취소·미선발·폐기·선발 후 취소 이후에도 지원받은 팀장은 공개 상태와 관계없이 전체 현재 프로필을 확인한다. 일반 검색에서 비공개로 전환하거나 팀 공간 접근이 종료되어도 이 관계는 유지되며, 공개 상태 변경 자체로 지원 상태·팀 소속을 변경하지 않는다.
- [ ] AC-22: 모든 팀의 목표 정원에 공식 인원 조건을 적용한다. 2~4명 공고에서 1명·5명 저장은 실패하고 2명·4명은 다른 조건을 충족하면 성공한다. 실패 시 팀·소속·정원을 변경하지 않는다.
- [ ] AC-23: 공식 최소 인원이 2명이어도 팀장 1명으로 목표 총 정원 4명인 팀을 생성할 수 있으며, 현재 확정 인원 1명·남은 자리 3명을 표시한다. 목표 정원 검증과 모집 중 현재 인원을 구분한다.
- [ ] AC-24: 공식 인원이 정확히 1명이면 목표 정원 1명·모집 역할 생략·추가 지원 불가를 적용한다. 고정 N명이면 N으로 고정하고, 범위·상한 없음이면 기본값 없이 직접 정원을 입력한다. 준비 모임 예외나 서비스 자체 상한을 추가하지 않는다.
- [ ] AC-25: 등록된 공고가 마감돼도 팀장·현재 팀원과 일반 사용자는 마감 표시·공고 상세·원문 링크를 확인한다. 팀 공간 접근은 기존 권한을 유지하고 신규 지원·신규 지원 대상 추천은 불가하다. 기존 지원자 AI 검토는 별도 허용 정책을 따른다.

- [ ] AC-29: 워크스페이스의 내 팀/내 지원 수, 작업 아이콘의 접근성 이름·선택 상태, 팀 카드의 역할·확정 인원·모집 배지를 확인할 수 있다. 선발·지원 취소·모집 종료는 결과를 설명하는 확인 팝업을 거치고 취소·닫기 시 상태를 변경하지 않는다.

- [ ] AC-31: 지원받은 팀장은 등록된 주당 참여 가능 시간 구간을 모든 프로젝트 합산 자기신고 참고 총량으로 확인하고 팀별 배정·확정 일정·잔여 시간과 혼동하지 않는다. 프로필 공통값 변경 후 각 팀의 현재 지원자 검토에는 변경된 값을 표시하되 팀별 확정 일정·약속을 자동 변경하지 않는다. 미입력은 구간 선택값으로 대신 표시하지 않는다.

- [ ] AC-32: 참가 자격은 원문 확인을 안내하되 비즈니스 로직에서 접수·선발을 차단하지 않는다. 학적·학년·전공·모집 역할 불일치나 정보 부족·서비스의 자격 해석으로 차단하지 않고 팀별 추가 학사 자격 제한·별도 자격 대기 상태를 만들지 않으며 접수 성공을 자격 충족 보장으로 표시하지 않는다. 공개 상태·마감·정원·중복·소속 제한은 유지한다.
- [ ] AC-33: 지원 후 비공개 전환은 기존 지원·소속을 유지하고 해당 지원을 받은 팀장에게 최신 프로필 직접 열람·AI 검토를 허용한다. 일반 팀원이나 지원 관계 없는 팀에 권한을 확대하지 않고 일반 사람 검색·AI 사람 추천에는 노출하지 않는다.
- [ ] AC-34: 새 선발 후보 추천에는 현재 유효한 지원 완료·검토 중만 포함하고 선발·미선발·취소·폐기는 제외한다. 후보 제외로 기존 기록을 삭제하지 않으며, 현재 권한·지원 관계에 따라 결과를 확인·재요청한다.
- [ ] AC-35: 공모전 팀 수는 모집 상태와 관계없이 연결된 모든 팀을 센다. 정원 충족이나 모집 종료는 팀 수를 줄이지 않지만 모집 중 필터와 신규 지원 가능 표시는 즉시 달라진다.

- [ ] AC-36: 같은 공모전의 서로 다른 팀에 동시 지원할 수 있다. 한 팀 선발 성공 시 즉시 소속을 확정하고 같은 공모전의 다른 지원 완료·검토 중 지원만 폐기한다. 다른 공모전과 이전 종결 지원은 변경하지 않으며, 선발 실패 시 다른 지원도 그대로 유지한다.
- [ ] AC-37: 폐기 상태·사유를 본인과 지원 팀장에게 표시하고 대기 수·새 AI 후보·선발 대상·팀 공간 접근에서 제외한다. 기록과 지원 팀장의 최신 프로필 직접 열람·기존 지원서 AI 검토 관계는 유지하며, 이후 선발된 팀 취소만으로 폐기 지원을 복원하지 않는다.
- [ ] AC-38: 팀장만 확인 후 모집을 다시 시작할 수 있다. 공고·팀 기한과 잔여 정원 조건을 충족할 때만 모집 중으로 변경하고 목록·필터·신규 추천·접수에 반영한다. 자리 반환은 자동 재개하지 않으며 취소·실패·기한 경과·정원 충족에서는 기존 상태를 유지한다.
- [ ] AC-39: 팀장 변경·위임 기능을 제공하지 않는다. 일반 팀원·지원자가 모집 재개나 팀장 관리 행동을 실행할 수 없다.

- [ ] AC-40: 해당 팀장의 명시적 검토 시작으로만 지원 완료가 검토 중으로 바뀐다. 목록·상세 조회와 AI 검토 요청·결과 열람은 상태를 바꾸지 않고, 검토 중을 거치지 않은 지원 완료에서도 선발·미선발을 처리할 수 있다.
- [ ] AC-41: 팀 모집 기한 경과·팀장 종료 뒤에도 공고 접수 마감 전이고 여석·현재 지원 및 소속 조건을 충족하면 기존 지원을 선발할 수 있다. 정원 충족 뒤 취소로 여석이 생긴 경우도 같으며 신규 접수는 명시적 재개 전까지 막는다. 공고 마감 경계부터 새 선발을 거부하고 본인 취소·자리 반환·기존 열람·AI 검토는 유지한다.
- [ ] AC-42: 팀장은 지원 완료·검토 중만 미선발로 처리한다. 미선발·지원 취소·폐기된 기존 시도를 다시 검토·선발하거나 다른 종료 상태로 바꾸지 않고, 미선발을 취소로 전환해 같은 팀 재지원 제한을 우회할 수 없다.
- [ ] AC-43: 모집 종료·정원 충족·팀 또는 공고 기한 경과만으로 대기 지원이 자동 미선발되지 않는다. 공고 마감 후 미처리 지원은 기존 상태와 마감·선발 불가 안내를 함께 표시하며 팀장은 미선발로 정리할 수 있다.
- [ ] AC-44: 미선발된 같은 팀에는 재지원하지 못하지만 다른 팀에는 현재 조건을 충족하면 지원할 수 있다. 폐기 뒤 현재 소속이 끝나고 모집 조건을 충족하면 새 지원으로 접수하며 기존 종료 상태·선발·소속을 복원하지 않는다.
- [ ] AC-45: 같은 공모전의 확정 팀원·팀장은 신규 지원을 제출할 수 없다. 일반 팀원이 본인 취소로 소속을 종료하면 현재 조건을 확인해 다른 팀에 지원할 수 있고, 다른 공모전의 신규 지원은 이 제한만으로 막지 않는다.
- [ ] AC-46: 팀 생성 성공 시 새 팀·팀장 소속과 같은 공모전의 본인 다른 대기 지원 폐기가 함께 반영된다. 생성 실패 시 어느 것도 일부만 반영하지 않으며 다른 공모전·기존 종료 지원은 변경하지 않는다. 폐기 사유에서 직접 팀 생성과 다른 팀 선발을 구분한다.
- [ ] AC-47: 팀장 선발 취소·강퇴·팀장 탈퇴·팀 삭제를 제공하지 않는다. 팀 생성 전에 팀장은 같은 공모전의 다른 팀으로 이동하거나 잘못 만든 팀을 삭제할 수 없음을 안내한다. 일반 팀원의 본인 취소와 현재 소속 해제는 유지한다.
