# 에이전트 작업 안내

이 문서는 에이전트가 작업을 시작할 때 읽는 최소 공통 지침입니다. 기술 규칙은 영역별 가이드를 참조하고 여기에 복제하지 않습니다.

## 필요한 문서만 읽기

- 작업 시작·재개·인계 시 [기준 브랜치 확인](development/workflow.md#development-baseline)에 따라 최신 `origin/develop`의 문서와 기준 SHA를 확인합니다. 현재 체크아웃이 `main`이거나 오래된 작업 브랜치라면 그 문서를 최신 개발 기준으로 간주하지 않습니다. `main`·문서 사이트는 릴리스 상태를 확인할 때 사용합니다.
- [문서 인덱스](README.md)와 이 안내에서 시작해 아래 표의 해당 행만 선택합니다. 여러 영역을 바꾸면 필요한 행을 함께 적용합니다.
- 구현에는 해당 기능 명세를 함께 읽고, 추가 기술 영역은 [개발 인덱스](development/README.md)에서 찾습니다.
- 경로·심볼을 먼저 검색하고 필요한 파일과 절을 읽습니다. `docs/` 전체를 일괄로 출력하거나 링크를 따라 전체 문서를 수집하지 않습니다.
- 같은 세션에서 읽은 지침은 내용이나 작업 범위가 바뀌었을 때 갱신합니다. 대화가 요약되거나 작업을 인계받으면 현재 계획과 변경 파일을 기준으로 필요한 지침을 다시 확인합니다.
- 작업 범위가 바뀌면 새로 관련된 문서만 추가합니다. 문서에 없는 정책은 기존 구현·승인 기록을 확인하고, 중요한 미정 사항을 임의로 결정하지 않습니다.

## 작업 원칙

- 사용자의 현재 요청과 이미 승인된 범위를 우선합니다. 이 지침은 이미 허용된 작업에 반복 승인을 요구하지 않습니다.
- 새로운 기능은 명세를 먼저 검토한 뒤 개발 계획과 구현으로 진행합니다. 에이전트가 작성한 `승인됨` 문구는 사람의 승인 기록을 대신하지 않습니다.
- 예정된 구조와 명령을 이미 구현된 것으로 취급하지 않습니다. 실제 파일과 설정을 확인합니다.
- 서비스명과 소개 문구는 [이름과 표기](branding.md)를 따릅니다. 인증, 도메인 모델, 운영 배포 플랫폼처럼 미정인 사항을 초기 기반 작업에서 임의로 확정하지 않습니다.
- 기존 사용자 변경을 보존하고 요청 범위에 필요한 파일만 수정합니다.
- 새 도구·추상화는 실제 필요가 있을 때 추가합니다. 빈 테스트로 CI를 통과시키지 않습니다.
- 변경에 맞는 검사만 실행합니다. 검사가 실패하면 원인을 확인하고, 실행하지 못한 검사는 이유를 기록합니다.
- 커밋·게시에는 관련 파일만 포함합니다. 실제 `.env`, 비밀값, 개인정보, 운영 데이터는 포함하지 않습니다.
- 브랜치를 만들기 전에 [작성·Git 컨벤션](development/conventions.md)의 브랜치 규칙을 확인하고, 사람과 같은 작업 종류 기준의 이름을 사용합니다. 도구가 이름을 자동 제안해도 저장소 규칙에 맞게 지정합니다.
- 요청한 기능이 실제로 동작하는지와 문서의 명령이 일치하는지 확인합니다. 설정 파일의 존재만으로 실행·검증 성공을 주장하지 않습니다.

## 작업 분할과 인계

- 인계에는 작업 경로·브랜치와 문서 기준 `develop` SHA를 포함합니다. 이어받는 작업은 최신 `develop`과 관련 문서의 차이를 확인하고, 기존 사용자 변경을 보존한 상태에서 적용 범위를 정합니다.
- 다른 에이전트에 맡길 때는 [팀 작업 흐름](development/workflow.md)의 「작업 분할과 인계」 항목을 전달합니다. 관련 지침의 경로·절을 지정하고 기술 규칙의 본문을 복제하지 않습니다.
- 각 작업의 수정 가능 파일·심볼과 범위 밖 항목을 명확히 합니다. 같은 파일이나 아직 합의하지 않은 인터페이스를 여러 작업자가 동시에 수정하도록 나누지 않습니다.
- 인계받은 에이전트는 맡은 작업과 관련 계약을 확인합니다. 범위를 넓히거나 중요한 계약을 바꿔야 하면 인계한 에이전트나 사람에게 알리고 계획에 반영합니다.
- 인계한 에이전트는 변경 diff와 검증 근거를 확인해 통합합니다. 에이전트의 검토 결과는 사람의 승인 기록을 대신하지 않습니다.

## 완료 보고

변경 결과, 수행한 검증과 결과, 남은 제한, 관련 PR을 간결하게 보고합니다. 명세 합의·구현 완료·배포 완료를 구분합니다. 운영 배포를 수행하지 않았다면 배포했다고 쓰지 않습니다.
