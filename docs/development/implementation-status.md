## PR 검토·반영 순서

기능별로 독립 검토할 수 있도록 PR의 비교 기준을 나눴습니다. 선행 PR의 코드를 반복해서 리뷰하지 않고 해당 PR의 변경만 확인합니다.

1. 정책 **#149**를 먼저 확인합니다.
2. 공고 입력 **#148**, 인증 **#150**, 프로필 **#151**은 #149를 기준으로 독립 검토합니다.
3. 공고 목록 **#152**는 같은 공고 문서를 사용하는 #148 다음입니다.
4. 팀 생성 **#153**은 프로필 잠금·텍스트 처리를 사용하는 #151 다음입니다.
5. 신규 지원 **#154**는 공통 참여 조건·재시도 처리를 사용하는 #153 다음입니다.

각 기능은 원자적 구현 커밋으로 작성했고, 리뷰에서 발견한 수정은 별도 목적의 커밋으로 남겼습니다. 의존 브랜치를 반영한 merge commit은 작업 브랜치의 연결 기록입니다. `main` 반영은 저장소의 [Squash merge 절차](workflow.md)를 따릅니다. 이 작업에서는 PR을 병합하지 않았습니다.

## 검증 결과

- 모든 기능을 조합한 로컬 PostgreSQL 18.6에서 **631개 테스트 통과**. Ruff·format·mypy와 Alembic 모델 차이를 확인합니다.
- 별도 격리 DB·HTTPS ASGI 요청으로 전체 흐름 1건 통과: 가입·자동 로그인, 두 사람의 프로필 저장, 비공개 상태 팀 생성, 비공개 지원 거부, 공개 후 지원, 재전송, 팀장 지원자 조회·선발, 알림, 선발자 취소·자리 반환·팀 공간 권한 종료, 로그아웃.
- 문서 원본 링크 58개, VitePress 빌드, 생성 사이트 링크·앵커·자산 검사 통과. 초기 공고/인증 문서의 게시 앵커 오류도 수정했습니다.
- PR CI는 저장소 기준 PostgreSQL 17.11에서 백엔드 검사와 마이그레이션을 실행합니다. 최신 실행은 각 PR의 Checks에서 확인합니다. 프론트 영향이 없는 경우 기존 규칙에 따라 프론트 실행 검사는 생략됩니다.
- 독립 리뷰어의 추가 경계·경합 검사도 실제 격리 schema에서 실행했습니다. 운영 DB나 실제 사용자 데이터는 사용하지 않았습니다.

설치·명령은 [로컬 실행](local-development.md), 범위는 [테스트·CI](testing.md)를 따릅니다. 이 결과는 실제 프론트의 브라우저 통합 검증이나 운영 배포 결과가 아닙니다.

## 다음 작업과 남은 경계

- **제품 화면 연결:** 현재 시연 데이터 기반 화면을 실제 인증·프로필·팀·지원·알림 API에 연결하고 브라우저 흐름을 검증합니다.
- **운영 데이터:** 실제 학사 원장과 공고 자료를 확인·적재합니다. 임의 자료를 공식 원장으로 만들지 않았습니다.
- **인증 운영:** 실제 비밀번호 차단 목록·버전, origin·서명 키, HTTPS/reverse proxy 또는 같은 site CORS, 세션·시도 키 정리와 보존을 준비합니다. 차단 목록이 없으면 가입을 허용하지 않습니다.
- **배포:** 마이그레이션 적용·운영 설정·관측·복구 절차와 배포 환경을 준비합니다. 이번 작업은 운영 배포를 수행하지 않았습니다.
- **기존 보류 정책:** 모집글/지원 메시지 편집, 공고 조건 변경 영향, 계정 탈퇴·보존 등은 기존 미정 또는 MVP 제외 범위를 유지합니다.
- **AI:** 설계가 진행되지 않았으므로 제공자·실행·저장·API 구현을 진행하지 않았습니다.
